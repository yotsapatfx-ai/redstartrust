## 2. วิธีแก้งานชิ้นที่ 1 — สำคัญที่สุด อ่านก่อนลงมือ

หน้าแรก Minimal Luxury **ไม่ได้แก้ที่ไฟล์ผลลัพธ์โดยตรง** มันถูกสร้างจากสองไฟล์:

```
design/Main.dc.html      โครงสร้าง HTML + แผนที่โลก (SVG ฝังไว้ 175 ประเทศ)
design/build-mockup.py   สไตล์ทั้งหมด + สคริปต์ทั้งหมด + ข้อมูลสมมติ + โลโก้ (base64)
        │
        └── python build-mockup.py  →  design/redstartrust-homepage-mockup.html
```

**ขั้นตอนแก้:**
1. แก้ `Main.dc.html` (โครงสร้าง/ข้อความ) หรือ `build-mockup.py` (CSS/JS/ข้อมูล)
2. รัน `python build-mockup.py` จากโฟลเดอร์ `design`
3. เปิดไฟล์ผลลัพธ์ตรวจด้วยเบราว์เซอร์
4. เผยแพร่ทับลิงก์เดิม (ดูข้อ 3)

> **ห้ามแก้ `redstartrust-homepage-mockup.html` ตรง ๆ** เพราะจะถูกเขียนทับทันทีที่รันบิลด์ครั้งถัดไป

> **ระวัง `</div>` เกินใน `Main.dc.html`** — เจอมาแล้วสองจุด (บล็อกแผนที่ และบล็อกเทียบตัวต่อตัว) ทั้งสองจุดทำให้
> คอนเทนเนอร์ `width: 1200px` ถูกปิดก่อนเวลา เนื้อหาที่ตามมาจึงกว้าง 1440px และไม่ตรงแนวกับบล็อกอื่น (แก้แล้ว 27 ส.ค. 69)
> **ทุกครั้งที่เพิ่มบล็อกใหม่ ให้ตรวจสมดุล `<div>` ของส่วนนั้นก่อน** และวัดจาก DOM ว่าได้ `left 120 · width 1200` จริง

**เครื่องมือใน `tools/`** (ใช้เฉพาะตอนต้องสร้างข้อมูลใหม่ ปกติไม่ต้องรัน):
`mkmap.py` แปลง GeoJSON เป็น SVG · `mkpins.py` คำนวณตำแหน่งหมุด · `fetch-logos.py` ดึงโลโก้ · `build-logo-data.py` แปลงเป็น base64

### ค่าฉายภาพของแผนที่ — จดไว้กันหลงทางรอบหน้า

แผนที่ใน `Main.dc.html` ใช้ **Robinson projection · viewBox `0 0 1000 455`** ค่าที่แปลงพิกัดจริงเป็นตำแหน่งบนแผนที่คือ

```
SCALE = 202.0 · MINX = -2.3020 · MAXY = 1.3160
X = (robinson_x - MINX) * SCALE      Y = (MAXY - robinson_y) * SCALE
```

**อย่าใช้ค่าที่อยู่ใน `tools/mkpins.py`** ค่านั้นเดาจากสมมติว่าแผนที่กว้างเต็ม ±180° ซึ่งไม่ตรงกับข้อมูลจริง
ทำให้หมุดเดิมคลาดจากประเทศตัวเองสูงสุด 54px (แก้แล้ว 27 ส.ค. 69)

**ค่าข้างบนได้มาอย่างไร:** ต้นทาง GeoJSON อยู่ในโฟลเดอร์ชั่วคราวของ session เก่าและหายไปแล้ว จึงไล่หาค่าที่ทำให้
จุดภายในของ 6 ประเทศที่รู้คำตอบแน่นอน (path ที่มี `data-hi="1"` = US/GB/CY/AE/ZA/AU) ตกในรูปของตัวเองครบทุกประเทศ
แล้วเลือกชุดที่จับคู่ประเทศอื่นได้มากที่สุด — ตรวจซ้ำด้วย `isPointInFill()` บนเบราว์เซอร์แล้ว

ตอนนี้ path บนแผนที่ **91 ประเทศมี `data-iso` และ `data-vol` ติดอยู่แล้ว** (จากทั้งหมด 175) ถ้าจะเพิ่มประเทศ
ให้ใช้ค่าฉายภาพข้างบนทดสอบว่าจุดตกใน path ไหน แล้วเขียนแอตทริบิวต์ลงไป — ชิลี (CL) ยังจับคู่ไม่ได้เพราะรูปแคบเกิน

**หน้าสมาชิก — ข้อที่ต้องยึด**
- **ฟอร์มไม่ต่อระบบจริง** กดส่งแล้ว preventDefault แล้วขึ้นคำเตือน ไม่มีการรับหรือส่งข้อมูลใด
- ทุกช่องตั้ง `autocomplete="off"` และ**มีกล่องเตือนสีส้มบนหน้าว่าอย่ากรอกรหัสผ่านจริง**
- แผงขวาย้ำว่า **การมีบัญชีไม่มีผลต่อดาวหรือคะแนนของโบรกเกอร์ใด** ตาม Core Pillar
- **หน้าสมัครเลือกบทบาทได้ 2 แบบ** — ผู้ใช้ทั่วไป / ตัวแทนโบรกเกอร์ เลือกตัวแทนแล้วจะเพิ่มชื่อโบรก เขตกำกับ เลขใบอนุญาต ตำแหน่ง และอีเมลโดเมนบริษัท — ปุ่มเปลี่ยนเป็น "ส่งคำขอเปิดบัญชีตัวแทน" เพราะต้องรอทีมตรวจยืนยันก่อน

**บล็อกที่อยู่สองหน้า — ใช้วิธีย้าย DOM ไม่ใช่ก็อปสองชุด**

| บล็อก | id | อยู่หน้า |
|---|---|---|
| ตารางอันดับ + เทียบตัวต่อตัว | `#rank-section` | Home กับ Rating |
| วอลลุ่มรายโซน | `#vol-zones` | Home กับ Trade Analytics |

`showPage()` ย้ายตัวบล็อกจริงไปไว้ใน `[data-slot]` ของหน้าที่กำลังแสดง
**ห้ามก็อปเป็นสองชุดเด็ดขาด** เพราะ id จะซ้ำ (`#rk-body`, `#cmp-body`, `#vz-*`) แล้วสคริปต์จะวาดลงได้ที่เดียว
หัวข้อของ `#rank-section` (`#rank-head`) ซ่อนเมื่ออยู่หน้า Rating เพราะหน้านั้นมีหัวข้อใหญ่อยู่แล้ว

แถบความน่าเชื่อถือกับท้ายเว็บใช้ร่วมกันทุกหน้า

**วิธีทำงาน:** `.page[data-page]` สี่บล็อกกับ `.hd-page[data-hero]` สี่หัวข้อ ซ่อน/แสดงด้วย `hidden`
`showPage(p)` สลับให้ทั้งคู่พร้อมตั้ง `aria-current` บนเมนู

> **เมนูต้องกดได้โดยไม่พึ่ง `location.hash`** เพราะไฟล์ที่เสิร์ฟจาก `data:` URL เขียน `location.hash` ไม่ได้
> ตัวจัดการคลิกจึงเรียก `showPage()` ตรง ๆ แล้วค่อยพยายามอัปเดต URL ใน `try/catch`
> **ตัวสลับหน้าต้องรันท้ายสุดของสคริปต์** เพราะแผนที่ต้องบูตตอนหน้าแรกยังมองเห็นอยู่ ไม่งั้นหมุดจะวัดขนาดไม่ได้

## 6. หลักการออกแบบที่ยึดมาตลอด — อย่าทิ้ง

1. **ดาวกับคะแนนเป็นคนละระบบ** ดาว = ผ่าน/ไม่ผ่าน · คะแนน = เปรียบเทียบ · ต้องเขียนกำกับทุกที่ที่อยู่ด้วยกัน
2. **ตัวเลขบนหน้าต้องนับได้จริงจากข้อมูลในหน้า** — สถิติหัวเว็บคำนวณสด ไม่พิมพ์ทิ้งไว้ · คะแนนรวม = ค่าเฉลี่ย 4 ด้านของปีนั้นเป๊ะ ๆ (ตรวจแล้ว 0 กรณีไม่ตรง)
3. **สถานะว่างต้องพูดตรง ๆ** เช่น *"ยังไม่เปิดตรวจในภูมิภาคนี้ — เราจะไม่ประกาศอันดับของขอบเขตที่ยังไม่ได้เข้าไปตรวจด้วยตัวเอง"* ห้ามปล่อยว่างหรือใส่ข้อมูลปลอม
4. **ทิศทางดี/แย่เขียนเป็นคำ ไม่ใช้ลูกศรอย่างเดียว** เพราะในตารางเดียวกันมีทั้งค่าที่ยิ่งสูงยิ่งดี (คะแนน) และยิ่งต่ำยิ่งดี (สเปรด ต้นทุน)
5. **รายที่ถูกเพิกถอนยังต้องแสดงในทะเบียนเสมอ** ตาม Core Pillar ข้อ 1
6. **บทรีวิวและคำชี้แจงห้ามเปลี่ยนดาว** ต้องมีข้อความกำกับบนหน้า
6a. **ห้ามใส่ชื่อโบรกเกอร์จริงในแถบเตือนภัยหรือข่าวเชิงลบ ถ้าไม่มีเอกสารจากหน่วยงานกำกับอ้างอิง**
   การประกาศว่าโบรกรายใดเถื่อนหรือมีข่าวเสียหายโดยไม่มีหลักฐาน คือการกล่าวหา ไม่ใช่การรายงาน
   ในต้นแบบจึงใช้ชื่อสมมติทั้งหมด และต้องคงไว้แบบนี้จนกว่าจะมีแหล่งอ้างอิงจริง
6c. **การ์ดที่ได้ดาวตั้งแต่ 1 ดวงขึ้นไปมีลาย "คลื่น + ดาว" จาง ๆ เป็นพื้นหลัง**
   ดาวจาง 5.5% มุมขวา + เส้นคลื่นเรียว 7 เส้น ความเข้ม 11% กวาดจากล่างซ้าย (ปรับตามภาพที่ Boss ส่ง 27 ส.ค. 69)
   ควบคุมด้วย `data-stars` ใช้กับการ์ด 3 อันดับแรก การ์ดย่อย และการ์ดหน้ารีวิว
   เป็น background จึงอยู่หลังตัวอักษรเสมอ ตรวจคอนทราสต์แล้วไม่กระทบการอ่าน
6d. **หน้า Broker Alerts ต้องแสดงคำชี้แจงของโบรกเกอร์คู่กับเรื่องที่แจ้งเตือนเสมอ**
   และทุกใบต้องมีบรรทัดกำกับว่า **คำชี้แจงไม่มีผลต่อจำนวนดาวหรือคะแนน** ตามหลักข้อ 6
   เรื่องที่ปิดแล้วและรายที่ถูกเพิกถอนยังต้องคงอยู่ในหน้า ไม่ลบทิ้ง
7. **แผง RedStar Thinking อ่านได้เฉพาะตัวเลขที่แสดงอยู่บนหน้า** ห้ามสร้างข้อมูลใหม่ ห้ามมีผลต่อดาวหรือคะแนน
   และต้องเขียนกำกับไว้ท้ายแผงว่าในต้นแบบนี้ข้อความสร้างจากกฎ ยังไม่ได้ต่อกับโมเดลจริง
8. **ห้ามใช้ media query กับเลย์เอาต์ของหน้านี้** เพราะเฟรมตรึงที่ 1440px แต่ media query จับความกว้าง
   ของหน้าต่างจริงซึ่งเล็กกว่าเสมอ เคยทำให้กริดสองคอลัมน์ถูกยุบทิ้งโดยไม่ตั้งใจมาแล้ว

## 7. วิธีตรวจงานก่อนส่งทุกครั้ง

รันสคริปต์ตรวจคอนทราสต์ผ่าน `javascript_tool` บนหน้าที่เปิดในเบราว์เซอร์ — ไล่ทุก element เทียบสีตัวอักษรกับพื้นหลังจริง (ซ้อนสีโปร่งใสด้วย) ตามสูตร WCAG 2.1 เกณฑ์ 4.5:1 (ตัวใหญ่ 3:1)

**ต้องตรวจ:** ทุกหมวดสินทรัพย์ · ทุกปี · ทุกภูมิภาค · ทั้งสถานะปกติและหลังกดใช้งาน · และ **อ่าน console หา error ทุกครั้ง**

**บทเรียนที่เจ็บที่สุด:** มีครั้งที่สคริปต์ตายทั้งไฟล์ (ตาราง + การ์ด + movers ว่างหมด) แต่ **console ไม่ขึ้น error ให้เห็น** ต้องไล่เช็คตัวแปร global ทีละตัวถึงเจอ — สาเหตุคือฟังก์ชันถูกเรียกตอนโหลดก่อนที่ตัวแปรที่มันใช้จะถูกสร้าง **ทุกครั้งที่เพิ่มฟังก์ชันที่ถูกเรียกตอนโหลด ต้องใส่ guard `typeof X === "undefined"` เสมอ**

## 8. ข้อมูลในต้นแบบ — สมมติทั้งหมด

- **โบรกเกอร์ 61 ราย · ประเทศ 7 · หมวด 6 · ปี 2024–2026** (ขยายจาก 12 ราย เมื่อ 27 ส.ค. 69)
- **ทุกหมวดในทุกประเทศมี 10 ราย** — `CAT_MEMBERS` เก็บรายชื่อหมวดละ 13 ราย ขึ้นไป แล้ว `rosterFor()` หยิบมา
  10 รายด้วยลำดับที่คงที่จากรหัสประเทศ (`ROWS_PER_CAT = 10`) แต่ละประเทศจึงได้ชุดรายชื่อไม่ซ้ำแบบกัน
- **ชื่อโบรกเกอร์ทั้งหมดเป็นผู้ให้บริการที่มีอยู่จริง** แต่คะแนน ดาว ต้นทุน และหน่วยงานกำกับรายประเทศเป็นข้อมูลสมมติ
- โบรกที่ไม่ได้เขียนแถวไว้ใน `ROSTER` ของประเทศนั้น ใช้ค่าตั้งต้นจาก `BASE` แล้วขยับด้วยค่าคงที่ที่หาจากชื่อ
- ตัวเลขสร้างแบบ **คงที่จากชื่อ** (hash) ไม่ใช่สุ่มใหม่ทุกครั้ง — เปิดคนละเครื่องเห็นเลขเดียวกัน
- **โลโก้ 11 จาก 12 รายเป็นของจริง** ดึงจากโดเมนทางการของโบรกเกอร์เอง ฝังเป็น base64 ใน `build-mockup.py` และเก็บสำเนาที่ `prototype/logos/` — ดูที่มาและข้อจำกัดใน `prototype/logos/README.md`
- **วอลลุ่มบนแผนที่ 91 ประเทศเป็นตัวเลขที่ผมตั้งไว้เองเป็นตัวอย่าง** ไม่ได้มาจากแหล่งข้อมูลใด เขียนกำกับไว้ในแถบอธิบายสีแล้ว
  - `data-vshare` = ดัชนีวอลลุ่มรวมของประเทศนั้น · `data-mix` = สัดส่วนที่แบ่งไปแต่ละสินทรัพย์
    เรียงตาม `["fx","futures","stocks","crypto","exchange","fund"]`
  - `data-mix` มาจากกลุ่มพฤติกรรม 6 แบบ: `retailfx` (ฟอเร็กซ์นำ) · `mature` (หุ้น/กองทุนนำ) · `fxhub`
    (ศูนย์กลางฟอเร็กซ์) · `asiaretail` · `cryptolean` (คริปโตสัดส่วนสูง) · `wealth` (กองทุนนำ)
  - **ชั้นสีคิดจากส่วนแบ่ง ไม่ใช่อันดับ** (>=5% = สูงสุด · >=1.5% = สูง · >=0.4% = ปานกลาง · ต่ำกว่านั้น = ต่ำ)
    จึงสลับหมวดแล้วเห็นแผนที่เปลี่ยนจริง เช่นหมวดฟอเร็กซ์อเมริกาจะจางลงมาก แต่หมวดกองทุนจะเข้มที่สุด
- **บทความ 14 บทในบล็อกข่าวเป็นตัวอย่างที่ผมเขียนเอง** หัวข้อเลือกให้เป็นเรื่องวิธีอ่านต้นทุน/ใบอนุญาต
  ไม่ใช่การกล่าวอ้างผลตรวจของโบรกรายใด และมีข้อความกำกับใต้กริดว่ายังไม่มีเนื้อหาจริง
- ข้อมูลจำลองมีจุดที่ไม่ตรงความจริง เช่น XM อยู่หมวด Exchange ในอังกฤษ — **เป็นข้อจำกัดของข้อมูลสมมติ ไม่ใช่บั๊กของดีไซน์**

## 10. ข้อจำกัดของเครื่องมือในเครื่องนี้

- **ไม่มี Node.js** → ประกอบ design canvas แบบแก้องค์ประกอบได้ไม่ได้ · ไฟล์ `Main.dc.html` + `canvas.json` เตรียมไว้พร้อมแล้วสำหรับตอนที่ติดตั้ง
- **Bash tool กลืน backslash** → เขียนสคริปต์ Python ที่มี `\n` หรือ `\'` ให้ใช้ **Write tool สร้างไฟล์** อย่าใช้ heredoc
- **Console ภาษาไทยเป็น cp874** → `print()` ที่มีอักขระอย่าง `·` จะพัง ใช้ ASCII ในข้อความ print
- **หน้าเว็บที่เผยแพร่โหลดไฟล์ภายนอกไม่ได้** → รูปทุกอย่างต้องฝังเป็น data URI
- **ตัดโค้ดด้วย slice แล้วเหลือ `});` ลอย → สคริปต์ตายทั้งไฟล์ แต่ console ไม่ขึ้น error** — วิธีตรวจเร็ว: เช็คว่า `typeof showPage` เป็น `undefined` ไหม ถ้าใช่คือสคริปต์ตายทั้งก้อน ไม่ใช่เฉพาะส่วนที่แก้
- **ไฟล์ที่บิลด์เป็นเนื้อหน้า ไม่มี doctype/charset** — ส่วนหัวเติมให้ตอนเผยแพร่ ถ้าเอาไฟล์ไปเปิดบน static server ตรง ๆ ภาษาไทยจะเพี้ยน → ใช้ `_preview.html` ที่ห่อ doctype+charset ไว้ตรวจแทน
- **วิธีตรวจงานตอนนี้** — `.claude/launch.json` มีคอนฟิก `mockup` เปิด static server ที่ port 8731 ชี้ไปที่โฟลเดอร์ design (เปิดไฟล์ตรงด้วย file:// ไม่ได้อีกแล้ว)
- **Windows ไม่เรนเดอร์ธง emoji** → ธงทุกใบต้องวาดเป็น SVG
