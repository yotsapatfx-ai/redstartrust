# P01 · สถานะการกำกับดูแลและตัวตนนิติบุคคล — ไฟล์ 5/6 (ข้อ 201–250)

**มิติ D1 · น้ำหนักเสา 10% · คุมด่าน G1 และ G6**
**ขอบเขตไฟล์นี้:** S09 กองทุนชดเชยนักลงทุนและประกันภัยเพิ่มเติม · S10 ที่อยู่จริง ช่องทางติดต่อตามกฎหมาย และการพิสูจน์ตัวตนองค์กร

## S09 · กองทุนชดเชยนักลงทุนและประกันภัยเพิ่มเติม (201–225)

**P01-201 ● · เว็บไซต์อ้างว่ามีกองทุนชดเชยนักลงทุนคุ้มครองหรือไม่** `w3` `WEB`

- **ตรวจอะไร:** ตรวจว่าเว็บสาธารณะของโบรกมีข้อความอ้างถึงกองทุนชดเชยนักลงทุน (investor compensation scheme / investor protection fund / กองทุนคุ้มครองผู้ลงทุน) หรือไม่ โดยกวาดหน้าแรก footer หน้า Regulation หน้า Legal หน้า Client Fund Protection และหน้า FAQ บันทึกข้อความที่พบแบบคำต่อคำ URL ของหน้าที่พบ และจำนวนคลิกจากหน้าแรกจนถึงจุดนั้น ข้อนี้ตรวจเฉพาะ "มีการอ้างหรือไม่" ยังไม่ตรวจว่าจริงหรือไม่
- **ขั้นตอนการตรวจ:**
  1. เปิดเบราว์เซอร์โหมดไม่บันทึกประวัติ พิมพ์โดเมนของโบรกเอง **ห้ามเข้าผ่านลิงก์โฆษณาหรือลิงก์แนะนำ**
  2. กด `Ctrl+F` ค้นทีละคำบนหน้าแรก: `compensation` `investor protection` `guarantee fund` `ชดเชย` `คุ้มครองผู้ลงทุน`
  3. เปิดหน้า Regulation · Legal · Security of Funds · FAQ · Terms ทีละหน้า แล้วทำซ้ำขั้น 2 กับทุกหน้า
  4. คัดลอกข้อความทุกจุดที่พบลงตาราง พร้อม URL และจำนวนคลิกจากหน้าแรก
  5. จับภาพเต็มหน้าทุกหน้าที่พบข้อความ ให้เห็น URL และนาฬิกาเครื่อง
  6. เก็บสำเนาถาวร (PDF) ของทุกหน้าที่พบ แล้วบันทึกผลและตั้งชื่อไฟล์ตามรูปแบบ Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพเต็มหน้าทุกหน้าที่พบข้อความ (`RST-BRKA-P01-201-01` เป็นต้นไป) · ตารางข้อความที่พบพร้อม URL และจำนวนคลิก · สำเนาถาวร PDF ทุกหน้า
- **ผ่าน:** พบข้อความอ้างถึงกองทุนชดเชยนักลงทุนอย่างน้อย 1 จุดบนเว็บสาธารณะ โดยไม่ต้องล็อกอิน
- **ไม่ผ่าน:** ไม่พบข้อความใดที่กล่าวถึงกองทุนชดเชยนักลงทุน ทั้งที่โบรกอ้างว่าถูกกำกับในเขตที่มีกองทุนดังกล่าว
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง — เช่น เว็บล่มตลอดช่วงที่พยายามเข้า
- **ตัวอย่าง:** Broker A มีหน้า *Security of Funds* ที่พูดเรื่องบัญชีแยกและธนาคารระดับ tier-1 อย่างละเอียด แต่ค้นทั้งเว็บด้วยคำ 5 คำแล้วไม่พบคำว่าชดเชยหรือ compensation เลย ทั้งที่ใบอนุญาตอยู่ในเขตที่มีกองทุน → **ไม่ผ่าน**

**P01-202 ● · ระบุชื่อกองทุนและหน่วยงานที่กำกับกองทุนชัดเจนหรือไม่** `w3` `WEB`

- **ตรวจอะไร:** ตรวจว่าข้อความที่พบในข้อ 201 ระบุ **ชื่อกองทุน** เป็นชื่อเฉพาะที่นำไปค้นต่อได้ทันที และระบุหน่วยงานหรือกฎหมายที่จัดตั้งกองทุนนั้นหรือไม่ ไม่นับคำกว้างเช่น "กองทุนคุ้มครองระดับยุโรป" "กองทุนของหน่วยงานกำกับ" ที่ไม่มีชื่อเฉพาะ บันทึกชื่อกองทุนทุกชื่อที่พบและตำแหน่งที่พบ
- **ขั้นตอนการตรวจ:**
  1. เปิดตารางข้อความจากข้อ 201
  2. อ่านข้อความในระยะ 3 บรรทัดรอบทุกจุดที่กล่าวถึงกองทุน แล้วคัดลอกชื่อเฉพาะที่ปรากฏ
  3. บันทึกว่าแต่ละจุดมีชื่อกองทุนหรือไม่ ถ้าไม่มี ให้บันทึกว่า "ไม่ระบุชื่อ"
  4. บันทึกว่าแต่ละจุดระบุหน่วยงานหรือกฎหมายที่จัดตั้งกองทุนหรือไม่
  5. นำชื่อกองทุนที่ได้ไปค้นในเครื่องมือค้นหา ว่ามีองค์กรชื่อนี้อยู่จริงหรือไม่ เก็บภาพหน้าทางการของกองทุน
  6. จับภาพให้เห็นชื่อกองทุนและชื่อหน่วยงานอยู่ในเฟรมเดียวกัน แล้วบันทึกผลและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพที่เห็นชื่อกองทุนและหน่วยงานในเฟรมเดียวกัน (`RST-BRKA-P01-202-01`) · ตารางชื่อกองทุนที่พบทุกจุด · ภาพหน้าทางการของกองทุน
- **ผ่าน:** ทุกจุดที่อ้างความคุ้มครองระบุชื่อกองทุนเฉพาะที่นำไปค้นต่อได้ และกองทุนนั้นมีตัวตนตามหน้าทางการ
- **ไม่ผ่าน:** มีจุดที่อ้างความคุ้มครองอย่างน้อย 1 จุดที่ไม่ระบุชื่อกองทุนเฉพาะ หรือระบุชื่อที่ค้นแล้วไม่พบองค์กรใด
- **ยังไม่ได้ตรวจ:** ข้อ 201 ยังไม่พบข้อความอ้างถึงกองทุนใด
- **ตัวอย่าง:** Broker B เขียนบนหน้า Regulation ว่า *"เงินของท่านได้รับความคุ้มครองจากกองทุนคุ้มครองนักลงทุนตามกฎหมาย"* โดยไม่มีชื่อกองทุนและไม่มีชื่อหน่วยงานใดในหน้าเดียวกัน ค้นทั้งเว็บก็ไม่พบชื่อเฉพาะ → **ไม่ผ่าน**

**P01-203 ● · วงเงินคุ้มครองสูงสุดต่อรายที่เว็บประกาศคือเท่าใด** `w3` `WEB`

- **ตรวจอะไร:** ค้นตัวเลขวงเงินคุ้มครองสูงสุดที่โบรกประกาศบนเว็บ บันทึก **ตัวเลข สกุลเงิน หน่วยนับ (ต่อราย/ต่อบัญชี) และเงื่อนไขที่เขียนกำกับ** ทุกจุดที่พบ เพราะโบรกบางรายประกาศตัวเลขต่างกันคนละหน้า ข้อนี้บันทึกสิ่งที่ประกาศเท่านั้น การเทียบกับแหล่งทางการทำในข้อ 205
- **ขั้นตอนการตรวจ:**
  1. ค้นทั้งเว็บด้วยคำว่า `up to` `maximum` `per client` `สูงสุด` `ต่อราย` และด้วยสัญลักษณ์สกุลเงิน
  2. บันทึกตัวเลขทุกตัวที่พบในบริบทความคุ้มครอง ลงตารางที่มีคอลัมน์: ตัวเลข · สกุลเงิน · หน่วยนับ · URL · วันที่พบ
  3. อ่านข้อความในระยะ 3 บรรทัดรอบแต่ละตัวเลข แล้วคัดลอกเงื่อนไขที่เขียนกำกับ
  4. เทียบตัวเลขทุกตัวในตาราง ทำเครื่องหมายจุดที่ตัวเลขไม่ตรงกันระหว่างหน้า
  5. เปิดเวอร์ชันภาษาอื่นของหน้าเดียวกัน (ถ้ามี) แล้วบันทึกตัวเลขในแต่ละภาษา
  6. จับภาพทุกจุดที่พบตัวเลข เก็บสำเนาถาวร แล้วบันทึกตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพทุกจุดที่แสดงตัวเลขวงเงิน (`RST-BRKA-P01-203-01` เป็นต้นไป) · ตารางวงเงิน 5 คอลัมน์ · สำเนาถาวรทุกหน้า
- **ผ่าน:** พบตัวเลขวงเงินพร้อมสกุลเงินและหน่วยนับ และทุกจุดบนเว็บระบุตัวเลขตรงกัน
- **ไม่ผ่าน:** อ้างความคุ้มครองโดยไม่มีตัวเลขวงเงินใดเลย หรือประกาศตัวเลขขัดกันระหว่างหน้าโดยไม่มีคำอธิบาย
- **ยังไม่ได้ตรวจ:** ข้อ 201 ยังไม่พบข้อความอ้างถึงกองทุนใด
- **ตัวอย่าง:** Broker C ระบุในหน้า FAQ ว่าคุ้มครองสูงสุด 20,000 หน่วยต่อราย แต่ในหน้า Regulation ระบุ 100,000 หน่วยต่อราย ไม่มีหน้าใดอธิบายว่าตัวเลขต่างกันเพราะอะไร → **ไม่ผ่าน**

**P01-204 ● · นิติบุคคลคู่สัญญาของเราเป็นสมาชิกกองทุนจริงหรือไม่** `w3` `REG+PUB`

- **ตรวจอะไร:** นำชื่อนิติบุคคลที่เราเซ็นสัญญาด้วยจริง (ผลจากข้อ 026–027) ไปค้นใน **ทะเบียนสมาชิกบนเว็บของกองทุนเอง** ไม่ใช่เว็บของโบรก เพื่อยืนยันว่ารายนี้เป็นสมาชิกที่ยังมีผล บันทึกสถานะสมาชิก วันที่มีผล และวันเวลาที่ค้นเป็นเวลา UTC
- **ขั้นตอนการตรวจ:**
  1. บันทึกชื่อนิติบุคคลคู่สัญญาแบบเต็มจากสัญญาที่เราได้รับจริง พร้อมเลขทะเบียนบริษัท
  2. ค้นชื่อกองทุนในเครื่องมือค้นหา แล้วเข้าเว็บทางการของกองทุนด้วยตนเอง **ห้ามเข้าผ่านลิงก์ที่โบรกให้** บันทึกโดเมนที่เข้า
  3. หาเมนูรายชื่อสมาชิก (members / covered firms / participating firms)
  4. ค้นด้วยชื่อนิติบุคคลคู่สัญญา จับภาพหน้าผลลัพธ์ให้เห็นโดเมนของกองทุน
  5. ค้นซ้ำด้วยเลขใบอนุญาตหรือเลขทะเบียนบริษัท จับภาพหน้าผลลัพธ์
  6. อ่านสถานะสมาชิกและวันที่มีผล บันทึกข้อความคำต่อคำ ห้ามสรุปเอง
  7. เก็บสำเนาถาวรของหน้ารายการ บันทึกวันเวลา UTC ที่ค้น แล้วตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพผลค้นทั้งสองวิธีที่เห็นโดเมนของกองทุน (`RST-BRKA-P01-204-01`, `-02`) · สำเนาถาวร PDF ของหน้ารายการ · บันทึกวันเวลา UTC
- **ผ่าน:** ค้นเจอนิติบุคคลคู่สัญญาในรายชื่อสมาชิกของกองทุน และสถานะสมาชิกยังมีผล ณ วันที่ตรวจ
- **ไม่ผ่าน:** ค้นไม่เจอนิติบุคคลคู่สัญญาในรายชื่อสมาชิก หรือเจอแต่สถานะสิ้นสุดแล้ว ทั้งที่เว็บโบรกยังอ้างความคุ้มครอง
- **ยังไม่ได้ตรวจ:** กองทุนไม่เปิดรายชื่อสมาชิกให้ค้นสาธารณะ (ต้องบันทึกข้อเท็จจริงนี้ไว้ พร้อมภาพหน้าเว็บกองทุนที่แสดงว่าไม่มีส่วนนี้ และห้ามตีความเป็นไม่ผ่าน)
- **ตัวอย่าง:** เว็บ Broker A อ้างความคุ้มครองจากกองทุน แต่รายชื่อสมาชิกบนเว็บกองทุนมีเฉพาะ *BrokerA (Europe) Ltd* ขณะที่สัญญาที่เราเซ็นเป็นของ *BrokerA Global LLC* ซึ่งไม่อยู่ในรายชื่อ → **ไม่ผ่าน**

**P01-205 ● · วงเงินที่โบรกโฆษณาตรงกับวงเงินที่กองทุนประกาศเองหรือไม่** `w3` `WEB+PUB`

- **ตรวจอะไร:** เทียบตัวเลขวงเงินจากข้อ 203 กับตัวเลขที่ประกาศบน **เว็บของกองทุนเอง** ทั้งตัวเลข สกุลเงิน และหน่วยนับ เพื่อจับการอ้างวงเงินเกินจริง บันทึกส่วนต่างเป็นตัวเลขและเป็นอัตราส่วน พร้อมวันที่ของทั้งสองแหล่ง
- **ขั้นตอนการตรวจ:**
  1. เปิดเว็บทางการของกองทุน หาหน้าที่อธิบายวงเงินคุ้มครอง (coverage limit / how much is covered)
  2. คัดลอกตัวเลข สกุลเงิน และหน่วยนับจากเว็บกองทุนเป็นข้อความ พร้อมบันทึกวันที่ปรับปรุงหน้านั้น (ถ้ามี)
  3. วางตัวเลขจากข้อ 203 และตัวเลขจากกองทุนลงตารางเทียบสองคอลัมน์
  4. คำนวณส่วนต่างเป็นจำนวนเงินและเป็นอัตราส่วน บันทึกลงตาราง
  5. ถ้าต่างกัน ค้นบนเว็บโบรกว่ามีคำอธิบายส่วนต่างหรือไม่ เช่น อ้างว่ารวมประกันเอกชนเข้าไปด้วย
  6. จับภาพทั้งสองแหล่งในวันเดียวกัน ให้เห็น URL และวันเวลา
  7. เก็บสำเนาถาวรทั้งสองแหล่ง บันทึกตารางเทียบและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าวงเงินของกองทุน (`RST-BRKA-P01-205-01`) · ภาพหน้าวงเงินของโบรก (`-02`) · ตารางเทียบพร้อมส่วนต่าง · สำเนาถาวรทั้งสองแหล่ง

**P01-207 ● · ระบุหรือไม่ว่าลูกค้าประเภทใดได้รับความคุ้มครอง** `w3` `WEB+DOC`

- **ตรวจอะไร:** ตรวจว่าเว็บและเอกสารสัญญาระบุหรือไม่ว่าความคุ้มครองครอบคลุมลูกค้าประเภทใด (รายย่อย / มืออาชีพ / คู่สัญญาที่มีสิทธิ) และตรวจว่า **ประเภทลูกค้าที่ระบบจัดให้บัญชีทดสอบของเรา** อยู่ในกลุ่มที่ได้รับความคุ้มครองหรือไม่ บันทึกประเภทที่ระบบระบุให้บัญชีเราจากหน้าโปรไฟล์หรือจากเอกสารยืนยันการจัดประเภท
- **ขั้นตอนการตรวจ:**
  1. ค้นบนเว็บและในเอกสารสัญญาด้วยคำว่า `retail client` `professional client` `eligible counterparty` `ลูกค้ารายย่อย` `ลูกค้ามืออาชีพ`
  2. คัดลอกข้อความที่ระบุกลุ่มที่ได้รับและไม่ได้รับความคุ้มครอง พร้อมเลขข้อและเลขหน้าของเอกสาร
  3. เปิดหน้าโปรไฟล์บัญชีทดสอบหรืออีเมลยืนยันการเปิดบัญชี หาจุดที่ระบุประเภทลูกค้าของเรา จับภาพ
  4. ถ้าไม่พบการจัดประเภทที่ใด ให้ถามฝ่ายบริการในฐานะลูกค้าว่า *"บัญชีของผมถูกจัดเป็นลูกค้าประเภทไหนครับ"* แล้วเก็บ transcript ทั้งบทสนทนา
  5. เทียบประเภทของบัญชีเรากับกลุ่มที่ได้รับความคุ้มครอง บันทึกผลว่า ได้ / ไม่ได้ / ไม่ระบุ
  6. เปิดเว็บกองทุนตรวจว่ากองทุนกำหนดกลุ่มผู้มีสิทธิไว้ตรงกันหรือไม่ จับภาพ
  7. บันทึกตารางสรุปและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อความระบุกลุ่มผู้มีสิทธิบนเว็บและในสัญญา (`RST-BRKA-P01-207-01`, `-02`) · ภาพหน้าโปรไฟล์ที่ระบุประเภทลูกค้าของเรา · transcript ฝ่ายบริการฉบับเต็ม (ถ้าใช้)
- **ผ่าน:** เว็บหรือสัญญาระบุกลุ่มผู้มีสิทธิชัดเจน และระบุได้ว่าประเภทของบัญชีทดสอบอยู่ในกลุ่มใด
- **ไม่ผ่าน:** อ้างความคุ้มครองโดยไม่ระบุกลุ่มผู้มีสิทธิที่ใดเลย หรือระบุไว้แต่ไม่มีจุดใดบอกว่าบัญชีของลูกค้าถูกจัดเป็นประเภทใด
- **ยังไม่ได้ตรวจ:** ยังไม่ได้รับเอกสารสัญญาและยังเปิดบัญชีไม่สำเร็จ

**P01-208 · ลูกค้าที่อยู่นอกประเทศของกองทุนได้รับความคุ้มครองหรือไม่** `w3` `PUB+SUP`

**P01-209 ● · entity ที่รับลูกค้าจากประเทศของเราอยู่ใต้กองทุนหรือไม่** `w3` `ACC+PUB`

- **หลักฐานที่ต้องเก็บ:** ภาพเต็มหน้าเปรียบเทียบ entity (`RST-BRKA-P01-210-01`) · ตารางเทียบรายชื่อ entity กับผลข้อ 209 · สำเนาถาวร

- **ยังไม่ได้ตรวจ:** โบรกมี entity เดียวตามผลข้อ 209
- **ตัวอย่าง:** Broker B มีหน้า *Our Entities* แสดง 3 ราย พร้อมคอลัมน์ใบอนุญาต แต่ไม่มีคอลัมน์ใดเรื่องกองทุน และ entity ที่รับลูกค้าจากประเทศของบัญชีทดสอบไม่ปรากฏในตารางเลย → **ไม่ผ่าน**

**P01-211 · เอกสารสัญญาระบุความคุ้มครองตรงกับที่เว็บโฆษณาหรือไม่** `w2` `DOC+WEB`

- **ตรวจอะไร:** เทียบข้อความเรื่องกองทุนชดเชยใน Client Agreement และเอกสารเปิดเผยข้อมูลที่ได้รับตอนสมัคร กับข้อความที่โฆษณาบนเว็บ ทั้งชื่อกองทุน วงเงิน และกลุ่มผู้มีสิทธิ บันทึกเลขข้อและเลขหน้าของทุกจุดที่พบในเอกสาร

  3. คัดลอกข้อความจากเอกสารและข้อความจากเว็บลงตารางเทียบสามแถว: ชื่อกองทุน · วงเงิน · กลุ่มผู้มีสิทธิ
  4. ทำเครื่องหมายทุกแถวที่สองแหล่งไม่ตรงกัน
  5. ถ้าเอกสารไม่กล่าวถึงเลย ให้ค้นซ้ำด้วยชื่อกองทุนจากข้อ 202 เพื่อยืนยัน
  6. จับภาพหน้าเอกสารที่พบ พร้อมให้เห็นเลขหน้า แล้วบันทึกตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ไฟล์ PDF เอกสารทุกฉบับ (`RST-BRKA-P01-211-01` เป็นต้นไป) · ภาพหน้าที่กล่าวถึงความคุ้มครองพร้อมเลขหน้า · ตารางเทียบสามแถว
- **ผ่าน:** เอกสารสัญญากล่าวถึงความคุ้มครองและสาระตรงกับที่เว็บโฆษณาทั้งสามแถว
- **ไม่ผ่าน:** เว็บโฆษณาความคุ้มครอง แต่เอกสารสัญญาไม่กล่าวถึงเลย หรือกล่าวถึงในสาระที่ขัดกับเว็บอย่างน้อย 1 แถว
- **ยังไม่ได้ตรวจ:** ระบบไม่ให้เข้าถึงเอกสารสัญญาก่อนฝากเงิน
- **ตัวอย่าง:** เว็บ Broker C พาดหัวว่าเงินลูกค้าได้รับความคุ้มครองจากกองทุน แต่ Client Agreement ข้อ 24.3 เขียนว่า *"บริษัทไม่ได้เป็นสมาชิกของกองทุนชดเชยนักลงทุนใด"* → **ไม่ผ่าน**

**P01-212 · ข้อยกเว้นความคุ้มครองถูกเปิดเผยในจุดที่ลูกค้าเห็นก่อนฝากเงินหรือไม่** `w3` `WEB+DOC`

- **ตรวจอะไร:** ตรวจว่าโบรกเปิดเผยข้อยกเว้นสำคัญหรือไม่ โดยเฉพาะข้อที่ว่า **การขาดทุนจากการเทรดและการเคลื่อนไหวของราคาไม่อยู่ในความคุ้มครอง** และตรวจว่าข้อความนั้นอยู่ในจุดที่ลูกค้าเห็นก่อนถึงขั้นฝากเงินหรือไม่ บันทึกจำนวนคลิกจากหน้าแรกและจากหน้าฝากเงินจนถึงจุดที่เปิดเผย
- **ขั้นตอนการตรวจ:**
  1. เปิดหน้าเว็บกองทุน คัดลอกรายการข้อยกเว้นทั้งหมดที่กองทุนประกาศ ลงเป็นรายการตั้งต้น
  2. สำหรับข้อยกเว้นแต่ละข้อ ค้นคำสำคัญของข้อนั้นบนเว็บโบรกทั้งเว็บ บันทึกว่าพบที่หน้าใดหรือไม่พบ
  3. ค้นซ้ำในเอกสารสัญญาและเอกสารเปิดเผยข้อมูล บันทึกเลขข้อและเลขหน้า
  4. เดินเส้นทางจากหน้าแรกไปหน้าฝากเงินตามที่ลูกค้าทั่วไปเดิน แล้วนับว่าต้องคลิกกี่ครั้งจึงจะถึงจุดที่เปิดเผยข้อยกเว้น
  5. บันทึกว่าจุดที่เปิดเผยอยู่ก่อนหรือหลังปุ่มฝากเงินในเส้นทางนั้น
  6. จับภาพจุดที่เปิดเผยและจับภาพหน้าฝากเงินในเซสชันเดียวกัน
  7. บันทึกตารางข้อยกเว้นพร้อมสถานะการเปิดเผย และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางข้อยกเว้นพร้อมสถานะการเปิดเผยและจำนวนคลิก (`RST-BRKA-P01-212-01`) · ภาพจุดที่เปิดเผยทุกจุด · ภาพหน้าฝากเงิน
- **ผ่าน:** ข้อยกเว้นเรื่องการขาดทุนจากการเทรดถูกเปิดเผยในจุดที่อยู่ในเส้นทางก่อนถึงหน้าฝากเงิน
- **ไม่ผ่าน:** ไม่เปิดเผยข้อยกเว้นเรื่องการขาดทุนจากการเทรดที่ใดเลย หรือเปิดเผยเฉพาะในเอกสารที่ต้องเปิดหลังฝากเงินแล้วเท่านั้น
- **ยังไม่ได้ตรวจ:** เว็บกองทุนไม่เผยแพร่รายการข้อยกเว้นสาธารณะ ทำให้ไม่มีรายการตั้งต้นให้เทียบ
- **ตัวอย่าง:** Broker A เปิดเผยข้อยกเว้นครบทุกข้อ แต่อยู่ในเอกสาร Risk Disclosure หน้า 14 ที่ระบบให้ดาวน์โหลดหลังยืนยันตัวตนเสร็จแล้วเท่านั้น ขณะที่แบนเนอร์กองทุนอยู่บนหน้าแรก → **ไม่ผ่าน**

**P01-213 ● · เว็บสื่อว่ากองทุนคุ้มครองการขาดทุนจากการเทรดหรือไม่** `w3` `WEB`

- **ตรวจอะไร:** ตรวจถ้อยคำและการจัดวางบนเว็บว่าทำให้ผู้อ่านทั่วไปเข้าใจว่าเงินลงทุนหรือผลขาดทุนจากการเทรดได้รับการรับประกันหรือไม่ โดยดูพาดหัว แบนเนอร์ ไอคอนรูปโล่ และข้อความข้างปุ่มฝากเงิน บันทึกถ้อยคำแบบคำต่อคำ ขนาดตัวอักษรเทียบกับข้อความข้างเคียง และตำแหน่งบนหน้า
- **ขั้นตอนการตรวจ:**
  1. จับภาพเต็มหน้าทุกหน้าที่มีแบนเนอร์หรือไอคอนเกี่ยวกับความคุ้มครอง ให้เห็น URL และนาฬิกาเครื่อง
  2. คัดลอกถ้อยคำในแบนเนอร์และพาดหัวทุกจุดแบบคำต่อคำ ลงตารางพร้อม URL
  3. ค้นทั้งเว็บด้วยคำว่า `protected` `guaranteed` `safe` `risk-free` `รับประกัน` `ปลอดภัย` `ไม่มีความเสี่ยง` แล้วบันทึกทุกจุดที่คำเหล่านี้อยู่ในระยะ 3 บรรทัดจากคำว่ากองทุนหรือ compensation
  4. สำหรับแต่ละจุด ตรวจว่ามีข้อความกำกับในเฟรมเดียวกันที่ระบุว่าความคุ้มครองไม่ครอบคลุมการขาดทุนจากการเทรดหรือไม่
  5. วัดว่าข้อความกำกับ (ถ้ามี) ต้องเลื่อนหน้าจอลงหรือกดขยายจึงจะเห็น หรือเห็นพร้อมกันในหน้าจอเดียว
  6. ทำซ้ำขั้น 1–5 บนหน้าจอมือถือ เพราะการจัดวางอาจตัดข้อความกำกับออก
  7. บันทึกตารางถ้อยคำพร้อมคำตัดสินรายจุด และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพเต็มหน้าทุกจุดทั้งเดสก์ท็อปและมือถือ (`RST-BRKA-P01-213-01` เป็นต้นไป) · ตารางถ้อยคำคำต่อคำพร้อมตำแหน่ง · สำเนาถาวร
- **ผ่าน:** ทุกจุดที่กล่าวถึงกองทุนมีข้อความกำกับในหน้าจอเดียวกันว่าความคุ้มครองไม่ครอบคลุมการขาดทุนจากการเทรด
- **ไม่ผ่าน:** มีอย่างน้อย 1 จุดที่วางคำว่ารับประกัน ปลอดภัย หรือคุ้มครองไว้กับกองทุน โดยไม่มีข้อความกำกับในหน้าจอเดียวกัน
- **ยังไม่ได้ตรวจ:** ข้อ 201 ยังไม่พบข้อความอ้างถึงกองทุนใด
- **ตัวอย่าง:** Broker B วางแบนเนอร์รูปโล่พร้อมข้อความ *"เงินทุนของท่านได้รับการคุ้มครองเต็มจำนวน"* ไว้ติดปุ่มฝากเงิน โดยข้อความกำกับอยู่ในหน้า Legal ที่ต้องคลิกอีก 3 ครั้ง และบนมือถือแบนเนอร์นี้แสดงเต็มจอโดยไม่มีลิงก์ใด → **ไม่ผ่าน**

**P01-214 · วงเงินคุ้มครองนับต่อรายลูกค้าหรือต่อบัญชี** `w2` `WEB+PUB`

- **ตรวจอะไร:** ตรวจหน่วยนับของวงเงินว่าเป็นต่อรายลูกค้าต่อหนึ่งบริษัท หรือเป็นต่อบัญชีเทรด เพราะลูกค้าที่มีหลายบัญชีอาจเข้าใจว่าได้วงเงินคูณจำนวนบัญชี บันทึกถ้อยคำของโบรกและถ้อยคำของกองทุนแบบคำต่อคำ พร้อมจำนวนบัญชีที่โบรกอนุญาตให้เปิดต่อหนึ่งผู้ใช้
- **ขั้นตอนการตรวจ:**
  1. คัดลอกถ้อยคำหน่วยนับจากทุกจุดบนเว็บโบรกที่ระบุวงเงิน ลงตาราง
  2. คัดลอกถ้อยคำหน่วยนับจากหน้าวงเงินของกองทุนเป็นข้อความ
  3. เปิดพื้นที่ลูกค้าของบัญชีทดสอบ บันทึกว่าระบบอนุญาตให้เปิดบัญชีย่อยได้กี่บัญชีต่อหนึ่งผู้ใช้ จับภาพ
  4. เทียบหน่วยนับสองแหล่ง ทำเครื่องหมายจุดที่ไม่ตรงกัน
  5. ตรวจว่าเว็บโบรกมีข้อความใดที่ทำให้เข้าใจว่าวงเงินคูณตามจำนวนบัญชีได้หรือไม่
  6. จับภาพทั้งสองแหล่งในวันเดียวกัน แล้วบันทึกตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพถ้อยคำหน่วยนับทั้งสองแหล่ง (`RST-BRKA-P01-214-01`, `-02`) · ภาพหน้าจัดการบัญชีย่อย · ตารางเทียบ
- **ผ่าน:** หน่วยนับที่โบรกระบุตรงกับที่กองทุนระบุ และไม่มีข้อความใดสื่อว่าวงเงินคูณตามจำนวนบัญชี
- **ไม่ผ่าน:** โบรกระบุหน่วยนับเป็นต่อบัญชีขณะที่กองทุนระบุเป็นต่อรายลูกค้า หรือมีข้อความที่สื่อว่าวงเงินคูณตามจำนวนบัญชี
- **ยังไม่ได้ตรวจ:** เว็บโบรกไม่ระบุหน่วยนับที่ใดเลย และเว็บกองทุนไม่เผยแพร่หน่วยนับสาธารณะ
- **ตัวอย่าง:** Broker A เขียนว่า *"คุ้มครองสูงสุด 20,000 หน่วยต่อบัญชี"* พร้อมชวนให้เปิดบัญชีย่อยได้ถึง 8 บัญชี ขณะที่เว็บกองทุนระบุชัดว่านับต่อรายลูกค้าต่อหนึ่งบริษัท → **ไม่ผ่าน**

**P01-215 · สกุลเงินและวิธีคำนวณวงเงินถูกระบุหรือไม่** `w2` `WEB+PUB`

- **ตรวจอะไร:** ตรวจว่าเว็บระบุหรือไม่ว่าวงเงินคุ้มครองเป็นสกุลเงินใด และคำนวณอย่างไรเมื่อบัญชีลูกค้าถือสกุลเงินอื่น เช่น ใช้อัตราแลกเปลี่ยน ณ วันใด บันทึกสกุลเงินของบัญชีทดสอบและสกุลเงินของวงเงินที่ประกาศ

  2. บันทึกสกุลเงินของวงเงินที่โบรกประกาศทุกจุด จากตารางข้อ 203

  4. เปิดเว็บกองทุน ค้นคำเดียวกัน แล้วคัดลอกวิธีคำนวณที่กองทุนประกาศ
  5. เทียบสองแหล่ง ทำเครื่องหมายกรณีที่โบรกไม่ระบุวิธีคำนวณขณะที่กองทุนระบุไว้
  6. จับภาพทุกแหล่ง แล้วบันทึกตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพสกุลเงินฐานของบัญชีทดสอบ (`RST-BRKA-P01-215-01`) · ภาพข้อความวิธีคำนวณทั้งสองแหล่ง · ตารางเทียบ
- **ผ่าน:** เว็บระบุสกุลเงินของวงเงินชัดเจน และระบุวิธีคำนวณสำหรับบัญชีสกุลเงินอื่น หรือสกุลเงินของบัญชีทดสอบตรงกับสกุลเงินของวงเงินอยู่แล้ว
- **ไม่ผ่าน:** ประกาศวงเงินโดยไม่ระบุสกุลเงิน หรือระบุสกุลเงินที่ต่างจากสกุลเงินบัญชีลูกค้าโดยไม่มีวิธีคำนวณใดกำกับ
- **ยังไม่ได้ตรวจ:** ยังเปิดบัญชีไม่สำเร็จจึงไม่ทราบสกุลเงินฐาน
- **ตัวอย่าง:** Broker C ประกาศวงเงินเป็นตัวเลขล้วนโดยไม่มีสัญลักษณ์สกุลเงินใด และบัญชีทดสอบเป็นสกุลเงินท้องถิ่น ค้นทั้งเว็บไม่พบวิธีคำนวณ → **ไม่ผ่าน**

**P01-216 ● · มีการอ้างประกันภัยเพิ่มเติมจากเอกชนหรือไม่ และระบุผู้รับประกันหรือไม่** `w3` `WEB`

- **ตรวจอะไร:** ตรวจว่าเว็บอ้างประกันภัยเพิ่มเติมจากบริษัทประกันเอกชน (excess insurance / additional insurance / civil liability) นอกเหนือจากกองทุนหรือไม่ และการอ้างนั้นระบุ **ชื่อบริษัทผู้รับประกัน** หรือไม่ บันทึกถ้อยคำ วงเงินที่อ้าง ชื่อผู้รับประกัน และตำแหน่งที่พบทุกจุด
- **ขั้นตอนการตรวจ:**
  1. ค้นทั้งเว็บด้วยคำว่า `insurance` `insured` `underwriter` `policy` `ประกันภัย` `กรมธรรม์` `ผู้รับประกัน`
  2. บันทึกทุกจุดที่พบลงตาราง พร้อม URL วันที่พบ และถ้อยคำคำต่อคำ
  3. สำหรับแต่ละจุด บันทึกว่าระบุชื่อบริษัทผู้รับประกันหรือไม่ ถ้าไม่ระบุ ให้บันทึกว่า "ไม่ระบุผู้รับประกัน"
  4. บันทึกว่าแต่ละจุดระบุวงเงินประกันหรือไม่ และเป็นตัวเลขเท่าใด
  5. ตรวจว่าเว็บมีลิงก์ไปยังสำเนากรมธรรม์ ใบรับรองการประกัน หรือหน้ายืนยันจากผู้รับประกันหรือไม่
  6. จับภาพทุกจุดที่พบ เก็บสำเนาถาวร แล้วบันทึกตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพทุกจุดที่อ้างประกัน (`RST-BRKA-P01-216-01` เป็นต้นไป) · ตารางการอ้างประกันพร้อมชื่อผู้รับประกันและวงเงิน · สำเนาถาวร
- **ผ่าน:** ไม่มีการอ้างประกันเอกชนเลย หรืออ้างแต่ระบุชื่อบริษัทผู้รับประกันครบทุกจุด
- **ไม่ผ่าน:** มีการอ้างประกันเอกชนอย่างน้อย 1 จุดโดยไม่ระบุชื่อบริษัทผู้รับประกัน
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** Broker A แสดงตราสัญลักษณ์ *"Insured up to 1,000,000"* บนหน้าแรก ค้นทั้งเว็บแล้วไม่มีที่ใดบอกว่าใครเป็นผู้รับประกันและไม่มีลิงก์ใด → **ไม่ผ่าน**

**P01-217 · ผู้รับประกันและกรมธรรม์ที่อ้าง ตรวจสอบได้จากแหล่งภายนอกหรือไม่** `w3` `WEB+PUB`

- **ตรวจอะไร:** นำชื่อผู้รับประกันและเลขกรมธรรม์ที่พบจากข้อ 216 ไปยืนยันจากแหล่งสาธารณะภายนอก เช่น เว็บทางการของผู้รับประกัน หรือทะเบียนผู้ประกอบธุรกิจประกันภัยของหน่วยงานกำกับประกันภัยในเขตนั้น บันทึกว่าพบการยืนยันหรือไม่ และพบจากแหล่งใด
- **ขั้นตอนการตรวจ:**
  1. บันทึกชื่อผู้รับประกันและเลขกรมธรรม์ทุกตัวจากตารางข้อ 216
  2. ค้นชื่อผู้รับประกันในเครื่องมือค้นหา แล้วเข้าเว็บทางการของบริษัทนั้นด้วยตนเอง บันทึกโดเมนที่เข้า
  3. ค้นชื่อโบรกและชื่อ entity คู่สัญญาบนเว็บผู้รับประกัน บันทึกว่าพบหรือไม่พบ
  4. เปิดเว็บหน่วยงานกำกับประกันภัยของเขตที่ผู้รับประกันตั้งอยู่ ค้นชื่อผู้รับประกันในทะเบียน จับภาพผลลัพธ์
  5. ตรวจว่าเอกสารหรือหน้าใดที่โบรกเผยแพร่ มีตราหรือลายเซ็นของผู้รับประกันที่ตรวจย้อนได้หรือไม่
  6. เก็บสำเนาถาวรของทุกหน้าที่ใช้ยืนยัน พร้อมวันเวลา UTC
  7. บันทึกตารางสถานะการยืนยันรายกรมธรรม์ และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพผลค้นทะเบียนผู้ประกอบธุรกิจประกันภัย (`RST-BRKA-P01-217-01`) · ภาพหน้าเว็บทางการของผู้รับประกัน · ตารางสถานะการยืนยัน · สำเนาถาวร
- **ผ่าน:** ผู้รับประกันที่โบรกอ้างมีตัวตนตามทะเบียนหรือเว็บทางการ และไม่มีข้อความใดจากแหล่งภายนอกที่ขัดกับสิ่งที่โบรกอ้าง
- **ไม่ผ่าน:** ค้นไม่พบผู้รับประกันที่โบรกอ้างในทะเบียนใดและไม่พบเว็บทางการของบริษัทนั้น
- **ยังไม่ได้ตรวจ:** ข้อ 216 พบว่าไม่มีการอ้างประกันเอกชน หรือเขตนั้นไม่มีทะเบียนผู้ประกอบธุรกิจประกันภัยที่ค้นสาธารณะได้
- **ตัวอย่าง:** Broker B อ้างว่ามีกรมธรรม์จาก *Northline Underwriters* ค้นชื่อนี้แล้วพบเพียงเว็บหน้าเดียวที่สร้างปีเดียวกับโดเมนโบรก และไม่พบในทะเบียนประกันภัยของเขตที่อ้าง → **ไม่ผ่าน**

**P01-218 ● · วงเงินประกันเอกชนที่โฆษณา เป็นต่อลูกค้าหรือเป็นวงเงินรวมทั้งกลุ่ม** `w3` `WEB`

- **ตรวจอะไร:** ตรวจว่าตัวเลขวงเงินประกันเอกชนที่โฆษณาเป็นวงเงินต่อลูกค้าหนึ่งราย หรือเป็นวงเงินรวม (aggregate) ของทั้งกลุ่มลูกค้าต่อหนึ่งเหตุการณ์ เพราะตัวเลขหลักล้านที่ใช้โฆษณามักเป็นวงเงินรวม บันทึกถ้อยคำคำต่อคำและตำแหน่งของคำว่า aggregate หรือ per client
- **ขั้นตอนการตรวจ:**
  1. เปิดทุกจุดที่อ้างวงเงินประกันจากตารางข้อ 216
  2. อ่านข้อความในระยะ 3 บรรทัดรอบตัวเลข ค้นคำว่า `aggregate` `in total` `per client` `combined` `รวมทั้งสิ้น` `ต่อราย`
  3. บันทึกหน่วยนับที่พบของแต่ละจุด ถ้าไม่พบคำใด ให้บันทึกว่า "ไม่ระบุหน่วยนับ"
  4. เทียบตัวเลขที่ใช้ในพาดหัวหรือแบนเนอร์ กับตัวเลขในข้อความรายละเอียด ทำเครื่องหมายจุดที่ต่างกัน
  5. ตรวจว่าตัวเลขวงเงินประกันถูกนำไปบวกรวมกับวงเงินกองทุนแล้วแสดงเป็นตัวเลขเดียวหรือไม่
  6. จับภาพทุกจุดทั้งเดสก์ท็อปและมือถือ แล้วบันทึกตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพทุกจุดที่แสดงวงเงินประกัน (`RST-BRKA-P01-218-01` เป็นต้นไป) · ตารางหน่วยนับรายจุด · สำเนาถาวร
- **ผ่าน:** ทุกจุดที่แสดงวงเงินประกันระบุหน่วยนับชัดเจน และตัวเลขในพาดหัวใช้หน่วยนับเดียวกับในรายละเอียด
- **ไม่ผ่าน:** ใช้ตัวเลขวงเงินรวมของทั้งกลุ่มในพาดหัวโดยไม่ระบุว่าเป็นวงเงินรวม หรือไม่ระบุหน่วยนับที่ใดเลย
- **ยังไม่ได้ตรวจ:** ข้อ 216 พบว่าไม่มีการอ้างประกันเอกชน
- **ตัวอย่าง:** Broker C พาดหัวว่า *"ประกันคุ้มครองสูงถึง 5,000,000 ต่อลูกค้า"* ขณะที่ย่อหน้ารายละเอียดในหน้าเดียวกันเขียนว่าวงเงินรวมของกรมธรรม์คือ 5,000,000 ต่อหนึ่งเหตุการณ์สำหรับลูกค้าทั้งหมด → **ไม่ผ่าน**

**P01-219 · เงื่อนไขและขั้นตอนการเคลมประกันเอกชนถูกเปิดเผยหรือไม่** `w2` `WEB+SUP`

- **ตรวจอะไร:** ตรวจว่าลูกค้าจะรู้หรือไม่ว่าต้องทำอย่างไรจึงจะได้รับเงินจากประกันเอกชนที่โบรกอ้าง โดยดูว่าเว็บระบุเงื่อนไขที่กระตุ้นการจ่าย ผู้มีสิทธิยื่นเคลม และขั้นตอนการยื่นหรือไม่ แล้วยืนยันซ้ำด้วยการถามฝ่ายบริการในฐานะลูกค้า
- **ขั้นตอนการตรวจ:**
  1. ค้นบนเว็บด้วยคำว่า `claim` `how to claim` `เคลม` `ยื่นคำขอ` ในบริบทประกัน แล้วบันทึกทุกจุดที่พบ
  2. บันทึกว่าเว็บระบุครบทั้งสามอย่างหรือไม่: เงื่อนไขที่กระตุ้นการจ่าย · ผู้มีสิทธิยื่น · ขั้นตอนการยื่น
  3. ส่งคำถามถึงฝ่ายบริการในฐานะลูกค้าว่า *"ถ้าเกิดเหตุที่ต้องใช้ประกันที่โฆษณาไว้ ผมต้องยื่นเรื่องกับใครและมีขั้นตอนอย่างไรครับ"* บันทึกเวลาที่ส่ง
  4. บันทึกเวลาที่ได้รับคำตอบครั้งแรก และเก็บ transcript ทั้งบทสนทนาโดยไม่ตัดทอน
  5. เทียบคำตอบที่ได้กับสิ่งที่เว็บระบุ ทำเครื่องหมายจุดที่ขัดกันหรือจุดที่ฝ่ายบริการตอบไม่ได้
  6. บันทึกตารางสามช่องพร้อมสถานะการเปิดเผย และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าที่อธิบายขั้นตอนการเคลม (`RST-BRKA-P01-219-01`) · transcript ฝ่ายบริการฉบับเต็มพร้อมเวลา (`-02`) · ตารางสามช่อง
- **ผ่าน:** เว็บระบุครบทั้งสามอย่าง หรือระบุไม่ครบแต่ฝ่ายบริการตอบเพิ่มเติมจนครบและไม่ขัดกับเว็บ
- **ไม่ผ่าน:** เว็บไม่ระบุแม้แต่อย่างเดียวในสามอย่าง และฝ่ายบริการตอบไม่ได้ว่าต้องยื่นเรื่องกับใคร
- **ยังไม่ได้ตรวจ:** ข้อ 216 พบว่าไม่มีการอ้างประกันเอกชน หรือฝ่ายบริการไม่ตอบภายในกรอบเวลา `[เกณฑ์เสนอ: 10 วันทำการ]`
- **ตัวอย่าง:** Broker A โฆษณาประกันบนหน้าแรก แต่ค้นทั้งเว็บไม่พบคำว่าเคลม และฝ่ายบริการตอบว่า *"เป็นเรื่องภายในของบริษัทครับ ลูกค้าไม่ต้องดำเนินการอะไร"* โดยไม่บอกช่องทางใด → **ไม่ผ่าน**

**P01-220 · ผู้รับประกันที่อ้าง ได้รับอนุญาตประกอบธุรกิจประกันภัยหรือไม่** `w2` `PUB`

- **ตรวจอะไร:** ตรวจสถานะใบอนุญาตของบริษัทผู้รับประกันที่โบรกอ้าง จากทะเบียนสาธารณะของหน่วยงานกำกับประกันภัยในเขตที่ผู้รับประกันตั้งอยู่ บันทึกชื่อหน่วยงาน สถานะที่ปรากฏ และวันเวลา UTC ที่ค้น
- **ขั้นตอนการตรวจ:**
  1. ระบุเขตที่ผู้รับประกันตั้งอยู่ จากที่อยู่บนเว็บทางการของผู้รับประกันหรือจากผลข้อ 217
  2. ค้นชื่อหน่วยงานกำกับประกันภัยของเขตนั้น แล้วเข้าเว็บทางการด้วยตนเอง บันทึกโดเมน
  3. หาเมนูทะเบียนสาธารณะ แล้วค้นด้วยชื่อผู้รับประกัน จับภาพผลลัพธ์ให้เห็นโดเมนหน่วยงาน
  4. อ่านช่องสถานะและประเภทธุรกิจที่ได้รับอนุญาต บันทึกข้อความคำต่อคำ
  5. ตรวจว่าประเภทที่ได้รับอนุญาตครอบคลุมประกันภัยประเภทที่โบรกอ้างหรือไม่
  6. เก็บสำเนาถาวรและบันทึกวันเวลา UTC แล้วตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพผลค้นทะเบียนประกันภัย (`RST-BRKA-P01-220-01`) · สำเนาถาวร · บันทึกวันเวลา UTC
- **ผ่าน:** ค้นเจอผู้รับประกันในทะเบียน สถานะเป็นได้รับอนุญาตอยู่ และประเภทที่ได้รับอนุญาตครอบคลุมประกันที่โบรกอ้าง
- **ไม่ผ่าน:** ค้นไม่เจอในทะเบียน หรือเจอแต่สถานะสิ้นสุด หรือประเภทที่ได้รับอนุญาตไม่ครอบคลุมประกันที่โบรกอ้าง
- **ยังไม่ได้ตรวจ:** ข้อ 216 พบว่าไม่มีการอ้างประกันเอกชน หรือเขตนั้นไม่มีทะเบียนที่ค้นสาธารณะได้
- **ตัวอย่าง:** Broker B อ้างประกันจากบริษัทที่ค้นเจอในทะเบียนจริง แต่ประเภทที่ได้รับอนุญาตเป็นเพียงนายหน้าประกันภัย ไม่ใช่ผู้รับประกันภัย และเว็บโบรกเรียกบริษัทนั้นว่าผู้รับประกัน → **ไม่ผ่าน**

**P01-221 ● · ถามฝ่ายบริการเรื่องความคุ้มครองแล้วคำตอบตรงกับเอกสารหรือไม่** `w3` `SUP`

- **ตรวจอะไร:** ทดสอบว่าลูกค้าที่ถามคำถามพื้นฐานเรื่องความคุ้มครองจะได้ข้อมูลตรงกับที่เผยแพร่หรือไม่ โดยถามคำถามชุดเดียวกัน 3 ครั้ง ต่างช่องทางและต่างวัน แล้วเทียบคำตอบทั้งสามกับข้อมูลจากข้อ 202 203 205 และ 207 บันทึกช่องทาง วันเวลาที่ส่ง เวลาที่ได้คำตอบครั้งแรก และคำตอบแบบคำต่อคำ
- **ขั้นตอนการตรวจ:**
  1. เตรียมคำถามชุดเดียวกัน 3 ข้อ: กองทุนที่คุ้มครองชื่ออะไร · วงเงินสูงสุดเท่าไร · บัญชีของผมได้รับความคุ้มครองหรือไม่
  2. ส่งคำถามชุดนี้ทางแชทสด บันทึกวันเวลา UTC ที่ส่ง และเก็บ transcript ฉบับเต็ม
  3. ส่งคำถามชุดเดียวกันทางอีเมลของโบรก ห่างจากครั้งแรกอย่างน้อย 1 สัปดาห์ บันทึกวันเวลาที่ส่ง
  4. ส่งคำถามชุดเดียวกันทางช่องทางที่สาม (แบบฟอร์มติดต่อหรือโทรศัพท์) ห่างจากครั้งที่สองอย่างน้อย 1 สัปดาห์ ถ้าเป็นการโทร ให้ตรวจก่อนว่ากฎหมายท้องถิ่นอนุญาตให้บันทึกเสียงหรือไม่ ถ้าไม่อนุญาตให้จดบันทึกทันทีหลังวางสายพร้อมเวลา
  5. คัดลอกคำตอบทั้งสามครั้งลงตารางเทียบ 3 คอลัมน์ ตามคำถาม 3 ข้อ
  6. เทียบทุกช่องกับข้อมูลที่เผยแพร่จากข้อ 202 203 205 และ 207 ทำเครื่องหมายทุกช่องที่ขัดกัน
  7. บันทึกตารางเทียบพร้อม transcript ทั้งสามครั้ง และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** transcript ทั้งสามครั้งฉบับเต็มพร้อมวันเวลา (`RST-BRKA-P01-221-01` ถึง `-03`) · ตารางเทียบ 3 คอลัมน์ · บันทึกย่อการโทรพร้อมเวลา (ถ้าใช้)
- **ผ่าน:** คำตอบทั้งสามครั้งสอดคล้องกันเองและไม่ขัดกับข้อมูลที่เผยแพร่ในทุกช่อง
- **ไม่ผ่าน:** มีอย่างน้อย 1 ช่องที่คำตอบขัดกับข้อมูลที่เผยแพร่ หรือคำตอบสามครั้งขัดกันเองในคำถามข้อเดียวกัน
- **ยังไม่ได้ตรวจ:** ได้รับคำตอบไม่ครบ 3 ช่องทางภายในกรอบเวลาที่กำหนด `[เกณฑ์เสนอ: 30 วัน นับจากวันส่งคำถามครั้งแรก]`
- **ตัวอย่าง:** แชทสดของ Broker A ตอบวงเงิน 20,000 อีเมลตอบ 100,000 และเจ้าหน้าที่ทางโทรศัพท์ตอบว่า *"คุ้มครองเต็มจำนวนเงินฝากครับ"* ขณะที่เว็บระบุ 20,000 → **ไม่ผ่าน**

**P01-222 · ตราหรือโลโก้ของกองทุนถูกใช้กับ entity ที่ไม่ได้เป็นสมาชิกหรือไม่** `w3` `WEB+PUB`

- **ตรวจอะไร:** ตรวจตำแหน่งที่วางตรา โลโก้ หรือชื่อกองทุนบนเว็บ ว่าอยู่ในหน้าหรือส่วนที่ให้บริการโดย entity ที่ไม่ได้เป็นสมาชิกกองทุนหรือไม่ โดยเทียบตำแหน่งของตรากับชื่อ entity ที่ระบุใน footer ของหน้าเดียวกัน
- **ขั้นตอนการตรวจ:**
  1. ทำรายการทุกหน้าที่ปรากฏตรา โลโก้ หรือชื่อกองทุน จับภาพเต็มหน้าทุกหน้า
  2. สำหรับแต่ละหน้า เลื่อนลงไปอ่าน footer แล้วบันทึกชื่อ entity ที่ระบุว่าเป็นผู้ให้บริการของหน้านั้น
  3. ทำตารางสองคอลัมน์: URL ของหน้า · entity ใน footer ของหน้านั้น
  4. เทียบ entity แต่ละรายกับผลการค้นรายชื่อสมาชิกจากข้อ 204 และ 209
  5. ทำเครื่องหมายทุกหน้าที่มีตรากองทุนแต่ footer ระบุ entity ที่ไม่อยู่ในรายชื่อสมาชิก
  6. ทำซ้ำขั้น 1–5 กับเวอร์ชันภาษาอื่นและโดเมนภูมิภาคอื่นของแบรนด์เดียวกัน
  7. บันทึกตารางสรุปพร้อมภาพทุกหน้า และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพเต็มหน้าที่เห็นทั้งตรากองทุนและ footer (`RST-BRKA-P01-222-01` เป็นต้นไป) · ตารางสองคอลัมน์ · สำเนาถาวรทุกหน้า
- **ผ่าน:** ทุกหน้าที่แสดงตรากองทุนมี footer ระบุ entity ที่อยู่ในรายชื่อสมาชิกกองทุน
- **ไม่ผ่าน:** มีอย่างน้อย 1 หน้าที่แสดงตรากองทุน แต่ footer ระบุ entity ที่ไม่อยู่ในรายชื่อสมาชิก
- **ยังไม่ได้ตรวจ:** กองทุนไม่เปิดรายชื่อสมาชิกสาธารณะ ทำให้เทียบไม่ได้
- **ตัวอย่าง:** โดเมนภูมิภาคของ Broker C แสดงตรากองทุนบนหน้าแรกเหมือนโดเมนหลักทุกประการ แต่ footer ของโดเมนภูมิภาคระบุ entity ที่จดทะเบียนคนละเขตและไม่อยู่ในรายชื่อสมาชิก → **ไม่ผ่าน**

**P01-223 ● · มีการอ้างวงเงินคุ้มครองรวมที่เกินกว่าที่แหล่งทางการรองรับหรือไม่** `w3` `WEB+PUB`

- **ตรวจอะไร:** ตรวจตัวเลขความคุ้มครองที่ใหญ่ที่สุดที่โบรกใช้สื่อสาร แล้วไล่ย้อนว่าตัวเลขนั้นประกอบขึ้นจากอะไรบ้าง และแต่ละส่วนมีแหล่งทางการรองรับหรือไม่ ข้อนี้จับกรณีที่โบรกบวกวงเงินกองทุนกับวงเงินประกันเอกชนหรือกับตัวเลขที่ไม่มีที่มา แล้วแสดงเป็นตัวเลขเดียว
- **ขั้นตอนการตรวจ:**
  1. รวบรวมตัวเลขความคุ้มครองทุกตัวจากข้อ 203 และ 216 แล้วหาตัวเลขที่ใหญ่ที่สุดที่ใช้สื่อสาร
  2. ค้นบนเว็บว่ามีหน้าใดอธิบายที่มาของตัวเลขนั้นหรือไม่ คัดลอกคำอธิบายเป็นข้อความ
  3. แยกตัวเลขนั้นเป็นองค์ประกอบตามคำอธิบาย เช่น ส่วนที่มาจากกองทุน กับส่วนที่มาจากประกันเอกชน
  4. เทียบส่วนที่มาจากกองทุนกับตัวเลขบนเว็บกองทุน ตามผลข้อ 205
  5. เทียบส่วนที่มาจากประกันเอกชนกับผลการยืนยันจากข้อ 217 และ 220
  6. บันทึกส่วนของตัวเลขที่ไม่มีแหล่งทางการใดรองรับ เป็นจำนวนเงินและเป็นอัตราส่วนของตัวเลขรวม
  7. บันทึกตารางแยกองค์ประกอบพร้อมภาพทุกแหล่ง และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพจุดที่แสดงตัวเลขใหญ่ที่สุด (`RST-BRKA-P01-223-01`) · ตารางแยกองค์ประกอบพร้อมแหล่งอ้างอิงรายส่วน · สำเนาถาวรของทุกแหล่งทางการที่ใช้เทียบ
- **ผ่าน:** ทุกองค์ประกอบของตัวเลขที่ใช้สื่อสารมีแหล่งทางการรองรับ และเว็บอธิบายที่มาของตัวเลขไว้ในหน้าเดียวกับที่แสดงตัวเลข
- **ไม่ผ่าน:** มีส่วนของตัวเลขที่ไม่มีแหล่งทางการใดรองรับ หรือมีแหล่งรองรับแต่เว็บไม่อธิบายที่มาไว้ที่ใดเลย
- **ยังไม่ได้ตรวจ:** ข้อ 203 และ 216 ไม่พบตัวเลขวงเงินใดบนเว็บ
- **ตัวอย่าง:** Broker A แสดงตัวเลข *"คุ้มครองรวมสูงสุด 1,020,000"* บนหน้าแรก ค้นทั้งเว็บพบเพียงคำอธิบายว่าเป็นกองทุน 20,000 บวกประกันเอกชน 1,000,000 แต่ผู้รับประกันที่อ้างค้นไม่พบในทะเบียนใดตามข้อ 217 → **ไม่ผ่าน**

**P01-224 · กองทุนที่อ้างมีประวัติการจ่ายชดเชยที่ค้นได้จากแหล่งสาธารณะหรือไม่** `w1` `PUB`

- **ตรวจอะไร:** ค้นจากเว็บของกองทุนและประกาศทางการว่ากองทุนนั้นเคยประกาศจ่ายชดเชยให้ลูกค้าของบริษัทใดหรือไม่ เพื่อบันทึกเป็นบริบทว่ากลไกนี้เคยทำงานจริงหรือเป็นเพียงกลไกบนกระดาษ ข้อนี้บันทึกข้อเท็จจริงจากแหล่งทางการเท่านั้น **ห้ามสรุปความสามารถในการจ่ายในอนาคต**
- **ขั้นตอนการตรวจ:**
  1. เปิดเว็บทางการของกองทุน หาเมนูข่าว ประกาศ หรือรายงานประจำปี

  3. บันทึกจำนวนรายการที่พบและช่วงปีที่ครอบคลุม ลงตาราง
  4. เปิดรายงานประจำปีล่าสุดของกองทุน (ถ้าเผยแพร่) บันทึกตัวเลขที่กองทุนรายงานไว้เอง พร้อมเลขหน้า **ห้ามคำนวณตัวเลขใหม่เอง**
  5. จับภาพหน้าประกาศและหน้ารายงานที่ใช้ ให้เห็น URL และวันที่
  6. เก็บสำเนาถาวรทุกหน้า แล้วบันทึกตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าประกาศของกองทุน (`RST-BRKA-P01-224-01` เป็นต้นไป) · ตารางรายการที่พบพร้อมวันที่ · สำเนาถาวรของรายงานประจำปีที่ใช้
- **ผ่าน:** ค้นพบประกาศหรือรายงานทางการของกองทุนที่ระบุการจ่ายชดเชยอย่างน้อย 1 รายการ และเก็บสำเนาถาวรได้
- **ไม่ผ่าน:** เว็บของกองทุนไม่มีส่วนประกาศหรือรายงานใดที่เผยแพร่สาธารณะเลย
- **ยังไม่ได้ตรวจ:** ข้อ 202 ยังไม่ได้ชื่อกองทุนที่ค้นต่อได้
- **ตัวอย่าง:** เว็บกองทุนที่ Broker B อ้าง มีเพียงหน้าแนะนำองค์กรหน้าเดียว ไม่มีเมนูประกาศ ไม่มีรายงานประจำปี และไม่มีรายชื่อสมาชิก → **ไม่ผ่าน**

**P01-225 ● · สรุปสถานะความคุ้มครองที่แท้จริงของบัญชีที่เราเปิด** `w3` `รวมทุกวิธี`

- **ตรวจอะไร:** รวบรวมผลจากทั้งหมวด S09 ลงตารางเดียว เพื่อสรุปว่า **บัญชีทดสอบที่เราเปิดจริง ได้รับความคุ้มครองจากอะไร วงเงินเท่าไร และมีแหล่งทางการใดรองรับ** แล้วเทียบกับสิ่งที่ลูกค้าคนหนึ่งจะเข้าใจจากหน้าเว็บที่เห็นก่อนฝากเงิน ข้อนี้เป็นข้อสรุปของ S09
- **ขั้นตอนการตรวจ:**

  3. บันทึกในแถวสรุปว่า วงเงินที่มีแหล่งทางการรองรับสำหรับบัญชีทดสอบคือเท่าใด หรือบันทึกว่า "ไม่มีแหล่งทางการรองรับ"

  6. ทำเครื่องหมายทุกจุดในเส้นทางที่แสดงความคุ้มครองเกินกว่าแถวสรุป
  7. บันทึกตารางสรุปฉบับสมบูรณ์พร้อมคำตัดสิน และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางสรุป 6 แถวพร้อม Evidence ID ทุกแถว (`RST-BRKA-P01-225-01`) · ภาพทุกจุดในเส้นทางจากหน้าแรกถึงหน้าฝากเงิน · บันทึกส่วนต่าง
- **ผ่าน:** ความคุ้มครองที่ลูกค้าเห็นในเส้นทางก่อนฝากเงิน ไม่เกินกว่าที่มีแหล่งทางการรองรับสำหรับบัญชีทดสอบ
- **ไม่ผ่าน:** มีอย่างน้อย 1 จุดในเส้นทางก่อนฝากเงินที่แสดงความคุ้มครองเกินกว่าที่มีแหล่งทางการรองรับ
- **ยังไม่ได้ตรวจ:** ยังเติมข้อมูลไม่ครบ 6 แถว
- **ตัวอย่าง:** ตารางสรุปของ Broker C พบว่า entity คู่สัญญาไม่อยู่ในรายชื่อสมาชิกกองทุนและประกันเอกชนยืนยันไม่ได้ ทำให้วงเงินที่มีแหล่งรองรับเป็นศูนย์ ขณะที่หน้าฝากเงินยังแสดงไอคอนโล่พร้อมข้อความคุ้มครอง → **ไม่ผ่าน**

## S10 · ที่อยู่จริง ช่องทางติดต่อตามกฎหมาย และการพิสูจน์ตัวตนองค์กร (226–250)

> หมวดนี้ต่อยอดจากข้อ 009 ที่เทียบ "ที่อยู่ในทะเบียนกับที่อยู่บนเว็บ" — หมวดนี้ไม่เทียบซ้ำ แต่ตรวจว่า **ที่อยู่และช่องทางติดต่อนั้นมีตัวตนใช้งานได้จริงหรือไม่**
> **ห้ามไปสำรวจสถานที่ในฐานะผู้ตรวจทุกกรณี** ใช้ได้เฉพาะแผนที่สาธารณะ ภาพถ่ายถนนสาธารณะ ทะเบียนสาธารณะ และการส่งไปรษณีย์ในฐานะลูกค้าทั่วไป

**P01-226 · เว็บแสดงที่อยู่ทางไปรษณีย์ที่ครบถ้วนพอส่งจดหมายได้หรือไม่** `w2` `WEB`

- **ตรวจอะไร:** ตรวจว่าที่อยู่ที่เว็บแสดงมีองค์ประกอบครบพอที่ลูกค้าจะจ่าหน้าซองส่งจดหมายได้จริงหรือไม่ โดยนับองค์ประกอบ 5 อย่าง: เลขที่และชื่ออาคาร · ชื่อถนน · เมือง · รหัสไปรษณีย์ · ประเทศ บันทึกที่อยู่ที่พบทุกจุดแบบคำต่อคำ พร้อม URL และองค์ประกอบที่ขาด
- **ขั้นตอนการตรวจ:**
  1. เปิด footer หน้าแรก หน้า Contact หน้า Legal และหน้า About แล้วคัดลอกที่อยู่ทุกแห่งเป็นข้อความ
  2. แยกที่อยู่แต่ละแห่งลงตารางที่มี 5 คอลัมน์ตามองค์ประกอบข้างต้น
  3. ทำเครื่องหมายช่องที่ว่างในแต่ละแถว แล้วนับจำนวนองค์ประกอบที่ขาด
  4. ค้นทั้งเว็บด้วยรหัสไปรษณีย์ที่พบ เพื่อดูว่ามีที่อยู่จุดอื่นที่ยังไม่ได้เก็บหรือไม่
  5. จับภาพทุกจุดที่แสดงที่อยู่ ให้เห็น URL และนาฬิกาเครื่อง
  6. เก็บสำเนาถาวรทุกหน้า แล้วบันทึกตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพทุกจุดที่แสดงที่อยู่ (`RST-BRKA-P01-226-01` เป็นต้นไป) · ตาราง 5 คอลัมน์พร้อมช่องที่ขาด · สำเนาถาวร
- **ผ่าน:** มีที่อยู่อย่างน้อย 1 แห่งบนเว็บสาธารณะที่มีองค์ประกอบครบทั้ง 5 อย่าง
- **ไม่ผ่าน:** ไม่มีที่อยู่ใดบนเว็บที่มีองค์ประกอบครบทั้ง 5 อย่าง หรือไม่แสดงที่อยู่ใดเลย
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** Broker A แสดงในหน้า Contact ว่า *"สำนักงานใหญ่ กรุงลอนดอน สหราชอาณาจักร"* โดยไม่มีเลขที่ ชื่อถนน และรหัสไปรษณีย์ ค้นทั้งเว็บแล้วไม่พบที่อยู่ที่ครบกว่านี้ → **ไม่ผ่าน**

**P01-227 ● · ที่อยู่ที่แสดงมีอยู่จริงบนแผนที่สาธารณะหรือไม่** `w3` `PUB`

- **ตรวจอะไร:** นำที่อยู่ที่ได้จากข้อ 226 ไปค้นในบริการแผนที่สาธารณะอย่างน้อย 2 เจ้า เพื่อยืนยันว่าที่อยู่นั้นเป็นพิกัดที่มีอยู่จริง ไม่ใช่ที่อยู่ที่ประกอบขึ้นเอง บันทึกพิกัดที่ได้จากแต่ละเจ้า ชื่ออาคารที่แผนที่แสดง และวันเวลาที่ค้น **ห้ามเดินทางไปสถานที่จริง**
- **ขั้นตอนการตรวจ:**
  1. คัดลอกที่อยู่จากข้อ 226 แบบคำต่อคำ ห้ามพิมพ์เองเพื่อกันพิมพ์ผิด
  2. วางที่อยู่ในบริการแผนที่สาธารณะเจ้าที่หนึ่ง บันทึกว่าระบบชี้ไปพิกัดใด และชื่ออาคารที่แสดง จับภาพให้เห็นทั้งช่องค้นหาและผลลัพธ์
  3. ทำซ้ำขั้น 2 กับบริการแผนที่สาธารณะเจ้าที่สอง
  4. เทียบพิกัดจากทั้งสองเจ้า บันทึกว่าชี้จุดเดียวกันหรือต่างกัน
  5. ถ้าเจ้าใดไม่พบที่อยู่ ให้ค้นซ้ำด้วยรหัสไปรษณีย์อย่างเดียว แล้วบันทึกว่าพิกัดที่ได้อยู่ในย่านเดียวกับที่อยู่ที่อ้างหรือไม่
  6. จับภาพผลลัพธ์ทุกครั้ง ให้เห็น URL และนาฬิกาเครื่อง
  7. บันทึกตารางผลจากทั้งสองเจ้า และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพผลค้นจากแผนที่สาธารณะทั้งสองเจ้า (`RST-BRKA-P01-227-01`, `-02`) · ตารางพิกัดและชื่ออาคาร · บันทึกวันเวลาที่ค้น
- **ผ่าน:** บริการแผนที่ทั้งสองเจ้าชี้ไปที่อยู่เดียวกันและเป็นพิกัดที่มีอยู่จริง
- **ไม่ผ่าน:** บริการแผนที่ทั้งสองเจ้าไม่พบที่อยู่นี้ หรือชี้ไปคนละพิกัดที่อยู่คนละย่านกัน
- **ยังไม่ได้ตรวจ:** ข้อ 226 ไม่พบที่อยู่ที่ครบพอจะนำไปค้นแผนที่ได้
- **ตัวอย่าง:** ที่อยู่ที่ Broker B แสดงระบุเลขที่ 188 บนถนนสายหนึ่ง แต่แผนที่ทั้งสองเจ้าแสดงว่าถนนสายนั้นมีเลขที่สูงสุดถึง 96 เท่านั้น และค้นด้วยรหัสไปรษณีย์แล้วได้คนละเขต → **ไม่ผ่าน**

**P01-228 · ภาพถ่ายถนนสาธารณะแสดงอาคารในลักษณะใด** `w2` `PUB`

- **ตรวจอะไร:** เปิดภาพถ่ายถนนระดับสายตาจากบริการแผนที่สาธารณะที่พิกัดของข้อ 227 แล้วบันทึกลักษณะของสิ่งปลูกสร้าง ณ พิกัดนั้น เช่น อาคารสำนักงาน อาคารพาณิชย์ ที่พักอาศัย ที่ดินว่าง หรือร้านค้า พร้อมบันทึก **ปีที่ถ่ายภาพ** ที่บริการนั้นระบุ ข้อนี้บันทึกข้อเท็จจริงจากภาพสาธารณะเท่านั้น **ห้ามสรุปว่าไม่มีสำนักงานจากภาพเพียงอย่างเดียว**
- **ขั้นตอนการตรวจ:**
  1. เปิดภาพถ่ายถนนระดับสายตาที่พิกัดจากข้อ 227
  2. บันทึกปีและเดือนที่บริการระบุว่าถ่ายภาพนั้น จับภาพให้เห็นข้อมูลนี้ในเฟรม
  3. บันทึกลักษณะสิ่งปลูกสร้างที่เห็น และป้ายชื่อทุกป้ายที่อ่านได้ที่หน้าอาคาร
  4. ตรวจว่าเห็นชื่อโบรกหรือชื่อ entity คู่สัญญาบนป้ายใดหรือไม่ บันทึกผล
  5. ถ้าบริการมีภาพหลายปี ให้เปิดย้อนอย่างน้อย 2 ปีที่ต่างกัน แล้วบันทึกว่าป้ายเปลี่ยนหรือไม่
  6. เทียบสิ่งที่เห็นกับภาพสำนักงานที่โบรกใช้บนเว็บ (ถ้ามี) บันทึกว่าตรงกันหรือไม่
  7. บันทึกตารางผลพร้อมภาพทุกมุม และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพถ่ายถนนสาธารณะทุกปีที่เปิดดู พร้อมข้อมูลปีที่ถ่ายในเฟรม (`RST-BRKA-P01-228-01` เป็นต้นไป) · ตารางบันทึกลักษณะอาคารและป้ายชื่อ · ภาพสำนักงานที่โบรกใช้บนเว็บ
- **ผ่าน:** ภาพถ่ายถนนสาธารณะแสดงสิ่งปลูกสร้างที่ใช้เป็นสถานประกอบการได้ ณ พิกัดที่อ้าง
- **ไม่ผ่าน:** ภาพถ่ายถนนสาธารณะที่พิกัดนั้นแสดงที่ดินว่างหรือสิ่งที่ไม่ใช่สิ่งปลูกสร้าง ในภาพทุกปีที่บริการมีให้ดู
- **ยังไม่ได้ตรวจ:** บริการแผนที่ไม่มีภาพถ่ายถนนระดับสายตาครอบคลุมพิกัดนั้น
- **ตัวอย่าง:** เว็บ Broker C ใช้ภาพอาคารกระจกสูง 30 ชั้นเป็นภาพสำนักงานใหญ่ แต่ภาพถ่ายถนนสาธารณะที่พิกัดตามที่อยู่ในหน้า Contact แสดงอาคารพาณิชย์ 3 ชั้นที่ชั้นล่างเป็นร้านอาหาร ทั้งนี้ภาพถนนยังแสดงเป็นสิ่งปลูกสร้างที่ใช้เป็นสถานประกอบการได้ → **ผ่าน** (แต่ต้องบันทึกส่วนต่างของภาพไว้ประกอบข้อ 250)

**P01-229 · ที่อยู่ที่แสดงเป็นที่อยู่ของผู้ให้บริการรับจดทะเบียนหรือไม่** `w3` `PUB`

- **ตรวจอะไร:** ตรวจว่าที่อยู่ที่โบรกแสดงเป็นที่อยู่ของบริษัทรับจดทะเบียน สำนักงานกฎหมาย หรือผู้ให้บริการที่อยู่จดทะเบียน (registered agent / company formation service) หรือไม่ โดยค้นที่อยู่นั้นในเครื่องมือค้นหาและในทะเบียนบริษัทสาธารณะ บันทึกชื่อผู้ให้บริการที่พบและแหล่งที่พบ
- **ขั้นตอนการตรวจ:**
  1. วางที่อยู่แบบเต็มในเครื่องมือค้นหาโดยใส่เครื่องหมายคำพูดคร่อม บันทึกจำนวนผลลัพธ์และชื่อองค์กรที่ปรากฏใน 3 หน้าแรก
  2. ค้นซ้ำด้วยที่อยู่บวกคำว่า `registered agent` `company formation` `virtual office` `registered office services`
  3. เปิดเว็บทางการของทุกองค์กรที่ผลค้นชี้ว่าให้บริการรับจดทะเบียนที่ที่อยู่นี้ จับภาพหน้าที่แสดงที่อยู่ตรงกัน
  4. เปิดทะเบียนบริษัทสาธารณะของเขตนั้น แล้วค้นด้วยที่อยู่ (ถ้าทะเบียนรองรับการค้นด้วยที่อยู่) บันทึกผล
  5. บันทึกว่าเว็บโบรกมีคำกำกับหรือไม่ว่าที่อยู่นี้เป็นสำนักงานจดทะเบียน ไม่ใช่สำนักงานปฏิบัติการ
  6. เก็บสำเนาถาวรของทุกหน้าที่ใช้ยืนยัน แล้วบันทึกผลและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพผลค้นที่อยู่แบบมีเครื่องหมายคำพูด (`RST-BRKA-P01-229-01`) · ภาพเว็บผู้ให้บริการรับจดทะเบียนที่ใช้ที่อยู่เดียวกัน · สำเนาถาวร
- **ผ่าน:** ที่อยู่ไม่ใช่ที่อยู่ของผู้ให้บริการรับจดทะเบียน หรือเป็นแต่เว็บโบรกมีคำกำกับว่าเป็นสำนักงานจดทะเบียน
- **ไม่ผ่าน:** ที่อยู่เป็นที่อยู่ของผู้ให้บริการรับจดทะเบียนหรือสำนักงานเสมือน โดยเว็บแสดงในลักษณะที่ทำให้เข้าใจว่าเป็นสำนักงานของโบรกเอง
- **ยังไม่ได้ตรวจ:** ข้อ 226 ไม่พบที่อยู่ที่ครบพอจะค้นได้
- **ตัวอย่าง:** ที่อยู่ที่ Broker A ใช้ในหน้า Contact ตรงกับที่อยู่ที่ประกาศอยู่บนเว็บของบริษัทรับจดทะเบียนรายหนึ่ง และเว็บโบรกพาดหัวส่วนนั้นว่า *"สำนักงานของเรา"* พร้อมภาพพนักงานในออฟฟิศ → **ไม่ผ่าน**

**P01-230 · มีนิติบุคคลอื่นจำนวนมากใช้ที่อยู่เดียวกันหรือไม่** `w2` `PUB`

- **ตรวจอะไร:** ค้นในทะเบียนบริษัทสาธารณะหรือแหล่งข้อมูลบริษัทสาธารณะว่ามีนิติบุคคลอื่นจดทะเบียนที่ที่อยู่เดียวกันกี่ราย บันทึกจำนวนที่พบ ชื่อแหล่งที่ค้น และวันเวลาที่ค้น ข้อนี้บันทึกข้อเท็จจริงเชิงปริมาณ **ห้ามสรุปว่าโบรกไม่มีตัวตนจากจำนวนเพียงอย่างเดียว**
- **ขั้นตอนการตรวจ:**
  1. เปิดทะเบียนบริษัทสาธารณะของเขตที่ที่อยู่นั้นตั้งอยู่ ตรวจว่ารองรับการค้นด้วยที่อยู่หรือไม่
  2. ค้นด้วยที่อยู่แบบเต็ม บันทึกจำนวนนิติบุคคลที่ผลลัพธ์แสดง จับภาพให้เห็นจำนวนในเฟรม
  3. ถ้าทะเบียนไม่รองรับการค้นด้วยที่อยู่ ให้ค้นในแหล่งข้อมูลบริษัทสาธารณะอื่นที่ระบุแหล่งที่มาของข้อมูลได้ บันทึกชื่อแหล่ง
  4. บันทึกว่าในรายชื่อที่พบมีชื่อที่คล้ายกับ entity ในกลุ่มของโบรกกี่ราย

- **ไม่ผ่าน:** แหล่งสาธารณะรองรับการค้นด้วยที่อยู่ แต่ผู้ตรวจไม่ได้บันทึกจำนวนและรายชื่อไว้
- **ยังไม่ได้ตรวจ:** ไม่มีแหล่งสาธารณะใดในเขตนั้นที่ค้นด้วยที่อยู่ได้
- **ตัวอย่าง:** ค้นที่อยู่ของ Broker B ในทะเบียนบริษัทสาธารณะ พบนิติบุคคล 412 รายที่ที่อยู่เดียวกัน โดยผู้ตรวจบันทึกจำนวน รายชื่อ 412 ราย แหล่งที่ค้น และเก็บสำเนาถาวรครบ → **ผ่าน** (บันทึกเป็นข้อสังเกตประกอบข้อ 250)

**P01-231 · ที่อยู่ระบุชั้น ห้อง หรือยูนิตที่เจาะจงหรือไม่** `w2` `WEB+PUB`

  1. อ่านที่อยู่จากตารางข้อ 226 บันทึกว่ามีคำว่า `floor` `suite` `unit` `room` `ชั้น` `ห้อง` หรือไม่

  3. เปิดภาพถ่ายถนนสาธารณะจากข้อ 228 แล้วนับจำนวนชั้นของอาคารที่เห็น บันทึกจำนวน

  6. จับภาพทุกแหล่ง แล้วบันทึกตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพที่อยู่บนเว็บที่เห็นหน่วยย่อย (`RST-BRKA-P01-231-01`) · ภาพถ่ายถนนที่นับชั้นได้ · ตารางเทียบกับที่อยู่ในทะเบียน
- **ผ่าน:** ที่อยู่ระบุหน่วยย่อย และหน่วยย่อยนั้นไม่ขัดกับจำนวนชั้นของอาคารตามภาพถ่ายถนนสาธารณะ
- **ไม่ผ่าน:** ที่อยู่ในอาคารหลายผู้เช่าแต่ไม่ระบุหน่วยย่อยใดเลย หรือระบุเลขชั้นที่สูงกว่าจำนวนชั้นของอาคารที่นับได้จากภาพ
- **ยังไม่ได้ตรวจ:** ไม่มีภาพถ่ายถนนสาธารณะให้นับจำนวนชั้น และทะเบียนไม่ระบุหน่วยย่อย
- **ตัวอย่าง:** Broker C ระบุที่อยู่เป็น *"ชั้น 12"* ของอาคารหนึ่ง แต่ภาพถ่ายถนนสาธารณะทุกปีแสดงอาคาร 4 ชั้น และทะเบียนบริษัทระบุเพียงเลขที่ถนนโดยไม่มีชั้น → **ไม่ผ่าน**

**P01-232 · ที่อยู่ในทุกช่องทางสอดคล้องกันหรือไม่** `w2` `WEB+DOC+PAY+PLT`

- **ตรวจอะไร:** รวบรวมที่อยู่ที่โบรกใช้ในทุกช่องทางที่ลูกค้าได้รับจริง แล้วเทียบว่าตรงกันหรือไม่ ครอบคลุม 6 ช่องทาง: footer เว็บ · หน้า Contact · Client Agreement · ท้ายอีเมลจากระบบ · ใบเสร็จหรือเอกสารการฝากเงิน · หน้าข้อมูลผู้พัฒนาในแอปสโตร์ บันทึกที่อยู่ที่พบในแต่ละช่องทางแบบคำต่อคำ
- **ขั้นตอนการตรวจ:**
  1. คัดลอกที่อยู่จาก footer และหน้า Contact ลงตารางช่องทางที่ 1 และ 2
  2. เปิด Client Agreement ค้นที่อยู่ในส่วนคู่สัญญา บันทึกพร้อมเลขข้อและเลขหน้า ลงช่องทางที่ 3
  3. เปิดอีเมลที่ระบบส่งมาให้บัญชีทดสอบ อ่านส่วนท้ายอีเมล คัดลอกที่อยู่ลงช่องทางที่ 4
  4. เปิดใบเสร็จหรือเอกสารยืนยันการฝากเงินที่ได้รับจริง คัดลอกที่อยู่ลงช่องทางที่ 5
  5. เปิดหน้าข้อมูลผู้พัฒนาแอปในแอปสโตร์ทั้งสองระบบ คัดลอกที่อยู่ลงช่องทางที่ 6
  6. เทียบทั้ง 6 แถวทีละบรรทัด ทำเครื่องหมายทุกช่องทางที่ที่อยู่ต่างจากช่องทางอื่น
  7. บันทึกตาราง 6 แถวพร้อมภาพทุกช่องทาง และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพที่อยู่จากทั้ง 6 ช่องทาง (`RST-BRKA-P01-232-01` ถึง `-06`) · ตารางเทียบ 6 แถว
- **ผ่าน:** ทุกช่องทางที่แสดงที่อยู่ ใช้ที่อยู่เดียวกัน หรือใช้ต่างกันแต่แต่ละที่อยู่มีคำกำกับบทบาทไว้ในช่องทางนั้น
- **ไม่ผ่าน:** มีอย่างน้อย 2 ช่องทางที่แสดงที่อยู่ต่างกันโดยไม่มีคำกำกับบทบาทใด
- **ยังไม่ได้ตรวจ:** ยังเก็บข้อมูลไม่ครบ 6 ช่องทาง
- **ตัวอย่าง:** footer และสัญญาของ Broker A ใช้ที่อยู่ในเขตหนึ่ง ท้ายอีเมลระบบใช้ที่อยู่อีกเขตหนึ่ง และหน้าแอปสโตร์ใช้ที่อยู่เขตที่สาม โดยไม่มีช่องทางใดอธิบายบทบาทของแต่ละที่อยู่ → **ไม่ผ่าน**

**P01-233 ● · ส่งไปรษณีย์ลงทะเบียนไปที่อยู่นั้นในฐานะลูกค้าแล้วถึงหรือไม่** `w3` `PUB+SUP`

- **ตรวจอะไร:** ทดสอบว่าที่อยู่ที่โบรกประกาศรับจดหมายได้จริงหรือไม่ โดยส่งจดหมายในฐานะ **ลูกค้าทั่วไป** ด้วยเรื่องที่ลูกค้าส่งได้ตามปกติ เช่น คำขอรับสำเนา statement เป็นเอกสาร หรือหนังสือสอบถามตามช่องทางที่โบรกประกาศ ส่งแบบลงทะเบียนที่มีใบตอบรับหรือติดตามสถานะได้ **ห้ามระบุว่าเป็นการตรวจสอบ ห้ามใช้ชื่อหรืออีเมลที่เชื่อมโยงกับ RedStarTrust** บันทึกวันที่ส่ง เลขติดตามพัสดุ และสถานะปลายทาง
- **ขั้นตอนการตรวจ:**
  1. ร่างจดหมายในฐานะลูกค้า โดยอ้างเลขบัญชีของบัญชีทดสอบ และขอสิ่งที่ลูกค้าขอได้ตามปกติ เก็บสำเนาจดหมายฉบับที่ส่ง
  2. จ่าหน้าซองด้วยที่อยู่จากข้อ 226 แบบคำต่อคำ ห้ามแก้ไขหรือเติมข้อมูลที่โบรกไม่ได้ประกาศ
  3. ส่งแบบลงทะเบียนที่ติดตามสถานะได้ บันทึกวันที่ส่ง เลขติดตาม และถ่ายภาพซองก่อนส่ง
  4. ติดตามสถานะพัสดุทุก 7 วัน จับภาพหน้าติดตามสถานะทุกครั้งพร้อมวันที่
  5. บันทึกวันที่สถานะเปลี่ยนเป็นนำจ่ายสำเร็จ หรือวันที่ถูกตีกลับพร้อมเหตุผลที่ไปรษณีย์ระบุ
  6. รอผลจนครบกรอบเวลาที่กำหนด `[เกณฑ์เสนอ: 45 วันปฏิทิน นับจากวันที่ส่ง]` แล้วบันทึกสถานะสุดท้าย
  7. ตรวจกล่องอีเมลและพื้นที่ลูกค้าของบัญชีทดสอบ ว่าโบรกตอบกลับเรื่องที่ส่งไปหรือไม่ พร้อมวันที่ตอบ
  8. บันทึกตารางไทม์ไลน์ทั้งหมดพร้อมหลักฐาน และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** สำเนาจดหมายฉบับที่ส่ง · ภาพซองก่อนส่ง (`RST-BRKA-P01-233-01`) · ใบรับฝากที่มีเลขติดตาม (`-02`) · ภาพหน้าติดตามสถานะทุกครั้ง (`-03` เป็นต้นไป) · ภาพใบตอบรับหรือภาพซองที่ถูกตีกลับ
- **ผ่าน:** สถานะพัสดุเปลี่ยนเป็นนำจ่ายสำเร็จที่ที่อยู่นั้น ภายในกรอบเวลาที่กำหนด
- **ไม่ผ่าน:** พัสดุถูกตีกลับด้วยเหตุผลว่าไม่มีผู้รับหรือที่อยู่ไม่ถูกต้อง หรือสถานะไม่เปลี่ยนเป็นนำจ่ายสำเร็จภายในกรอบเวลาที่กำหนด
- **ยังไม่ได้ตรวจ:** บริการไปรษณีย์ไม่ให้บริการติดตามสถานะไปยังปลายทางนั้น หรือยังไม่ครบกรอบเวลา
- **ตัวอย่าง:** จดหมายถึง Broker B ที่จ่าหน้าตามที่อยู่ในหน้า Contact ทุกตัวอักษร ถูกตีกลับหลัง 21 วันโดยไปรษณีย์ระบุเหตุผลว่าไม่มีผู้รับตามที่อยู่นี้ ขณะที่หน้า Contact ยังแสดงที่อยู่เดิม → **ไม่ผ่าน**

**P01-234 · ใบตอบรับไปรษณีย์ระบุผู้รับที่เชื่อมโยงกับโบรกหรือไม่** `w2` `PUB`

- **ตรวจอะไร:** กรณีจดหมายจากข้อ 233 นำจ่ายสำเร็จ ตรวจว่าข้อมูลผู้รับที่ปรากฏในใบตอบรับหรือในระบบติดตามพัสดุ เชื่อมโยงกับชื่อโบรกหรือชื่อ entity คู่สัญญาหรือไม่ หรือเป็นชื่อบุคคลหรือองค์กรที่ไม่เกี่ยวข้อง บันทึกชื่อผู้รับแบบคำต่อคำ

  1. เปิดใบตอบรับหรือหน้ารายละเอียดการนำจ่ายในระบบติดตามพัสดุ จับภาพให้เห็นเลขติดตามในเฟรม

- **ผ่าน:** ชื่อผู้รับตรงหรือเชื่อมโยงกับชื่อ entity คู่สัญญาหรือชื่อแบรนด์ของโบรก
- **ไม่ผ่าน:** ชื่อผู้รับเป็นองค์กรหรือบุคคลที่ไม่เชื่อมโยงกับโบรกและไม่มีคำอธิบายใดบนเว็บโบรกที่กล่าวถึงผู้รับรายนั้น
- **ยังไม่ได้ตรวจ:** จดหมายจากข้อ 233 ยังไม่นำจ่ายสำเร็จ หรือระบบไปรษณีย์ไม่เปิดเผยชื่อผู้รับ
- **ตัวอย่าง:** จดหมายถึง Broker A นำจ่ายสำเร็จ แต่ใบตอบรับระบุผู้รับเป็นสำนักงานบัญชีแห่งหนึ่ง ซึ่งค้นแล้วพบว่าเป็นผู้ให้บริการที่อยู่จดทะเบียนตามผลข้อ 229 และเว็บโบรกไม่มีที่ใดกล่าวถึงรายนี้ → **ไม่ผ่าน**

**P01-235 ● · เบอร์โทรที่ประกาศโทรติดและมีผู้รับสายหรือไม่** `w3` `SUP`

**P01-242 · ส่งข้อร้องเรียนตามช่องทางที่ประกาศแล้วได้รับการรับเรื่องหรือไม่** `w3` `SUP`

- **ตรวจอะไร:** ทดสอบช่องทางร้องเรียนจริง โดยยื่นเรื่องที่เป็นข้อร้องเรียนจริงของบัญชีทดสอบตามช่องทางที่โบรกประกาศ **ในฐานะลูกค้าทั่วไป** แล้ววัดว่าได้รับการรับทราบและเลขรับเรื่องหรือไม่ ภายในกรอบเวลาที่โบรกประกาศเอง บันทึกเวลา UTC ที่ยื่น เวลาที่ได้รับการรับทราบ และเวลาที่ได้รับคำตอบขั้นสุดท้าย **ห้ามสร้างข้อร้องเรียนเท็จ** ต้องเป็นประเด็นที่เกิดขึ้นจริงกับบัญชีทดสอบ

  3. เก็บสำเนาข้อความหรืออีเมลที่ยื่นฉบับเต็ม พร้อม header
  4. บันทึกเวลา UTC ที่ได้รับการรับทราบครั้งแรก และบันทึกว่าได้รับเลขรับเรื่องหรือไม่

  6. ติดตามจนได้รับคำตอบขั้นสุดท้าย หรือจนครบกรอบเวลาที่เอกสารระบุ บันทึกทุกการติดต่อพร้อมเวลา
  7. บันทึกไทม์ไลน์ฉบับเต็มพร้อม transcript ทุกชิ้น และตั้งชื่อไฟล์ตาม Evidence ID

- **ผ่าน:** ได้รับการรับทราบพร้อมเลขรับเรื่องภายในกรอบเวลาที่โบรกประกาศไว้เอง
- **ไม่ผ่าน:** ไม่ได้รับการรับทราบใดภายในกรอบเวลาที่โบรกประกาศไว้เอง หรือช่องทางที่ประกาศใช้ยื่นไม่ได้

**P01-243 · หน่วยงานระงับข้อพิพาทภายนอกที่ระบุไว้ ยืนยันได้กับหน่วยงานนั้นหรือไม่** `w3` `PUB`

  1. บันทึกชื่อหน่วยงานระงับข้อพิพาทที่โบรกระบุ พร้อมหน้าหรือเลขข้อของเอกสารที่พบ

  3. หาหน้าที่อธิบายขอบเขตการรับเรื่อง แล้วคัดลอกเงื่อนไขเป็นข้อความ
  4. ค้นในเว็บหน่วยงานว่ามีรายชื่อผู้ประกอบธุรกิจที่อยู่ในขอบเขตหรือไม่ ถ้ามี ให้ค้นชื่อ entity คู่สัญญาของเรา จับภาพผลลัพธ์
  5. เทียบเงื่อนไขของหน่วยงานกับสถานะของบัญชีทดสอบ เช่น ประเทศที่อยู่และประเภทลูกค้า บันทึกว่าเข้าเงื่อนไขหรือไม่
  6. ตรวจว่าลิงก์ที่โบรกให้ไว้พาไปยังโดเมนเดียวกับเว็บทางการหรือไม่ บันทึกผล
  7. เก็บสำเนาถาวรทุกหน้า บันทึกวันเวลา UTC แล้วตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าขอบเขตการรับเรื่องบนเว็บหน่วยงาน (`RST-BRKA-P01-243-01`) · ภาพผลค้นชื่อ entity คู่สัญญา (`-02`) · สำเนาถาวร · บันทึกเปรียบเทียบโดเมนของลิงก์ที่โบรกให้
- **ผ่าน:** หน่วยงานที่ระบุมีอยู่จริงตามเว็บทางการ และเงื่อนไขการรับเรื่องครอบคลุมลูกค้าในลักษณะเดียวกับบัญชีทดสอบ
- **ไม่ผ่าน:** ค้นไม่พบหน่วยงานที่โบรกระบุ หรือพบแต่เงื่อนไขของหน่วยงานระบุชัดว่าไม่รับเรื่องจากลูกค้าของ entity คู่สัญญาของเรา
- **ยังไม่ได้ตรวจ:** โบรกไม่ระบุหน่วยงานระงับข้อพิพาทภายนอกใดเลย (ให้บันทึกข้อเท็จจริงนี้และเชื่อมกับผลข้อ 241)
- **ตัวอย่าง:** Broker A ระบุชื่อหน่วยงานระงับข้อพิพาทแห่งหนึ่งในนโยบายข้อร้องเรียน เข้าเว็บทางการของหน่วยงานนั้นแล้วพบว่ารับเรื่องเฉพาะลูกค้าของบริษัทที่ตั้งอยู่ในเขตหนึ่ง ขณะที่ entity คู่สัญญาของเราจดทะเบียนคนละเขตและไม่อยู่ในรายชื่อ → **ไม่ผ่าน**

**P01-246 · แชทสดตอบโดยคนจริงและระบุ entity ผู้ให้บริการหรือไม่** `w2` `SUP`

  2. จับเวลาตั้งแต่ส่งข้อความแรกจนมีผู้ตอบที่ไม่ใช่ข้อความอัตโนมัติ บันทึกเป็นวินาที
  3. ถามในฐานะลูกค้าว่า *"ผมกำลังทำสัญญากับบริษัทชื่ออะไรครับ"* แล้วบันทึกคำตอบแบบคำต่อคำ

- **ผ่าน:** มีคนตอบอย่างน้อย 2 ใน 3 ครั้ง และชื่อ entity ที่ระบุตรงกับ entity คู่สัญญาในสัญญาที่เราได้รับ
- **ไม่ผ่าน:** แชทสดไม่มีคนตอบเลยทั้งสามครั้ง หรือมีคนตอบแต่ระบุชื่อ entity ที่ไม่ตรงกับ entity คู่สัญญาในสัญญา
- **ยังไม่ได้ตรวจ:** เว็บไม่มีแชทสด หรือยังทดสอบไม่ครบ 3 ครั้ง
- **ตัวอย่าง:** แชทสดของ Broker A มีคนตอบทั้งสามครั้ง แต่ทุกครั้งตอบเพียงชื่อแบรนด์และเลี่ยงคำถามเรื่องชื่อบริษัท ครั้งที่สามตอบชื่อ entity ที่จดทะเบียนคนละเขตกับ entity ในสัญญาที่เราเซ็น → **ไม่ผ่าน**

**P01-247 · ข้อมูลติดต่อในแอปตรงกับที่แสดงบนเว็บหรือไม่** `w2` `PLT+WEB`

  3. คัดลอกที่อยู่ เบอร์โทร และอีเมลที่แอปแสดง ลงตารางแยกตามระบบปฏิบัติการ
  4. เทียบทุกค่ากับข้อมูลบนเว็บจากผลข้อ 226 235 และ 238 ทำเครื่องหมายทุกค่าที่ต่างกัน
  5. ตรวจว่าแอปแสดงชื่อ entity ผู้ให้บริการหรือไม่ บันทึกชื่อที่พบ

- **หลักฐานที่ต้องเก็บ:** ภาพหน้าจอ About/Help/Contact ในแอปทั้งสองระบบ (`RST-BRKA-P01-247-01` เป็นต้นไป) · ตารางเทียบแอปกับเว็บ · บันทึกเวอร์ชันแอปและวันที่
- **ผ่าน:** ที่อยู่ เบอร์โทร และอีเมลในแอปตรงกับที่แสดงบนเว็บทุกค่า หรือต่างกันแต่แอปมีคำกำกับบทบาทของแต่ละค่า
- **ไม่ผ่าน:** มีอย่างน้อย 1 ค่าในแอปที่ต่างจากบนเว็บโดยไม่มีคำกำกับใด
- **ยังไม่ได้ตรวจ:** โบรกไม่มีแอปในแอปสโตร์ทางการ

**P01-248 · ข้อมูลผู้จดทะเบียนโดเมนและอายุโดเมนสอดคล้องกับที่โบรกอ้างหรือไม่** `w1` `PUB`

  2. บันทึกวันที่จดทะเบียนครั้งแรก วันที่ปรับปรุงล่าสุด และวันหมดอายุ จับภาพให้เห็นในเฟรมเดียว
  3. บันทึกว่าข้อมูลผู้จดทะเบียนถูกเปิดเผยหรือถูกปกปิด ถ้าเปิดเผย ให้บันทึกชื่อและประเทศที่ปรากฏ
  4. เทียบวันที่จดทะเบียนโดเมนกับปีก่อตั้งที่โบรกอ้างบนเว็บ คำนวณส่วนต่างเป็นจำนวนปี
  5. ทำซ้ำขั้น 1–4 กับโดเมนภูมิภาคอื่นของแบรนด์เดียวกันที่พบ บันทึกลงตารางเดียวกัน

- **ผ่าน:** วันที่จดทะเบียนโดเมนไม่ขัดกับปีก่อตั้งที่โบรกอ้าง หรือขัดกันแต่เว็บมีคำอธิบายเช่นเปลี่ยนโดเมนจากเดิม
- **ไม่ผ่าน:** โดเมนที่ใช้สมัครจดทะเบียนหลังปีที่โบรกอ้างว่าให้บริการมาแล้วอย่างมีนัย โดยไม่มีคำอธิบายใดบนเว็บ `[เกณฑ์เสนอ: ส่วนต่างเกิน 3 ปี]`

**P01-249 · ที่อยู่หรือช่องทางติดต่อเปลี่ยนระหว่างรอบตรวจโดยไม่แจ้งลูกค้าหรือไม่** `w2` `WEB+SUP`

**P01-250 · สรุปการพิสูจน์ตัวตนองค์กรจากทุกช่องทางที่ลูกค้าเข้าถึงได้** `w3` `รวมทุกวิธี`

  4. เทียบจำนวนช่องทางที่ใช้ได้จริง กับจำนวนช่องทางที่โบรกประกาศไว้บนเว็บ บันทึกส่วนต่าง
  5. ตรวจว่าในบรรดาช่องทางที่ใช้ได้จริง มีอย่างน้อย 1 ช่องทางที่เป็นช่องทางตามกฎหมาย คือที่อยู่ทางไปรษณีย์หรือช่องทางร้องเรียนที่ประกาศไว้ หรือไม่
  6. บันทึกข้อสังเกตประกอบจากข้อ 228 229 230 และ 231 เรื่องลักษณะของที่อยู่ ลงในหมายเหตุของตาราง
  7. บันทึกตารางสรุปฉบับสมบูรณ์พร้อมคำตัดสิน และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางสรุป 6 ช่องทางพร้อม Evidence ID ทุกแถว (`RST-BRKA-P01-250-01`) · บันทึกจำนวนช่องทางที่ประกาศเทียบกับที่ใช้ได้จริง · หมายเหตุข้อสังเกตเรื่องที่อยู่
- **ผ่าน:** มีช่องทางตามกฎหมายอย่างน้อย 1 ช่องทางที่พิสูจน์แล้วว่าใช้ได้จริง คือที่อยู่ทางไปรษณีย์นำจ่ายสำเร็จ หรือช่องทางร้องเรียนที่ประกาศไว้ได้รับการรับเรื่อง
- **ไม่ผ่าน:** ไม่มีช่องทางตามกฎหมายใดที่พิสูจน์แล้วว่าใช้ได้จริง ทั้งที่โบรกประกาศช่องทางเหล่านั้นไว้บนเว็บ
- **ยังไม่ได้ตรวจ:** ยังเติมสถานะไม่ครบ 6 แถว
- **ตัวอย่าง:** ตารางสรุปของ Broker B พบว่าแชทสดและอีเมล support ใช้ได้จริง แต่จดหมายลงทะเบียนถูกตีกลับ อีเมล complaints ตีกลับ เบอร์สายด่วนร้องเรียนไม่มีในระบบ และหน่วยงานระงับข้อพิพาทที่ระบุไม่รับเรื่องจาก entity คู่สัญญาของเรา ทำให้ไม่มีช่องทางตามกฎหมายใดใช้ได้เลย → **ไม่ผ่าน**
