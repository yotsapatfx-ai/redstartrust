## S03 · สิทธิของโบรกในการใช้เงินลูกค้าตามสัญญา (051–075)

**P02-051 ● · สัญญามีข้อให้สิทธิโบรกนำเงินลูกค้าไปใช้เพื่อประโยชน์ของตนเองหรือไม่** `w3` `DOC` `G3`

- **ตรวจอะไร:** เปิดสัญญาลูกค้าฉบับที่เราได้รับตอนสมัคร (Client Agreement หรือ Terms of Business) แล้วอ่านทั้งฉบับเพื่อหาข้อที่ให้สิทธิโบรก "ใช้" "นำไปใช้" "จัดการ" หรือ "โอน" เงินของลูกค้าเพื่อวัตถุประสงค์ของโบรกเอง บันทึกเลขข้อ ชื่อหัวข้อ ข้อความแบบคำต่อคำ และหน้าที่พบ จุดที่ต้องอ่านเป็นพิเศษคือหมวด Client Money · Client Funds · Segregation · Collateral · Security Interest · General Terms ท้ายเล่ม ไม่นับข้อที่พูดถึงการหักค่าธรรมเนียมตามปกติ ซึ่งแยกไปตรวจในข้อ 065–066
- **ขั้นตอนการตรวจ:**
  1. ดาวน์โหลดสัญญาลูกค้าทุกฉบับที่ต้องกดยอมรับตอนสมัคร เก็บเป็น PDF พร้อมบันทึกวันที่ดาวน์โหลดและ URL ต้นทาง
  2. ค้นในไฟล์ทีละคำ: `use` `utilise` `utilize` `employ` `own account` `for its own purposes` `นำไปใช้` `เพื่อประโยชน์ของบริษัท` บันทึกจำนวนที่พบต่อคำ
  3. อ่านข้อความเต็มของทุกจุดที่พบ พร้อมย่อหน้าก่อนหน้าและถัดไป เพื่อไม่ให้เข้าใจบริบทผิด
  4. คัดลอกข้อความของทุกข้อที่เข้าข่ายลงตารางบันทึก พร้อมเลขข้อและเลขหน้า
  5. ทำเครื่องหมายแยกว่าข้อใดเป็นสิทธิใช้เงินเพื่อประโยชน์ของโบรก และข้อใดเป็นเพียงการดำเนินการตามคำสั่งลูกค้า
  6. จับภาพหน้าเอกสารที่พบข้อความ ให้เห็นเลขข้อและเลขหน้าในเฟรมเดียวกัน
  7. บันทึกผลลงแบบฟอร์มและตั้งชื่อไฟล์ตามรูปแบบ Evidence ID
- **หลักฐานที่ต้องเก็บ:** PDF สัญญาทุกฉบับพร้อม hash (`RST-BRKA-P02-051-01`) · ภาพหน้าที่พบข้อความเห็นเลขข้อ (`RST-BRKA-P02-051-02` เป็นต้นไป) · ตารางข้อความคำต่อคำพร้อมเลขข้อ
- **ผ่าน:** ไม่พบข้อใดให้สิทธิโบรกนำเงินลูกค้าไปใช้เพื่อประโยชน์ของโบรกเอง หรือพบแต่ข้อนั้นระบุขอบเขตและเงื่อนไขไว้ครบทั้งสามอย่าง คือ วัตถุประสงค์ที่ใช้ได้ · ยอดสูงสุดหรือฐานคำนวณ · เงื่อนไขที่ต้องคืน
- **ไม่ผ่าน:** พบข้อให้สิทธิโบรกนำเงินลูกค้าไปใช้เพื่อประโยชน์ของโบรกเอง โดยขาดอย่างน้อย 1 ใน 3 อย่างข้างต้น
- **ยังไม่ได้ตรวจ:** ไม่ได้รับสัญญาฉบับเต็มตอนสมัคร และหาฉบับเดียวกันบนเว็บสาธารณะไม่พบ
- **ตัวอย่าง:** Broker A เขียนในข้อ 14.3 ว่าบริษัทอาจใช้เงินในบัญชีลูกค้าเพื่อวัตถุประสงค์ทางธุรกิจของบริษัท โดยไม่ระบุเพดานหรือเงื่อนไขคืน แต่มีคำว่า "ตามที่กฎหมายอนุญาต" กำกับไว้ — คำกำกับนี้ไม่ใช่ขอบเขตที่ระบุได้ → **ไม่ผ่าน** ตกด่าน G3

**P02-052 ● · สัญญามีข้อโอนกรรมสิทธิ์หลักประกัน (title transfer) หรือไม่** `w3` `DOC` `G3`

- **ตรวจอะไร:** ตรวจว่าสัญญามีข้อที่ทำให้เงินหรือหลักประกันที่ลูกค้าวางไว้ **เปลี่ยนกรรมสิทธิ์ไปเป็นของโบรก** หรือไม่ ซึ่งเป็นข้อที่เปลี่ยนสถานะลูกค้าจาก "เจ้าของเงินที่ถูกฝากไว้" เป็น "เจ้าหนี้ไม่มีประกันของบริษัท" ในกรณีบริษัทล้มละลาย บันทึกเลขข้อ ข้อความคำต่อคำ และคำนิยามที่เกี่ยวข้องในหมวดคำนิยามท้ายสัญญา
- **ขั้นตอนการตรวจ:**
  1. เปิดสัญญาทุกฉบับที่เก็บไว้จากข้อ 051
  2. ค้นทีละคำ: `title transfer` `TTCA` `transfer of title` `full ownership` `absolute interest` `outright transfer` `โอนกรรมสิทธิ์` `กรรมสิทธิ์ในหลักประกัน`
  3. เปิดหมวดคำนิยาม (Definitions) ค้นคำเดียวกันซ้ำ เพราะหลายฉบับซ่อนสาระไว้ในคำนิยาม
  4. อ่านข้อความเต็มทุกจุดที่พบ บันทึกว่าเงินส่วนใดถูกโอนกรรมสิทธิ์ — ทั้งบัญชี · เฉพาะยอดที่ใช้เป็นหลักประกัน · หรือเฉพาะยอดที่เกินเกณฑ์
  5. ค้นต่อว่ามีข้อความใดระบุผลของการโอนกรรมสิทธิ์เมื่อบริษัทล้มละลายหรือไม่ (`insolvency` `default` `unsecured creditor` `เจ้าหนี้ไม่มีประกัน`)
  6. จับภาพทุกจุดที่พบพร้อมเลขข้อและเลขหน้า
  7. บันทึกผลลงแบบฟอร์มและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อ title transfer เต็มข้อ (`RST-BRKA-P02-052-01`) · ภาพหมวดคำนิยามที่เกี่ยวข้อง (`-02`) · ตารางบันทึกว่าเงินส่วนใดถูกโอนกรรมสิทธิ์
- **ผ่าน:** ไม่มีข้อโอนกรรมสิทธิ์หลักประกันในสัญญา หรือมีแต่ระบุชัดทั้งขอบเขตยอดเงินและผลที่เกิดกับลูกค้าเมื่อบริษัทล้มละลาย ในข้อเดียวกันหรือข้อที่อ้างถึงกันโดยตรง
- **ไม่ผ่าน:** มีข้อโอนกรรมสิทธิ์หลักประกัน แต่ไม่ระบุขอบเขตยอดเงิน หรือไม่ระบุผลที่เกิดกับลูกค้าเมื่อบริษัทล้มละลาย
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** Broker B เขียนในคำนิยามว่า "Collateral" หมายถึงเงินที่โอนกรรมสิทธิ์ให้บริษัทโดยสมบูรณ์ แต่ในเนื้อสัญญาไม่มีข้อใดอธิบายว่าลูกค้าจะอยู่ในสถานะใดหากบริษัทล้มละลาย → **ไม่ผ่าน** ตกด่าน G3

**P02-053 · ข้อโอนกรรมสิทธิ์ระบุยอดที่ครอบคลุมและเงื่อนไขคืนกรรมสิทธิ์หรือไม่** `w2` `DOC`

- **ตรวจอะไร:** กรณีที่ข้อ 052 พบข้อโอนกรรมสิทธิ์ ให้ตรวจรายละเอียดต่อว่าสัญญาระบุ **ฐานคำนวณยอดที่โอน** และ **เงื่อนไขที่เงินจะกลับมาเป็นของลูกค้า** ไว้หรือไม่ บันทึกสูตรหรือถ้อยคำที่ใช้กำหนดยอด และเหตุการณ์ที่ทำให้ต้องคืน เช่น ปิดสถานะทั้งหมด · ยอดหลักประกันเกินความจำเป็น · ลูกค้าร้องขอ
- **ขั้นตอนการตรวจ:**
  1. เปิดข้อ title transfer ที่บันทึกไว้จากข้อ 052
  2. อ่านหาถ้อยคำที่กำหนดยอด: `such amount as` `equal to` `margin requirement` `excess` `ยอดเท่ากับ` `ส่วนที่เกิน` บันทึกคำต่อคำ
  3. อ่านหาถ้อยคำที่กำหนดการคืน: `re-transfer` `return` `release` `equivalent collateral` `คืน` `ปลดหลักประกัน` บันทึกคำต่อคำ
  4. บันทึกว่าการคืนเกิดขึ้นอัตโนมัติ หรือต้องให้ลูกค้าร้องขอ และมีกรอบเวลากี่วันทำการ
  5. ทำตารางสองคอลัมน์: ฐานคำนวณยอดที่โอน · เงื่อนไขและกรอบเวลาการคืน แล้วทำเครื่องหมายช่องที่สัญญาไม่ระบุ
  6. บันทึกตารางพร้อมภาพหน้าเอกสารและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางสองคอลัมน์พร้อมข้อความคำต่อคำ · ภาพข้อที่ระบุยอดและเงื่อนไขคืน (`RST-BRKA-P02-053-01`)
- **ผ่าน:** สัญญาระบุครบทั้งฐานคำนวณยอดที่โอนและเงื่อนไขการคืน โดยระบุกรอบเวลาการคืนเป็นจำนวนวันที่นับได้
- **ไม่ผ่าน:** ขาดฐานคำนวณยอด หรือขาดเงื่อนไขการคืน หรือระบุการคืนไว้แต่ไม่มีกรอบเวลาที่นับได้
- **ยังไม่ได้ตรวจ:** สัญญาไม่มีข้อโอนกรรมสิทธิ์เลย (ให้บันทึกว่าไม่เกี่ยวข้อง และไม่นำเข้าสูตรคะแนน)
- **ตัวอย่าง:** Broker C ระบุว่าจะคืนกรรมสิทธิ์ส่วนที่เกินความจำเป็น "ภายในเวลาอันสมควร" โดยไม่ระบุจำนวนวัน → **ไม่ผ่าน**

**P02-054 ● · สัญญาให้สิทธิโบรกหักกลบหนี้ระหว่างบัญชีของลูกค้าหรือไม่** `w3` `DOC` `G3`

- **ตรวจอะไร:** ตรวจข้อ set-off / netting ในสัญญา ว่าให้สิทธิโบรกนำยอดคงเหลือในบัญชีหนึ่งของลูกค้าไปหักกับยอดติดลบในอีกบัญชีหนึ่งได้หรือไม่ บันทึกเลขข้อ ขอบเขตบัญชีที่ครอบคลุม (บัญชีเทรดทุกบัญชี · บัญชีสกุลเงินต่างกัน · บัญชีที่เปิดกับ entity คนละราย) และเงื่อนไขที่จุดชนวนสิทธินี้
- **ขั้นตอนการตรวจ:**
  1. ค้นในสัญญาทุกฉบับทีละคำ: `set-off` `set off` `netting` `combine accounts` `consolidate` `หักกลบ` `หักกลบลบหนี้` `รวมบัญชี`
  2. อ่านข้อความเต็มทุกจุด บันทึกเลขข้อและข้อความคำต่อคำ
  3. บันทึกว่าสิทธิหักกลบครอบคลุมบัญชีใดบ้าง โดยอ่านคำนิยามของคำว่า "Account" หรือ "บัญชี" ในหมวดคำนิยามประกอบ
  4. บันทึกเหตุที่ทำให้โบรกใช้สิทธิได้ — เกิดเมื่อผิดนัดเท่านั้น หรือใช้ได้ทุกเมื่อตามดุลพินิจ
  5. บันทึกว่าสัญญากำหนดให้ต้องแจ้งลูกค้าก่อนหรือหลังใช้สิทธิ และกำหนดกรอบเวลาแจ้งไว้หรือไม่
  6. เปิดพอร์ทัลลูกค้าของเราเอง นับจำนวนบัญชีที่เราถืออยู่จริง แล้วทำเครื่องหมายว่าบัญชีใดเข้าข่ายถูกหักกลบตามนิยามนั้น
  7. จับภาพข้อสัญญาและหน้ารายการบัญชีในพอร์ทัล บันทึกผลและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อ set-off เต็มข้อ (`RST-BRKA-P02-054-01`) · ภาพหมวดคำนิยามคำว่าบัญชี (`-02`) · ภาพหน้ารายการบัญชีในพอร์ทัล (`-03`) · ตารางขอบเขตบัญชีที่ถูกครอบคลุม
- **ผ่าน:** ไม่มีข้อหักกลบ หรือมีแต่จำกัดเฉพาะบัญชีของลูกค้าเองกับนิติบุคคลคู่สัญญารายเดียวกัน และระบุเหตุที่ใช้สิทธิเป็นรายการปิด
- **ไม่ผ่าน:** มีข้อหักกลบที่ให้ใช้สิทธิได้ตามดุลพินิจโดยไม่จำกัดเหตุ หรือครอบคลุมบัญชีที่เปิดกับนิติบุคคลรายอื่น
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** Broker A ระบุสิทธิหักกลบเฉพาะกรณีลูกค้าผิดนัด แต่คำนิยาม "Account" ครอบคลุมบัญชีทุกบัญชีที่ลูกค้าเปิดกับบริษัทในกลุ่มทั่วโลก โดยไม่มีรายชื่อบริษัทในกลุ่มระบุไว้ → **ไม่ผ่าน** ตกด่าน G3

**P02-055 · สิทธิหักกลบครอบคลุมบัญชีของบุคคลอื่นหรือบริษัทในเครือหรือไม่** `w2` `DOC`

- **ตรวจอะไร:** ขยายผลจากข้อ 054 โดยเจาะจงว่าข้อหักกลบลามไปถึง **บัญชีของบุคคลอื่นที่เกี่ยวข้องกับลูกค้า** (บัญชีร่วม · ผู้ค้ำ · บัญชีนิติบุคคลที่ลูกค้าเป็นกรรมการ) หรือถึง **หนี้ที่ลูกค้ามีกับบริษัทในเครือของโบรก** หรือไม่ บันทึกถ้อยคำที่ทำให้ขอบเขตขยาย และตรวจว่าสัญญาระบุรายชื่อบริษัทในเครือไว้หรือไม่
- **ขั้นตอนการตรวจ:**
  1. เปิดข้อ set-off ที่บันทึกจากข้อ 054
  2. ค้นภายในข้อนั้นและข้อที่อ้างถึงกัน ด้วยคำว่า `affiliate` `group company` `related entity` `associated company` `joint account` `บริษัทในเครือ` `บัญชีร่วม`
  3. บันทึกทุกคำที่ทำให้ขอบเขตขยายออกไปนอกคู่สัญญาโดยตรง พร้อมเลขข้อ
  4. ค้นทั้งสัญญาว่ามีภาคผนวกหรือรายชื่อบริษัทในเครือแนบไว้หรือไม่ ถ้ามีให้บันทึกจำนวนรายชื่อ ถ้าไม่มีให้บันทึกว่า "ไม่มีรายชื่อ"
  5. ค้นบนเว็บสาธารณะของโบรกว่ามีหน้ารายชื่อบริษัทในกลุ่มที่ตรงกันหรือไม่ เก็บสำเนาถาวรของหน้านั้น
  6. บันทึกผลลงตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อความที่ขยายขอบเขต (`RST-BRKA-P02-055-01`) · ภาพภาคผนวกรายชื่อหรือบันทึกว่าไม่มี · สำเนาถาวรหน้ารายชื่อบริษัทในกลุ่มบนเว็บ
- **ผ่าน:** สิทธิหักกลบจำกัดเฉพาะหนี้ระหว่างลูกค้ากับนิติบุคคลคู่สัญญาโดยตรง หรือขยายไปบริษัทในเครือแต่มีรายชื่อบริษัทในเครือระบุไว้ในเอกสารที่ลูกค้าได้รับ
- **ไม่ผ่าน:** สิทธิหักกลบขยายไปบริษัทในเครือหรือบัญชีของบุคคลอื่น โดยไม่มีรายชื่อหรือคำนิยามที่ระบุขอบเขตได้แน่นอน
- **ยังไม่ได้ตรวจ:** สัญญาไม่มีข้อหักกลบเลย
- **ตัวอย่าง:** Broker B ระบุว่าอาจหักกลบกับหนี้ที่ลูกค้ามีต่อ "บริษัทใด ๆ ในกลุ่ม" โดยเว็บมีหน้ารายชื่อ 6 บริษัทที่ระบุครบและสัญญาอ้างถึงหน้านั้นตรง ๆ → **ผ่าน**

**P02-056 ● · สัญญาให้สิทธิยึดหน่วงหรือสิทธิเหนือทรัพย์ในเงินลูกค้าหรือไม่** `w3` `DOC`

- **ตรวจอะไร:** ตรวจว่าสัญญาสร้าง **สิทธิยึดหน่วง (lien) · สิทธิจำนำ (pledge) · หลักประกันทางธุรกิจ (charge / security interest)** เหนือเงินหรือทรัพย์สินของลูกค้าที่อยู่กับโบรกหรือไม่ ซึ่งต่างจากข้อโอนกรรมสิทธิ์ตรงที่กรรมสิทธิ์ยังเป็นของลูกค้าแต่โบรกมีสิทธิเหนือทรัพย์นั้น บันทึกเลขข้อ ประเภทสิทธิ ทรัพย์ที่ถูกครอบคลุม และหนี้ที่สิทธินี้ประกัน
- **ขั้นตอนการตรวจ:**
  1. ค้นในสัญญาทุกฉบับทีละคำ: `lien` `pledge` `charge` `security interest` `encumbrance` `retain` `สิทธิยึดหน่วง` `จำนำ` `หลักประกัน`
  2. อ่านข้อความเต็มทุกจุด บันทึกเลขข้อและข้อความคำต่อคำ
  3. บันทึกว่าสิทธินี้ครอบคลุมทรัพย์ใด — เงินสดในบัญชี · หลักประกันที่วางไว้ · สถานะที่เปิดอยู่ · ทุกอย่างที่อยู่ในครอบครองของโบรก
  4. บันทึกว่าสิทธินี้ประกันหนี้ประเภทใด — เฉพาะหนี้จากการเทรด หรือหนี้ทุกประเภทที่ลูกค้ามีต่อโบรก
  5. อ่านหาว่าสัญญากำหนดให้ต้องแจ้งลูกค้าก่อนบังคับใช้สิทธิหรือไม่ และมีกรอบเวลากี่วัน
  6. จับภาพทุกข้อที่พบพร้อมเลขข้อและเลขหน้า
  7. บันทึกผลลงตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อสิทธิยึดหน่วง/จำนำเต็มข้อ (`RST-BRKA-P02-056-01`) · ตารางสรุป ประเภทสิทธิ · ทรัพย์ที่ครอบคลุม · หนี้ที่ประกัน
- **ผ่าน:** ไม่มีข้อสร้างสิทธิเหนือทรัพย์ หรือมีแต่จำกัดเฉพาะหนี้ที่เกิดจากการเทรดในบัญชีนั้นเอง และระบุทรัพย์ที่ครอบคลุมไว้เป็นรายการปิด
- **ไม่ผ่าน:** มีข้อสร้างสิทธิเหนือทรัพย์ที่ครอบคลุมหนี้ทุกประเภท หรือครอบคลุมทรัพย์แบบปลายเปิดว่า "ทรัพย์สินใด ๆ ที่อยู่ในความครอบครองของบริษัท"
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** Broker C ระบุว่าบริษัทมีสิทธิยึดหน่วงเหนือ "เงินและทรัพย์สินใด ๆ ของลูกค้าที่อยู่ในความครอบครองของบริษัทหรือบริษัทในเครือ เพื่อประกันภาระผูกพันใด ๆ ของลูกค้า" → **ไม่ผ่าน** (ปลายเปิดทั้งทรัพย์และหนี้)

**P02-057 · ข้อยึดหน่วงระบุเหตุที่ใช้สิทธิและการแจ้งลูกค้าล่วงหน้าหรือไม่** `w2` `DOC`

- **ตรวจอะไร:** กรณีข้อ 056 พบสิทธิเหนือทรัพย์ ให้ตรวจต่อว่าสัญญาระบุ **เหตุที่จุดชนวนการบังคับใช้สิทธิ** เป็นรายการที่นับได้หรือไม่ และระบุ **วิธีกับกรอบเวลาการแจ้งลูกค้า** ไว้หรือไม่ บันทึกจำนวนเหตุที่ระบุ ช่องทางแจ้ง และจำนวนวันล่วงหน้า
- **ขั้นตอนการตรวจ:**
  1. เปิดข้อสิทธิเหนือทรัพย์ที่บันทึกจากข้อ 056
  2. ค้นภายในข้อนั้นด้วยคำว่า `event of default` `upon` `if the client fails` `เมื่อ` `กรณีที่ลูกค้าผิดนัด` แล้วนับจำนวนเหตุที่ระบุ
  3. บันทึกว่าเหตุเหล่านั้นเป็นรายการปิด หรือจบด้วยถ้อยคำปลายเปิด เช่น "หรือกรณีอื่นใดที่บริษัทเห็นสมควร"
  4. ค้นด้วยคำว่า `notice` `notify` `prior written` `แจ้ง` `บอกกล่าว` ในข้อเดียวกันและข้อที่อ้างถึงกัน
  5. บันทึกช่องทางแจ้งที่ระบุ และจำนวนวันล่วงหน้า ถ้าไม่ระบุให้บันทึกว่า "ไม่ระบุ"
  6. บันทึกผลลงตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางรายการเหตุที่ระบุ พร้อมสถานะปิด/ปลายเปิด · ภาพข้อความส่วนการแจ้ง (`RST-BRKA-P02-057-01`)
- **ผ่าน:** เหตุที่ใช้สิทธิเป็นรายการปิด และสัญญาระบุช่องทางแจ้งพร้อมจำนวนวันล่วงหน้าที่นับได้
- **ไม่ผ่าน:** เหตุที่ใช้สิทธิมีถ้อยคำปลายเปิด หรือไม่ระบุการแจ้งลูกค้า หรือระบุการแจ้งแต่ไม่มีจำนวนวันที่นับได้
- **ยังไม่ได้ตรวจ:** สัญญาไม่มีข้อสร้างสิทธิเหนือทรัพย์เลย
- **ตัวอย่าง:** Broker A ระบุเหตุไว้ 5 ข้อชัดเจน แต่ข้อที่ 6 เขียนว่า "หรือเหตุอื่นใดที่บริษัทพิจารณาว่ากระทบต่อความมั่นคงของบัญชี" → **ไม่ผ่าน**

**P02-058 ● · สัญญาให้สิทธิโบรกนำเงินหรือหลักประกันลูกค้าไปให้ยืมต่อหรือไม่** `w3` `DOC` `G3`

- **ตรวจอะไร:** ตรวจว่าสัญญาให้สิทธิโบรกนำเงินหรือหลักประกันของลูกค้าไป **ให้ยืม จำนำต่อ หรือใช้เป็นหลักประกันของโบรกเอง** กับบุคคลที่สาม (rehypothecation / re-use) หรือไม่ บันทึกเลขข้อ ข้อความคำต่อคำ ผู้รับที่ระบุไว้ และมีการกำหนดเพดานหรือไม่ ข้อนี้ต่างจากข้อ 060 ตรงที่ข้อ 060 ตรวจการ "ฝากต่อ" ส่วนข้อนี้ตรวจการ "นำไปใช้ต่อเป็นหลักประกันหรือให้ยืม"
- **ขั้นตอนการตรวจ:**
  1. ค้นในสัญญาทุกฉบับทีละคำ: `rehypothecat` `re-use` `reuse` `lend` `on-lend` `borrow` `repledge` `ให้ยืม` `นำไปใช้ต่อ` `จำนำต่อ`
  2. อ่านข้อความเต็มทุกจุด บันทึกเลขข้อและข้อความคำต่อคำ
  3. บันทึกว่าสิทธินี้ครอบคลุมเงินสดในบัญชี หลักประกัน หรือทั้งสองอย่าง
  4. ค้นในข้อเดียวกันว่ามีการกำหนดเพดานเป็นร้อยละหรือจำนวนเงินหรือไม่ ถ้าไม่มีให้บันทึกว่า "ไม่มีเพดาน"
  5. ค้นว่ามีการระบุประเภทหรือชื่อคู่สัญญาปลายทางหรือไม่ ถ้าไม่มีให้บันทึกว่า "ไม่ระบุปลายทาง"
  6. ค้นบนเว็บสาธารณะของโบรกด้วยคำเดียวกัน เพื่อดูว่าโบรกเปิดเผยเรื่องนี้นอกสัญญาหรือไม่ เก็บสำเนาถาวร
  7. จับภาพข้อสัญญาและหน้าเว็บที่พบ บันทึกผลและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อสัญญาที่ให้สิทธินำไปใช้ต่อ (`RST-BRKA-P02-058-01`) · สำเนาถาวรหน้าเว็บที่กล่าวถึงเรื่องนี้ (`-02`) · ตารางบันทึก ขอบเขต · เพดาน · ปลายทาง
- **ผ่าน:** ไม่มีข้อให้สิทธินำเงินหรือหลักประกันลูกค้าไปใช้ต่อ หรือมีแต่ระบุครบทั้งเพดานที่คำนวณได้และประเภทคู่สัญญาปลายทาง
- **ไม่ผ่าน:** มีข้อให้สิทธินำไปใช้ต่อ โดยไม่มีเพดานที่คำนวณได้ หรือไม่ระบุประเภทคู่สัญญาปลายทาง
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** Broker B ระบุสิทธินำหลักประกันของลูกค้าไปใช้ต่อได้ พร้อมกำหนดเพดานที่ 140% ของภาระหนี้ของลูกค้า และระบุว่าปลายทางต้องเป็นสถาบันการเงินที่ได้รับอนุญาต → **ผ่าน**

**P02-059 · สัญญาระบุเพดานสัดส่วนเงินลูกค้าที่โบรกนำไปใช้ต่อได้หรือไม่** `w2` `DOC`

- **ตรวจอะไร:** เจาะรายละเอียดเพดานที่พบในข้อ 058 ว่าเขียนเป็นตัวเลขที่ลูกค้าคำนวณเองได้หรือไม่ และคำนวณจากฐานใด — ยอดหนี้ของลูกค้าเอง · ยอดเงินในบัญชี · หรือยอดรวมทั้งพอร์ต บันทึกสูตรคำต่อคำและทดลองคำนวณกับยอดจริงในบัญชีทดสอบของเรา
- **ขั้นตอนการตรวจ:**
  1. คัดลอกถ้อยคำกำหนดเพดานจากข้อ 058 มาวางในแบบฟอร์มบันทึก
  2. ระบุฐานคำนวณที่สัญญาใช้ และตัวคูณหรือร้อยละที่ระบุ
  3. เปิดพอร์ทัลลูกค้า บันทึกยอดเงินคงเหลือและยอดหลักประกันที่ใช้อยู่ ณ วันที่ตรวจ พร้อมเวลา UTC
  4. แทนค่าลงในสูตรของสัญญา คำนวณยอดสูงสุดที่โบรกนำไปใช้ต่อได้ตามสัญญา บันทึกผลลัพธ์
  5. บันทึกว่าคำนวณได้หรือไม่ ถ้าคำนวณไม่ได้ให้ระบุว่าขาดตัวแปรใด
  6. จับภาพหน้าจอยอดในพอร์ทัลพร้อมเวลา และบันทึกผลลงไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** แผ่นคำนวณที่แสดงสูตรและการแทนค่า · ภาพยอดในพอร์ทัลพร้อมเวลา (`RST-BRKA-P02-059-01`)
- **ผ่าน:** เพดานเขียนเป็นสูตรที่แทนค่าจากตัวเลขที่ลูกค้าเห็นในพอร์ทัลได้ครบทุกตัวแปร และคำนวณออกมาเป็นตัวเลขเดียว
- **ไม่ผ่าน:** เพดานอ้างอิงตัวแปรที่ลูกค้ามองไม่เห็น หรือเขียนเชิงคุณภาพว่า "ในสัดส่วนที่เหมาะสม"
- **ยังไม่ได้ตรวจ:** สัญญาไม่มีข้อให้สิทธินำเงินไปใช้ต่อเลย
- **ตัวอย่าง:** Broker C กำหนดเพดานเป็น "สัดส่วนที่คณะกรรมการบริหารความเสี่ยงกำหนดเป็นคราว ๆ" ซึ่งลูกค้าไม่มีทางเห็นตัวเลข → **ไม่ผ่าน**

**P02-060 ● · สัญญาระบุการนำเงินลูกค้าไปฝากต่อกับบุคคลที่สามหรือไม่** `w3` `DOC`

- **ตรวจอะไร:** ตรวจว่าสัญญาแจ้งให้ลูกค้าทราบหรือไม่ว่าเงินของลูกค้าอาจถูกฝากต่อไว้กับบุคคลที่สาม เช่น ธนาคาร · ผู้รับฝากทรัพย์สิน (custodian) · ผู้ให้บริการชำระเงิน · โบรกเกอร์ผู้รับช่วง และระบุ **ประเภท** ของผู้รับฝากไว้หรือไม่ บันทึกเลขข้อ ประเภทที่ระบุ และเงื่อนไขการคัดเลือกผู้รับฝากที่สัญญาอ้าง
- **ขั้นตอนการตรวจ:**
  1. ค้นในสัญญาทุกฉบับทีละคำ: `third party` `custodian` `depositary` `intermediate broker` `bank` `payment provider` `บุคคลที่สาม` `ผู้รับฝาก` `สถาบันการเงิน`
  2. อ่านข้อความเต็มทุกจุด บันทึกเลขข้อและข้อความคำต่อคำ
  3. บันทึกประเภทผู้รับฝากที่สัญญาระบุ ถ้าเขียนกว้างว่า "บุคคลที่สามใด ๆ" ให้บันทึกว่า "ไม่ระบุประเภท"
  4. ค้นต่อว่าสัญญาระบุเกณฑ์คัดเลือกผู้รับฝากหรือไม่ เช่น ต้องเป็นสถาบันที่อยู่ภายใต้การกำกับ บันทึกคำต่อคำ
  5. เปิดหน้าฝากเงินในพอร์ทัลของเรา บันทึกชื่อผู้รับเงินปลายทางที่ระบบให้โอนไปจริง แล้วเทียบว่าตรงกับประเภทที่สัญญาระบุหรือไม่
  6. จับภาพทั้งข้อสัญญาและหน้ารายละเอียดผู้รับเงินในพอร์ทัล
  7. บันทึกผลลงตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อสัญญาเรื่องบุคคลที่สาม (`RST-BRKA-P02-060-01`) · ภาพหน้ารายละเอียดผู้รับเงินตอนฝาก (`-02`) · ตารางเทียบประเภทที่ระบุกับผู้รับเงินจริง
- **ผ่าน:** สัญญาระบุประเภทผู้รับฝากไว้ และผู้รับเงินปลายทางที่พอร์ทัลให้โอนไปจริงอยู่ในประเภทที่ระบุ
- **ไม่ผ่าน:** สัญญาไม่ระบุประเภทผู้รับฝากเลย หรือระบุไว้แต่ผู้รับเงินจริงเป็นคนละประเภทกับที่ระบุ
- **ยังไม่ได้ตรวจ:** ยังไม่ได้ทำรายการฝากเงินจริง จึงยังไม่เห็นชื่อผู้รับเงินปลายทาง
- **ตัวอย่าง:** Broker A ระบุในสัญญาว่าเงินจะฝากไว้กับ "ธนาคารที่อยู่ภายใต้การกำกับดูแล" แต่หน้าฝากเงินให้โอนไปยังบัญชีของบริษัทตัวกลางชำระเงินที่ไม่ใช่ธนาคาร โดยไม่มีคำอธิบายใด → **ไม่ผ่าน**

**P02-061 · สัญญาระบุความรับผิดของโบรกหากผู้รับฝากบุคคลที่สามล้มละลายหรือไม่** `w2` `DOC`

- **ตรวจอะไร:** ตรวจว่าสัญญาโยนความเสี่ยงจากการล้มละลายหรือผิดนัดของผู้รับฝากบุคคลที่สามไปที่ลูกค้าหรือไม่ อ่านหาข้อยกเว้นความรับผิดที่ผูกกับบุคคลที่สาม บันทึกเลขข้อ ถ้อยคำที่ยกเว้นความรับผิด และเงื่อนไขที่โบรกยังคงรับผิดอยู่ (ถ้ามี)
- **ขั้นตอนการตรวจ:**
  1. เปิดข้อเรื่องบุคคลที่สามที่บันทึกจากข้อ 060 และหมวด Liability / Limitation of Liability
  2. ค้นทีละคำ: `not be liable` `no responsibility` `at your risk` `insolvency of` `default of` `ไม่รับผิด` `ความเสี่ยงของลูกค้า`
  3. บันทึกข้อความคำต่อคำของทุกจุดที่ยกเว้นความรับผิดในกรณีบุคคลที่สามมีปัญหา
  4. ค้นต่อว่ามีข้อความใดระบุว่าโบรกยังคงรับผิดในกรณีที่ตนเองประมาทเลินเล่อในการคัดเลือกผู้รับฝากหรือไม่ บันทึกคำต่อคำ
  5. ทำตารางสองคอลัมน์: ความเสี่ยงที่ลูกค้ารับ · ความเสี่ยงที่โบรกยังรับ
  6. จับภาพทุกข้อที่พบ บันทึกผลและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางสองคอลัมน์พร้อมข้อความคำต่อคำ · ภาพข้อยกเว้นความรับผิด (`RST-BRKA-P02-061-01`)
- **ผ่าน:** สัญญาระบุว่าโบรกยังคงรับผิดอย่างน้อยในกรณีที่ตนประมาทเลินเล่อในการคัดเลือกหรือกำกับผู้รับฝาก
- **ไม่ผ่าน:** สัญญายกเว้นความรับผิดของโบรกทั้งหมดในกรณีผู้รับฝากบุคคลที่สามล้มละลายหรือผิดนัด โดยไม่มีข้อยกเว้นกลับสำหรับความประมาทเลินเล่อของโบรก
- **ยังไม่ได้ตรวจ:** สัญญาไม่กล่าวถึงการฝากต่อกับบุคคลที่สามเลย
- **ตัวอย่าง:** Broker B เขียนว่าบริษัทไม่รับผิดต่อการกระทำหรือการล้มละลายของบุคคลที่สาม แต่ต่อท้ายว่า "เว้นแต่เกิดจากความประมาทเลินเล่อร้ายแรงของบริษัทในการคัดเลือก" → **ผ่าน**

**P02-062 ● · สัญญาระบุการนำเงินลูกค้าไปฝากนอกเขตกำกับหรือต่างประเทศหรือไม่** `w3` `DOC`

- **ตรวจอะไร:** ตรวจว่าสัญญาแจ้งหรือไม่ว่าเงินลูกค้าอาจถูกฝากไว้ในเขตอำนาจอื่นนอกประเทศที่ออกใบอนุญาต และแจ้งผลที่ตามมาหรือไม่ ว่ากฎหมายคุ้มครองเงินลูกค้าและสิทธิของลูกค้าในเขตอำนาจนั้นอาจต่างจากเขตอำนาจเดิม บันทึกเลขข้อ ประเทศหรือภูมิภาคที่ระบุ และถ้อยคำเตือน
- **ขั้นตอนการตรวจ:**
  1. ค้นในสัญญาทุกฉบับทีละคำ: `outside` `jurisdiction` `overseas` `outside the EEA` `different legal system` `นอกประเทศ` `ต่างประเทศ` `เขตอำนาจ`
  2. อ่านข้อความเต็มทุกจุด บันทึกเลขข้อและข้อความคำต่อคำ
  3. บันทึกว่าสัญญาระบุประเทศหรือภูมิภาคปลายทางไว้หรือไม่ ถ้าไม่ระบุให้บันทึกว่า "ไม่ระบุปลายทาง"
  4. บันทึกว่ามีถ้อยคำเตือนถึงความต่างของการคุ้มครองตามกฎหมายหรือไม่ คัดลอกคำต่อคำ
  5. เทียบประเทศที่ระบุกับประเทศที่ออกใบอนุญาตของนิติบุคคลคู่สัญญา (ใช้ผลจาก P01) บันทึกว่าตรงกันหรือต่างกัน
  6. จับภาพข้อสัญญาพร้อมเลขข้อและเลขหน้า
  7. บันทึกผลลงตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อสัญญาเรื่องเขตอำนาจของผู้รับฝาก (`RST-BRKA-P02-062-01`) · ตารางบันทึกประเทศที่ระบุเทียบกับประเทศที่ออกใบอนุญาต
- **ผ่าน:** สัญญาไม่ระบุการฝากเงินนอกเขตกำกับ หรือระบุพร้อมคำเตือนถึงความต่างของการคุ้มครองตามกฎหมายในข้อเดียวกัน
- **ไม่ผ่าน:** สัญญาระบุว่าอาจฝากเงินนอกเขตกำกับ แต่ไม่มีคำเตือนถึงความต่างของการคุ้มครองตามกฎหมายที่ใดในเอกสารที่ลูกค้าได้รับ
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** Broker C ระบุว่าเงินอาจฝากไว้กับสถาบันในเขตอำนาจอื่น พร้อมย่อหน้าเตือนว่าสิทธิของลูกค้าในกรณีล้มละลายอาจต่างออกไป → **ผ่าน**

**P02-063 · สัญญาระบุว่าใครเป็นผู้รับดอกเบี้ยที่เกิดจากเงินลูกค้าหรือไม่** `w2` `DOC`

- **ตรวจอะไร:** ตรวจว่าสัญญาระบุการจัดการดอกเบี้ยหรือผลตอบแทนที่เกิดจากเงินลูกค้าที่ฝากไว้กับสถาบันการเงินหรือไม่ ว่าตกเป็นของโบรกหรือจ่ายคืนลูกค้า บันทึกเลขข้อ ถ้อยคำคำต่อคำ และตรวจว่ามีการสละสิทธิรับดอกเบี้ยแฝงอยู่ในข้อใดหรือไม่
- **ขั้นตอนการตรวจ:**
  1. ค้นในสัญญาทุกฉบับทีละคำ: `interest` `accrue` `waive` `entitled to retain` `ดอกเบี้ย` `ผลตอบแทน` `สละสิทธิ`
  2. อ่านข้อความเต็มทุกจุด บันทึกเลขข้อและข้อความคำต่อคำ
  3. บันทึกว่าใครเป็นผู้รับดอกเบี้ยตามสัญญา — โบรก · ลูกค้า · หรือไม่ระบุ
  4. ถ้าระบุว่าลูกค้าสละสิทธิ ให้บันทึกว่าข้อความนั้นอยู่ในหมวดใดและต้องเลื่อนอ่านกี่หน้าจากต้นเอกสารจึงถึง
  5. ค้นบนเว็บสาธารณะด้วยคำเดียวกัน ว่าโบรกกล่าวถึงเรื่องดอกเบี้ยเงินลูกค้านอกสัญญาหรือไม่ เก็บสำเนาถาวร
  6. บันทึกผลลงตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อสัญญาเรื่องดอกเบี้ย (`RST-BRKA-P02-063-01`) · สำเนาถาวรหน้าเว็บที่กล่าวถึง (ถ้ามี) · ตารางบันทึกผู้รับดอกเบี้ย
- **ผ่าน:** สัญญาระบุชัดว่าใครเป็นผู้รับดอกเบี้ยที่เกิดจากเงินลูกค้า ไม่ว่าจะเป็นโบรกหรือลูกค้า
- **ไม่ผ่าน:** สัญญาไม่ระบุเรื่องดอกเบี้ยจากเงินลูกค้าเลย หรือระบุไว้กำกวมจนชี้ไม่ได้ว่าใครเป็นผู้รับ
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** Broker A ระบุในข้อ 9.6 ว่าลูกค้าตกลงสละสิทธิรับดอกเบี้ยใด ๆ ที่เกิดจากเงินในบัญชีลูกค้า ข้อความอยู่ในหมวดที่มีหัวข้อชัดเจน → **ผ่าน** (ระบุชัดว่าใครรับ แม้เงื่อนไขจะไม่เป็นคุณกับลูกค้า)

**P02-064 · สัญญาให้สิทธิโบรกนำเงินลูกค้าไปลงทุนในตราสารใดหรือไม่** `w2` `DOC+WEB`

- **ตรวจอะไร:** ตรวจว่าสัญญาให้สิทธิโบรกนำเงินลูกค้าไปลงทุนในตราสารหรือกองทุนใดหรือไม่ เช่น กองทุนตลาดเงิน (qualifying money market fund) หรือพันธบัตร บันทึกเลขข้อ ประเภทตราสารที่ระบุ และตรวจว่ามีการอธิบายความเสี่ยงของตราสารนั้นให้ลูกค้าทราบหรือไม่
- **ขั้นตอนการตรวจ:**
  1. ค้นในสัญญาทุกฉบับทีละคำ: `money market fund` `MMF` `invest` `qualifying` `government bond` `treasury` `กองทุนตลาดเงิน` `ลงทุน` `พันธบัตร`
  2. อ่านข้อความเต็มทุกจุด บันทึกเลขข้อและประเภทตราสารที่ระบุ
  3. บันทึกว่าสัญญาระบุว่าลูกค้าปฏิเสธการนำเงินไปลงทุนแบบนี้ได้หรือไม่ และต้องทำอย่างไร
  4. ค้นในสัญญาและบนเว็บว่ามีการอธิบายความเสี่ยงของตราสารประเภทนั้นหรือไม่ เก็บสำเนาถาวรของหน้าที่พบ
  5. ทำตารางสามคอลัมน์: ตราสารที่ระบุ · สิทธิปฏิเสธของลูกค้า · การอธิบายความเสี่ยง แล้วทำเครื่องหมายช่องที่ว่าง
  6. จับภาพทุกแหล่ง บันทึกผลและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อสัญญาเรื่องการลงทุนเงินลูกค้า (`RST-BRKA-P02-064-01`) · สำเนาถาวรหน้าเว็บที่อธิบายความเสี่ยง · ตารางสามคอลัมน์
- **ผ่าน:** สัญญาไม่ให้สิทธิลงทุนเงินลูกค้า หรือให้สิทธิแต่ระบุประเภทตราสารเป็นรายการปิดพร้อมมีคำอธิบายความเสี่ยงในเอกสารที่ลูกค้าได้รับ
- **ไม่ผ่าน:** สัญญาให้สิทธิลงทุนเงินลูกค้าโดยไม่ระบุประเภทตราสารเป็นรายการปิด หรือไม่มีคำอธิบายความเสี่ยงที่ใดเลย
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** Broker B ระบุว่าอาจนำเงินลูกค้าไปลงทุนใน "ตราสารสภาพคล่องสูงตามที่บริษัทเห็นสมควร" โดยไม่มีรายการตราสารและไม่มีคำอธิบายความเสี่ยง → **ไม่ผ่าน**

**P02-065 ● · สัญญาให้สิทธิโบรกหักเงินจากบัญชีลูกค้าโดยไม่แจ้งล่วงหน้าหรือไม่** `w3` `DOC` `G3`

- **ตรวจอะไร:** ตรวจว่าสัญญาให้สิทธิโบรกหักเงินออกจากบัญชีลูกค้าได้โดยไม่ต้องแจ้งหรือขอความยินยอมล่วงหน้าหรือไม่ และหักได้ในกรณีใดบ้าง บันทึกเลขข้อ รายการที่หักได้ และถ้อยคำเรื่องการแจ้ง จุดที่ต้องอ่านคือหมวด Fees and Charges · Debits · Costs · Indemnity และภาคผนวกตารางค่าธรรมเนียม
- **ขั้นตอนการตรวจ:**
  1. ค้นในสัญญาทุกฉบับทีละคำ: `debit` `deduct` `without notice` `without prior` `at any time` `หัก` `หักจากบัญชี` `โดยไม่ต้องแจ้ง`

  3. ทำรายการค่าใช้จ่ายทุกประเภทที่สัญญาระบุว่าหักได้ พร้อมระบุว่าแต่ละประเภทมีอัตราระบุไว้หรือไม่

  6. ทำตารางเทียบ "สิทธิหักตามสัญญา" กับ "การหักที่เกิดจริงและการแจ้ง"
  7. จับภาพข้อสัญญาและรายการใน statement บันทึกผลและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อสัญญาเรื่องการหักเงิน (`RST-BRKA-P02-065-01`) · statement ที่แสดงรายการหักจริง (`-02`) · ภาพกล่องอีเมลและกล่องข้อความช่วงเดียวกัน (`-03`) · ตารางเทียบ
- **ผ่าน:** ทุกประเภทค่าใช้จ่ายที่หักได้โดยไม่แจ้งล่วงหน้า มีอัตราหรือสูตรคำนวณระบุไว้ในเอกสารที่ลูกค้าได้รับ
- **ไม่ผ่าน:** มีอย่างน้อย 1 ประเภทที่สัญญาให้หักได้โดยไม่แจ้งล่วงหน้า และไม่มีอัตราหรือสูตรคำนวณระบุไว้ที่ใดในเอกสารที่ลูกค้าได้รับ
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง

**P02-066 · รายการค่าใช้จ่ายที่หักได้ตามสัญญาเป็นรายการปิดหรือปลายเปิด** `w2` `DOC`

- **ตรวจอะไร:** เจาะรายละเอียดจากข้อ 065 ว่ารายการค่าใช้จ่ายที่โบรกหักได้ ถูกเขียนเป็น **รายการปิด** ที่นับจำนวนได้ หรือจบด้วยถ้อยคำปลายเปิด บันทึกจำนวนรายการที่ระบุ จำนวนรายการที่มีอัตรากำกับ และถ้อยคำปลายเปิดทุกจุด
- **ขั้นตอนการตรวจ:**
  1. เปิดรายการค่าใช้จ่ายที่บันทึกไว้จากข้อ 065 พร้อมภาคผนวกตารางค่าธรรมเนียม
  2. นับจำนวนรายการที่ระบุชื่อชัดเจน บันทึกตัวเลข
  3. นับจำนวนรายการที่มีอัตราหรือสูตรกำกับ บันทึกตัวเลข
  4. ค้นถ้อยคำปลายเปิดทีละคำ: `including but not limited to` `any other` `such other` `as the company may determine` `รวมถึงแต่ไม่จำกัดเพียง` `อื่นใด` `ตามที่บริษัทกำหนด`
  5. บันทึกทุกจุดที่พบถ้อยคำปลายเปิด พร้อมเลขข้อ
  6. คำนวณสัดส่วนรายการที่มีอัตรากำกับต่อรายการทั้งหมด บันทึกเป็นร้อยละ
  7. บันทึกตารางสรุปและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางรายการค่าใช้จ่ายทั้งหมดพร้อมสถานะมีอัตรา/ไม่มีอัตรา · ภาพทุกจุดที่พบถ้อยคำปลายเปิด (`RST-BRKA-P02-066-01` เป็นต้นไป)
- **ผ่าน:** รายการค่าใช้จ่ายเป็นรายการปิด ไม่มีถ้อยคำปลายเปิดใด และทุกรายการมีอัตราหรือสูตรกำกับ
- **ไม่ผ่าน:** พบถ้อยคำปลายเปิดอย่างน้อย 1 จุด หรือมีรายการที่ไม่มีอัตราหรือสูตรกำกับอย่างน้อย 1 รายการ
- **ยังไม่ได้ตรวจ:** ไม่ได้รับภาคผนวกตารางค่าธรรมเนียมและหาบนเว็บสาธารณะไม่พบ
- **ตัวอย่าง:** Broker C ระบุรายการค่าใช้จ่าย 11 รายการพร้อมอัตราครบทุกรายการ แต่ปิดท้ายด้วย "และค่าใช้จ่ายอื่นใดตามที่บริษัทแจ้งเป็นคราว ๆ" → **ไม่ผ่าน**

**P02-067 ● · สัญญาให้สิทธิโบรกอายัดหรือระงับการถอนตามดุลพินิจฝ่ายเดียวหรือไม่** `w3` `DOC`

- **ตรวจอะไร:** ตรวจว่าสัญญาให้สิทธิโบรกระงับ อายัด หรือชะลอคำสั่งถอนเงินของลูกค้าตามดุลพินิจของโบรกเองหรือไม่ บันทึกเลขข้อ เหตุที่ระบุ ระยะเวลาสูงสุดที่ระงับได้ และช่องทางที่ลูกค้าใช้โต้แย้ง ข้อนี้ตรวจเฉพาะ **ถ้อยคำในสัญญา** ส่วนการทดสอบถอนจริงอยู่ในเสา P03

  2. อ่านข้อความเต็มทุกจุด บันทึกเลขข้อและข้อความคำต่อคำ
  3. ทำรายการเหตุที่สัญญาระบุว่าใช้สิทธิระงับได้ และทำเครื่องหมายว่าเหตุใดวัดได้ด้วยข้อเท็จจริง เหตุใดขึ้นกับดุลพินิจล้วน

- **ผ่าน:** สัญญาระบุเหตุระงับเป็นรายการปิดที่วัดได้ด้วยข้อเท็จจริง และกำหนดหน้าที่แจ้งเหตุผลแก่ลูกค้าไว้
- **ไม่ผ่าน:** สัญญาให้สิทธิระงับตามดุลพินิจโดยไม่จำกัดเหตุ หรือไม่กำหนดหน้าที่แจ้งเหตุผลแก่ลูกค้า

**P02-068 · เงื่อนไขการอายัดระบุระยะเวลาสูงสุดและช่องทางอุทธรณ์หรือไม่** `w2` `DOC`

- **ผ่าน:** สัญญากำหนดทั้งเพดานระยะเวลาการระงับเป็นจำนวนวันที่นับได้ และช่องทางโต้แย้งพร้อมกรอบเวลาที่โบรกต้องตอบ

**P02-069 ● · สิทธิเหนือเงินลูกค้าถูกเปิดเผยก่อนจุดฝากเงินหรือซ่อนในเอกสารแนบ** `w3` `DOC` `G3`

  5. บันทึกว่าข้อความอยู่ในเอกสารหลักที่ต้องติ๊กยอมรับ หรืออยู่ในเอกสารแนบท้ายที่แยกไฟล์ต่างหาก

  7. อัดวิดีโอการเดินทางจากหน้าฝากเงินไปถึงข้อความที่ลึกที่สุด บันทึกเวลารวมเป็นวินาที

- **ตรวจอะไร:** ตรวจว่ากระบวนการสมัครแยกความยินยอมสำหรับข้อโอนกรรมสิทธิ์หลักประกันออกจากความยินยอมรวมของสัญญาหรือไม่ บันทึกจำนวนช่องติ๊กทั้งหมดในขั้นตอนสมัคร ข้อความข้างแต่ละช่อง และว่าช่องใดมีสถานะติ๊กไว้ล่วงหน้า
- **ขั้นตอนการตรวจ:**
  1. เข้ากระบวนการสมัครในเบราว์เซอร์โหมดไม่บันทึกประวัติ ทำจนถึงหน้าสุดท้ายก่อนกดยืนยัน

  4. บันทึกว่าช่องใดถูกติ๊กไว้ล่วงหน้าตั้งแต่หน้าจอโหลดเสร็จ

- **ผ่าน:** มีช่องยินยอมแยกเฉพาะสำหรับข้อโอนกรรมสิทธิ์ และช่องนั้นไม่ถูกติ๊กไว้ล่วงหน้า หรือสัญญาไม่มีข้อโอนกรรมสิทธิ์เลย
- **ไม่ผ่าน:** มีข้อโอนกรรมสิทธิ์ในสัญญา แต่ไม่มีช่องยินยอมแยก หรือมีช่องแยกแต่ถูกติ๊กไว้ล่วงหน้า

**P02-071 · ลูกค้าปฏิเสธหรือถอนความยินยอมข้อโอนกรรมสิทธิ์ได้ตามสัญญาหรือไม่** `w2` `DOC`

- **ตรวจอะไร:** ตรวจว่าสัญญาเปิดทางให้ลูกค้า **เลือกไม่ใช้** หรือ **ถอนความยินยอม** ข้อโอนกรรมสิทธิ์หรือข้อให้สิทธิใช้เงินได้หรือไม่ และถ้าได้ ต้องทำอย่างไร บันทึกเลขข้อ ขั้นตอนที่ระบุ ผลที่ตามมา และตรวจว่าพอร์ทัลลูกค้ามีเมนูให้ทำเรื่องนี้จริงหรือไม่

  2. อ่านข้อความเต็มทุกจุด บันทึกเลขข้อและขั้นตอนที่สัญญากำหนด
  3. บันทึกผลที่ตามมาหากลูกค้าใช้สิทธินี้ เช่น บัญชีถูกปิด · ต้องเปลี่ยนประเภทบัญชี · เลเวอเรจลดลง
  4. ล็อกอินพอร์ทัลลูกค้า เปิดหมวดตั้งค่าบัญชีและเอกสาร ค้นหาเมนูที่ตรงกับขั้นตอนในสัญญา จับภาพผลการค้น
  5. บันทึกว่าพบเมนูหรือไม่ ถ้าไม่พบ ให้บันทึกรายชื่อเมนูทั้งหมดที่มีในหมวดนั้นเพื่อยืนยันว่าค้นครบ
  6. บันทึกผลลงตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อสัญญาส่วนการปฏิเสธหรือถอนความยินยอม (`RST-BRKA-P02-071-01`) · ภาพหมวดตั้งค่าในพอร์ทัลพร้อมรายชื่อเมนู (`-02`)
- **ผ่าน:** สัญญาระบุขั้นตอนการปฏิเสธหรือถอนความยินยอมไว้ และพบช่องทางที่ตรงกับขั้นตอนนั้นในพอร์ทัลหรือในเอกสารที่ลูกค้าได้รับ หรือสัญญาไม่มีข้อโอนกรรมสิทธิ์เลย
- **ไม่ผ่าน:** สัญญามีข้อโอนกรรมสิทธิ์แต่ไม่ระบุขั้นตอนการปฏิเสธหรือถอนความยินยอมใด ๆ
- **ยังไม่ได้ตรวจ:** ยังไม่มีบัญชีที่ล็อกอินพอร์ทัลได้
- **ตัวอย่าง:** Broker A ระบุว่าลูกค้าอาจแจ้งความประสงค์ยกเลิกข้อตกลงหลักประกันเป็นลายลักษณ์อักษร และในพอร์ทัลมีแบบฟอร์มออนไลน์ตรงกับข้อนั้น → **ผ่าน**

**P02-072 · ฝ่ายบริการตอบคำถามเรื่องสิทธิของโบรกเหนือเงินลูกค้าอย่างไร** `w2` `SUP`

- **ตรวจอะไร:** ถามฝ่ายบริการในฐานะลูกค้าที่สงสัย ด้วยคำถามที่ลูกค้าทั่วไปถามได้ ว่าบริษัทมีสิทธินำเงินในบัญชีของเราไปใช้หรือไม่ และเทียบคำตอบกับข้อสัญญาที่พบจากข้อ 051–068 บันทึกเวลาที่ส่งคำถาม เวลาที่ได้คำตอบแรก ข้อความคำตอบเต็ม และเอกสารหรือเลขข้อที่พนักงานอ้างถึง

  2. ส่งคำถามชุดเดียวกันผ่านแชทสด บันทึกเวลาส่งและเวลาที่ได้คำตอบแรกเป็นเวลา UTC

  5. เทียบคำตอบทั้งสองช่องทางกับข้อสัญญาที่บันทึกไว้ ทำเครื่องหมายจุดที่คำตอบขัดกับสัญญา
  6. บันทึกว่าพนักงานอ้างเลขข้อหรือเอกสารใดประกอบหรือไม่
  7. บันทึกผลลงตารางสามคอลัมน์และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** transcript แชทเต็ม (`RST-BRKA-P02-072-01`) · อีเมลตอบกลับเต็มพร้อมหัวจดหมาย (`-02`) · ตารางเทียบคำตอบกับข้อสัญญา
- **ผ่าน:** คำตอบจากทั้งสองช่องทางไม่ขัดกับข้อสัญญาที่บันทึกไว้ในข้อ 051–068
- **ไม่ผ่าน:** มีคำตอบอย่างน้อย 1 ช่องทางที่ขัดกับข้อสัญญา เช่น ยืนยันว่าบริษัทไม่มีสิทธิใช้เงินลูกค้า ขณะที่สัญญามีข้อให้สิทธินั้น

**P02-073 · ถ้อยคำการตลาดเรื่องความปลอดภัยของเงินขัดกับสิทธิในสัญญาหรือไม่** `w2` `DOC+WEB`

**P02-074 · สัญญาให้สิทธิโบรกแก้ไขข้อว่าด้วยการใช้เงินลูกค้าฝ่ายเดียวหรือไม่** `w2` `DOC`

- **ตรวจอะไร:** ตรวจข้อ variation / amendment ในสัญญา ว่าให้สิทธิโบรกแก้ไขข้อที่เกี่ยวกับสิทธิเหนือเงินลูกค้าโดยแจ้งฝ่ายเดียวหรือไม่ และกำหนดระยะเวลาแจ้งล่วงหน้ากี่วัน บันทึกเลขข้อ จำนวนวันแจ้งล่วงหน้า ช่องทางแจ้ง และสิทธิของลูกค้าที่จะปิดบัญชีโดยไม่มีค่าปรับหากไม่ยอมรับ
- **ขั้นตอนการตรวจ:**
  1. ค้นในสัญญาทุกฉบับทีละคำ: `amend` `vary` `variation` `modify` `unilateral` `แก้ไขเพิ่มเติม` `เปลี่ยนแปลงเงื่อนไข`
  2. อ่านข้อความเต็มทุกจุด บันทึกเลขข้อและข้อความคำต่อคำ
  3. บันทึกจำนวนวันแจ้งล่วงหน้าที่ระบุ ถ้าไม่ระบุให้บันทึกว่า "ไม่ระบุ"
  4. บันทึกช่องทางที่โบรกใช้แจ้ง เช่น อีเมล · ประกาศบนเว็บ · ข้อความในพอร์ทัล
  5. ค้นว่ามีข้อความให้ลูกค้าปิดบัญชีและถอนเงินทั้งหมดโดยไม่มีค่าปรับได้หรือไม่ หากไม่ยอมรับการแก้ไข บันทึกคำต่อคำ
  6. ตรวจว่าข้อแก้ไขนี้ยกเว้นข้อว่าด้วยเงินลูกค้าออกจากขอบเขตหรือไม่ บันทึกผล
  7. บันทึกตารางสรุปและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อ variation เต็มข้อ (`RST-BRKA-P02-074-01`) · ตารางบันทึกจำนวนวัน ช่องทาง และสิทธิปิดบัญชี
- **ผ่าน:** สัญญากำหนดระยะเวลาแจ้งล่วงหน้าเป็นจำนวนวันที่นับได้ และให้สิทธิลูกค้าปิดบัญชีถอนเงินทั้งหมดโดยไม่มีค่าปรับหากไม่ยอมรับ
- **ไม่ผ่าน:** ไม่มีระยะเวลาแจ้งล่วงหน้าที่นับได้ หรือไม่ให้สิทธิลูกค้าปิดบัญชีโดยไม่มีค่าปรับ อย่างน้อย 1 อย่าง
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** Broker A ระบุว่าการแก้ไขมีผลทันทีเมื่อประกาศบนเว็บ และการที่ลูกค้าใช้บริการต่อถือว่ายอมรับ โดยไม่มีระยะเวลาแจ้งล่วงหน้า → **ไม่ผ่าน**

**P02-095 · งบการเงินสาธารณะระบุชื่อผู้สอบบัญชีและความเห็นหรือไม่** `w2` `PUB`

  7. เก็บสำเนาถาวรของหน้าเว็บและภาพหน้ารายงาน บันทึกผลและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** สำเนาถาวรหน้าเว็บที่มีตัวเลข (`RST-BRKA-P02-096-01`) · ภาพหน้ารายงานที่มีตัวเลขคู่กัน (`-02`) · ตารางสี่คอลัมน์พร้อมส่วนต่างเป็นร้อยละ
- **ผ่าน:** ทุกตัวเลขที่โบรกโฆษณามีตัวเลขคู่กันในรายงานสาธารณะ และส่วนต่างของทุกคู่ไม่เกิน `[เกณฑ์เสนอ: 5%]`
- **ไม่ผ่าน:** มีอย่างน้อย 1 ตัวเลขที่หาคู่ในรายงานสาธารณะไม่พบ หรือมีส่วนต่างเกิน `[เกณฑ์เสนอ: 5%]`
- **ยังไม่ได้ตรวจ:** ไม่พบตัวเลขทางการเงินใดบนเว็บ หรือไม่พบรายงานสาธารณะจากข้อ 090
- **ตัวอย่าง:** Broker B โฆษณาว่า "ถือเงินลูกค้ากว่า 2,000 ล้าน" โดยไม่ระบุวันที่อ้างอิง ขณะที่งบการเงินฉบับล่าสุดบนเว็บเดียวกันแสดงยอดเงินลูกค้า 780 ล้าน → **ไม่ผ่าน**

**P02-097 · เมื่อพบส่วนต่างจากการกระทบยอด โบรกชี้แจงและแก้ไขภายในเวลาเท่าใด** `w2` `SUP+STM`

- **ตรวจอะไร:** ทดสอบกระบวนการจริงเมื่อลูกค้าแจ้งส่วนต่างที่พบจากการกระทบยอด โดยแจ้งผ่านช่องทางลูกค้าปกติในฐานะลูกค้าที่สงสัย แล้ววัดสามช่วงเวลา คือ เวลาที่ได้รับการตอบรับครั้งแรก · เวลาที่ได้รับคำชี้แจงที่ระบุสาเหตุ · เวลาที่ยอดถูกแก้ไขใน statement บันทึกทั้งสามช่วงเป็นชั่วโมงและวันทำการ
- **ขั้นตอนการตรวจ:**
  1. เลือกส่วนต่างที่พบจริงจากข้อ 077, 078 หรือ 082 ที่ยังไม่มีคำอธิบาย ถ้าไม่พบส่วนต่างใดเลยให้บันทึกว่าไม่มีกรณีทดสอบ
  2. เขียนคำถามในฐานะลูกค้าที่สงสัย ระบุเลขอ้างอิงรายการ วันที่ และจำนวนเงินที่ต่างกัน ห้ามระบุว่าเป็นการตรวจ
  3. ส่งคำถามผ่านช่องทางที่โบรกระบุเป็นช่องทางหลัก บันทึกเวลาส่งเป็นเวลา UTC
  4. จับเวลาถึงการตอบรับครั้งแรก และถึงคำชี้แจงที่ระบุสาเหตุ บันทึกทั้งสองเป็นชั่วโมงและแปลงเป็นวันทำการ
  5. ดาวน์โหลด statement ซ้ำทุก 3 วัน จนกว่ายอดจะถูกแก้ไขหรือครบ 30 วัน บันทึกวันที่ยอดเปลี่ยน
  6. บันทึก transcript ทั้งบทสนทนา ห้ามตัดทอน
  7. ทำตารางไทม์ไลน์สามช่วงเวลาพร้อมหลักฐานประกอบแต่ละจุด
  8. บันทึกผลและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** transcript เต็มทุกช่องทาง (`RST-BRKA-P02-097-01`) · statement ทุกฉบับที่ดาวน์โหลดระหว่างรอพร้อม hash (`-02` เป็นต้นไป) · ตารางไทม์ไลน์สามช่วงเวลา
- **ผ่าน:** ได้รับคำชี้แจงที่ระบุสาเหตุภายใน `[เกณฑ์เสนอ: 10 วันทำการ]` นับจากเวลาที่ส่งคำถาม
- **ไม่ผ่าน:** ไม่ได้รับคำชี้แจงที่ระบุสาเหตุภายใน `[เกณฑ์เสนอ: 10 วันทำการ]` หรือได้รับคำตอบที่ไม่ระบุสาเหตุใด
- **ยังไม่ได้ตรวจ:** ไม่พบส่วนต่างใดในช่วงตรวจ จึงไม่มีกรณีทดสอบ
- **ตัวอย่าง:** Broker A ตอบรับใน 2 ชั่วโมงและตอบว่า "กำลังตรวจสอบ" อีก 4 ครั้งตลอด 14 วันทำการ โดยไม่เคยระบุสาเหตุของส่วนต่าง → **ไม่ผ่าน**

**P02-098 · เก็บสำเนาถาวรและ hash ของ statement ทุกฉบับหรือไม่** `w1` `STM`

- **ตรวจอะไร:** ตรวจกระบวนการของผู้ตรวจเอง ว่า statement และรายงานสาธารณะทุกไฟล์ที่ดาวน์โหลดในไฟล์นี้ ถูกเก็บเป็นสำเนาถาวร คำนวณ hash และบันทึกลงทะเบียนหลักฐานครบถ้วนหรือไม่ พร้อมตรวจว่าไม่มีไฟล์ใดถูกแก้ไขหลังเก็บ
- **ขั้นตอนการตรวจ:**
  1. รวบรวมรายชื่อไฟล์ทั้งหมดที่ดาวน์โหลดในข้อ 076–097
  2. คำนวณ hash ของทุกไฟล์ใหม่ ณ วันที่ตรวจ
  3. เทียบ hash ที่คำนวณใหม่กับที่บันทึกไว้ในทะเบียนหลักฐานตอนดาวน์โหลด
  4. ทำเครื่องหมายไฟล์ที่ hash ไม่ตรง หรือไม่มี hash บันทึกไว้แต่แรก
  5. ตรวจว่าทุกไฟล์มีวันเวลาที่ดาวน์โหลดกำกับในทะเบียนหลักฐาน
  6. บันทึกผลลงแบบฟอร์มควบคุมคุณภาพหลักฐานและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางรายชื่อไฟล์ทั้งหมดพร้อม hash เดิม hash ใหม่ และสถานะตรง/ไม่ตรง
- **ผ่าน:** ทุกไฟล์มี hash บันทึกไว้ตั้งแต่ตอนดาวน์โหลด และ hash ที่คำนวณใหม่ตรงกันทุกไฟล์
- **ไม่ผ่าน:** มีอย่างน้อย 1 ไฟล์ที่ไม่มี hash บันทึกไว้ หรือ hash ที่คำนวณใหม่ไม่ตรงกับที่บันทึก
- **ยังไม่ได้ตรวจ:** ยังไม่ได้ดาวน์โหลด statement หรือรายงานใดในไฟล์นี้
- **ตัวอย่าง:** ตรวจ 22 ไฟล์ พบว่า 21 ไฟล์ hash ตรง แต่ 1 ไฟล์ถูกเปิดแล้วบันทึกทับด้วยโปรแกรมอ่าน PDF ทำให้ hash เปลี่ยน → **ไม่ผ่าน**

**P02-099 · กระทบยอดซ้ำ 3 รอบห่างกันรอบละ 1 เดือน ผลคงเส้นคงวาหรือไม่** `w2` `STM`

- **ตรวจอะไร:** ทำการกระทบยอดตามวิธีของข้อ 077 และ 078 ซ้ำ 3 รอบ ห่างกันรอบละ 1 เดือน แล้วดูว่าผลลัพธ์คงที่หรือแกว่ง บันทึกจำนวนรายการที่กระทบยอดไม่ลงตัวในแต่ละรอบ และมูลค่ารวมของส่วนต่างในแต่ละรอบ
- **ขั้นตอนการตรวจ:**
  1. กำหนดวันกระทบยอดไว้ล่วงหน้า 3 วัน ห่างกันรอบละ 1 เดือน บันทึกวันที่ทั้งสาม
  2. ในแต่ละรอบ ทำตามขั้นตอนของข้อ 077 และ 078 ครบทุกขั้น
  3. บันทึกจำนวนรายการทั้งหมด จำนวนรายการที่กระทบยอดไม่ลงตัว และมูลค่ารวมของส่วนต่างในรอบนั้น
  4. คำนวณสัดส่วนรายการที่ไม่ลงตัวต่อรายการทั้งหมด บันทึกเป็นร้อยละของแต่ละรอบ
  5. ทำกราฟหรือตารางเทียบผลทั้ง 3 รอบ ทำเครื่องหมายรอบที่ผลแย่ลงกว่ารอบก่อน
  6. บันทึกตารางสรุปและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางกระทบยอดของทั้ง 3 รอบ (`RST-BRKA-P02-099-01` ถึง `-03`) · ตารางสรุปเทียบสามรอบพร้อมร้อยละ
- **ผ่าน:** ทั้ง 3 รอบมีรายการที่กระทบยอดไม่ลงตัวเป็นศูนย์
- **ไม่ผ่าน:** มีอย่างน้อย 1 รอบที่มีรายการกระทบยอดไม่ลงตัวและไม่มีคำอธิบายจากเอกสารที่ลูกค้าเข้าถึงได้
- **ยังไม่ได้ตรวจ:** ทำได้ไม่ครบ 3 รอบในช่วงตรวจ
- **ตัวอย่าง:** Broker C รอบที่ 1 และ 2 กระทบยอดลงตัวทั้งหมด รอบที่ 3 มี 1 รายการที่ต่างไป 15 หน่วยและไม่มีบรรทัดค่าธรรมเนียมใดอธิบายได้ → **ไม่ผ่าน**

**P02-100 · สรุปผลการกระทบยอดที่ลูกค้าทำเองได้และความเปิดเผยของรายงาน** `w3` `รวมทุกวิธี` `G3`

- **ตรวจอะไร:** รวมผลของ S04 ทั้งหมดเป็นคำตอบเดียวว่า **ลูกค้ารายย่อยคนหนึ่งตรวจสอบเงินของตนเองได้ครบวงจรหรือไม่** โดยประเมิน 3 คำถามชี้ขาด คือ (ก) ได้รายงานที่แยกยอดเงินสดมาตรวจเองได้ไหม (ข) ยอดที่ตรวจกระทบกันลงตัวไหม (ค) โบรกเปิดเผยรายงานทางการเงินให้สาธารณะตรวจได้ไหม ข้อนี้เป็นข้อสรุปของ S04 และผูกด่าน G3
- **ขั้นตอนการตรวจ:**
  1. สร้างตารางสรุปที่มีแถวเป็นคำถามชี้ขาด 3 ข้อ พร้อมช่องคำตอบ ใช่ / ไม่ใช่ / ยังไม่ได้ตรวจ
  2. เติมคำตอบข้อ (ก) จากผลข้อ 076 และ 080 พร้อม Evidence ID อ้างอิง
  3. เติมคำตอบข้อ (ข) จากผลข้อ 077, 078, 081, 082 และ 099 พร้อม Evidence ID อ้างอิง
  4. เติมคำตอบข้อ (ค) จากผลข้อ 090, 091, 092 และ 095 พร้อม Evidence ID อ้างอิง
  5. ทำคอลัมน์ที่สอง บันทึกจุดอ่อนที่พบในแต่ละคำถามเป็นข้อความสั้น พร้อมเลข Evidence ID
  6. นับจำนวนคำตอบ "ไม่ใช่" และจำนวนคำตอบ "ยังไม่ได้ตรวจ" บันทึกตัวเลขทั้งสอง
  7. ตรวจว่ามีคำถามใดที่ตอบ "ไม่ใช่" เพราะโบรกไม่ให้เครื่องมือแก่ลูกค้าเลย ไม่ใช่เพราะพบส่วนต่าง ทำเครื่องหมายไว้
  8. บันทึกตารางสรุปฉบับสมบูรณ์พร้อมคำตัดสินและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางสรุป 3 คำถามชี้ขาดพร้อม Evidence ID ทุกแถว (`RST-BRKA-P02-100-01`) · รายการจุดอ่อนที่พบพร้อมเลขอ้างอิง
- **ผ่าน:** ตอบ "ใช่" ครบทั้ง 3 คำถามชี้ขาด
- **ไม่ผ่าน:** ตอบ "ไม่ใช่" อย่างน้อย 1 คำถามชี้ขาด
- **ยังไม่ได้ตรวจ:** มีคำถามชี้ขาดอย่างน้อย 1 ข้อที่ยังเก็บหลักฐานไม่ครบจนตอบไม่ได้
- **ตัวอย่าง:** Broker B ให้ดาวน์โหลด statement ที่แยกยอดเงินสดได้ และการกระทบยอดฝากถอนลงตัวทั้ง 3 รอบ แต่ไม่มีรายงานทางการเงินใดบนเว็บที่เปิดอ่านได้โดยไม่ต้องกรอกข้อมูลติดต่อ ตอบ "ไม่ใช่" 1 ใน 3 คำถาม → **ไม่ผ่าน** ตกด่าน G3
