# P02 · ความปลอดภัยของเงินลูกค้า — ไฟล์ 3/6 (ข้อ 101–150)

**มิติ D1 · น้ำหนักเสา 11% · คุมด่าน G3**
**ขอบเขตไฟล์นี้:** S05 กองทุนชดเชยและประกันเพิ่มเติม · S06 ความเพียงพอของเงินกองทุนที่เปิดเผยต่อสาธารณะ

> รูปแบบและกฎการเขียนดูที่ [`../INSPECTION-STANDARD.md`](../INSPECTION-STANDARD.md)
> `●` = โชว์บนเว็บ · `w1/w2/w3` = น้ำหนัก · `G1–G6` = ด่านบังคับ
> **ชื่อโบรกในตัวอย่างเป็นชื่อสมมติทั้งหมด · กองทุนใช้ "กองทุนชดเชย X" · ผู้สอบบัญชีใช้ "สำนักงานสอบบัญชี Y"**
> Evidence ID ในไฟล์นี้ใช้รหัสโบรกสมมติ `BRKA`
> **หมายเหตุขอบเขต:** ไฟล์นี้ตรวจ "ตาข่ายรองรับ" ของเงินลูกค้าเมื่อโบรกมีปัญหา แหล่งหลักฐานที่ใช้ได้มีเพียง 5 ทาง คือ **เว็บของกองทุนชดเชยเองและทะเบียนสมาชิกของกองทุน** · หน้าเปิดเผยสาธารณะของโบรก · เอกสารสัญญาที่เราได้รับตอนสมัคร · งบการเงินและเอกสารที่โบรกหรือนายทะเบียนเปิดเผยต่อสาธารณะ · และการถามฝ่ายบริการ**ในฐานะลูกค้าที่กังวลว่าเงินจะได้คืนไหม** **ห้ามขอเอกสารภายใน ห้ามขอรายงานผู้สอบบัญชีที่ไม่เปิดสาธารณะ ห้ามสัมภาษณ์ ห้ามเปิดเผยตัว** ทุกตัวเลขที่บันทึกต้องมีวันที่กำกับ เพราะวงเงินคุ้มครองและตัวเลขเงินกองทุนเปลี่ยนได้ตามรอบ

## S05 · กองทุนชดเชยและประกันเพิ่มเติม (101–125)

**P02-101 ● · ระบุตัวกองทุนชดเชยที่ครอบคลุมเงินของเราได้จากแหล่งทางการหรือไม่** `w3` `PUB+REG` `G3`

- **ตรวจอะไร:** ตรวจว่าเงินในบัญชีที่เราเปิดจริงอยู่ภายใต้กองทุนชดเชยนักลงทุนกองใดกองหนึ่งหรือไม่ โดย **ห้ามสรุปจากคำโฆษณาบนเว็บโบรก** ต้องเริ่มจากเขตอำนาจของนิติบุคคลคู่สัญญาที่ระบุในสัญญาของเรา แล้วไปหาเว็บทางการของกองทุนชดเชยในเขตอำนาจนั้นด้วยตนเอง บันทึกชื่อเต็มของกองทุน หน่วยงานที่กำกับกองทุน โดเมนทางการ และวันที่เข้าดู ถ้าเขตอำนาจนั้นไม่มีกองทุนชดเชยนักลงทุนเลย ต้องบันทึกข้อเท็จจริงนี้พร้อมหลักฐานจากหน้าของหน่วยงาน
- **ขั้นตอนการตรวจ:**
  1. เปิดสัญญาลูกค้าที่เราได้รับตอนสมัคร คัดลอกชื่อนิติบุคคลคู่สัญญาและเขตอำนาจที่ระบุในข้อกฎหมายที่ใช้บังคับ
  2. ค้นในเครื่องมือค้นหาด้วยคำว่า `investor compensation scheme` + ชื่อเขตอำนาจ และ `กองทุนคุ้มครองผู้ลงทุน` + ชื่อเขตอำนาจ **ห้ามเข้าผ่านลิงก์ที่โบรกให้**
  3. เข้าเว็บของกองทุนหรือหน้าของหน่วยงานกำกับที่อธิบายกองทุนนั้น บันทึกโดเมนที่เข้าแบบเต็ม
  4. คัดลอกชื่อเต็มของกองทุน ชื่อหน่วยงานที่กำกับกองทุน และฐานอำนาจตามกฎหมายที่หน้านั้นระบุ
  5. ถ้าค้นแล้วไม่พบกองทุนใดในเขตอำนาจนั้น ให้เปิดหน้า FAQ หรือหน้าคุ้มครองผู้ลงทุนของหน่วยงานกำกับ แล้วจับภาพข้อความที่ยืนยันว่าไม่มีกองทุน
  6. จับภาพเต็มหน้าพร้อม URL และนาฬิกาเครื่อง เก็บสำเนาถาวรเป็น PDF
  7. บันทึกผลลงตาราง "กองทุนที่ครอบคลุมบัญชีของเรา" และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพเต็มหน้าเว็บกองทุนหรือหน้าหน่วยงานที่เห็นโดเมนทางการ (`RST-BRKA-P02-101-01`) · สำเนา PDF ถาวร · ภาพหน้าสัญญาที่ระบุเขตอำนาจ (`RST-BRKA-P02-101-02`) · ตารางบันทึกพร้อมวันที่เข้าดู
- **ผ่าน:** ระบุกองทุนชดเชยที่มีเว็บทางการหรือหน้าทางการของหน่วยงานรองรับได้ 1 กอง สำหรับเขตอำนาจของนิติบุคคลคู่สัญญาของเรา
- **ไม่ผ่าน:** เขตอำนาจของนิติบุคคลคู่สัญญาไม่มีกองทุนชดเชยนักลงทุนใดรองรับ ขณะที่โบรกรับเงินฝากจากลูกค้ารายย่อย
- **ยังไม่ได้ตรวจ:** เว็บของกองทุนหรือหน้าของหน่วยงานเข้าไม่ได้ตลอดช่วงที่พยายามเข้า และไม่มีสำเนาสาธารณะอื่นให้อ้างอิง
- **ตัวอย่าง:** สัญญาของ Broker A ระบุคู่สัญญาเป็นนิติบุคคลในเขตอำนาจนอกชายฝั่งแห่งหนึ่ง ค้นเว็บหน่วยงานกำกับของเขตนั้นทั้งหมดแล้วพบหน้า FAQ ที่ระบุว่าไม่มีกองทุนชดเชยผู้ลงทุน ขณะที่หน้าไทยของ Broker A ยังโฆษณาว่า "เงินทุนของคุณได้รับการคุ้มครอง" → **ไม่ผ่าน** ตกด่าน G3

**P02-102 ● · ชื่อนิติบุคคลคู่สัญญาปรากฏในทะเบียนสมาชิกบนเว็บของกองทุนเองหรือไม่** `w3` `PUB+REG` `G3`

- **ตรวจอะไร:** ตรวจว่านิติบุคคลที่เป็นคู่สัญญาของเรา (ไม่ใช่บริษัทแม่ ไม่ใช่บริษัทพี่น้อง) มีชื่ออยู่ในรายชื่อสมาชิกหรือรายชื่อบริษัทที่ได้รับความคุ้มครอง ซึ่งเผยแพร่บน **เว็บของกองทุนชดเชย X เอง** หรือบนทะเบียนของหน่วยงานที่กำกับกองทุน ต้องค้นด้วยชื่อเต็มทีละตัวอักษร และบันทึกทั้งกรณีพบและไม่พบ พร้อมวันที่ปรับปรุงรายชื่อที่หน้านั้นระบุ
- **ขั้นตอนการตรวจ:**
  1. คัดลอกชื่อนิติบุคคลคู่สัญญาแบบเต็มจากสัญญาเป็นข้อความ ห้ามพิมพ์เอง
  2. เปิดเว็บกองทุนชดเชย X จากข้อ 101 หาเมนู members / covered firms / รายชื่อสมาชิก
  3. ค้นด้วยชื่อเต็ม จับภาพหน้าผลลัพธ์ที่เห็นทั้งคำค้นและผลลัพธ์ในเฟรมเดียวกัน
  4. ค้นซ้ำด้วยคำหลักเพียงคำเดียวของชื่อ (เช่น คำแรกของชื่อบริษัท) เพื่อกันกรณีสะกดต่างเล็กน้อย บันทึกทุกรายการที่ใกล้เคียง
  5. ถ้ารายชื่อเป็นไฟล์ PDF หรือ Excel ให้ดาวน์โหลดทั้งไฟล์ แล้วค้นในไฟล์ บันทึกชื่อไฟล์และวันที่ปรับปรุงที่ระบุในไฟล์
  6. บันทึกวันที่ปรับปรุงรายชื่อที่หน้าเว็บหรือไฟล์ระบุ ถ้าไม่ระบุให้บันทึกว่า "ไม่ระบุวันที่ปรับปรุง"
  7. เก็บสำเนาถาวรของหน้ารายชื่อ และบันทึกผลพร้อมตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าผลค้นในทะเบียนสมาชิกที่เห็นโดเมนของกองทุน (`RST-BRKA-P02-102-01`) · ไฟล์รายชื่อสมาชิกฉบับดาวน์โหลด (`RST-BRKA-P02-102-02`) · สำเนา PDF ถาวร · บันทึกวันที่ปรับปรุงรายชื่อ
- **ผ่าน:** พบชื่อนิติบุคคลคู่สัญญาของเราในทะเบียนสมาชิกที่กองทุนหรือหน่วยงานกำกับกองทุนเผยแพร่เอง
- **ไม่ผ่าน:** ไม่พบชื่อนิติบุคคลคู่สัญญาของเราในทะเบียนสมาชิก ขณะที่โบรกอ้างความคุ้มครองจากกองทุนนี้บนเว็บ
- **ยังไม่ได้ตรวจ:** กองทุนไม่เผยแพร่รายชื่อสมาชิกต่อสาธารณะ (ต้องบันทึกข้อเท็จจริงนี้พร้อมภาพหน้าที่ยืนยัน และห้ามตีความเป็นไม่ผ่าน)
- **ตัวอย่าง:** หน้าไทยของ Broker B แสดงตราสัญลักษณ์กองทุนชดเชย X แต่ค้นรายชื่อสมาชิกบนเว็บกองทุนแล้วพบเฉพาะ *BrokerB Europe Ltd* ส่วนคู่สัญญาในสัญญาของเราคือ *BrokerB Global Ltd* ซึ่งไม่อยู่ในรายชื่อ → **ไม่ผ่าน** ตกด่าน G3

**P02-103 · รหัสอ้างอิงของโบรกในทะเบียนกองทุนตรงกับเลขใบอนุญาตที่โบรกอ้างหรือไม่** `w2` `PUB+REG`

- **ตรวจอะไร:** ในทะเบียนสมาชิกของกองทุนมักมีคอลัมน์รหัสอ้างอิง เช่น เลขใบอนุญาต เลขสมาชิก หรือเลขทะเบียนบริษัท ตรวจว่ารหัสในแถวของโบรกตรงกับเลขใบอนุญาตที่โบรกแสดงบนเว็บของตนหรือไม่ จุดนี้จับกรณีที่ชื่อคล้ายกันแต่เป็นคนละนิติบุคคล บันทึกรหัสทุกคอลัมน์ในแถวนั้นแบบคำต่อคำ
- **ขั้นตอนการตรวจ:**
  1. เปิดแถวของโบรกในทะเบียนสมาชิกจากข้อ 102 แล้วจับภาพทั้งแถวพร้อมหัวตาราง
  2. คัดลอกค่าทุกคอลัมน์ในแถวนั้นลงตารางบันทึก พร้อมชื่อหัวคอลัมน์
  3. เปิด footer และหน้า Regulation ของเว็บโบรก คัดลอกเลขใบอนุญาตและเลขทะเบียนบริษัทที่โบรกแสดง
  4. เทียบรหัสทั้งสองฝั่งทีละตัวอักษรด้วยเครื่องมือเทียบข้อความ บันทึกจุดที่ต่าง
  5. ถ้าต่างกัน ค้นในทะเบียนของหน่วยงานกำกับว่ารหัสของกองทุนหมายถึงนิติบุคคลใด แล้วบันทึกชื่อที่ได้
  6. บันทึกผลลงตารางเทียบสามคอลัมน์ (ทะเบียนกองทุน · เว็บโบรก · ทะเบียนหน่วยงาน) และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพแถวในทะเบียนกองทุนพร้อมหัวตาราง (`RST-BRKA-P02-103-01`) · ภาพเลขใบอนุญาตบนเว็บโบรก (`RST-BRKA-P02-103-02`) · ตารางเทียบสามคอลัมน์
- **ผ่าน:** รหัสอ้างอิงในทะเบียนกองทุนตรงกับเลขใบอนุญาตหรือเลขทะเบียนบริษัทที่โบรกแสดงบนเว็บ
- **ไม่ผ่าน:** รหัสอ้างอิงในทะเบียนกองทุนชี้ไปนิติบุคคลอื่นที่ไม่ใช่คู่สัญญาของเรา
- **ยังไม่ได้ตรวจ:** ทะเบียนสมาชิกของกองทุนไม่มีคอลัมน์รหัสอ้างอิงใด ๆ
- **ตัวอย่าง:** ทะเบียนกองทุนแสดงเลขใบอนุญาต 118/10 คู่กับชื่อ *BrokerC Ltd* ส่วนเว็บ Broker C แสดงเลข 284/15 ค้นในทะเบียนหน่วยงานพบว่าเลข 118/10 เป็นของบริษัทที่เลิกกิจการแล้ว → **ไม่ผ่าน**

**P02-104 ● · วงเงินคุ้มครองสูงสุดต่อรายที่กองทุนประกาศเองคือเท่าใด** `w3` `PUB`

- **ตรวจอะไร:** อ่านวงเงินคุ้มครองสูงสุดต่อผู้เสียหายหนึ่งรายจาก **หน้าของกองทุนชดเชย X เอง** ไม่ใช่จากเว็บโบรก บันทึกตัวเลข สกุลเงิน หน่วยนับ (ต่อราย · ต่อบัญชี · ต่อสถาบัน) เพดานร้อยละของมูลค่าเรียกร้อง (ถ้ามี) และวันที่ประกาศหรือวันที่ปรับปรุงหน้านั้น เพราะหลายกองทุนจ่ายเป็นร้อยละของมูลค่าโดยมีเพดานกำกับ ไม่ใช่จ่ายเต็มจำนวน
- **ขั้นตอนการตรวจ:**
  1. เปิดหน้า coverage / compensation limits / วงเงินคุ้มครอง บนเว็บกองทุนชดเชย X
  2. คัดลอกข้อความที่ระบุวงเงินแบบคำต่อคำ ห้ามสรุปเอง
  3. บันทึกตัวเลข สกุลเงิน และหน่วยนับที่หน้าระบุ (ต่อราย · ต่อบัญชี · ต่อสถาบัน)
  4. ค้นในหน้าเดียวกันด้วยคำว่า `%` `percentage` `ร้อยละ` เพื่อหาเงื่อนไขจ่ายเป็นสัดส่วน บันทึกถ้าพบ
  5. บันทึกวันที่ปรับปรุงหน้า หรือวันที่ประกาศที่ระบุในเอกสารอ้างอิงของหน้านั้น
  6. คำนวณจำนวนเงินที่เราจะได้รับจริงตามยอดคงเหลือในบัญชีทดสอบของเรา ณ วันที่ตรวจ แล้วบันทึกวิธีคำนวณ
  7. จับภาพเต็มหน้าพร้อม URL เก็บสำเนาถาวร และบันทึกผลตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพเต็มหน้าวงเงินคุ้มครองบนเว็บกองทุน (`RST-BRKA-P02-104-01`) · สำเนา PDF ถาวร · ตารางบันทึกตัวเลขพร้อมวันที่ · บันทึกวิธีคำนวณยอดที่จะได้รับจริง
- **ผ่าน:** หน้าของกองทุนระบุวงเงินคุ้มครองสูงสุดเป็นตัวเลขที่เจาะจง พร้อมสกุลเงินและหน่วยนับ
- **ไม่ผ่าน:** หน้าของกองทุนไม่ระบุวงเงินเป็นตัวเลข หรือระบุเพียงว่า "พิจารณาเป็นรายกรณี" โดยไม่มีเพดานใด
- **ยังไม่ได้ตรวจ:** ยังไม่ได้ระบุตัวกองทุนจากข้อ 101 หรือหน้าวงเงินเข้าไม่ได้
- **ตัวอย่าง:** เว็บกองทุนชดเชย X ระบุ *"จ่าย 90% ของมูลค่าเรียกร้อง สูงสุด 20,000 ต่อราย"* บัญชีทดสอบของเรามียอด 30,000 คำนวณแล้วจะได้รับ 20,000 หน้าระบุวันที่ปรับปรุงชัดเจน → **ผ่าน** (แต่ต้องนำตัวเลข 90% ไปเทียบกับคำโฆษณาของโบรกในข้อ 114)

**P02-105 ● · กองทุนคุ้มครองเหตุใดบ้าง — เฉพาะกรณีล้มละลาย หรือรวมกรณีไม่คืนเงิน** `w3` `PUB`

- **ตรวจอะไร:** อ่านหน้า eligibility / เงื่อนไขการจ่าย บนเว็บกองทุนชดเชย X แล้วแยกให้ชัดว่ากองทุนจ่ายในเหตุใดบ้าง เพราะลูกค้าส่วนใหญ่เข้าใจผิดว่ากองทุนคุ้มครองทุกกรณีที่โบรกไม่คืนเงิน ทั้งที่กองทุนจำนวนมากจ่ายเฉพาะกรณีที่บริษัท **ล้มละลายหรือถูกประกาศผิดนัด** เท่านั้น ไม่ครอบคลุมกรณีขาดทุนจากการเทรด สเปรดผิดปกติ ระบบล่ม หรือโบรกปฏิเสธคำขอถอนโดยยังดำเนินกิจการอยู่ บันทึกรายการเหตุที่คุ้มครองและไม่คุ้มครองแบบคำต่อคำ
- **ขั้นตอนการตรวจ:**
  1. เปิดหน้าเงื่อนไขการจ่ายของกองทุนชดเชย X และหน้า FAQ ของกองทุน
  2. คัดลอกข้อความที่ระบุ "เหตุที่ทำให้เกิดสิทธิเรียกร้อง" ทั้งหมดลงตาราง
  3. ค้นในหน้าด้วยคำว่า `insolvency` `default` `failure` `ล้มละลาย` `ผิดนัด` บันทึกบริบทของทุกคำที่พบ
  4. ค้นด้วยคำว่า `not covered` `exclusion` `ไม่คุ้มครอง` `ข้อยกเว้น` แล้วคัดลอกรายการข้อยกเว้นทั้งหมด
  5. ทำตารางสองคอลัมน์: เหตุที่คุ้มครอง กับ เหตุที่ไม่คุ้มครอง
  6. ทำเครื่องหมายในตารางว่ากรณี "โบรกยังเปิดกิจการแต่ปฏิเสธคำขอถอน" อยู่ฝั่งใด
  7. จับภาพเต็มหน้าทุกหน้า เก็บสำเนาถาวร และบันทึกผลตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพเต็มหน้าเงื่อนไขการจ่ายและหน้าข้อยกเว้น (`RST-BRKA-P02-105-01`, `-02`) · สำเนา PDF ถาวร · ตารางสองคอลัมน์เหตุที่คุ้มครอง/ไม่คุ้มครอง
- **ผ่าน:** หน้าของกองทุนระบุเหตุที่ทำให้เกิดสิทธิเรียกร้องเป็นรายการที่เจาะจง อ่านแล้วรู้ทันทีว่ากรณีใดได้และกรณีใดไม่ได้
- **ไม่ผ่าน:** หน้าของกองทุนไม่ระบุเหตุที่คุ้มครองเลย หรือระบุกว้างจนไม่สามารถบอกได้ว่ากรณีปฏิเสธคำขอถอนอยู่ในหรือนอกความคุ้มครอง
- **ยังไม่ได้ตรวจ:** ยังไม่ได้ระบุตัวกองทุนจากข้อ 101
- **ตัวอย่าง:** เว็บกองทุนชดเชย X ระบุว่าจ่ายเมื่อ *"บริษัทถูกศาลสั่งพิทักษ์ทรัพย์ หรือหน่วยงานประกาศว่าไม่สามารถคืนทรัพย์สินลูกค้าได้"* และมีข้อยกเว้นชัดเจนว่าไม่ครอบคลุมการขาดทุนจากการลงทุน อ่านแล้วตัดสินได้ว่ากรณีปฏิเสธคำขอถอนขณะยังเปิดกิจการไม่เข้าเงื่อนไข → **ผ่าน**

**P02-106 · ประเภทตราสารที่กองทุนคุ้มครอง ครอบคลุมสิ่งที่เราเทรดจริงหรือไม่** `w2` `PUB+PLT`

- **ตรวจอะไร:** เทียบรายการประเภทตราสารหรือบริการที่กองทุนชดเชย X ระบุว่าคุ้มครอง กับรายการตราสารที่เราเทรดจริงในบัญชีทดสอบ เพราะกองทุนบางกองคุ้มครองเฉพาะบริการลงทุนในตราสารที่กำหนด และอาจไม่รวมสัญญา CFD หรือคริปโต บันทึกรายการทั้งสองฝั่งพร้อมแหล่งที่มา
- **ขั้นตอนการตรวจ:**
  1. เปิดหน้าของกองทุนที่ระบุประเภทตราสารหรือบริการที่คุ้มครอง คัดลอกรายการทั้งหมดเป็นข้อความ
  2. เข้าแพลตฟอร์มของโบรกด้วยบัญชีทดสอบ เปิดหน้ารายการสินค้า บันทึกทุกหมวดที่เปิดให้เทรด
  3. เปิด statement ของบัญชีทดสอบ บันทึกประเภทตราสารที่เราเปิดสถานะจริงในรอบที่ผ่านมา
  4. ทำตารางสองคอลัมน์: ตราสารที่กองทุนคุ้มครอง กับ ตราสารที่เราถือหรือเทรดจริง
  5. ทำเครื่องหมายทุกแถวที่เราเทรดจริงแต่ไม่ปรากฏในรายการที่กองทุนคุ้มครอง
  6. บันทึกตารางพร้อมภาพหลักฐานทั้งสองฝั่ง และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าประเภทตราสารที่กองทุนคุ้มครอง (`RST-BRKA-P02-106-01`) · ภาพหน้ารายการสินค้าในแพลตฟอร์ม (`RST-BRKA-P02-106-02`) · statement บัญชีทดสอบ · ตารางเทียบ
- **ผ่าน:** ตราสารทุกประเภทที่เราเทรดจริงอยู่ในรายการที่กองทุนระบุว่าคุ้มครอง
- **ไม่ผ่าน:** มีตราสารอย่างน้อย 1 ประเภทที่เราเทรดจริงและอยู่นอกรายการที่กองทุนคุ้มครอง ขณะที่โบรกโฆษณาความคุ้มครองโดยไม่ระบุข้อยกเว้นนี้
- **ยังไม่ได้ตรวจ:** หน้าของกองทุนไม่ระบุประเภทตราสารเลย
- **ตัวอย่าง:** กองทุนชดเชย X ระบุคุ้มครองบริการลงทุนในตราสารทางการเงินตามรายการแนบท้าย ซึ่งรวมสัญญาส่วนต่าง แต่ไม่รวมสินทรัพย์ดิจิทัล ขณะที่บัญชีทดสอบของเราถือทั้ง CFD ดัชนีและ CFD คริปโต และหน้าโปรโมชันของ Broker A เขียนว่า "ทุกสถานะของคุณได้รับการคุ้มครอง" → **ไม่ผ่าน**

**P02-107 ● · กฎเกณฑ์ของกองทุนคุ้มครองลูกค้าที่มีถิ่นที่อยู่นอกประเทศหรือไม่** `w3` `PUB`

- **ตรวจอะไร:** ตรวจว่ากองทุนชดเชย X จำกัดสิทธิเรียกร้องไว้เฉพาะผู้มีถิ่นที่อยู่ในเขตอำนาจนั้นหรือไม่ เพราะลูกค้าไทยที่เปิดบัญชีกับนิติบุคคลต่างประเทศมักถูกตัดสิทธิด้วยเงื่อนไขถิ่นที่อยู่ ทั้งที่โบรกโฆษณาความคุ้มครองในหน้าภาษาไทย บันทึกข้อความเงื่อนไขถิ่นที่อยู่แบบคำต่อคำ พร้อมระบุว่าเงื่อนไขอิงถิ่นที่อยู่ของลูกค้า หรืออิงที่ตั้งของสาขาที่ให้บริการ
- **ขั้นตอนการตรวจ:**
  1. เปิดหน้า eligibility / who can claim ของกองทุนชดเชย X
  2. ค้นด้วยคำว่า `resident` `residence` `domicile` `EEA` `ถิ่นที่อยู่` `สัญชาติ` บันทึกบริบทของทุกคำที่พบ
  3. คัดลอกข้อความเงื่อนไขถิ่นที่อยู่แบบคำต่อคำ พร้อมเลขข้อหรือหัวข้อที่พบ
  4. บันทึกว่าเงื่อนไขอิง "ถิ่นที่อยู่ของลูกค้า" หรือ "ที่ตั้งของสาขาที่ทำสัญญา"
  5. เทียบกับถิ่นที่อยู่ที่เราแจ้งไว้ตอนเปิดบัญชี (จากภาพหน้าจอขั้นตอนสมัคร) แล้วบันทึกว่าเราเข้าเงื่อนไขหรือไม่
  6. เปิดหน้าภาษาไทยของโบรก ค้นว่ามีคำเตือนเรื่องเงื่อนไขถิ่นที่อยู่หรือไม่ บันทึกผล
  7. จับภาพเต็มหน้าทั้งสองฝั่ง เก็บสำเนาถาวร และบันทึกผลตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าเงื่อนไขผู้มีสิทธิบนเว็บกองทุน (`RST-BRKA-P02-107-01`) · ภาพหน้าภาษาไทยของโบรกส่วนที่กล่าวถึงความคุ้มครอง (`RST-BRKA-P02-107-02`) · ภาพถิ่นที่อยู่ที่เราแจ้งตอนสมัคร · สำเนา PDF ถาวร
- **ผ่าน:** กองทุนไม่จำกัดสิทธิด้วยถิ่นที่อยู่ หรือจำกัดแต่โบรกเตือนไว้ในหน้าที่กล่าวถึงความคุ้มครองในภาษาที่ลูกค้ากลุ่มนั้นอ่าน
- **ไม่ผ่าน:** กองทุนจำกัดสิทธิด้วยถิ่นที่อยู่ในลักษณะที่ตัดลูกค้ากลุ่มที่โบรกรับสมัคร แต่หน้าของโบรกในภาษาของกลุ่มนั้นไม่มีคำเตือนใด
- **ยังไม่ได้ตรวจ:** หน้าของกองทุนไม่กล่าวถึงเงื่อนไขถิ่นที่อยู่ทั้งฝั่งอนุญาตและฝั่งห้าม
- **ตัวอย่าง:** เว็บกองทุนชดเชย X ระบุว่าจ่ายเฉพาะผู้เรียกร้องที่มีถิ่นที่อยู่ในเขตเศรษฐกิจนั้น ขณะที่หน้าไทยของ Broker B แสดงตราสัญลักษณ์กองทุนพร้อมข้อความ "คุ้มครองสูงสุด 20,000" โดยไม่มีคำเตือนเรื่องถิ่นที่อยู่แม้แต่บรรทัดเดียว → **ไม่ผ่าน**

**P02-108 · นิยาม "ลูกค้ารายย่อย" ของกองทุน ตรงกับการจัดประเภทบัญชีของเราหรือไม่** `w2` `PUB+DOC`

- **ตรวจอะไร:** กองทุนชดเชยมักจ่ายเฉพาะลูกค้ารายย่อย และตัดสิทธิลูกค้ามืออาชีพ คู่สัญญาที่มีคุณสมบัติ สถาบันการเงิน และผู้เกี่ยวข้องกับบริษัท ตรวจว่านิยาม "ลูกค้ารายย่อย" ที่กองทุนใช้ ตรงกับประเภทบัญชีที่โบรกจัดให้เราตามเอกสารที่เราได้รับหรือไม่ บันทึกทั้งนิยามของกองทุนและถ้อยคำจัดประเภทที่ปรากฏในเอกสารของเรา
- **ขั้นตอนการตรวจ:**
  1. คัดลอกนิยาม "ลูกค้ารายย่อย" หรือ retail client จากหน้าของกองทุนชดเชย X แบบคำต่อคำ
  2. คัดลอกรายการประเภทลูกค้าที่กองทุน **ไม่** คุ้มครอง ลงตารางแยก
  3. เปิดเอกสารยืนยันการเปิดบัญชีและสัญญาลูกค้าของเรา ค้นด้วยคำว่า `client categorisation` `retail` `professional` `จัดประเภทลูกค้า`
  4. บันทึกประเภทที่โบรกจัดให้เราแบบคำต่อคำ พร้อมเลขข้อและหน้าที่พบ
  5. เทียบว่าประเภทของเราอยู่ในกลุ่มที่กองทุนคุ้มครองหรือกลุ่มที่ถูกตัดสิทธิ
  6. บันทึกผลลงตารางเทียบ พร้อมภาพหลักฐานทั้งสองฝั่ง และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพนิยามลูกค้ารายย่อยบนเว็บกองทุน (`RST-BRKA-P02-108-01`) · ภาพหน้าเอกสารที่ระบุประเภทลูกค้าของเรา (`RST-BRKA-P02-108-02`) · ตารางเทียบ
- **ผ่าน:** ประเภทลูกค้าที่โบรกจัดให้เราอยู่ในกลุ่มที่กองทุนระบุว่าคุ้มครอง
- **ไม่ผ่าน:** ประเภทลูกค้าที่โบรกจัดให้เราอยู่ในกลุ่มที่กองทุนระบุว่าไม่คุ้มครอง
- **ยังไม่ได้ตรวจ:** เอกสารที่เราได้รับไม่ระบุประเภทลูกค้าเลย และค้นในพอร์ทัลแล้วไม่พบส่วนแสดงประเภทลูกค้า

  5. ค้นด้วยคำว่า `levy` `contribution` `borrow` `เงินสมทบ` `กู้ยืม` เพื่อหาแหล่งเงินเพิ่มเติมที่กองทุนเรียกเก็บได้ บันทึกผล
  6. บันทึกยอดเงินคงเหลือของกองทุน ณ วันที่รายงานล่าสุด ถ้ารายงานประจำปีระบุไว้
  7. บันทึกผลลงตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ไฟล์ระเบียบกองทุนฉบับเต็ม (`RST-BRKA-P02-113-01`) · ภาพข้อความเพดานรวมพร้อมเลขข้อ (`RST-BRKA-P02-113-02`) · ตารางบันทึกเพดานและวิธีเฉลี่ยจ่าย
- **ผ่าน:** กองทุนระบุชัดว่าไม่มีเพดานรวม หรือมีเพดานรวมพร้อมตัวเลขและวิธีเฉลี่ยจ่ายที่อ่านแล้วคำนวณได้
- **ไม่ผ่าน:** กองทุนมีเพดานรวมแต่ไม่ระบุตัวเลข หรือไม่ระบุวิธีเฉลี่ยจ่ายเมื่อยอดเรียกร้องเกินเพดาน
- **ยังไม่ได้ตรวจ:** กองทุนไม่เผยแพร่ระเบียบหรือกฎเกณฑ์ฉบับเต็มต่อสาธารณะ
- **ตัวอย่าง:** ระเบียบของกองทุนชดเชย X ระบุเพดานรวมต่อการล้มหนึ่งครั้ง แต่ไม่มีข้อใดบอกว่าจะเฉลี่ยจ่ายอย่างไรเมื่อยอดเรียกร้องเกินเพดาน อ่านแล้วลูกค้าคำนวณสิ่งที่จะได้รับไม่ได้เลย → **ไม่ผ่าน**

**P02-114 ● · คำโฆษณาความคุ้มครองบนเว็บโบรกตรงกับตัวเลขที่กองทุนประกาศหรือไม่** `w3` `WEB+PUB` `G3`

- **ตรวจอะไร:** เทียบทุกข้อความบนเว็บโบรกที่กล่าวถึงความคุ้มครองเงินลูกค้า กับตัวเลขและเงื่อนไขที่บันทึกไว้จากเว็บกองทุนในข้อ 104–107 ต้องเก็บข้อความโฆษณาทุกจุดทุกภาษาที่โบรกให้บริการ แล้วชี้ให้ได้ว่าจุดใดเกินจริง จุดใดตัดเงื่อนไขสำคัญออก เช่น ตัดคำว่าจ่ายเป็นร้อยละ ตัดเงื่อนไขถิ่นที่อยู่ หรือตัดข้อยกเว้นประเภทตราสาร นี่คือจุดที่ลูกค้าไทยเข้าใจผิดมากที่สุด
- **ขั้นตอนการตรวจ:**
  1. เปิดเว็บโบรกทุกหน้าที่กล่าวถึงความคุ้มครอง (หน้าแรก · หน้าความปลอดภัยของเงินทุน · หน้าโปรโมชัน · footer) ทั้งฉบับภาษาไทยและภาษาอังกฤษ
  2. คัดลอกข้อความโฆษณาความคุ้มครองทุกจุดแบบคำต่อคำ พร้อม URL และภาษาของหน้า
  3. จับภาพเต็มหน้าทุกจุดพร้อมให้เห็น URL และนาฬิกาเครื่อง
  4. เปิดตารางบันทึกจากข้อ 104 · 105 · 106 · 107 วางเทียบกับข้อความโฆษณาแต่ละจุด
  5. ทำเครื่องหมายทุกจุดที่ตัวเลขไม่ตรง และทุกจุดที่ตัดเงื่อนไขสำคัญออก (ร้อยละการจ่าย · ถิ่นที่อยู่ · ประเภทตราสาร · ประเภทลูกค้า)
  6. เทียบเพิ่มว่าหน้าภาษาไทยกับหน้าภาษาอังกฤษระบุเงื่อนไขต่างกันหรือไม่ บันทึกส่วนต่าง
  7. เก็บสำเนา PDF ถาวรของทุกหน้าโฆษณา และบันทึกผลลงตารางเทียบตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพเต็มหน้าโฆษณาความคุ้มครองทุกจุดทุกภาษา (`RST-BRKA-P02-114-01` เป็นต้นไป) · สำเนา PDF ถาวร · ตารางเทียบ "ข้อความโฆษณา · ตัวเลขจากกองทุน · ส่วนต่าง"
- **ผ่าน:** ข้อความโฆษณาทุกจุดตรงกับตัวเลขที่กองทุนประกาศ และระบุเงื่อนไขสำคัญที่กระทบสิทธิของลูกค้ากลุ่มที่หน้านั้นเจาะจงไว้ครบ
- **ไม่ผ่าน:** มีข้อความโฆษณาอย่างน้อย 1 จุดที่ระบุตัวเลขสูงกว่าที่กองทุนประกาศ หรือตัดเงื่อนไขสำคัญออกจนลูกค้าเข้าใจว่าได้รับความคุ้มครองมากกว่าจริง
- **ยังไม่ได้ตรวจ:** เว็บโบรกไม่มีข้อความใดกล่าวถึงความคุ้มครองเลย จึงไม่มีสิ่งให้เทียบ
- **ตัวอย่าง:** หน้าไทยของ Broker A เขียนว่า "เงินของคุณได้รับความคุ้มครองสูงสุด 20,000 ต่อบัญชี" ขณะที่เว็บกองทุนชดเชย X ระบุจ่าย 90% ของมูลค่าเรียกร้อง สูงสุด 20,000 ต่อราย และจำกัดเฉพาะผู้มีถิ่นที่อยู่ในเขตนั้น หน้าไทยไม่กล่าวถึงทั้งร้อยละและถิ่นที่อยู่ → **ไม่ผ่าน** ตกด่าน G3

**P02-115 · ตราสัญลักษณ์กองทุนบนเว็บโบรกลิงก์ไปหน้าทางการของกองทุนหรือไม่** `w1` `WEB`

- **ตรวจอะไร:** ตรวจว่าตราสัญลักษณ์ ตราประทับ หรือแบนเนอร์ที่โบรกใช้แสดงความคุ้มครองนั้น กดแล้วไปที่หน้าทางการของกองทุนหรือหน่วยงานกำกับหรือไม่ หรือเป็นเพียงภาพนิ่งที่กดไม่ได้ หรือลิงก์กลับไปหน้าการตลาดของโบรกเอง บันทึกปลายทางของทุกลิงก์แบบเต็ม รวมพารามิเตอร์ติดตามที่ต่อท้าย
- **ขั้นตอนการตรวจ:**
  1. เปิดทุกหน้าของโบรกที่มีตราสัญลักษณ์เกี่ยวกับความคุ้มครองหรือการกำกับดูแล จับภาพตำแหน่งที่พบ
  2. วางเมาส์บนตราสัญลักษณ์ทีละอัน อ่าน URL ปลายทางที่แถบสถานะแสดง แล้วบันทึกแบบเต็ม
  3. คลิกตราสัญลักษณ์ทีละอันในแท็บใหม่ บันทึกโดเมนปลายทางที่โหลดจริงหลังการเปลี่ยนเส้นทางทุกชั้น
  4. เทียบโดเมนปลายทางกับโดเมนทางการของกองทุนที่บันทึกไว้ในข้อ 101 บันทึกว่าตรงหรือไม่ตรง
  5. บันทึกทุกอันที่เป็นภาพนิ่งกดไม่ได้ พร้อมภาพประกอบ
  6. บันทึกผลลงตาราง "ตำแหน่งตรา · URL ที่แสดง · โดเมนปลายทางจริง" และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพตราสัญลักษณ์ทุกจุดพร้อม URL ของหน้า (`RST-BRKA-P02-115-01` เป็นต้นไป) · ภาพหน้าปลายทางหลังคลิก (`RST-BRKA-P02-115-02`) · ตารางบันทึกปลายทาง
- **ผ่าน:** ตราสัญลักษณ์ทุกอันลิงก์ไปโดเมนทางการของกองทุนหรือหน่วยงานกำกับ หรือเป็นภาพนิ่งที่มีข้อความระบุชื่อกองทุนเต็มให้ค้นต่อได้เอง
- **ไม่ผ่าน:** มีตราสัญลักษณ์อย่างน้อย 1 อันที่ลิงก์กลับไปหน้าการตลาดของโบรกเอง หรือเป็นภาพนิ่งที่ไม่ระบุชื่อกองทุนจนค้นต่อไม่ได้
- **ยังไม่ได้ตรวจ:** เว็บโบรกไม่มีตราสัญลักษณ์เกี่ยวกับความคุ้มครองเลย
- **ตัวอย่าง:** หน้าแรกของ Broker B แสดงตราวงกลมข้อความ "PROTECTED FUNDS" กดแล้วไปหน้าเปิดบัญชีของ Broker B เอง และไม่มีข้อความใดระบุชื่อกองทุน → **ไม่ผ่าน**

**P02-116 ● · ประกันเพิ่มเติมที่โบรกอ้าง มีเอกสารระบุผู้รับประกันภัยจริงหรือไม่** `w3` `WEB+DOC`

- **ตรวจอะไร:** โบรกจำนวนมากโฆษณา "ประกันเพิ่มเติม" หรือ excess insurance ที่คุ้มครองเกินวงเงินกองทุน ตรวจว่าคำโฆษณานั้นมีเอกสารสาธารณะรองรับหรือไม่ ต้องหาให้ได้ว่าใครคือผู้รับประกันภัย (ชื่อนิติบุคคลเต็ม) เลขกรมธรรม์หรือเลขอ้างอิง และหน้าที่เผยแพร่เอกสารนั้น ถ้าโบรกอ้างประกันแต่ไม่มีชื่อผู้รับประกันภัยปรากฏที่ใดเลย ให้ถือว่าเป็นคำโฆษณาที่ตรวจสอบไม่ได้
- **ขั้นตอนการตรวจ:**
  1. ค้นทั้งเว็บโบรกด้วยคำว่า `insurance` `insured` `excess` `underwriter` `ประกัน` `กรมธรรม์` บันทึกทุกหน้าที่พบ
  2. คัดลอกข้อความที่กล่าวถึงประกันแบบคำต่อคำ พร้อม URL ของหน้า
  3. ค้นในหน้าเดียวกันหาชื่อนิติบุคคลผู้รับประกันภัยและเลขกรมธรรม์ บันทึกถ้าพบ ถ้าไม่พบให้บันทึกว่า "ไม่ระบุผู้รับประกัน"
  4. เปิดเอกสารสัญญาลูกค้าและเอกสารเปิดเผยที่เราได้รับตอนสมัคร ค้นคำเดียวกัน บันทึกเลขข้อที่พบ
  5. ดาวน์โหลดใบสรุปกรมธรรม์หรือหนังสือรับรองความคุ้มครองถ้าโบรกเผยแพร่ไว้ บันทึกชื่อไฟล์และวันที่ในเอกสาร
  6. บันทึกผลลงตาราง "แหล่งที่กล่าวถึงประกัน · ชื่อผู้รับประกัน · เลขกรมธรรม์ · วันที่เอกสาร" ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพทุกหน้าที่กล่าวถึงประกันเพิ่มเติม (`RST-BRKA-P02-116-01` เป็นต้นไป) · ไฟล์ใบสรุปกรมธรรม์ถ้ามี (`RST-BRKA-P02-116-02`) · สำเนา PDF ถาวร · ตารางบันทึก
- **ผ่าน:** พบชื่อนิติบุคคลผู้รับประกันภัยเต็มพร้อมเลขกรมธรรม์หรือเลขอ้างอิง จากเว็บโบรกหรือเอกสารที่เราได้รับ
- **ไม่ผ่าน:** โบรกโฆษณาประกันเพิ่มเติม แต่ไม่มีชื่อผู้รับประกันภัยหรือเลขอ้างอิงใดปรากฏทั้งบนเว็บและในเอกสารที่เราได้รับ
- **ยังไม่ได้ตรวจ:** โบรกไม่ได้กล่าวถึงประกันเพิ่มเติมที่ใดเลย (บันทึกข้อเท็จจริงนี้ และไม่นับเป็นไม่ผ่าน)
- **ตัวอย่าง:** หน้า "ความปลอดภัยของเงินทุน" ของ Broker C เขียนว่า "คุ้มครองเพิ่มเติมสูงสุด 1,000,000 ต่อบัญชีโดยผู้รับประกันชั้นนำระดับโลก" ค้นทั้งเว็บและเอกสารสัญญาแล้วไม่พบชื่อบริษัทประกันใดเลย → **ไม่ผ่าน**

**P02-117 · ผู้รับประกันภัยที่ระบุ ค้นเจอในทะเบียนผู้ประกอบธุรกิจประกันภัยหรือไม่** `w2` `REG`

- **ตรวจอะไร:** นำชื่อนิติบุคคลผู้รับประกันภัยที่ได้จากข้อ 116 ไปค้นในทะเบียนสาธารณะของหน่วยงานกำกับธุรกิจประกันภัยในเขตอำนาจที่ระบุ ตรวจว่ามีตัวตนจริง สถานะยังใช้งานอยู่ และมีใบอนุญาตประกอบธุรกิจประกันวินาศภัยหรือประกันภัยประเภทที่เกี่ยวข้องหรือไม่ ต้องเข้าเว็บหน่วยงานด้วยตนเอง ห้ามเข้าผ่านลิงก์ที่โบรกให้
- **ขั้นตอนการตรวจ:**
  1. คัดลอกชื่อผู้รับประกันภัยแบบเต็มจากเอกสารในข้อ 116 เป็นข้อความ ห้ามพิมพ์เอง
  2. ค้นในเครื่องมือค้นหาว่าเขตอำนาจใดกำกับผู้รับประกันรายนี้ แล้วเข้าเว็บทางการของหน่วยงานกำกับประกันภัยเขตนั้นด้วยตนเอง
  3. หาเมนูทะเบียนผู้ประกอบธุรกิจ แล้วค้นด้วยชื่อเต็ม จับภาพหน้าผลลัพธ์ที่เห็นทั้งคำค้นและผลลัพธ์
  4. บันทึกสถานะใบอนุญาต ประเภทธุรกิจที่ได้รับอนุญาต และวันที่มีผล จากหน้ารายการ
  5. ถ้าค้นไม่พบ ให้ค้นซ้ำด้วยคำหลักคำเดียวของชื่อ แล้วบันทึกทุกรายการที่ใกล้เคียง
  6. บันทึกวันเวลาที่ค้นเป็นเวลา UTC เก็บสำเนา PDF ถาวร และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าผลค้นในทะเบียนที่เห็นโดเมนหน่วยงาน (`RST-BRKA-P02-117-01`) · สำเนา PDF ถาวร · บันทึกวันเวลา UTC · ตารางบันทึกสถานะและประเภทใบอนุญาต
- **ผ่าน:** ค้นเจอผู้รับประกันภัยในทะเบียนสาธารณะ สถานะใช้งานอยู่ และได้รับอนุญาตประกอบธุรกิจประกันภัย ณ วันที่ตรวจ
- **ไม่ผ่าน:** ค้นไม่เจอในทะเบียนใด หรือเจอแต่สถานะสิ้นสุด ถูกเพิกถอน หรือถูกระงับ
- **ยังไม่ได้ตรวจ:** ข้อ 116 ไม่พบชื่อผู้รับประกันภัย หรือหน่วยงานกำกับเขตนั้นไม่เปิดทะเบียนให้ค้นสาธารณะ
- **ตัวอย่าง:** เอกสารของ Broker A ระบุผู้รับประกันเป็นนิติบุคคลในเขตอำนาจนอกชายฝั่ง ค้นในทะเบียนหน่วยงานกำกับประกันภัยของเขตนั้นแล้วพบรายการ สถานะ Active พร้อมประเภทใบอนุญาตประกันวินาศภัย → **ผ่าน**

**P02-118 ● · ประกันเพิ่มเติมระบุว่าใครเป็นผู้เอาประกันและใครเป็นผู้รับประโยชน์** `w3` `DOC+WEB`

- **ตรวจอะไร:** ประเด็นที่ถูกมองข้ามที่สุดคือประกันเพิ่มเติมส่วนใหญ่ทำขึ้นเพื่อคุ้มครอง **ตัวบริษัทโบรก** จากความรับผิด ไม่ใช่คุ้มครองลูกค้าโดยตรง ตรวจว่าเอกสารที่โบรกเผยแพร่ระบุหรือไม่ว่าใครคือผู้เอาประกัน ใครคือผู้รับประโยชน์ และลูกค้าเรียกร้องจากผู้รับประกันได้โดยตรงหรือต้องรอผ่านกระบวนการล้มละลายของโบรกก่อน บันทึกข้อความที่ระบุสิทธิเรียกร้องแบบคำต่อคำ
- **ขั้นตอนการตรวจ:**
  1. เปิดเอกสารประกันทุกฉบับที่ได้จากข้อ 116 และหน้าเว็บที่กล่าวถึงประกันเพิ่มเติม
  2. ค้นด้วยคำว่า `insured` `policyholder` `beneficiary` `named` `ผู้เอาประกัน` `ผู้รับประโยชน์` บันทึกบริบททุกจุดที่พบ
  3. คัดลอกข้อความที่ระบุตัวผู้เอาประกันและผู้รับประโยชน์แบบคำต่อคำ พร้อมเลขข้อ
  4. ค้นด้วยคำว่า `direct claim` `third party` `เรียกร้องโดยตรง` เพื่อดูว่าลูกค้ามีสิทธิเรียกร้องตรงหรือไม่ บันทึกผล
  5. บันทึกลำดับขั้นที่ลูกค้าต้องผ่านก่อนได้รับเงินตามที่เอกสารระบุ ถ้าไม่ระบุให้บันทึกว่า "ไม่ระบุลำดับขั้น"
  6. จับภาพทุกข้อความที่เกี่ยวข้อง เก็บสำเนา PDF ถาวร และบันทึกผลตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อความระบุผู้เอาประกันและผู้รับประโยชน์พร้อมเลขข้อ (`RST-BRKA-P02-118-01`) · สำเนา PDF ถาวรของเอกสารประกัน · บันทึกลำดับขั้นการเรียกร้อง
- **ผ่าน:** เอกสารระบุชัดว่าลูกค้าเป็นผู้รับประโยชน์ หรือระบุชัดว่าลูกค้าไม่ใช่ผู้รับประโยชน์พร้อมอธิบายลำดับขั้นที่ลูกค้าต้องผ่าน
- **ไม่ผ่าน:** โบรกโฆษณาว่าประกันคุ้มครองเงินของลูกค้า แต่เอกสารไม่ระบุตัวผู้รับประโยชน์เลย จนลูกค้าไม่อาจรู้ว่าตนเรียกร้องได้หรือไม่
- **ยังไม่ได้ตรวจ:** ข้อ 116 ไม่พบเอกสารประกันใดเลย จึงไม่มีข้อความให้อ่าน
- **ตัวอย่าง:** หน้าเว็บ Broker B เขียนว่า "เงินของลูกค้าได้รับการประกันเพิ่มเติม" แต่ใบสรุปกรมธรรม์ที่โบรกเผยแพร่ระบุผู้เอาประกันเป็นบริษัทโบรกและระบุว่าเป็นประกันความรับผิดของบริษัท ไม่มีข้อใดให้สิทธิลูกค้าเรียกร้องโดยตรง และหน้าเว็บไม่อธิบายจุดนี้ → **ไม่ผ่าน**

**P02-119 · วงเงินประกันเพิ่มเติมเป็นต่อรายหรือเป็นเพดานรวมทั้งกลุ่มลูกค้า** `w2` `DOC+WEB`

- **ตรวจอะไร:** ตรวจหน่วยนับของวงเงินประกันเพิ่มเติม เพราะโบรกมักโฆษณาตัวเลขใหญ่โดยไม่บอกว่าเป็นเพดานรวมทั้งบริษัท ซึ่งเมื่อหารด้วยจำนวนลูกค้าแล้วเหลือน้อยมาก บันทึกตัวเลขวงเงิน หน่วยนับ (ต่อราย · ต่อบัญชี · รวมทั้งกลุ่ม · ต่อเหตุการณ์) และคำนวณวงเงินเฉลี่ยต่อรายถ้าโบรกเปิดเผยจำนวนลูกค้า
- **ขั้นตอนการตรวจ:**
  1. คัดลอกข้อความวงเงินประกันเพิ่มเติมจากทุกแหล่งที่พบในข้อ 116 แบบคำต่อคำ
  2. ค้นในข้อความด้วยคำว่า `per client` `per account` `aggregate` `in total` `ต่อราย` `รวม` แล้วบันทึกหน่วยนับที่พบ
  3. ถ้าพบข้อความหลายจุดที่ระบุหน่วยนับต่างกัน ให้บันทึกทุกจุดพร้อม URL และภาษาของหน้า
  4. ค้นบนเว็บโบรกด้วยคำว่า `clients worldwide` `traders` `ลูกค้าทั่วโลก` เพื่อหาจำนวนลูกค้าที่โบรกอ้าง บันทึกตัวเลขและวันที่
  5. ถ้าวงเงินเป็นเพดานรวมและมีจำนวนลูกค้าที่โบรกอ้าง ให้คำนวณวงเงินเฉลี่ยต่อราย แล้วบันทึกวิธีคำนวณ
  6. บันทึกผลลงตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อความวงเงินทุกจุด (`RST-BRKA-P02-119-01` เป็นต้นไป) · ภาพหน้าที่ระบุจำนวนลูกค้า (`RST-BRKA-P02-119-02`) · ตารางบันทึกวงเงินพร้อมหน่วยนับ · บันทึกวิธีคำนวณ
- **ผ่าน:** ทุกจุดที่โฆษณาวงเงินระบุหน่วยนับไว้ชัดในบรรทัดหรือย่อหน้าเดียวกันกับตัวเลข
- **ไม่ผ่าน:** มีจุดโฆษณาอย่างน้อย 1 จุดที่แสดงตัวเลขวงเงินโดยไม่ระบุหน่วยนับ หรือระบุหน่วยนับต่างกันระหว่างหน้า
- **ยังไม่ได้ตรวจ:** ข้อ 116 ไม่พบข้อความวงเงินประกันเพิ่มเติมใดเลย
- **ตัวอย่าง:** หน้าไทยของ Broker C พาดหัวว่า "ประกันเพิ่มเติม 5,000,000" ส่วนหน้าอังกฤษของโบรกเดียวกันระบุว่าเป็นเพดานรวมทั้งกลุ่มลูกค้าต่อเหตุการณ์ หน้าไทยไม่มีคำใดบอกหน่วยนับ → **ไม่ผ่าน**

**P02-120 · กรมธรรม์ประกันเพิ่มเติมยังไม่หมดอายุ ณ วันที่ตรวจหรือไม่** `w2` `DOC+SUP`

- **ตรวจอะไร:** ตรวจว่าเอกสารประกันที่โบรกเผยแพร่ยังมีผลอยู่หรือเป็นเอกสารเก่าที่หมดอายุแล้ว บันทึกวันเริ่มความคุ้มครองและวันสิ้นสุดที่ระบุในเอกสาร แล้วเทียบกับวันที่ตรวจ ถ้าเอกสารไม่ระบุวันสิ้นสุด ให้ถามฝ่ายบริการในฐานะลูกค้าที่กังวลว่าความคุ้มครองยังมีผลอยู่หรือไม่ แล้วบันทึกคำตอบเป็นลายลักษณ์อักษร
- **ขั้นตอนการตรวจ:**
  1. เปิดเอกสารประกันทุกฉบับจากข้อ 116 ค้นด้วยคำว่า `period` `expiry` `valid until` `ระยะเวลาคุ้มครอง` `สิ้นสุด`
  2. บันทึกวันเริ่มและวันสิ้นสุดความคุ้มครองแบบคำต่อคำ พร้อมเลขข้อที่พบ
  3. เทียบวันสิ้นสุดกับวันที่ตรวจ แล้วบันทึกจำนวนวันคงเหลือหรือจำนวนวันที่เลยมาแล้ว
  4. ถ้าเอกสารไม่ระบุวันสิ้นสุด ให้ส่งคำถามถึงฝ่ายบริการผ่านช่องทางลูกค้าปกติ ในฐานะลูกค้าที่ถามว่า "ความคุ้มครองเพิ่มเติมที่โฆษณาไว้ยังมีผลถึงเมื่อไร"
  5. จับเวลาตั้งแต่ส่งคำถามจนได้รับคำตอบที่มีเนื้อหา เป็นเวลา UTC แล้วบันทึก
  6. บันทึกคำตอบของฝ่ายบริการแบบคำต่อคำ พร้อมชื่อช่องทางและรหัสเคส
  7. ถ้าคำตอบขัดกับเอกสาร ให้ทำตารางเทียบสองคอลัมน์ แล้วบันทึกส่วนต่าง
  8. เก็บสำเนาบทสนทนา ภาพหน้าเอกสาร และบันทึกผลตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อความระยะเวลาคุ้มครองพร้อมเลขข้อ (`RST-BRKA-P02-120-01`) · สำเนาบทสนทนากับฝ่ายบริการพร้อมรหัสเคส (`RST-BRKA-P02-120-02`) · บันทึกเวลา UTC ที่ส่งและที่ได้รับคำตอบ
- **ผ่าน:** เอกสารระบุวันสิ้นสุดความคุ้มครองที่ยังไม่ผ่านพ้น ณ วันที่ตรวจ หรือฝ่ายบริการยืนยันเป็นลายลักษณ์อักษรว่ายังมีผล และคำตอบไม่ขัดกับเอกสาร
- **ไม่ผ่าน:** เอกสารที่โบรกเผยแพร่มีวันสิ้นสุดที่ผ่านพ้นไปแล้ว ณ วันที่ตรวจ ขณะที่เว็บยังโฆษณาความคุ้มครองนั้นอยู่
- **ยังไม่ได้ตรวจ:** ข้อ 116 ไม่พบเอกสารประกัน หรือเอกสารไม่ระบุวันสิ้นสุดและฝ่ายบริการไม่ตอบภายใน [เกณฑ์เสนอ: 10 วันทำการนับจากเวลาที่ส่งคำถาม]
- **ตัวอย่าง:** ใบสรุปกรมธรรม์ที่ Broker A เผยแพร่ระบุระยะเวลาคุ้มครองสิ้นสุดเมื่อ 14 เดือนก่อนวันที่ตรวจ ขณะที่หน้าแรกยังแสดงข้อความประกันเพิ่มเติมอยู่ → **ไม่ผ่าน**

**P02-121 · ข้อยกเว้นของประกันเพิ่มเติมถูกเปิดเผยคู่กับคำโฆษณาหรือไม่** `w2` `DOC+WEB`

- **ตรวจอะไร:** ตรวจว่าเอกสารหรือหน้าเว็บที่กล่าวถึงประกันเพิ่มเติม เปิดเผยรายการข้อยกเว้นที่ทำให้ผู้รับประกันไม่ต้องจ่ายหรือไม่ ข้อยกเว้นที่ต้องมองหาเป็นพิเศษคือ การฉ้อโกงโดยผู้บริหารของโบรกเอง · ความเสียหายจากการโจมตีทางไซเบอร์ · การขาดทุนจากการเทรด · และกรณีที่โบรกไม่ได้แยกบัญชีเงินลูกค้าตามที่กำหนด บันทึกรายการข้อยกเว้นทั้งหมดแบบคำต่อคำ และบันทึกว่าข้อยกเว้นปรากฏในหน้าเดียวกับคำโฆษณาหรือถูกซ่อนไว้คนละที่
- **ขั้นตอนการตรวจ:**
  1. เปิดเอกสารประกันทุกฉบับจากข้อ 116 ค้นด้วยคำว่า `exclusion` `not covered` `shall not apply` `ข้อยกเว้น` `ไม่คุ้มครอง`
  2. คัดลอกรายการข้อยกเว้นทั้งหมดลงตาราง พร้อมเลขข้อและชื่อเอกสาร
  3. ทำเครื่องหมายในตารางว่าข้อยกเว้นสี่กลุ่มสำคัญ (ฉ้อโกงโดยผู้บริหาร · ไซเบอร์ · ขาดทุนจากการเทรด · ไม่แยกบัญชี) ปรากฏหรือไม่ปรากฏ
  4. เปิดหน้าเว็บที่โฆษณาประกันเพิ่มเติม ตรวจว่ามีลิงก์หรือข้อความชี้ไปยังรายการข้อยกเว้นหรือไม่ บันทึกตำแหน่ง
  5. วัดว่าลูกค้าต้องคลิกกี่ครั้งจากหน้าโฆษณาจึงจะถึงรายการข้อยกเว้น แล้วบันทึกจำนวนคลิก
  6. จับภาพทุกหน้าที่เกี่ยวข้อง เก็บสำเนา PDF ถาวร และบันทึกผลตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพรายการข้อยกเว้นพร้อมเลขข้อ (`RST-BRKA-P02-121-01`) · ภาพหน้าโฆษณาที่แสดงว่ามีหรือไม่มีลิงก์ไปข้อยกเว้น (`RST-BRKA-P02-121-02`) · ตารางข้อยกเว้น · บันทึกจำนวนคลิก
- **ผ่าน:** หน้าที่โฆษณาประกันเพิ่มเติมแสดงข้อยกเว้นในหน้าเดียวกัน หรือมีลิงก์ตรงไปยังรายการข้อยกเว้นภายใน [เกณฑ์เสนอ: 1 คลิกจากหน้าโฆษณา]
- **ไม่ผ่าน:** โบรกโฆษณาประกันเพิ่มเติมโดยไม่มีลิงก์หรือข้อความใดชี้ไปยังรายการข้อยกเว้นเลย
- **ยังไม่ได้ตรวจ:** ข้อ 116 ไม่พบเอกสารประกัน จึงไม่มีรายการข้อยกเว้นให้อ่าน
- **ตัวอย่าง:** หน้าประกันเพิ่มเติมของ Broker B แสดงตัวเลขวงเงินขนาดใหญ่ ส่วนรายการข้อยกเว้นอยู่ในไฟล์ PDF ที่ต้องเข้าหน้า Legal แล้วเลื่อนหาเองรวม 4 คลิก และในนั้นระบุว่าไม่คุ้มครองกรณีบริษัทไม่แยกบัญชีเงินลูกค้า → **ไม่ผ่าน**

**P02-122 ● · ฝ่ายบริการตอบคำถามเรื่องความคุ้มครองตรงกับเอกสารหรือไม่** `w3` `SUP` `G3`

- **ตรวจอะไร:** ถามฝ่ายบริการในฐานะลูกค้าที่กังวลว่าเงินจะได้คืนไหม แล้วเทียบคำตอบกับสิ่งที่บันทึกไว้จากเว็บกองทุนและเอกสารประกันในข้อ 104–121 ต้องถามคำถามชุดเดียวกันผ่านช่องทางที่ต่างกันและคนละรอบเวลา เพื่อดูว่าคำตอบสอดคล้องกันหรือไม่ ห้ามเปิดเผยว่าเป็นผู้ตรวจ ห้ามอ้างชื่อ RedStarTrust และห้ามขอเอกสารภายในใด ๆ บันทึกคำตอบทุกคำและรหัสเคสทุกครั้ง

  3. ส่งคำถามชุดเดียวกันผ่านอีเมลฝ่ายบริการ ห่างจากรอบแชท [เกณฑ์เสนอ: อย่างน้อย 3 วัน] บันทึกเวลาส่งและรหัสเคส

  6. คัดลอกคำตอบทั้งสามรอบแบบคำต่อคำลงตารางสามคอลัมน์
  7. เทียบคำตอบแต่ละรอบกับตัวเลขที่บันทึกไว้จากเว็บกองทุนในข้อ 104 · 107 และเอกสารประกันในข้อ 118 แล้วทำเครื่องหมายทุกจุดที่ขัดกัน

  9. เก็บสำเนาบทสนทนาทุกช่องทาง ภาพหน้าจอ และบันทึกผลตาม Evidence ID

**P02-123 · เงินที่อยู่ระหว่างทางในช่องทางชำระเงิน อยู่ในความคุ้มครองหรือไม่** `w2` `DOC+PUB`

- **ตรวจอะไร:** ตรวจว่าเงินที่ลูกค้าฝากแล้วแต่ยังไม่เข้าบัญชีเทรด และเงินที่โบรกอนุมัติถอนแล้วแต่ยังอยู่ที่ผู้ให้บริการชำระเงิน อยู่ในความคุ้มครองของกองทุนหรือประกันเพิ่มเติมหรือไม่ ช่วงเวลานี้คือช่องว่างที่ลูกค้าเสียเงินบ่อยที่สุดเมื่อโบรกมีปัญหา บันทึกข้อความจากเงื่อนไขการฝากถอนที่ระบุว่าเงินเปลี่ยนมือเมื่อใด และเทียบกับนิยาม "เงินลูกค้า" ที่กองทุนใช้
- **ขั้นตอนการตรวจ:**
  1. เปิดเงื่อนไขการฝากถอนและสัญญาลูกค้าของโบรก ค้นด้วยคำว่า `received` `cleared` `settlement` `ถือว่าได้รับ` `เข้าบัญชี`
  2. คัดลอกข้อความที่ระบุว่าเงินถือว่าเป็นเงินลูกค้าตั้งแต่เมื่อใด แบบคำต่อคำ พร้อมเลขข้อ
  3. เปิดหน้าของกองทุนชดเชย X ที่ให้นิยาม "เงินหรือทรัพย์สินของลูกค้า" แล้วคัดลอกนิยามแบบคำต่อคำ
  4. ทำตารางเส้นเวลาสี่จุด (ลูกค้าโอนออก · ผู้ให้บริการชำระเงินรับ · โบรกรับ · ยอดขึ้นในบัญชีเทรด) แล้วทำเครื่องหมายว่าจุดใดอยู่ในนิยามของกองทุน
  5. ทำเส้นเวลาเดียวกันสำหรับขาถอน (โบรกอนุมัติ · โบรกส่งคำสั่ง · ผู้ให้บริการรับ · เงินถึงลูกค้า) แล้วทำเครื่องหมายเช่นเดียวกัน
  6. บันทึกจุดที่เป็นช่องว่างไม่มีใครคุ้มครอง พร้อมอ้างเลขข้อของทั้งสองแหล่ง และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อความเงื่อนไขการฝากถอนพร้อมเลขข้อ (`RST-BRKA-P02-123-01`) · ภาพนิยามเงินลูกค้าบนเว็บกองทุน (`RST-BRKA-P02-123-02`) · ตารางเส้นเวลาสองขา
- **ผ่าน:** เอกสารของโบรกและนิยามของกองทุนอ่านรวมกันแล้วระบุได้ว่าเงินอยู่ในความคุ้มครองตั้งแต่จุดใด โดยไม่มีจุดใดในเส้นเวลาที่ตัดสินไม่ได้
- **ไม่ผ่าน:** มีอย่างน้อย 1 จุดในเส้นเวลาที่เอกสารทั้งสองฝั่งไม่ครอบคลุม จนไม่อาจบอกได้ว่าเงินช่วงนั้นใครรับผิดชอบ
- **ยังไม่ได้ตรวจ:** ยังไม่ได้ระบุตัวกองทุนจากข้อ 101 หรือกองทุนไม่เผยแพร่นิยามเงินลูกค้า
- **ตัวอย่าง:** สัญญาของ Broker C ระบุว่าเงินถือเป็นเงินลูกค้าเมื่อ "เข้าบัญชีของบริษัทเรียบร้อยแล้ว" ส่วนนิยามของกองทุนครอบคลุมเฉพาะทรัพย์สินที่บริษัทถือครองอยู่ ทำให้ช่วงที่เงินอยู่กับผู้ให้บริการชำระเงินไม่มีฝ่ายใดคุ้มครอง และไม่มีเอกสารใดกล่าวถึงช่วงนี้ → **ไม่ผ่าน**

**P02-124 · การย้ายนิติบุคคลคู่สัญญาระหว่างทาง กระทบความคุ้มครองหรือไม่** `w2` `DOC+WEB`

- **ตรวจอะไร:** ตรวจว่าสัญญาให้สิทธิโบรกย้ายบัญชีของเราไปอยู่กับนิติบุคคลอื่นในกลุ่มหรือไม่ และถ้าย้ายแล้วความคุ้มครองจากกองทุนจะเปลี่ยนไปอย่างไร เพราะการย้ายจากนิติบุคคลที่มีกองทุนรองรับไปยังนิติบุคคลนอกชายฝั่งที่ไม่มีกองทุน คือวิธีที่ทำให้ลูกค้าเสียความคุ้มครองโดยไม่รู้ตัว บันทึกข้อสัญญาที่ให้สิทธิย้าย เงื่อนไขการแจ้งล่วงหน้า และสิทธิปฏิเสธของลูกค้า
- **ขั้นตอนการตรวจ:**
  1. เปิดสัญญาลูกค้าฉบับที่เราได้รับ ค้นด้วยคำว่า `transfer` `novation` `assign` `group entity` `โอนสิทธิ` `เปลี่ยนคู่สัญญา`
  2. คัดลอกข้อสัญญาที่ให้สิทธิโบรกย้ายบัญชีแบบคำต่อคำ พร้อมเลขข้อ
  3. บันทึกว่าสัญญากำหนดให้แจ้งล่วงหน้ากี่วัน และลูกค้ามีสิทธิปฏิเสธหรือถอนเงินก่อนย้ายหรือไม่
  4. เปิดหน้าเว็บโบรกที่ระบุรายชื่อนิติบุคคลในกลุ่มและเขตอำนาจของแต่ละแห่ง คัดลอกรายชื่อทั้งหมด
  5. ทำตารางว่านิติบุคคลใดในกลุ่มอยู่ในกองทุนชดเชยและนิติบุคคลใดไม่อยู่ โดยใช้ผลค้นทะเบียนสมาชิกจากข้อ 102
  6. ทำเครื่องหมายทุกนิติบุคคลปลายทางที่ไม่มีกองทุนรองรับ แล้วบันทึกผลตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อสัญญาที่ให้สิทธิย้ายพร้อมเลขข้อ (`RST-BRKA-P02-124-01`) · ภาพหน้ารายชื่อนิติบุคคลในกลุ่ม (`RST-BRKA-P02-124-02`) · ตารางนิติบุคคลกับสถานะกองทุน
- **ผ่าน:** สัญญาไม่ให้สิทธิย้ายคู่สัญญาโดยลำพัง หรือให้สิทธิแต่กำหนดให้แจ้งล่วงหน้าและให้ลูกค้าถอนเงินหรือปฏิเสธได้ก่อนย้าย
- **ไม่ผ่าน:** สัญญาให้สิทธิโบรกย้ายบัญชีไปนิติบุคคลอื่นได้โดยไม่ต้องแจ้งล่วงหน้าหรือไม่ให้สิทธิลูกค้าปฏิเสธ ขณะที่มีนิติบุคคลปลายทางอย่างน้อย 1 แห่งที่ไม่มีกองทุนรองรับ
- **ยังไม่ได้ตรวจ:** สัญญาไม่มีข้อใดกล่าวถึงการย้ายคู่สัญญาทั้งฝั่งอนุญาตและฝั่งห้าม
- **ตัวอย่าง:** สัญญาของ Broker A ข้อหนึ่งระบุว่าบริษัทอาจโอนสิทธิและหน้าที่ไปยังนิติบุคคลใดในกลุ่มได้ทุกเมื่อโดยการประกาศบนเว็บไซต์ และรายชื่อนิติบุคคลในกลุ่มมีสองแห่งที่อยู่ในเขตอำนาจซึ่งไม่มีกองทุนชดเชยเลย → **ไม่ผ่าน**

**P02-125 · หน้าเปรียบเทียบตามประเทศหรือประเภทบัญชี ระบุความคุ้มครองที่ต่างกันหรือไม่** `w1` `WEB`

- **ไม่ผ่าน:** ตัวเลือกบนหน้าเปรียบเทียบชี้ไปนิติบุคคลที่มีความคุ้มครองต่างกัน แต่หน้านั้นเปรียบเทียบเฉพาะสเปรดหรือเลเวอเรจโดยไม่กล่าวถึงความคุ้มครองเลย
- **ยังไม่ได้ตรวจ:** โบรกไม่มีหน้าเลือกประเทศหรือหน้าเปรียบเทียบประเภทบัญชี
- **ตัวอย่าง:** หน้าเปรียบเทียบของ Broker B แสดงบัญชี Standard กับ Pro โดยบอกความต่างเฉพาะสเปรดและค่าคอมมิชชัน แต่กด Pro แล้วไปหน้าที่ footer ระบุนิติบุคคลนอกชายฝั่งซึ่งไม่อยู่ในทะเบียนสมาชิกกองทุน ขณะที่ Standard อยู่กับนิติบุคคลที่มีกองทุนรองรับ → **ไม่ผ่าน**

## S06 · ความเพียงพอของเงินกองทุนที่เปิดเผยต่อสาธารณะ (126–150)

**P02-126 ● · งบการเงินฉบับล่าสุดของนิติบุคคลคู่สัญญา เข้าถึงได้จากแหล่งสาธารณะหรือไม่** `w3` `PUB+REG` `G3`

- **ตรวจอะไร:** ตรวจว่าเราในฐานะลูกค้ารายย่อยหาอ่านงบการเงินของนิติบุคคลที่ถือเงินของเราได้หรือไม่ โดยไล่หาจากสามแหล่งตามลำดับ คือ เว็บของโบรกเอง · เว็บของหน่วยงานกำกับ · และนายทะเบียนบริษัทของเขตอำนาจนั้น ต้องเป็นงบของ **นิติบุคคลคู่สัญญา** ไม่ใช่ของบริษัทแม่หรือบริษัทในเครือ บันทึกแหล่งที่พบ ปีบัญชีของงบ วันที่เผยแพร่ และค่าธรรมเนียมที่ต้องจ่าย (ถ้ามี)
- **ขั้นตอนการตรวจ:**
  1. ค้นในเว็บโบรกด้วยคำว่า `financial statements` `annual report` `audited` `งบการเงิน` บันทึกทุกหน้าและไฟล์ที่พบ
  2. เปิดหน้ารายการของโบรกในทะเบียนหน่วยงานกำกับจากงานเสา P01 แล้วหาส่วนที่แนบงบการเงินหรือรายงานทางการเงิน
  3. ค้นนายทะเบียนบริษัทของเขตอำนาจที่นิติบุคคลคู่สัญญาจดทะเบียน แล้วค้นด้วยเลขทะเบียนบริษัท จับภาพหน้าผลลัพธ์
  4. ดาวน์โหลดงบการเงินฉบับล่าสุดที่หาได้ บันทึกชื่อไฟล์ ปีบัญชี วันที่เผยแพร่ และแหล่งที่ดาวน์โหลด
  5. เทียบชื่อนิติบุคคลบนหน้าปกงบกับชื่อคู่สัญญาในสัญญาของเราทีละตัวอักษร บันทึกว่าตรงหรือไม่
  6. บันทึกค่าธรรมเนียมที่ต้องจ่ายเพื่อเข้าถึงงบ ถ้านายทะเบียนคิดค่าบริการ
  7. เก็บไฟล์งบและภาพหน้าแหล่งที่มา แล้วบันทึกผลตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ไฟล์งบการเงินฉบับเต็ม (`RST-BRKA-P02-126-01`) · ภาพหน้าแหล่งที่ดาวน์โหลดพร้อม URL (`RST-BRKA-P02-126-02`) · ตารางบันทึกแหล่ง ปีบัญชี วันที่เผยแพร่ และค่าธรรมเนียม
- **ผ่าน:** หางบการเงินของนิติบุคคลคู่สัญญาได้จากแหล่งสาธารณะอย่างน้อย 1 แหล่ง โดยไม่ต้องเป็นผู้มีสถานะพิเศษ
- **ไม่ผ่าน:** ค้นครบทั้งสามแหล่งแล้วไม่พบงบการเงินของนิติบุคคลคู่สัญญาเลย ขณะที่นิติบุคคลนั้นรับฝากเงินจากลูกค้ารายย่อย
- **ยังไม่ได้ตรวจ:** เขตอำนาจนั้นไม่มีนายทะเบียนบริษัทที่เปิดค้นสาธารณะ และทั้งโบรกและหน่วยงานกำกับไม่เผยแพร่งบ (ต้องบันทึกข้อเท็จจริงนี้พร้อมภาพยืนยันทั้งสามแหล่ง)
- **ตัวอย่าง:** ค้นเว็บ Broker A ไม่พบงบการเงิน ทะเบียนหน่วยงานกำกับไม่แนบงบ และนายทะเบียนบริษัทของเขตอำนาจนั้นเปิดให้ค้นได้แต่แสดงเฉพาะชื่อกรรมการ ไม่มีงบการเงินให้ดาวน์โหลด → **ไม่ผ่าน** ตกด่าน G3

**P02-127 · งบการเงินฉบับล่าสุดที่หาได้ มีอายุเกินกว่าที่ยอมรับได้หรือไม่** `w2` `PUB`

- **ตรวจอะไร:** ตรวจความสดของข้อมูลทางการเงิน โดยวัดระยะห่างระหว่าง **วันสิ้นรอบบัญชีของงบฉบับล่าสุดที่หาได้** กับ **วันที่เราตรวจ** เพราะงบที่เก่ากว่าสองปีแทบไม่บอกอะไรเกี่ยวกับฐานะปัจจุบัน บันทึกวันสิ้นรอบบัญชี วันที่ผู้สอบบัญชีลงนาม วันที่เผยแพร่ และคำนวณอายุเป็นจำนวนเดือน
- **ขั้นตอนการตรวจ:**
  1. เปิดไฟล์งบการเงินจากข้อ 126 แล้วบันทึกวันสิ้นรอบบัญชีที่ระบุบนหน้างบแสดงฐานะการเงิน
  2. บันทึกวันที่ผู้สอบบัญชีลงนามในรายงานของผู้สอบบัญชี
  3. บันทึกวันที่เผยแพร่หรือวันที่นายทะเบียนรับงบ ถ้าแหล่งที่มาระบุไว้
  4. คำนวณจำนวนเดือนจากวันสิ้นรอบบัญชีถึงวันที่ตรวจ แล้วบันทึกวิธีคำนวณ
  5. ตรวจว่ามีงบฉบับใหม่กว่านี้ในแหล่งอื่นหรือไม่ โดยค้นซ้ำทั้งสามแหล่งจากข้อ 126
  6. บันทึกผลลงตารางพร้อมภาพหน้าที่แสดงวันที่ทุกจุด และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้างบที่แสดงวันสิ้นรอบบัญชี (`RST-BRKA-P02-127-01`) · ภาพหน้ารายงานผู้สอบบัญชีที่แสดงวันลงนาม (`RST-BRKA-P02-127-02`) · ตารางคำนวณอายุงบ
- **ผ่าน:** งบฉบับล่าสุดที่หาได้มีวันสิ้นรอบบัญชีห่างจากวันที่ตรวจไม่เกิน [เกณฑ์เสนอ: 18 เดือน]
- **ไม่ผ่าน:** งบฉบับล่าสุดที่หาได้มีวันสิ้นรอบบัญชีห่างจากวันที่ตรวจเกิน [เกณฑ์เสนอ: 18 เดือน]
- **ยังไม่ได้ตรวจ:** ข้อ 126 ไม่พบงบการเงินใดเลย
- **ตัวอย่าง:** งบฉบับล่าสุดของ Broker C ที่หาได้จากนายทะเบียนมีวันสิ้นรอบบัญชีห่างจากวันที่ตรวจ 31 เดือน และค้นทั้งสามแหล่งแล้วไม่มีฉบับใหม่กว่า → **ไม่ผ่าน**

**P02-128 · งบการเงินผ่านการสอบบัญชี และระบุชื่อสำนักงานสอบบัญชีหรือไม่** `w2` `PUB`

- **ตรวจอะไร:** ตรวจว่างบที่ได้เป็นงบที่ผ่านการสอบบัญชีจริงหรือเป็นงบที่ผู้บริหารจัดทำเอง โดยดูว่ามีรายงานของผู้สอบบัญชีแนบอยู่หรือไม่ มีชื่อสำนักงานสอบบัญชี Y เต็ม มีลายมือชื่อผู้สอบบัญชีที่ระบุชื่อบุคคลและเลขทะเบียน และมีวันที่ลงนามหรือไม่ บันทึกทุกองค์ประกอบที่พบและที่ขาด
- **ขั้นตอนการตรวจ:**
  1. เปิดไฟล์งบจากข้อ 126 แล้วหาส่วนรายงานของผู้สอบบัญชี บันทึกเลขหน้าที่พบ
  2. ค้นในไฟล์ด้วยคำว่า `independent auditor` `audit report` `รายงานของผู้สอบบัญชี` ถ้าไม่พบให้บันทึกว่าไม่มีรายงานผู้สอบบัญชี
  3. คัดลอกชื่อสำนักงานสอบบัญชีเต็ม ชื่อผู้ลงนาม เลขทะเบียนผู้สอบบัญชี และวันที่ลงนาม
  4. ค้นในไฟล์ด้วยคำว่า `unaudited` `management accounts` `ยังไม่ได้ตรวจสอบ` เพื่อกันกรณีเป็นงบที่ยังไม่ผ่านการสอบบัญชี
  5. จับภาพหน้ารายงานผู้สอบบัญชีทั้งหน้าให้เห็นลายมือชื่อและวันที่
  6. บันทึกผลลงตารางองค์ประกอบที่พบและที่ขาด แล้วตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้ารายงานผู้สอบบัญชีเต็มหน้าพร้อมเลขหน้า (`RST-BRKA-P02-128-01`) · ตารางองค์ประกอบ (ชื่อสำนักงาน · ชื่อผู้ลงนาม · เลขทะเบียน · วันที่ลงนาม)
- **ผ่าน:** งบมีรายงานของผู้สอบบัญชีที่ระบุชื่อสำนักงานสอบบัญชีเต็มและวันที่ลงนามครบถ้วน
- **ไม่ผ่าน:** งบไม่มีรายงานของผู้สอบบัญชีแนบ หรือระบุชัดว่าเป็นงบที่ยังไม่ผ่านการสอบบัญชี
- **ยังไม่ได้ตรวจ:** ข้อ 126 ไม่พบงบการเงินใดเลย
- **ตัวอย่าง:** ไฟล์ที่ Broker B เผยแพร่บนหน้า About ใช้ชื่อว่า "รายงานประจำปี" มีตารางตัวเลขทางการเงินครบ แต่ค้นทั้งไฟล์แล้วไม่มีรายงานของผู้สอบบัญชี และหน้าสุดท้ายระบุว่าตัวเลขจัดทำโดยฝ่ายบริหาร → **ไม่ผ่าน**

**P02-129 ● · ความเห็นของผู้สอบบัญชีเป็นแบบไม่มีเงื่อนไขหรือไม่** `w3` `PUB` `G3`

- **ตรวจอะไร:** อ่านย่อหน้าความเห็นในรายงานของผู้สอบบัญชี แล้วจำแนกว่าเป็นความเห็นแบบใดใน 4 แบบ คือ ไม่มีเงื่อนไข · มีเงื่อนไข · ไม่แสดงความเห็น · หรือความเห็นว่างบไม่ถูกต้อง ต้องคัดลอกถ้อยคำความเห็นแบบคำต่อคำและบันทึกเหตุผลที่ผู้สอบบัญชีให้ไว้ทุกข้อ เพราะความเห็นที่ไม่ใช่แบบไม่มีเงื่อนไขคือสัญญาณตรงว่ามีปัญหาที่ผู้สอบบัญชีเองยังยืนยันตัวเลขไม่ได้
- **ขั้นตอนการตรวจ:**
  1. เปิดรายงานของผู้สอบบัญชีจากข้อ 128 แล้วหาหัวข้อ "ความเห็น" หรือ `Opinion` บันทึกเลขหน้า
  2. คัดลอกย่อหน้าความเห็นทั้งย่อหน้าแบบคำต่อคำ
  3. ค้นในรายงานด้วยคำว่า `qualified` `except for` `adverse` `disclaimer` `มีเงื่อนไข` `ยกเว้น` `ไม่แสดงความเห็น` บันทึกทุกจุดที่พบ
  4. จำแนกความเห็นลงหนึ่งใน 4 แบบ แล้วบันทึกถ้อยคำที่ใช้จำแนก
  5. ถ้าไม่ใช่แบบไม่มีเงื่อนไข ให้คัดลอกย่อหน้า "เกณฑ์ในการแสดงความเห็น" ทั้งย่อหน้า และสรุปเหตุผลทุกข้อลงตาราง
  6. ค้นบนเว็บโบรกว่ามีการกล่าวถึงความเห็นของผู้สอบบัญชีหรือไม่ บันทึกผล
  7. จับภาพหน้าความเห็นเต็มหน้า เก็บสำเนาถาวร และบันทึกผลตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าความเห็นของผู้สอบบัญชีเต็มหน้า (`RST-BRKA-P02-129-01`) · ภาพย่อหน้าเกณฑ์ในการแสดงความเห็นถ้ามี (`RST-BRKA-P02-129-02`) · ตารางเหตุผลที่ผู้สอบบัญชีระบุ
- **ผ่าน:** ความเห็นของผู้สอบบัญชีในงบฉบับล่าสุดเป็นแบบไม่มีเงื่อนไข
- **ไม่ผ่าน:** ความเห็นเป็นแบบมีเงื่อนไข ไม่แสดงความเห็น หรือความเห็นว่างบไม่ถูกต้อง
- **ยังไม่ได้ตรวจ:** ข้อ 128 ไม่พบรายงานของผู้สอบบัญชีในงบที่ได้
- **ตัวอย่าง:** รายงานผู้สอบบัญชีของ Broker A ระบุความเห็นแบบมีเงื่อนไข โดยเกณฑ์ในการแสดงความเห็นอธิบายว่าไม่สามารถได้รับหลักฐานเพียงพอเกี่ยวกับยอดคงเหลือในบัญชีเงินลูกค้า ณ วันสิ้นรอบบัญชี → **ไม่ผ่าน** ตกด่าน G3

**P02-130 ● · รายงานผู้สอบบัญชีมีวรรคเน้นเรื่องการดำเนินงานต่อเนื่องหรือไม่** `w3` `PUB` `G3`

- **ตรวจอะไร:** ค้นหาวรรคที่ผู้สอบบัญชีเน้นถึงความไม่แน่นอนที่มีสาระสำคัญเกี่ยวกับความสามารถในการดำเนินงานต่อเนื่อง ซึ่งเป็นคำเตือนที่ตรงที่สุดว่าบริษัทอาจไปต่อไม่ได้ ต้องคัดลอกวรรคทั้งหมดแบบคำต่อคำ บันทึกเหตุการณ์หรือสภาวการณ์ที่ผู้สอบบัญชีอ้าง และตรวจต่อว่าหมายเหตุประกอบงบข้อที่วรรคนั้นอ้างถึงเขียนว่าอะไร รวมทั้งตรวจว่าโบรกเปิดเผยเรื่องนี้ต่อลูกค้าหรือไม่
- **ขั้นตอนการตรวจ:**
  1. ค้นในไฟล์งบด้วยคำว่า `going concern` `material uncertainty` `ดำเนินงานต่อเนื่อง` `ความไม่แน่นอนที่มีสาระสำคัญ` บันทึกทุกเลขหน้าที่พบ
  2. คัดลอกวรรคที่พบทั้งวรรคแบบคำต่อคำ พร้อมหัวข้อของวรรคนั้น
  3. เปิดหมายเหตุประกอบงบข้อที่วรรคนั้นอ้างถึง แล้วคัดลอกเนื้อหาทั้งข้อ
  4. บันทึกเหตุการณ์หรือสภาวการณ์ที่ระบุไว้ลงตาราง (เช่น ขาดทุนสะสม · หนี้สินหมุนเวียนสูงกว่าสินทรัพย์หมุนเวียน · พึ่งพาการสนับสนุนจากบริษัทแม่)
  5. ค้นบนเว็บโบรกและในเอกสารเปิดเผยที่เราได้รับ ว่ามีการกล่าวถึงความไม่แน่นอนนี้หรือไม่ บันทึกผล
  6. จับภาพวรรคและหมายเหตุประกอบงบเต็มหน้า เก็บสำเนาถาวร และบันทึกผลตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพวรรคเรื่องการดำเนินงานต่อเนื่องพร้อมเลขหน้า (`RST-BRKA-P02-130-01`) · ภาพหมายเหตุประกอบงบข้อที่อ้างถึง (`RST-BRKA-P02-130-02`) · ตารางเหตุการณ์ที่ระบุ
- **ผ่าน:** รายงานของผู้สอบบัญชีไม่มีวรรคเรื่องความไม่แน่นอนที่มีสาระสำคัญเกี่ยวกับการดำเนินงานต่อเนื่อง
- **ไม่ผ่าน:** รายงานของผู้สอบบัญชีมีวรรคดังกล่าว ขณะที่โบรกยังรับฝากเงินจากลูกค้ารายย่อยและไม่เปิดเผยเรื่องนี้ในช่องทางที่ลูกค้าเห็นได้
- **ยังไม่ได้ตรวจ:** ข้อ 128 ไม่พบรายงานของผู้สอบบัญชีในงบที่ได้
- **ตัวอย่าง:** งบของ Broker C มีวรรคระบุความไม่แน่นอนที่มีสาระสำคัญเกี่ยวกับการดำเนินงานต่อเนื่อง โดยอ้างหมายเหตุที่อธิบายว่าบริษัทมีหนี้สินหมุนเวียนสูงกว่าสินทรัพย์หมุนเวียนและต้องพึ่งการสนับสนุนทางการเงินจากบริษัทแม่ ขณะที่หน้าเว็บยังโปรโมตการฝากเงินขั้นต่ำ → **ไม่ผ่าน** ตกด่าน G3

**P02-131 · ส่วนของผู้ถือหุ้นในงบฉบับล่าสุดเป็นบวกหรือไม่** `w2` `PUB`

- **ตรวจอะไร:** อ่านงบแสดงฐานะการเงินแล้วบันทึกยอดรวมส่วนของผู้ถือหุ้น ณ วันสิ้นรอบบัญชี พร้อมองค์ประกอบย่อย (ทุนที่ออกและชำระแล้ว · ส่วนเกินมูลค่าหุ้น · กำไรหรือขาดทุนสะสม) เพราะส่วนของผู้ถือหุ้นติดลบหมายความว่าหนี้สินมากกว่าสินทรัพย์ ซึ่งเป็นสัญญาณตรงว่าบริษัทไม่มีทุนรองรับความเสียหายเหลืออยู่ บันทึกตัวเลขพร้อมสกุลเงินและหน่วย (บาท · พันบาท · ล้านบาท) ตามที่หัวตารางระบุ
- **ขั้นตอนการตรวจ:**
  1. เปิดงบแสดงฐานะการเงินในไฟล์จากข้อ 126 บันทึกเลขหน้า
  2. บันทึกหน่วยที่หัวตารางระบุแบบคำต่อคำ ห้ามสันนิษฐานหน่วยเอง
  3. คัดลอกยอดรวมส่วนของผู้ถือหุ้นทั้งปีปัจจุบันและปีเปรียบเทียบลงตาราง
  4. คัดลอกองค์ประกอบย่อยทุกบรรทัดในส่วนของผู้ถือหุ้นลงตารางเดียวกัน
  5. คำนวณส่วนต่างระหว่างสองปี แล้วบันทึกทั้งจำนวนเงินและร้อยละ
  6. จับภาพหน้างบแสดงฐานะการเงินให้เห็นทั้งหัวตารางหน่วยและยอดรวม แล้วบันทึกผลตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้างบแสดงฐานะการเงินพร้อมหัวตารางหน่วย (`RST-BRKA-P02-131-01`) · ตารางบันทึกส่วนของผู้ถือหุ้นสองปีพร้อมองค์ประกอบย่อย
- **ผ่าน:** ยอดรวมส่วนของผู้ถือหุ้น ณ วันสิ้นรอบบัญชีล่าสุดเป็นบวก
- **ไม่ผ่าน:** ยอดรวมส่วนของผู้ถือหุ้น ณ วันสิ้นรอบบัญชีล่าสุดเป็นศูนย์หรือติดลบ
- **ยังไม่ได้ตรวจ:** ข้อ 126 ไม่พบงบการเงิน หรืองบที่ได้ไม่มีงบแสดงฐานะการเงินแนบมาด้วย
- **ตัวอย่าง:** งบของ Broker B แสดงส่วนของผู้ถือหุ้นติดลบ โดยขาดทุนสะสมมากกว่าทุนที่ชำระแล้ว ขณะที่หน้าเว็บยังเปิดรับฝากเงินจากลูกค้าใหม่ → **ไม่ผ่าน**

**P02-132 · อัตราส่วนเงินกองทุนที่ต้องดำรงตามเกณฑ์ ถูกเปิดเผยต่อสาธารณะหรือไม่** `w2` `PUB+REG`

- **ตรวจอะไร:** ธุรกิจนายหน้าที่อยู่ภายใต้การกำกับต้องดำรงเงินกองทุนตามอัตราส่วนที่หน่วยงานกำหนด ตรวจว่าตัวเลขอัตราส่วนนี้ของนิติบุคคลคู่สัญญาถูกเปิดเผยที่ใดหรือไม่ โดยไล่หาจากงบการเงิน หมายเหตุประกอบงบ รายงานเปิดเผยข้อมูลของบริษัท และหน้าของหน่วยงานกำกับ บันทึกชื่ออัตราส่วนที่ใช้ ตัวเลขที่พบ วันที่ของตัวเลข และแหล่งที่มา
- **ขั้นตอนการตรวจ:**
  1. ค้นในไฟล์งบด้วยคำว่า `capital adequacy` `own funds` `capital ratio` `เงินกองทุน` `อัตราส่วนเงินกองทุน` บันทึกทุกเลขหน้าที่พบ
  2. คัดลอกชื่ออัตราส่วนและตัวเลขที่พบลงตาราง พร้อมวันที่ที่ตัวเลขอ้างถึง
  3. เปิดหมายเหตุประกอบงบเรื่องการบริหารเงินกองทุน แล้วคัดลอกเนื้อหาทั้งข้อ
  4. ค้นบนเว็บโบรกด้วยคำเดียวกัน บันทึกทุกหน้าและไฟล์ที่พบ
  5. เปิดหน้ารายการของโบรกในทะเบียนหน่วยงานกำกับ ตรวจว่าหน่วยงานเผยแพร่ตัวเลขเงินกองทุนของบริษัทหรือไม่ บันทึกผล
  6. บันทึกผลลงตาราง "แหล่ง · ชื่ออัตราส่วน · ตัวเลข · วันที่" และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าที่แสดงอัตราส่วนเงินกองทุนพร้อมเลขหน้าหรือ URL (`RST-BRKA-P02-132-01`) · ภาพหมายเหตุประกอบงบเรื่องเงินกองทุน (`RST-BRKA-P02-132-02`) · ตารางบันทึก
- **ผ่าน:** พบตัวเลขอัตราส่วนเงินกองทุนของนิติบุคคลคู่สัญญาจากแหล่งสาธารณะอย่างน้อย 1 แหล่ง พร้อมวันที่ที่ตัวเลขอ้างถึง
- **ไม่ผ่าน:** ค้นครบทั้งงบ หมายเหตุประกอบงบ เว็บโบรก และทะเบียนหน่วยงานแล้วไม่พบตัวเลขอัตราส่วนเงินกองทุนใดเลย
- **ยังไม่ได้ตรวจ:** ข้อ 126 ไม่พบงบการเงิน และหน่วยงานกำกับไม่เปิดเผยข้อมูลทางการเงินของผู้ประกอบธุรกิจ
- **ตัวอย่าง:** หมายเหตุประกอบงบของ Broker A มีข้อว่าด้วยการบริหารเงินกองทุน ระบุอัตราส่วนเงินกองทุนต่อสินทรัพย์เสี่ยง ณ วันสิ้นรอบบัญชีเป็นตัวเลขชัดเจนพร้อมตัวเลขปีเปรียบเทียบ → **ผ่าน**

**P02-133 ● · อัตราส่วนเงินกองทุนสูงกว่าขั้นต่ำที่หน่วยงานกำหนดหรือไม่** `w3` `PUB+REG` `G3`

- **ตรวจอะไร:** นำตัวเลขอัตราส่วนเงินกองทุนจากข้อ 132 ไปเทียบกับ **ขั้นต่ำที่หน่วยงานกำกับประกาศเอง** ไม่ใช่ขั้นต่ำที่โบรกอ้าง ต้องหาประกาศหรือหน้าเกณฑ์ของหน่วยงานให้ได้ก่อน แล้วจึงคำนวณส่วนต่าง บันทึกทั้งตัวเลขของบริษัท ตัวเลขขั้นต่ำ วันที่ของทั้งสองฝั่ง และส่วนต่างเป็นจุดร้อยละ เพราะบริษัทที่ดำรงเงินกองทุนแค่เฉียดขั้นต่ำมีกันชนรองรับความเสียหายน้อยมาก
- **ขั้นตอนการตรวจ:**
  1. เข้าเว็บทางการของหน่วยงานกำกับด้วยตนเอง หาหน้าเกณฑ์การดำรงเงินกองทุนของผู้ประกอบธุรกิจประเภทเดียวกับโบรก
  2. คัดลอกอัตราส่วนขั้นต่ำที่หน่วยงานกำหนดแบบคำต่อคำ พร้อมเลขที่ประกาศและวันที่มีผล
  3. บันทึกว่าเกณฑ์ขั้นต่ำนั้นใช้กับผู้ประกอบธุรกิจประเภทใด และตรงกับประเภทใบอนุญาตของนิติบุคคลคู่สัญญาหรือไม่
  4. นำตัวเลขของบริษัทจากข้อ 132 มาวางเทียบ แล้วคำนวณส่วนต่างเป็นจุดร้อยละ บันทึกวิธีคำนวณ
  5. บันทึกวันที่ของตัวเลขทั้งสองฝั่ง และระบุว่าห่างกันกี่เดือน
  6. ค้นในงบและเว็บโบรกว่ามีข้อความใดระบุว่าบริษัทไม่เป็นไปตามเกณฑ์ในระหว่างรอบบัญชีหรือไม่ บันทึกผล
  7. จับภาพหน้าเกณฑ์ของหน่วยงานพร้อม URL เก็บสำเนา PDF ถาวร และบันทึกผลตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าเกณฑ์ขั้นต่ำบนเว็บหน่วยงานพร้อม URL (`RST-BRKA-P02-133-01`) · สำเนา PDF ถาวรของประกาศ · ภาพตัวเลขของบริษัท (`RST-BRKA-P02-133-02`) · ตารางเทียบพร้อมวิธีคำนวณส่วนต่าง
- **ผ่าน:** อัตราส่วนเงินกองทุนของนิติบุคคลคู่สัญญา ณ วันที่ล่าสุดที่เปิดเผย สูงกว่าขั้นต่ำที่หน่วยงานกำกับประกาศ และไม่มีข้อความใดในงบระบุว่าบริษัทไม่เป็นไปตามเกณฑ์ในระหว่างรอบบัญชี
- **ไม่ผ่าน:** อัตราส่วนต่ำกว่าขั้นต่ำที่หน่วยงานประกาศ หรือมีข้อความในงบระบุว่าบริษัทไม่เป็นไปตามเกณฑ์ในช่วงใดของรอบบัญชี
- **ยังไม่ได้ตรวจ:** ข้อ 132 ไม่พบตัวเลขของบริษัท หรือหน่วยงานกำกับไม่เผยแพร่เกณฑ์ขั้นต่ำต่อสาธารณะ
- **ตัวอย่าง:** หมายเหตุประกอบงบของ Broker C แสดงอัตราส่วนเงินกองทุน ณ วันสิ้นรอบบัญชีสูงกว่าขั้นต่ำที่หน่วยงานประกาศ แต่ในหมายเหตุเดียวกันมีข้อความว่าบริษัทมีอัตราส่วนต่ำกว่าเกณฑ์เป็นเวลาสองเดือนในระหว่างรอบบัญชีและได้แก้ไขแล้ว → **ไม่ผ่าน** ตกด่าน G3

**P02-134 · ทุนจดทะเบียนชำระแล้วในงบ ตรงกับตัวเลขที่โบรกโฆษณาหรือไม่** `w2` `PUB+WEB`

- **ตรวจอะไร:** เทียบยอดทุนที่ออกและชำระแล้วในงบการเงินและในทะเบียนบริษัท กับตัวเลขที่โบรกใช้โฆษณาบนเว็บ เช่น "ทุนจดทะเบียน X ล้าน" เพราะโบรกมักใช้ทุนจดทะเบียนที่ยังไม่เรียกชำระ หรือใช้ทุนของบริษัทแม่มาโฆษณาแทนทุนของนิติบุคคลคู่สัญญา บันทึกตัวเลขทั้งสามแหล่งพร้อมวันที่และหน่วย
- **ขั้นตอนการตรวจ:**
  1. บันทึกยอด "ทุนที่ออกและชำระแล้ว" จากงบแสดงฐานะการเงิน พร้อมหน่วยและสกุลเงิน
  2. เปิดหมายเหตุประกอบงบเรื่องทุนเรือนหุ้น คัดลอกทั้งจำนวนหุ้นที่ออก มูลค่าที่ตราไว้ และยอดที่เรียกชำระแล้ว
  3. ค้นทั้งเว็บโบรกด้วยคำว่า `paid-up capital` `share capital` `ทุนจดทะเบียน` `ทุนชำระแล้ว` บันทึกทุกจุดพร้อม URL
  4. เปิดรายการของนิติบุคคลคู่สัญญาในทะเบียนบริษัท บันทึกยอดทุนที่ทะเบียนแสดงและวันที่ปรับปรุง
  5. ทำตารางเทียบสามคอลัมน์ (งบการเงิน · เว็บโบรก · ทะเบียนบริษัท) แล้วทำเครื่องหมายจุดที่ไม่ตรง
  6. ตรวจว่าตัวเลขบนเว็บอ้างถึงนิติบุคคลใด ถ้าเป็นบริษัทแม่ให้บันทึกชื่อบริษัทนั้นไว้ แล้วบันทึกผลตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหมายเหตุประกอบงบเรื่องทุนเรือนหุ้น (`RST-BRKA-P02-134-01`) · ภาพหน้าเว็บที่โฆษณาตัวเลขทุน (`RST-BRKA-P02-134-02`) · ภาพรายการในทะเบียนบริษัท · ตารางเทียบสามคอลัมน์
- **ผ่าน:** ตัวเลขทุนที่โบรกโฆษณาตรงกับทุนที่ออกและชำระแล้วของนิติบุคคลคู่สัญญาตามงบและทะเบียน หรือต่างแต่ระบุชัดในหน้าเดียวกันว่าเป็นตัวเลขของนิติบุคคลใด
- **ไม่ผ่าน:** โบรกโฆษณาตัวเลขทุนที่สูงกว่าทุนที่ชำระแล้วของนิติบุคคลคู่สัญญา โดยไม่ระบุว่าเป็นทุนที่ยังไม่เรียกชำระหรือเป็นทุนของนิติบุคคลอื่น
- **ยังไม่ได้ตรวจ:** ข้อ 126 ไม่พบงบการเงิน และทะเบียนบริษัทไม่แสดงยอดทุน
- **ตัวอย่าง:** หน้าไทยของ Broker A พาดหัวว่า "ทุนจดทะเบียนกว่า 100 ล้าน" ขณะที่งบของนิติบุคคลคู่สัญญาแสดงทุนที่ชำระแล้วเพียงเศษเสี้ยวของตัวเลขนั้น และตัวเลข 100 ล้านตรงกับทุนของบริษัทแม่ในอีกเขตอำนาจโดยหน้าเว็บไม่ระบุจุดนี้ → **ไม่ผ่าน**

**P02-135 · โบรกเผยแพร่รายงานเปิดเผยข้อมูลความเสี่ยงและเงินกองทุนต่อสาธารณะหรือไม่** `w1` `PUB+WEB`

- **ตรวจอะไร:** ผู้ประกอบธุรกิจในหลายเขตอำนาจต้องเผยแพร่รายงานเปิดเผยข้อมูลความเสี่ยงและเงินกองทุนประจำปีต่อสาธารณะ ตรวจว่านิติบุคคลคู่สัญญาเผยแพร่รายงานนี้หรือไม่ ปีล่าสุดคือปีใด และรายงานครอบคลุมนิติบุคคลใด บันทึกชื่อไฟล์ ปี วันที่เผยแพร่ และตำแหน่งที่พบบนเว็บ พร้อมนับจำนวนคลิกจากหน้าแรกถึงไฟล์
- **ขั้นตอนการตรวจ:**
  1. ค้นในเว็บโบรกด้วยคำว่า `Pillar 3` `risk disclosure report` `capital disclosure` `เปิดเผยข้อมูลความเสี่ยง` บันทึกทุกหน้าที่พบ
  2. เปิดหน้า Legal · Regulation · Investor relations ทีละหน้า แล้วไล่ดูรายการเอกสารทั้งหมดที่เผยแพร่
  3. ดาวน์โหลดรายงานฉบับล่าสุดที่พบ บันทึกชื่อไฟล์ ปีที่ครอบคลุม และวันที่เผยแพร่
  4. เปิดหน้าแรกของรายงาน ตรวจว่าครอบคลุมนิติบุคคลใด แล้วเทียบกับชื่อคู่สัญญาในสัญญาของเรา
  5. นับจำนวนคลิกจากหน้าแรกของเว็บถึงไฟล์รายงาน แล้วบันทึกเส้นทางที่ใช้
  6. จับภาพหน้าที่เผยแพร่รายงานพร้อม URL เก็บไฟล์รายงาน และบันทึกผลตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ไฟล์รายงานฉบับล่าสุด (`RST-BRKA-P02-135-01`) · ภาพหน้าเว็บที่เผยแพร่พร้อม URL (`RST-BRKA-P02-135-02`) · บันทึกเส้นทางและจำนวนคลิก
- **ผ่าน:** โบรกเผยแพร่รายงานเปิดเผยข้อมูลความเสี่ยงและเงินกองทุนของนิติบุคคลคู่สัญญา และเข้าถึงได้จากหน้าแรกภายใน [เกณฑ์เสนอ: 3 คลิก]
- **ไม่ผ่าน:** ไม่พบรายงานดังกล่าวบนเว็บของโบรกเลย หรือพบแต่ครอบคลุมเฉพาะนิติบุคคลอื่นที่ไม่ใช่คู่สัญญาของเรา
- **ยังไม่ได้ตรวจ:** เขตอำนาจของนิติบุคคลคู่สัญญาไม่มีข้อกำหนดให้เผยแพร่รายงานประเภทนี้ (ต้องบันทึกข้อเท็จจริงนี้พร้อมภาพหน้าเกณฑ์ของหน่วยงาน)
- **ตัวอย่าง:** เว็บ Broker B มีหน้า Legal ที่ลิสต์เอกสารสิบกว่าฉบับ ค้นครบทุกหน้าแล้วพบเฉพาะรายงานเปิดเผยข้อมูลของบริษัทในเครือที่อยู่คนละเขตอำนาจ ไม่มีฉบับของนิติบุคคลคู่สัญญาเราเลย → **ไม่ผ่าน**

**P02-136 · ยอดเงินลูกค้าที่บริษัทถือไว้ มีสัดส่วนเท่าใดเทียบกับส่วนของผู้ถือหุ้น** `w2` `PUB`

- **ตรวจอะไร:** คำนวณสัดส่วนระหว่างยอดเงินลูกค้าที่บริษัทถือไว้ตามงบ กับส่วนของผู้ถือหุ้น เพื่อดูว่าทุนของบริษัทเล็กเพียงใดเมื่อเทียบกับเงินที่ต้องดูแล สัดส่วนนี้ไม่ใช่คำตัดสินว่าบริษัทดีหรือไม่ดี แต่บอกขนาดของกันชนที่มีอยู่ ต้องหาบรรทัดยอดเงินลูกค้าให้เจอทั้งฝั่งสินทรัพย์และฝั่งหนี้สิน แล้วบันทึกชื่อบรรทัดตามที่งบใช้จริง
- **ขั้นตอนการตรวจ:**
  1. ค้นในงบด้วยคำว่า `client money` `client funds` `segregated` `เงินลูกค้า` `บัญชีแยก` บันทึกทุกบรรทัดและเลขหน้าที่พบ
  2. คัดลอกยอดเงินลูกค้าฝั่งสินทรัพย์และฝั่งหนี้สินลงตาราง พร้อมชื่อบรรทัดตามที่งบใช้
  3. เปิดหมายเหตุประกอบงบที่อธิบายบรรทัดนั้น แล้วคัดลอกเนื้อหาทั้งข้อ
  4. นำยอดส่วนของผู้ถือหุ้นจากข้อ 131 มาวางเทียบ แล้วคำนวณสัดส่วนเงินลูกค้าต่อส่วนของผู้ถือหุ้น
  5. ตรวจว่ายอดฝั่งสินทรัพย์กับฝั่งหนี้สินเท่ากันหรือไม่ ถ้าต่างให้บันทึกส่วนต่างและคำอธิบายที่หมายเหตุให้ไว้
  6. บันทึกตารางคำนวณพร้อมภาพหลักฐาน และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพบรรทัดยอดเงินลูกค้าทั้งสองฝั่งพร้อมเลขหน้า (`RST-BRKA-P02-136-01`) · ภาพหมายเหตุประกอบงบที่อธิบายบรรทัดนั้น (`RST-BRKA-P02-136-02`) · ตารางคำนวณสัดส่วน
- **ผ่าน:** งบแสดงยอดเงินลูกค้าที่บริษัทถือไว้เป็นบรรทัดที่ระบุได้ และยอดฝั่งสินทรัพย์กับฝั่งหนี้สินตรงกัน หรือต่างแต่มีคำอธิบายในหมายเหตุประกอบงบ
- **ไม่ผ่าน:** ยอดเงินลูกค้าฝั่งสินทรัพย์ต่ำกว่าฝั่งหนี้สินโดยไม่มีคำอธิบายใดในหมายเหตุประกอบงบ
- **ยังไม่ได้ตรวจ:** งบไม่แสดงยอดเงินลูกค้าเป็นบรรทัดแยก และหมายเหตุประกอบงบไม่กล่าวถึง
- **ตัวอย่าง:** งบของ Broker C แสดงหนี้สินต่อลูกค้าสูงกว่าสินทรัพย์ที่เป็นเงินลูกค้าในบัญชีแยก โดยหมายเหตุประกอบงบไม่มีข้อใดอธิบายส่วนต่างนี้ → **ไม่ผ่าน**

**P02-137 · สินทรัพย์สภาพคล่องเพียงพอต่อหนี้สินหมุนเวียนหรือไม่** `w2` `PUB`

- **ตรวจอะไร:** คำนวณอัตราส่วนสภาพคล่องจากงบแสดงฐานะการเงิน โดยเทียบสินทรัพย์หมุนเวียนกับหนี้สินหมุนเวียน แล้วคำนวณซ้ำอีกครั้งโดยนับเฉพาะเงินสดและรายการเทียบเท่าเงินสด เพราะบริษัทที่มีสินทรัพย์หมุนเวียนส่วนใหญ่เป็นลูกหนี้จากบริษัทในเครือ อาจมีสภาพคล่องจริงต่ำกว่าที่อัตราส่วนแรกแสดง บันทึกทั้งสองค่าและวิธีคำนวณ
- **ขั้นตอนการตรวจ:**
  1. บันทึกยอดรวมสินทรัพย์หมุนเวียนและหนี้สินหมุนเวียนจากงบแสดงฐานะการเงิน พร้อมเลขหน้า
  2. คัดลอกทุกบรรทัดย่อยในสินทรัพย์หมุนเวียนลงตาราง พร้อมยอดของแต่ละบรรทัด
  3. คำนวณอัตราส่วนสินทรัพย์หมุนเวียนต่อหนี้สินหมุนเวียน แล้วบันทึกวิธีคำนวณ
  4. คำนวณซ้ำโดยใช้เฉพาะเงินสดและรายการเทียบเท่าเงินสดเป็นตัวตั้ง แล้วบันทึกค่าที่ได้
  5. ทำเครื่องหมายทุกบรรทัดในสินทรัพย์หมุนเวียนที่เป็นลูกหนี้จากบุคคลหรือกิจการที่เกี่ยวข้องกัน โดยอ้างหมายเหตุประกอบงบ
  6. บันทึกทั้งสองอัตราส่วนพร้อมภาพหลักฐาน และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้างบแสดงฐานะการเงินส่วนสินทรัพย์และหนี้สินหมุนเวียน (`RST-BRKA-P02-137-01`) · ตารางบรรทัดย่อยพร้อมเครื่องหมายรายการที่เกี่ยวข้องกัน · ตารางคำนวณสองอัตราส่วน
- **ผ่าน:** สินทรัพย์หมุนเวียนสูงกว่าหนี้สินหมุนเวียน ณ วันสิ้นรอบบัญชีล่าสุด
- **ไม่ผ่าน:** หนี้สินหมุนเวียนสูงกว่าสินทรัพย์หมุนเวียน ณ วันสิ้นรอบบัญชีล่าสุด
- **ยังไม่ได้ตรวจ:** งบไม่แยกสินทรัพย์และหนี้สินเป็นหมุนเวียนกับไม่หมุนเวียน และหมายเหตุประกอบงบไม่ให้ข้อมูลพอที่จะแยกได้
- **ตัวอย่าง:** งบของ Broker A แสดงสินทรัพย์หมุนเวียนสูงกว่าหนี้สินหมุนเวียนเล็กน้อย แต่เมื่อคำนวณโดยใช้เฉพาะเงินสดพบว่าต่ำกว่ามาก เพราะสินทรัพย์หมุนเวียนส่วนใหญ่เป็นลูกหนี้จากบริษัทในเครือ ข้อนี้ยังตัดสินตามเกณฑ์แรกว่า → **ผ่าน** แต่ต้องบันทึกข้อสังเกตส่งต่อไปข้อ 139

**P02-138 · ผลประกอบการย้อนหลังสามปีขาดทุนต่อเนื่องหรือไม่** `w2` `PUB`

- **ตรวจอะไร:** ดูแนวโน้มกำไรขาดทุนย้อนหลังสามรอบบัญชีจากงบกำไรขาดทุนที่หาได้ เพราะบริษัทที่ขาดทุนติดต่อกันจะกัดกินส่วนของผู้ถือหุ้นลงเรื่อย ๆ จนกระทบความสามารถในการคืนเงินลูกค้า บันทึกกำไรหรือขาดทุนสุทธิของแต่ละปี รายได้รวมของแต่ละปี และคำนวณแนวโน้ม ถ้าหางบได้ไม่ครบสามปี ให้บันทึกจำนวนปีที่หาได้จริง
- **ขั้นตอนการตรวจ:**
  1. ดาวน์โหลดงบการเงินย้อนหลังให้ได้มากที่สุดเท่าที่แหล่งสาธารณะจากข้อ 126 มี บันทึกปีของแต่ละฉบับ
  2. บันทึกกำไรหรือขาดทุนสุทธิและรายได้รวมของแต่ละปีลงตาราง พร้อมเลขหน้าที่อ้างอิง
  3. ใช้ตัวเลขปีเปรียบเทียบในงบแต่ละฉบับเพื่อเติมปีที่ขาด แล้วทำเครื่องหมายว่าตัวเลขใดมาจากคอลัมน์เปรียบเทียบ
  4. ตรวจว่าตัวเลขปีเดียวกันจากคนละฉบับตรงกันหรือไม่ ถ้าต่างให้บันทึกส่วนต่างและคำอธิบายที่งบให้ไว้
  5. คำนวณจำนวนปีที่ขาดทุนติดต่อกันจนถึงปีล่าสุด แล้วบันทึกผล
  6. บันทึกตารางสามปีพร้อมภาพหลักฐานทุกฉบับ และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ไฟล์งบย้อนหลังทุกฉบับที่ได้ (`RST-BRKA-P02-138-01` เป็นต้นไป) · ภาพหน้างบกำไรขาดทุนแต่ละปี · ตารางสามปีพร้อมแหล่งอ้างอิงเลขหน้า
- **ผ่าน:** ผลประกอบการไม่ได้ขาดทุนติดต่อกันครบสามรอบบัญชีล่าสุด หรือขาดทุนแต่ส่วนของผู้ถือหุ้นยังเป็นบวกและมีหมายเหตุอธิบายแหล่งเงินทุนสนับสนุน
- **ไม่ผ่าน:** ขาดทุนสุทธิติดต่อกันครบสามรอบบัญชีล่าสุด และส่วนของผู้ถือหุ้นลดลงทุกปีโดยไม่มีคำอธิบายในหมายเหตุประกอบงบ
- **ยังไม่ได้ตรวจ:** หางบได้น้อยกว่าสองรอบบัญชี จึงยังดูแนวโน้มไม่ได้
- **ตัวอย่าง:** งบของ Broker B สามฉบับล่าสุดแสดงขาดทุนสุทธิทุกปี ส่วนของผู้ถือหุ้นลดลงต่อเนื่องทั้งสามปี และไม่มีหมายเหตุใดกล่าวถึงแผนเพิ่มทุนหรือการสนับสนุนจากผู้ถือหุ้น → **ไม่ผ่าน**

**P02-139 · รายการกับบุคคลหรือกิจการที่เกี่ยวข้องกัน มีนัยสำคัญต่อฐานะการเงินหรือไม่** `w2` `PUB`

- **ตรวจอะไร:** อ่านหมายเหตุประกอบงบเรื่องรายการกับบุคคลหรือกิจการที่เกี่ยวข้องกัน แล้วบันทึกยอดเงินให้กู้ยืม ลูกหนี้ เจ้าหนี้ และค่าบริการที่จ่ายให้บริษัทในกลุ่ม เพราะเงินที่ไหลออกไปยังบริษัทในเครือคือช่องทางที่ทำให้ทุนของนิติบุคคลคู่สัญญาบางลงโดยไม่ปรากฏเป็นขาดทุน บันทึกทุกรายการพร้อมชื่อคู่สัญญาที่หมายเหตุระบุ
- **ขั้นตอนการตรวจ:**
  1. ค้นในงบด้วยคำว่า `related part` `intercompany` `รายการกับบุคคลที่เกี่ยวข้อง` `กิจการที่เกี่ยวข้องกัน` บันทึกเลขหน้าที่พบ
  2. คัดลอกตารางรายการทั้งหมดในหมายเหตุนั้นลงตารางบันทึก พร้อมชื่อคู่สัญญาและลักษณะความสัมพันธ์
  3. แยกรายการเป็นสองกลุ่ม คือ ยอดคงค้าง ณ วันสิ้นรอบบัญชี กับ รายการที่เกิดขึ้นระหว่างปี
  4. คำนวณสัดส่วนยอดลูกหนี้จากกิจการที่เกี่ยวข้องกันเทียบกับสินทรัพย์รวม แล้วบันทึกวิธีคำนวณ
  5. ตรวจว่าหมายเหตุระบุเงื่อนไขของรายการหรือไม่ (มีหลักประกันหรือไม่ · มีกำหนดชำระคืนหรือไม่ · คิดดอกเบี้ยหรือไม่) บันทึกทุกข้อที่ระบุและที่ไม่ระบุ
  6. บันทึกผลลงตารางพร้อมภาพหน้าหมายเหตุ และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าหมายเหตุรายการกับกิจการที่เกี่ยวข้องกันทุกหน้า (`RST-BRKA-P02-139-01` เป็นต้นไป) · ตารางบันทึกรายการพร้อมชื่อคู่สัญญา · ตารางคำนวณสัดส่วน
- **ผ่าน:** งบเปิดเผยรายการกับกิจการที่เกี่ยวข้องกันครบถ้วน โดยระบุชื่อคู่สัญญา ยอดเงิน และเงื่อนไขการชำระคืนของยอดคงค้างทุกรายการ
- **ไม่ผ่าน:** งบแสดงยอดลูกหนี้หรือเงินให้กู้ยืมแก่กิจการที่เกี่ยวข้องกัน โดยไม่ระบุเงื่อนไขการชำระคืนหรือไม่ระบุว่ามีหลักประกันหรือไม่
- **ยังไม่ได้ตรวจ:** งบไม่มีหมายเหตุเรื่องรายการกับกิจการที่เกี่ยวข้องกัน และค้นทั้งไฟล์แล้วไม่พบคำที่เกี่ยวข้อง
- **ตัวอย่าง:** หมายเหตุของ Broker A แสดงเงินให้กู้ยืมแก่บริษัทในกลุ่มเป็นสัดส่วนสูงของสินทรัพย์รวม โดยระบุเพียงว่า "ไม่มีกำหนดชำระคืน" และไม่กล่าวถึงหลักประกันใด → **ไม่ผ่าน**

**P02-140 · โครงสร้างรายได้บอกได้หรือไม่ว่าโบรกเป็นคู่สัญญากับลูกค้าเอง** `w1` `PUB`

- **ตรวจอะไร:** อ่านหมายเหตุประกอบงบเรื่องรายได้ แล้วแยกว่ารายได้ของบริษัทมาจากค่าคอมมิชชันและค่าธรรมเนียม หรือมาจากกำไรจากการเป็นคู่สัญญากับลูกค้าโดยตรง เพราะสัดส่วนนี้บอกว่าโบรกได้เงินเมื่อลูกค้าเทรด หรือได้เงินเมื่อลูกค้าขาดทุน ซึ่งเป็นข้อมูลที่ลูกค้าควรรู้ก่อนตัดสินใจฝากเงิน บันทึกทุกบรรทัดรายได้พร้อมชื่อบรรทัดตามที่งบใช้จริง
- **ขั้นตอนการตรวจ:**
  1. เปิดหมายเหตุประกอบงบเรื่องรายได้ บันทึกเลขหน้า แล้วคัดลอกทุกบรรทัดพร้อมยอดเงิน
  2. จำแนกแต่ละบรรทัดลงสามกลุ่ม คือ ค่าคอมมิชชันและค่าธรรมเนียม · กำไรจากการซื้อขายกับลูกค้า · รายได้อื่น
  3. บันทึกบรรทัดที่จำแนกไม่ได้ไว้แยกต่างหาก พร้อมชื่อบรรทัดตามงบ
  4. คำนวณสัดส่วนของแต่ละกลุ่มต่อรายได้รวม แล้วบันทึกวิธีคำนวณ
  5. ค้นบนเว็บโบรกด้วยคำว่า `dealing on own account` `market maker` `principal` `คู่สัญญา` `ผู้ดูแลสภาพคล่อง` เพื่อดูว่าโบรกเปิดเผยรูปแบบธุรกิจนี้ต่อลูกค้าหรือไม่
  6. บันทึกตารางสัดส่วนพร้อมภาพหลักฐานทั้งสองฝั่ง และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าหมายเหตุเรื่องรายได้พร้อมเลขหน้า (`RST-BRKA-P02-140-01`) · ภาพหน้าเว็บที่กล่าวถึงรูปแบบธุรกิจ (`RST-BRKA-P02-140-02`) · ตารางจำแนกรายได้พร้อมสัดส่วน
- **ผ่าน:** หมายเหตุประกอบงบแยกรายได้ละเอียดพอที่จะจำแนกได้ว่ากลุ่มใดมาจากการเป็นคู่สัญญากับลูกค้า และเว็บโบรกเปิดเผยรูปแบบธุรกิจนี้ในหน้าที่ลูกค้าเข้าถึงได้
- **ไม่ผ่าน:** หมายเหตุแสดงว่ารายได้ส่วนใหญ่มาจากการเป็นคู่สัญญากับลูกค้า แต่เว็บโบรกไม่มีข้อความใดเปิดเผยรูปแบบธุรกิจนี้
- **ยังไม่ได้ตรวจ:** งบแสดงรายได้เป็นยอดรวมบรรทัดเดียวโดยไม่มีหมายเหตุแยกประเภท
- **ตัวอย่าง:** หมายเหตุของ Broker C แสดงว่ารายได้เกือบทั้งหมดมาจากกำไรจากการซื้อขายกับลูกค้า ขณะที่เว็บทุกหน้าใช้คำว่า "โบรกเกอร์ที่ส่งคำสั่งเข้าตลาดโดยตรง" และไม่มีหน้าใดกล่าวถึงการเป็นคู่สัญญา → **ไม่ผ่าน**

**P02-141 · หมายเหตุประกอบงบเปิดเผยคดีความหรือค่าปรับจากหน่วยงานหรือไม่** `w2` `PUB+REG`

- **ตรวจอะไร:** อ่านหมายเหตุประกอบงบเรื่องคดีความและหนี้สินที่อาจเกิดขึ้น แล้วบันทึกทุกคดีและทุกค่าปรับที่ระบุไว้ พร้อมยอดเงินและสถานะ จากนั้นค้นในหน้าประกาศคำสั่งลงโทษของหน่วยงานกำกับเพื่อดูว่ามีเรื่องที่หน่วยงานประกาศแต่ไม่ปรากฏในงบหรือไม่ ทั้งสองฝั่งเป็นแหล่งสาธารณะที่ลูกค้าเข้าถึงได้เอง
- **ขั้นตอนการตรวจ:**
  1. ค้นในไฟล์งบด้วยคำว่า `litigation` `contingent` `penalty` `fine` `คดีความ` `ค่าปรับ` `หนี้สินที่อาจเกิดขึ้น` บันทึกเลขหน้าที่พบ
  2. คัดลอกเนื้อหาหมายเหตุที่เกี่ยวข้องทั้งข้อ พร้อมยอดเงินและสถานะของแต่ละเรื่อง
  3. เข้าเว็บทางการของหน่วยงานกำกับด้วยตนเอง หาหน้าประกาศคำสั่งลงโทษหรือข่าวการบังคับใช้กฎหมาย
  4. ค้นด้วยชื่อนิติบุคคลคู่สัญญาแบบเต็มและด้วยคำหลักคำเดียวของชื่อ บันทึกทุกรายการที่พบพร้อมวันที่
  5. ทำตารางเทียบสองคอลัมน์ (เรื่องที่งบเปิดเผย · เรื่องที่หน่วยงานประกาศ) แล้วทำเครื่องหมายเรื่องที่ปรากฏฝั่งเดียว
  6. จับภาพทุกหน้าที่เกี่ยวข้อง เก็บสำเนา PDF ถาวร และบันทึกผลตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าหมายเหตุเรื่องคดีความและหนี้สินที่อาจเกิดขึ้น (`RST-BRKA-P02-141-01`) · ภาพหน้าประกาศคำสั่งลงโทษบนเว็บหน่วยงาน (`RST-BRKA-P02-141-02`) · ตารางเทียบสองคอลัมน์
- **ผ่าน:** ทุกเรื่องที่หน่วยงานกำกับประกาศในรอบบัญชีของงบ ปรากฏในหมายเหตุประกอบงบด้วย หรือไม่มีเรื่องใดในทั้งสองฝั่ง
- **ไม่ผ่าน:** หน่วยงานกำกับประกาศคำสั่งลงโทษหรือค่าปรับที่เกิดในรอบบัญชีของงบ แต่หมายเหตุประกอบงบไม่กล่าวถึงเรื่องนั้นเลย
- **ยังไม่ได้ตรวจ:** หน่วยงานกำกับไม่เผยแพร่คำสั่งลงโทษต่อสาธารณะ จึงไม่มีฝั่งให้เทียบ
- **ตัวอย่าง:** เว็บหน่วยงานกำกับประกาศค่าปรับกรณีบกพร่องเรื่องการแยกบัญชีเงินลูกค้าในรอบบัญชีเดียวกับงบฉบับล่าสุดของ Broker B แต่ค้นทั้งไฟล์งบแล้วไม่มีหมายเหตุใดกล่าวถึงเรื่องนี้ → **ไม่ผ่าน**

**P02-142 · มีการเปลี่ยนผู้สอบบัญชีในช่วงสามรอบบัญชีล่าสุดหรือไม่** `w1` `PUB`

- **ตรวจอะไร:** เทียบชื่อสำนักงานสอบบัญชีที่ลงนามในงบแต่ละปีที่หาได้ เพราะการเปลี่ยนผู้สอบบัญชีบ่อยผิดปกติเป็นสัญญาณที่ควรบันทึกไว้ประกอบการอ่านงบ ต้องบันทึกชื่อสำนักงานของทุกปี วันที่ลงนามของทุกปี และค้นว่ามีคำอธิบายเหตุผลการเปลี่ยนในงบหรือในประกาศของบริษัทหรือไม่ ห้ามตีความว่าการเปลี่ยนผู้สอบบัญชีคือความผิดในตัวเอง
- **ขั้นตอนการตรวจ:**
  1. เปิดไฟล์งบทุกฉบับที่ได้จากข้อ 138 แล้วบันทึกชื่อสำนักงานสอบบัญชีที่ลงนามในแต่ละฉบับ
  2. บันทึกวันที่ลงนามและชื่อผู้ลงนามของแต่ละปีลงตารางเรียงตามปี
  3. ทำเครื่องหมายทุกปีที่ชื่อสำนักงานเปลี่ยนจากปีก่อนหน้า แล้วนับจำนวนครั้งที่เปลี่ยน
  4. ค้นในงบด้วยคำว่า `change of auditor` `resignation` `เปลี่ยนผู้สอบบัญชี` `ลาออก` บันทึกทุกข้อความที่พบ
  5. ค้นบนเว็บโบรกและหน้าประกาศของนายทะเบียนว่ามีการแจ้งเปลี่ยนผู้สอบบัญชีพร้อมเหตุผลหรือไม่ บันทึกผล
  6. บันทึกตารางรายปีพร้อมภาพหลักฐาน และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าลงนามผู้สอบบัญชีของทุกปีที่ได้ (`RST-BRKA-P02-142-01` เป็นต้นไป) · ตารางรายปี (ปี · ชื่อสำนักงาน · ชื่อผู้ลงนาม · วันที่ลงนาม) · ภาพประกาศเปลี่ยนผู้สอบบัญชีถ้ามี
- **ผ่าน:** ไม่มีการเปลี่ยนสำนักงานสอบบัญชีในสามรอบบัญชีล่าสุด หรือมีการเปลี่ยนแต่มีคำอธิบายเหตุผลในงบหรือในประกาศสาธารณะ
- **ไม่ผ่าน:** เปลี่ยนสำนักงานสอบบัญชีตั้งแต่ [เกณฑ์เสนอ: 2 ครั้งขึ้นไปในสามรอบบัญชีล่าสุด] โดยไม่มีคำอธิบายเหตุผลในแหล่งสาธารณะใด
- **ยังไม่ได้ตรวจ:** หางบได้น้อยกว่าสองรอบบัญชี จึงยังเทียบชื่อผู้สอบบัญชีไม่ได้
- **ตัวอย่าง:** งบสามฉบับล่าสุดของ Broker A ลงนามโดยสำนักงานสอบบัญชี Y คนละแห่งทั้งสามปี และค้นทั้งงบ เว็บโบรก และประกาศของนายทะเบียนแล้วไม่พบคำอธิบายใด → **ไม่ผ่าน**

**P02-143 ● · งบที่โบรกเผยแพร่เอง ตรงกับฉบับที่นายทะเบียนหรือหน่วยงานเผยแพร่หรือไม่** `w3` `PUB+REG`

- **ตรวจอะไร:** ถ้าหางบได้จากสองแหล่งขึ้นไป ต้องเทียบว่าเป็นฉบับเดียวกันหรือไม่ โดยเทียบตัวเลขหลักห้าบรรทัด คือ สินทรัพย์รวม · หนี้สินรวม · ส่วนของผู้ถือหุ้น · รายได้รวม · กำไรหรือขาดทุนสุทธิ พร้อมเทียบวันสิ้นรอบบัญชีและวันที่ผู้สอบบัญชีลงนาม เพราะไฟล์ที่โบรกเผยแพร่เองอาจเป็นฉบับที่ตัดทอนหรือเป็นคนละฉบับกับที่ยื่นต่อนายทะเบียน

- **ยังไม่ได้ตรวจ:** เว็บไม่แสดงตัวเลขขนาดกิจการใด หรือข้อ 126 ไม่พบงบการเงิน
- **ตัวอย่าง:** หน้าแรกของ Broker C แสดงว่ามีลูกค้าหลายล้านรายทั่วโลกโดยไม่ระบุนิติบุคคล ขณะที่งบของนิติบุคคลคู่สัญญาแสดงหนี้สินต่อลูกค้าที่คำนวณเฉลี่ยแล้วเหลือหลักไม่กี่หน่วยต่อราย และไม่มีข้อความใดอธิบายว่าตัวเลขบนหน้าแรกเป็นของทั้งกลุ่ม → **ไม่ผ่าน**

**P02-148 · การยื่นงบการเงินต่อนายทะเบียนเป็นไปตามกำหนดเวลาหรือล่าช้า** `w1` `REG`

- **ตรวจอะไร:** ตรวจว่านิติบุคคลคู่สัญญายื่นงบการเงินต่อนายทะเบียนตรงตามกำหนดหรือยื่นล่าช้า โดยเทียบวันที่นายทะเบียนรับงบกับกำหนดเวลาที่กฎหมายของเขตอำนาจนั้นกำหนด บันทึกวันที่รับงบของทุกปีที่หาได้ และบันทึกทุกปีที่ไม่มีงบยื่นเลย เพราะประวัติการยื่นล่าช้าเป็นสัญญาณเรื่องวินัยการรายงานที่ลูกค้าตรวจสอบได้จากแหล่งสาธารณะ
- **ขั้นตอนการตรวจ:**
  1. เปิดหน้ารายการของนิติบุคคลคู่สัญญาในนายทะเบียนบริษัท แล้วเปิดส่วนประวัติการยื่นเอกสาร
  2. บันทึกวันที่นายทะเบียนรับงบของทุกรอบบัญชีที่ปรากฏ ลงตารางเรียงตามปี
  3. หาหน้ากำหนดเวลายื่นงบบนเว็บของนายทะเบียน คัดลอกกำหนดเวลาแบบคำต่อคำพร้อม URL
  4. คำนวณจำนวนวันจากวันสิ้นรอบบัญชีถึงวันที่นายทะเบียนรับงบของแต่ละปี แล้วเทียบกับกำหนดเวลา
  5. ทำเครื่องหมายทุกปีที่ยื่นเกินกำหนด และทุกรอบบัญชีที่ไม่ปรากฏการยื่นเลย
  6. จับภาพหน้าประวัติการยื่นและหน้ากำหนดเวลา เก็บสำเนา และบันทึกผลตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าประวัติการยื่นเอกสารในนายทะเบียน (`RST-BRKA-P02-148-01`) · ภาพหน้ากำหนดเวลายื่นบนเว็บนายทะเบียนพร้อม URL (`RST-BRKA-P02-148-02`) · ตารางคำนวณรายปี
- **ผ่าน:** ทุกรอบบัญชีในสามปีล่าสุดมีการยื่นงบต่อนายทะเบียนภายในกำหนดเวลาที่นายทะเบียนประกาศ
- **ไม่ผ่าน:** มีรอบบัญชีอย่างน้อย 1 รอบในสามปีล่าสุดที่ยื่นเกินกำหนด หรือไม่ปรากฏการยื่นเลย
- **ยังไม่ได้ตรวจ:** นายทะเบียนไม่แสดงประวัติการยื่นเอกสาร หรือไม่เผยแพร่กำหนดเวลายื่นต่อสาธารณะ
- **ตัวอย่าง:** ประวัติการยื่นของ Broker A ในนายทะเบียนแสดงว่ารอบบัญชีล่าสุดยังไม่มีงบยื่น ทั้งที่พ้นกำหนดที่นายทะเบียนประกาศมาแล้วสี่เดือน → **ไม่ผ่าน**

**P02-149 · หนี้สินที่อาจเกิดขึ้นและภาระผูกพันนอกงบดุล ถูกเปิดเผยเป็นตัวเลขหรือไม่** `w2` `PUB`

- **ตรวจอะไร:** อ่านหมายเหตุประกอบงบเรื่องภาระผูกพันและหนี้สินที่อาจเกิดขึ้น แล้วบันทึกทุกรายการพร้อมยอดเงิน เช่น สัญญาเช่าระยะยาว การค้ำประกันที่บริษัทออกให้ผู้อื่น และภาระจากตราสารอนุพันธ์ เพราะรายการเหล่านี้ไม่ปรากฏในงบแสดงฐานะการเงินแต่กระทบความสามารถในการคืนเงินลูกค้าได้จริง บันทึกทุกรายการที่ระบุยอดเงินและทุกรายการที่ระบุว่าไม่อาจประมาณได้
- **ขั้นตอนการตรวจ:**
  1. ค้นในไฟล์งบด้วยคำว่า `commitment` `contingent liabilit` `off-balance` `ภาระผูกพัน` `หนี้สินที่อาจเกิดขึ้น` บันทึกเลขหน้าที่พบ
  2. คัดลอกทุกรายการในหมายเหตุนั้นลงตาราง พร้อมยอดเงินและลักษณะของภาระ
  3. ทำเครื่องหมายรายการที่งบระบุว่า "ไม่อาจประมาณจำนวนได้" แล้วนับจำนวนรายการนั้น
  4. คำนวณยอดรวมของรายการที่มีตัวเลข แล้วเทียบกับส่วนของผู้ถือหุ้นจากข้อ 131 บันทึกสัดส่วน
  5. ตรวจว่ามีการค้ำประกันที่บริษัทออกให้บริษัทในเครือหรือไม่ ถ้ามีให้บันทึกชื่อผู้รับประโยชน์และวงเงิน
  6. บันทึกผลลงตารางพร้อมภาพหน้าหมายเหตุ และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าหมายเหตุเรื่องภาระผูกพันและหนี้สินที่อาจเกิดขึ้นทุกหน้า (`RST-BRKA-P02-149-01` เป็นต้นไป) · ตารางบันทึกรายการพร้อมยอดเงิน · ตารางคำนวณสัดส่วนต่อส่วนของผู้ถือหุ้น
- **ผ่าน:** งบมีหมายเหตุเรื่องภาระผูกพันและหนี้สินที่อาจเกิดขึ้น โดยระบุยอดเงินของทุกรายการ หรือระบุเหตุผลที่ประมาณจำนวนไม่ได้เป็นรายรายการ
- **ไม่ผ่าน:** งบกล่าวถึงภาระผูกพันหรือหนี้สินที่อาจเกิดขึ้นโดยไม่ระบุยอดเงินและไม่อธิบายเหตุผลที่ประมาณไม่ได้แม้แต่รายการเดียว
- **ยังไม่ได้ตรวจ:** งบไม่มีหมายเหตุเรื่องนี้ และค้นทั้งไฟล์แล้วไม่พบคำที่เกี่ยวข้อง
- **ตัวอย่าง:** หมายเหตุของ Broker B ระบุว่าบริษัทออกหนังสือค้ำประกันให้บริษัทในเครือหลายฉบับ แต่ไม่ระบุวงเงินของฉบับใดเลย และไม่มีข้อความอธิบายว่าเหตุใดจึงประมาณจำนวนไม่ได้ → **ไม่ผ่าน**

**P02-150 ● · ตัวเลขฐานะการเงินที่โบรกใช้สื่อสาร สอดคล้องกันทุกแหล่งสาธารณะหรือไม่** `w3` `WEB+PUB+SUP`

- **ตรวจอะไร:** ข้อปิดท้ายหมวดนี้เป็นการตรวจความสอดคล้องข้ามแหล่ง โดยรวบรวมตัวเลขฐานะการเงินของนิติบุคคลคู่สัญญาจากทุกแหล่งที่ลูกค้ารายย่อยเข้าถึงได้ คือ เว็บโบรก · งบการเงิน · ทะเบียนหน่วยงานกำกับ · นายทะเบียนบริษัท · และคำตอบของฝ่ายบริการ แล้วชี้ว่าแหล่งใดขัดกันบ้าง เพราะความไม่สอดคล้องระหว่างสิ่งที่โบรกบอกลูกค้ากับสิ่งที่เอกสารทางการระบุ คือสัญญาณที่ลูกค้าตรวจสอบได้เองโดยไม่ต้องเป็นผู้เชี่ยวชาญ
- **ขั้นตอนการตรวจ:**
  1. รวบรวมตัวเลขห้าตัวจากทุกแหล่งที่บันทึกไว้ในข้อ 126–149 คือ ส่วนของผู้ถือหุ้น · ทุนที่ชำระแล้ว · อัตราส่วนเงินกองทุน · ยอดเงินลูกค้าที่ถือไว้ · กำไรหรือขาดทุนสุทธิ
  2. จัดลงตารางหนึ่งแถวต่อหนึ่งตัวเลข และหนึ่งคอลัมน์ต่อหนึ่งแหล่ง พร้อมวันที่ของตัวเลขทุกช่อง
  3. ส่งคำถามถึงฝ่ายบริการผ่านช่องทางลูกค้าปกติ ในฐานะลูกค้าที่ถามว่า "บริษัทที่ถือเงินของฉันมีทุนเท่าไร และดูงบการเงินได้ที่ไหน" บันทึกเวลาที่ส่งเป็นเวลา UTC
  4. บันทึกคำตอบของฝ่ายบริการแบบคำต่อคำพร้อมรหัสเคส แล้วเติมลงคอลัมน์สุดท้ายของตาราง
  5. ทำเครื่องหมายทุกช่องที่ขัดกับช่องอื่นในแถวเดียวกัน โดยไม่นับกรณีที่ต่างเพราะเป็นคนละวันที่ ให้บันทึกส่วนต่างแยกไว้
  6. สำหรับทุกความขัดแย้งที่พบ ให้ระบุว่าแหล่งใดเป็นแหล่งทางการและแหล่งใดเป็นคำกล่าวของโบรก
  7. เก็บสำเนาบทสนทนา ภาพหลักฐานทุกแหล่ง และบันทึกตารางสรุปตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางความสอดคล้องข้ามแหล่งฉบับสมบูรณ์ (`RST-BRKA-P02-150-01`) · สำเนาบทสนทนากับฝ่ายบริการพร้อมรหัสเคส (`RST-BRKA-P02-150-02`) · บันทึกเวลา UTC · ภาพหลักฐานอ้างอิงจากทุกแหล่งที่ใช้
- **ผ่าน:** ตัวเลขทุกตัวที่ปรากฏในสองแหล่งขึ้นไปสอดคล้องกัน หรือต่างกันเฉพาะเพราะเป็นคนละวันที่โดยมีวันที่กำกับให้เห็นทั้งสองฝั่ง
- **ไม่ผ่าน:** มีตัวเลขอย่างน้อย 1 ตัวที่คำกล่าวของโบรกหรือตัวเลขบนเว็บขัดกับเอกสารทางการสำหรับวันที่เดียวกัน โดยไม่มีคำอธิบายใด
- **ยังไม่ได้ตรวจ:** ข้อ 126 ไม่พบงบการเงิน และไม่มีแหล่งทางการใดให้ตัวเลขเทียบกับคำกล่าวของโบรก
- **ตัวอย่าง:** ฝ่ายบริการของ Broker A ตอบว่าบริษัทมีทุนจดทะเบียนหลักร้อยล้านและ "ฐานะการเงินแข็งแกร่งมาก" ขณะที่งบรอบบัญชีล่าสุดของนิติบุคคลคู่สัญญาแสดงส่วนของผู้ถือหุ้นติดลบ และเว็บแสดงตัวเลขทุนที่เป็นของบริษัทแม่โดยไม่ระบุ → **ไม่ผ่าน**
