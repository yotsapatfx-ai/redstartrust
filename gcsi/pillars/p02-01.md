## S01 · การประกาศแยกบัญชีเงินลูกค้า (001–025)

**P02-001 ● · เว็บไซต์มีคำประกาศแยกบัญชีเงินลูกค้าหรือไม่** `w3` `WEB` `G3`

- **ตรวจอะไร:** ตรวจว่าเว็บไซต์สาธารณะของโบรกมีข้อความที่ประกาศว่าเงินของลูกค้าถูกเก็บแยกจากเงินของบริษัทหรือไม่ โดยเปิดดูหน้าแรก · footer · หน้า About · หน้า Legal · หน้า Security / Fund Safety · หน้า Deposit / Funding · หน้า FAQ บันทึกข้อความที่พบแบบคำต่อคำ URL ของหน้าที่พบ และตำแหน่งบนหน้า ไม่นับข้อความกว้าง ๆ ว่า "เงินของคุณปลอดภัย" ที่ไม่มีคำว่าแยกบัญชีหรือคำที่มีความหมายเดียวกัน
- **ขั้นตอนการตรวจ:**
  1. เปิดเบราว์เซอร์โหมดไม่บันทึกประวัติ เข้าหน้าแรกของโบรกโดยพิมพ์โดเมนเอง **ห้ามเข้าผ่านลิงก์โฆษณาหรือลิงก์แนะนำ**
  2. จับภาพเต็มหน้าแรกพร้อมให้เห็น URL และนาฬิกาเครื่อง
  3. กด `Ctrl+F` ค้นทีละคำ: `segregat` `segregated account` `client money` `client funds` `แยกบัญชี` `บัญชีแยก` `เงินลูกค้า` บันทึกจำนวนที่พบต่อคำ
  4. เปิดหน้า About · Legal · Security · Fund Safety · Deposit · FAQ ทีละหน้า แล้วทำซ้ำขั้น 2–3 กับทุกหน้า
  5. คัดลอกข้อความทุกจุดที่พบลงตารางบันทึก พร้อม URL และตำแหน่ง (หัวข้อ/ย่อหน้า/footer)
  6. เก็บสำเนาถาวรของทุกหน้าที่พบข้อความ แล้วบันทึกผลและตั้งชื่อไฟล์ตามรูปแบบ Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพเต็มหน้าทุกหน้าที่เปิด (`RST-BRKA-P02-001-01` ถึง `-06`) · ตารางข้อความที่พบพร้อม URL · สำเนาถาวร (PDF) ของหน้าที่พบข้อความ
- **ผ่าน:** พบข้อความบนเว็บสาธารณะอย่างน้อย 1 จุดที่ระบุว่าเงินลูกค้าถูกเก็บแยกจากเงินของบริษัท โดยไม่ต้องล็อกอิน
- **ไม่ผ่าน:** ค้นครบทุกหน้าตามขั้นตอนแล้วไม่พบข้อความใดที่ระบุการแยกเงินลูกค้า
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง — เช่น เว็บล่มตลอดช่วงที่พยายามเข้า
- **ตัวอย่าง:** Broker A มีหน้า *Why Us* เขียนว่า *"เงินทุนของคุณได้รับการปกป้องด้วยมาตรฐานสูงสุด"* ค้นทั้งเว็บด้วยคำสำคัญทั้ง 7 คำแล้วไม่พบคำว่าแยกบัญชีหรือ segregated เลย → **ไม่ผ่าน** ตกด่าน G3

**P02-002 ● · คำประกาศระบุว่าแยกจาก "เงินของบริษัท" ชัดเจนหรือไม่** `w3` `WEB`

- **ตรวจอะไร:** อ่านข้อความคำประกาศที่พบในข้อ 001 ทีละจุด แล้วตรวจว่าข้อความนั้นระบุคู่เปรียบเทียบครบหรือไม่ คือบอกว่าเงินลูกค้าแยกจาก **เงินของบริษัท / เงินทุนหมุนเวียนของบริษัท / own funds / corporate funds** ไม่ใช่แยกจากสิ่งอื่นที่ไม่มีความหมาย เช่น "แยกตามสกุลเงิน" หรือ "แยกตามประเภทบัญชี" บันทึกคำที่ใช้แทน "เงินของบริษัท" ในแต่ละจุด
- **ขั้นตอนการตรวจ:**
  1. เปิดตารางข้อความจากข้อ 001
  2. อ่านข้อความเต็มประโยคของแต่ละจุด ห้ามอ่านเฉพาะคำสำคัญ
  3. บันทึกว่าประโยคนั้นบอกว่า "แยกจากอะไร" โดยคัดลอกคำนั้นมาแบบคำต่อคำ ถ้าไม่บอก ให้บันทึกว่า "ไม่ระบุคู่เปรียบเทียบ"
  4. จำแนกแต่ละจุดเป็น 3 กลุ่ม: แยกจากเงินบริษัท · แยกจากสิ่งอื่น · ไม่ระบุ
  5. จับภาพประโยคเต็มของทุกจุดให้เห็นบริบทรอบข้าง 2 บรรทัด
  6. บันทึกตารางจำแนกและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพประโยคเต็มทุกจุด (`RST-BRKA-P02-002-01` เป็นต้นไป) · ตารางจำแนก 3 กลุ่ม
- **ผ่าน:** มีอย่างน้อย 1 จุดที่ระบุชัดว่าเงินลูกค้าแยกจากเงินของบริษัทหรือคำที่มีความหมายเดียวกัน
- **ไม่ผ่าน:** ทุกจุดที่พบไม่ระบุคู่เปรียบเทียบ หรือระบุการแยกที่ไม่เกี่ยวกับการแยกจากเงินบริษัท
- **ยังไม่ได้ตรวจ:** ไม่พบข้อความใดจากข้อ 001 (ให้ผูกผลกับข้อ 001 และบันทึกเหตุผล)
- **ตัวอย่าง:** Broker B เขียนว่า *"บัญชีลูกค้าถูกแยกออกเป็นบัญชีย่อยตามสกุลเงินเพื่อความสะดวก"* เป็นการแยกภายในบัญชีเดียวกัน ไม่ได้บอกว่าแยกจากเงินบริษัท → **ไม่ผ่าน**

**P02-003 ● · คำประกาศอยู่ในจุดที่ลูกค้าเห็นก่อนตัดสินใจฝากเงินหรือไม่** `w2` `WEB+ACC`

- **ตรวจอะไร:** วัดว่าลูกค้าใหม่ต้องคลิกกี่ครั้งจากหน้าแรกจึงจะถึงคำประกาศแยกเงิน และตรวจว่าคำประกาศปรากฏอยู่ในเส้นทางสมัคร–ฝากเงินหรือซ่อนอยู่ในหน้าที่ต้องตั้งใจหาเท่านั้น บันทึกจำนวนคลิกที่สั้นที่สุด ชื่อเมนูที่ต้องกดตามลำดับ และตรวจว่าหน้าฝากเงินเองมีลิงก์หรือข้อความอ้างถึงคำประกาศหรือไม่
- **ขั้นตอนการตรวจ:**
  1. เปิดหน้าแรกในโหมดไม่บันทึกประวัติ แล้วไล่หาคำประกาศโดยใช้เมนูปกติเท่านั้น **ห้ามใช้ช่องค้นหาและห้ามพิมพ์ URL ตรง**
  2. นับจำนวนคลิกที่สั้นที่สุดที่ไปถึงคำประกาศ บันทึกชื่อเมนูทุกขั้นตามลำดับ
  3. ทำซ้ำจากหน้าสมัคร (Open Account) นับคลิกจากจุดนั้นถึงคำประกาศ
  4. เปิดหน้าฝากเงินในพอร์ทัลลูกค้า ค้นคำว่า `segregat` `client money` `แยกบัญชี` บันทึกว่าพบหรือไม่
  5. จับภาพทุกขั้นของเส้นทางที่คลิก พร้อม URL และนาฬิกาเครื่อง
  6. บันทึกจำนวนคลิก เส้นทางเมนู และผลการค้นในหน้าฝากเงิน ลงแบบฟอร์มพร้อมตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพทุกขั้นของเส้นทางคลิก (`RST-BRKA-P02-003-01` เป็นต้นไป) · ตารางเส้นทางเมนูพร้อมจำนวนคลิก · ภาพหน้าฝากเงินหลังค้นคำ
- **ผ่าน:** คำประกาศเข้าถึงได้ภายในจำนวนคลิกที่กำหนด `[เกณฑ์เสนอ: ไม่เกิน 3 คลิกจากหน้าแรก]` หรือปรากฏอยู่ในหน้าฝากเงิน
- **ไม่ผ่าน:** ต้องคลิกเกินเกณฑ์และหน้าฝากเงินไม่มีการอ้างถึงคำประกาศเลย
- **ยังไม่ได้ตรวจ:** ไม่พบคำประกาศบนเว็บ (ผลผูกกับข้อ 001)
- **ตัวอย่าง:** Broker C ซ่อนคำประกาศไว้ในข้อ 14.3 ของ Terms ที่ต้องคลิก 5 ครั้งจึงถึง และหน้าฝากเงินไม่มีคำใดกล่าวถึง → **ไม่ผ่าน**

**P02-004 ● · สัญญาลูกค้ามีข้อว่าด้วยการแยกเงินลูกค้าหรือไม่** `w3` `DOC` `G3`

- **ตรวจอะไร:** เปิดไฟล์ Client Agreement / Terms of Business ฉบับที่ระบบให้ระหว่างสมัคร แล้วค้นข้อสัญญาที่ว่าด้วยการเก็บรักษาเงินลูกค้า บันทึกเลขข้อ เลขหน้า และข้อความเต็มของข้อนั้น ถ้ามีเอกสารแยกชื่อ Client Money Policy หรือ Client Funds Protection ให้เก็บด้วยและบันทึกว่าเอกสารใดถูกอ้างถึงในสัญญาหลัก
- **ขั้นตอนการตรวจ:**
  1. ดาวน์โหลดเอกสารสัญญาทุกฉบับที่ระบบให้ตอนสมัคร บันทึกวันเวลาที่ดาวน์โหลดเป็นเวลา UTC
  2. เปิดไฟล์แล้วค้นทีละคำ: `segregat` `client money` `client funds` `safeguard` `trust account` `แยกบัญชี` `เงินของลูกค้า`
  3. บันทึกเลขข้อและเลขหน้าของทุกจุดที่พบ พร้อมคัดลอกข้อความเต็มของข้อนั้น
  4. ตรวจว่าสัญญาอ้างถึงเอกสารแยกฉบับใดหรือไม่ ถ้ามี ให้ดาวน์โหลดเอกสารนั้นและทำซ้ำขั้น 2–3
  5. จับภาพหน้าเอกสารที่มีข้อสัญญาให้เห็นเลขหน้าและเลขข้อในเฟรมเดียวกัน
  6. คำนวณ hash ของไฟล์ทุกฉบับ บันทึกลงทะเบียนหลักฐาน แล้วตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ไฟล์ PDF สัญญาทั้งฉบับ (`RST-BRKA-P02-004-01`) · ไฟล์นโยบายแยกฉบับถ้ามี (`-02`) · ภาพหน้าที่มีข้อสัญญาพร้อมเลขข้อ · ตาราง hash
- **ผ่าน:** พบข้อสัญญาอย่างน้อย 1 ข้อที่ระบุการเก็บเงินลูกค้าแยกจากเงินของบริษัท พร้อมเลขข้ออ้างอิงได้
- **ไม่ผ่าน:** ค้นครบทุกเอกสารที่ได้รับแล้วไม่พบข้อใดกล่าวถึงการแยกเงินลูกค้า
- **ยังไม่ได้ตรวจ:** ระบบไม่ให้เข้าถึงสัญญาก่อนฝากเงิน (ต้องบันทึกข้อเท็จจริงนี้ไว้)
- **ตัวอย่าง:** Broker A มีข้อความโฆษณาเรื่องแยกบัญชีบนหน้าเว็บ แต่ค้นในสัญญา 42 หน้าที่ให้เซ็นแล้วไม่มีข้อใดกล่าวถึงเลย → **ไม่ผ่าน** ตกด่าน G3

**P02-005 · ถ้อยคำในสัญญากับถ้อยคำบนเว็บสอดคล้องกันหรือไม่** `w2` `DOC+WEB`

- **ตรวจอะไร:** วางข้อความคำประกาศบนเว็บ (ข้อ 001–002) คู่กับข้อสัญญา (ข้อ 004) แล้วเทียบสาระ 4 ประเด็น: แยกจากอะไร · เก็บไว้ที่ใด · ใครเป็นผู้ถือ · มีข้อยกเว้นหรือไม่ บันทึกทุกประเด็นที่เว็บพูดแต่สัญญาไม่พูด และทุกประเด็นที่สัญญาพูดแต่เว็บไม่พูด
- **ขั้นตอนการตรวจ:**
  1. คัดลอกข้อความจากเว็บและจากสัญญาเป็นข้อความล้วน ห้ามพิมพ์เอง
  2. สร้างตาราง 2 คอลัมน์ (เว็บ / สัญญา) และ 4 แถวตามประเด็นข้างต้น
  3. เติมข้อความจริงลงแต่ละช่อง ช่องใดไม่มีข้อมูลให้เขียนว่า "ไม่ระบุ"
  4. ทำเครื่องหมายทุกแถวที่สองคอลัมน์ให้สาระต่างกัน หรือคอลัมน์หนึ่งว่างอีกคอลัมน์ไม่ว่าง
  5. อ่านซ้ำเฉพาะแถวที่ต่างกัน แล้วบันทึกว่าความต่างนั้นทำให้ระดับการคุ้มครองที่ลูกค้าเข้าใจต่างกันหรือไม่
  6. บันทึกตารางเทียบพร้อมภาพทั้งสองแหล่งวางคู่กัน และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางเทียบ 4 ประเด็น · ภาพเทียบคู่เว็บ–สัญญา (`RST-BRKA-P02-005-01`)
- **ผ่าน:** ทั้งสี่ประเด็นสอดคล้องกัน หรือต่างเฉพาะรายละเอียดที่ไม่เปลี่ยนระดับการคุ้มครองที่ลูกค้าเข้าใจ
- **ไม่ผ่าน:** มีอย่างน้อย 1 ประเด็นที่เว็บให้ภาพการคุ้มครองสูงกว่าที่สัญญาผูกพันไว้จริง
- **ยังไม่ได้ตรวจ:** ขาดข้อมูลจากฝั่งใดฝั่งหนึ่ง (ผลผูกกับข้อ 001 และ 004)

- **ผ่าน:** ไม่มีคำรับประกันเด็ดขาด หรือมีแต่มีข้อสัญญารองรับและมีคำกำกับความหมายในหน้าเดียวกัน
- **ไม่ผ่าน:** มีคำรับประกันเด็ดขาดอย่างน้อย 1 จุดที่ไม่มีข้อสัญญาใดรองรับและไม่มีคำกำกับ
- **ยังไม่ได้ตรวจ:** ไม่พบคำประกาศบนเว็บ
- **ตัวอย่าง:** หน้า Fund Safety ของ Broker A พาดหัวว่า *"เงินของคุณปลอดภัย 100% ทุกบาท"* ขณะที่สัญญาข้อ 9.7 ระบุว่าบริษัทไม่รับผิดต่อความเสียหายจากสถาบันการเงินที่รับฝาก → **ไม่ผ่าน**

**P02-017 ● · ฝ่ายบริการตอบคำถามเรื่องการแยกบัญชีเงินลูกค้าอย่างไร** `w3` `SUP` `G3`

- **ตรวจอะไร:** ทดสอบถามฝ่ายบริการในฐานะลูกค้าที่กังวลเรื่องความปลอดภัยของเงิน ด้วยคำถามที่ลูกค้าทั่วไปถามได้ คือ "เงินที่ผมฝากเข้าไปเก็บไว้ที่ไหน แยกจากเงินของบริษัทหรือเปล่า" บันทึกเวลาที่ส่งคำถาม เวลาที่ได้รับคำตอบครั้งแรก คำตอบแบบคำต่อคำ และเทียบว่าคำตอบสอดคล้องกับคำประกาศบนเว็บและข้อสัญญาหรือไม่ **ห้ามกดดัน ห้ามล่อให้พูดผิด ห้ามเปิดเผยตัว**
- **ขั้นตอนการตรวจ:**
  1. เข้าแชทสดในฐานะลูกค้าที่มีบัญชีจริง บันทึกวันเวลาที่เริ่มสนทนาเป็นเวลา UTC
  2. ถามคำถามมาตรฐาน 3 ข้อตามลำดับ: เงินฝากเก็บไว้ที่ไหน · แยกจากเงินบริษัทหรือไม่ · มีเอกสารให้อ่านเพิ่มหรือไม่
  3. รอคำตอบโดยไม่ถามซ้ำและไม่เร่ง บันทึกเวลาที่ได้รับคำตอบแต่ละข้อ
  4. บันทึก transcript ทั้งบทสนทนาโดยไม่ตัดทอน พร้อมชื่อ/รหัสพนักงานที่ระบบแสดง
  5. เทียบคำตอบแต่ละข้อกับคำประกาศจากข้อ 001–002 และข้อสัญญาจากข้อ 004 บันทึกจุดที่ตรงและจุดที่ขัดกัน
  6. ทำซ้ำทั้งชุด 3 รอบ ห่างกันรอบละ 1 สัปดาห์ กับพนักงานคนละคน แล้วบันทึกตารางสรุปและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** transcript เต็มทั้ง 3 รอบ (`RST-BRKA-P02-017-01` ถึง `-03`) · ภาพหน้าจอแชทที่เห็นเวลาและชื่อพนักงาน · ตารางเทียบคำตอบกับคำประกาศ
- **ผ่าน:** ทั้ง 3 รอบได้คำตอบที่ยืนยันว่าเงินลูกค้าถูกเก็บแยกจากเงินบริษัท และไม่มีรอบใดที่คำตอบขัดกับคำประกาศหรือข้อสัญญา
- **ไม่ผ่าน:** มีอย่างน้อย 1 รอบที่คำตอบขัดกับคำประกาศหรือข้อสัญญา หรือพนักงานปฏิเสธที่จะตอบว่าเงินแยกบัญชีหรือไม่
- **ยังไม่ได้ตรวจ:** ไม่มีช่องทางติดต่อที่ตอบกลับภายในรอบตรวจ `[เกณฑ์เสนอ: ไม่ได้รับคำตอบภายใน 7 วันทำการต่อรอบ]`
- **ตัวอย่าง:** รอบที่ 1 และ 2 พนักงาน Broker B ตอบว่าเงินอยู่ในบัญชีแยกที่ธนาคารพาณิชย์ รอบที่ 3 พนักงานตอบว่า *"เงินอยู่ในบัญชีของบริษัทครับ ใช้บัญชีเดียวกันหมด"* ซึ่งขัดกับคำประกาศบนเว็บ → **ไม่ผ่าน** ตกด่าน G3

**P02-018 · ฝ่ายบริการอ้างอิงเอกสารหรือหน้าเว็บประกอบคำตอบหรือไม่** `w2` `SUP+WEB`

- **ตรวจอะไร:** ตรวจว่าเมื่อถามเรื่องการแยกเงิน ฝ่ายบริการชี้ไปยังเอกสารหรือหน้าเว็บที่ตรวจสอบต่อได้หรือไม่ และลิงก์/ชื่อเอกสารที่ให้มานั้นเปิดได้จริงและมีเนื้อหาตรงกับที่อ้างหรือไม่ บันทึกลิงก์ทุกรายการที่ได้รับพร้อมผลการเปิด
- **ขั้นตอนการตรวจ:**
  1. เปิด transcript ทั้ง 3 รอบจากข้อ 017
  2. คัดรายการลิงก์และชื่อเอกสารทุกชิ้นที่พนักงานให้มา ลงตารางพร้อมรอบที่ได้รับ
  3. เปิดลิงก์แต่ละรายการในโหมดไม่บันทึกประวัติ บันทึกว่าเปิดได้ · เปิดไม่ได้ · เปลี่ยนเส้นทางไปหน้าอื่น
  4. ค้นในหน้าที่เปิดได้ด้วยคำว่า `segregat` `client money` `แยกบัญชี` บันทึกว่าพบเนื้อหาตรงกับที่พนักงานอ้างหรือไม่
  5. จับภาพทุกหน้าที่เปิด พร้อม URL และนาฬิกาเครื่อง
  6. บันทึกตารางลิงก์พร้อมสถานะและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางลิงก์/เอกสารที่ได้รับพร้อมสถานะการเปิด · ภาพทุกหน้าที่เปิดได้ (`RST-BRKA-P02-018-01` เป็นต้นไป)
- **ผ่าน:** อย่างน้อย 1 รอบที่พนักงานให้ลิงก์หรือชื่อเอกสารที่เปิดได้จริงและมีเนื้อหาเรื่องการแยกเงินตรงกับที่อ้าง
- **ไม่ผ่าน:** ทุกรอบไม่มีการอ้างอิงเอกสารใด หรืออ้างอิงแต่ลิงก์เปิดไม่ได้/เนื้อหาไม่ตรงกับที่อ้างทุกรายการ
- **ยังไม่ได้ตรวจ:** ยังไม่มี transcript จากข้อ 017
- **ตัวอย่าง:** พนักงาน Broker C ส่งลิงก์หน้า *Client Fund Protection* ทั้ง 3 รอบ แต่ลิงก์ทุกครั้งเปิดแล้วขึ้น 404 และค้นในเว็บก็ไม่พบหน้าชื่อนี้ → **ไม่ผ่าน**

**P02-019 · คำตอบเรื่องการแยกเงินจากช่องทางต่างกันตรงกันหรือไม่** `w2` `SUP`

- **ตรวจอะไร:** ถามคำถามชุดเดียวกันกับข้อ 017 ผ่านช่องทางที่ต่างกันอย่างน้อย 2 ช่องทาง (แชทสด และอีเมล/ระบบตั๋ว) แล้วเทียบสาระของคำตอบ บันทึกเวลาส่ง–เวลาตอบของแต่ละช่องทาง และจุดที่คำตอบให้สาระต่างกัน
- **ขั้นตอนการตรวจ:**
  1. ส่งคำถามชุดเดียวกันทางอีเมลหรือระบบตั๋วในวันเดียวกับรอบที่ 1 ของข้อ 017 บันทึกเวลาส่งเป็นเวลา UTC
  2. รอคำตอบโดยไม่ทวงถาม บันทึกเวลาที่ได้รับคำตอบครั้งแรก
  3. คัดสาระคำตอบจากทั้งสองช่องทางลงตาราง 3 แถวตามคำถาม 3 ข้อ
  4. ทำเครื่องหมายทุกแถวที่สองช่องทางให้สาระต่างกัน
  5. ถ้าต่างกัน ให้เทียบแต่ละคำตอบกับคำประกาศบนเว็บ บันทึกว่าช่องทางใดตรงกับคำประกาศ
  6. เก็บ transcript และอีเมลฉบับเต็ม แล้วบันทึกตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** อีเมลฉบับเต็มพร้อม header (`RST-BRKA-P02-019-01`) · transcript แชท (`-02`) · ตารางเทียบสองช่องทาง
- **ผ่าน:** สองช่องทางให้สาระตรงกันทั้ง 3 คำถาม
- **ไม่ผ่าน:** มีอย่างน้อย 1 คำถามที่สองช่องทางให้สาระขัดกันในสาระสำคัญว่าเงินแยกหรือไม่แยก
- **ยังไม่ได้ตรวจ:** ช่องทางที่สองไม่ตอบกลับภายในรอบตรวจ `[เกณฑ์เสนอ: 7 วันทำการ]`
- **ตัวอย่าง:** แชทของ Broker A ตอบว่าเงินอยู่ในบัญชีแยกที่ธนาคารในเขตกำกับ แต่อีเมลตอบว่าเงินถูกเก็บกับผู้ให้บริการชำระเงินภายนอก โดยไม่มีคำอธิบายเชื่อมสองคำตอบ → **ไม่ผ่าน**

**P02-020 · ขั้นตอนสมัครแสดงคำประกาศแยกเงินให้อ่านและยืนยันหรือไม่** `w2` `ACC`

- **ตรวจอะไร:** ระหว่างสมัครบัญชีจริง บันทึกทุกหน้าจอที่มีการให้ติ๊กยอมรับเอกสาร แล้วตรวจว่าเอกสารที่ต้องยอมรับมีข้อว่าด้วยการแยกเงินหรือไม่ ต้องคลิกเปิดอ่านได้จริงก่อนติ๊กหรือไม่ และระบบส่งสำเนาเอกสารฉบับที่ยอมรับกลับมาให้หรือไม่ บันทึกลำดับหน้าจอและข้อความกำกับช่องติ๊กแบบคำต่อคำ
- **ขั้นตอนการตรวจ:**
  1. เริ่มสมัครบัญชีจริงผ่านหน้าเว็บหลัก **ห้ามใช้ลิงก์แนะนำ** และอัดวิดีโอตลอดขั้นตอนสมัคร
  2. จับภาพทุกหน้าจอที่มีช่องติ๊กยอมรับ พร้อมข้อความกำกับช่องนั้น
  3. คลิกเปิดเอกสารทุกฉบับที่ลิงก์จากช่องติ๊ก บันทึกว่าเปิดได้หรือไม่ และดาวน์โหลดไฟล์ไว้
  4. ค้นในไฟล์แต่ละฉบับด้วยคำว่า `segregat` `client money` `แยกบัญชี` บันทึกว่าพบในฉบับใด
  5. หลังสมัครเสร็จ ตรวจกล่องอีเมลและพอร์ทัลว่าได้รับสำเนาเอกสารฉบับที่ยอมรับหรือไม่ บันทึกเวลาที่ได้รับ
  6. บันทึกลำดับหน้าจอทั้งหมดพร้อมผลการค้น แล้วตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** วิดีโอขั้นตอนสมัครทั้งชุด (`RST-BRKA-P02-020-01`) · ภาพทุกหน้าจอที่มีช่องติ๊ก · ไฟล์เอกสารทุกฉบับที่ลิงก์จากช่องติ๊ก · ภาพอีเมลสำเนาเอกสาร
- **ผ่าน:** เอกสารที่ต้องยอมรับมีข้อว่าด้วยการแยกเงิน เปิดอ่านได้ก่อนติ๊ก และได้รับสำเนากลับมาหลังสมัคร
- **ไม่ผ่าน:** เอกสารที่ต้องยอมรับไม่มีข้อว่าด้วยการแยกเงินเลย หรือเปิดอ่านไม่ได้ก่อนติ๊ก
- **ยังไม่ได้ตรวจ:** ยังไม่ได้ดำเนินการสมัครในรอบตรวจนี้
- **ตัวอย่าง:** หน้าสมัครของ Broker B มีช่องติ๊กเดียวว่า *"ข้าพเจ้ายอมรับข้อกำหนดทั้งหมด"* โดยลิงก์เอกสารเปิดไม่ได้จนกว่าจะสมัครเสร็จ และเมื่อเปิดได้ภายหลังพบว่ามีข้อแยกเงินอยู่จริง → **ไม่ผ่าน** (อ่านไม่ได้ก่อนติ๊ก)

**P02-021 · เอกสารฉบับที่ได้ตอนสมัครกับฉบับบนเว็บสาธารณะตรงกันหรือไม่** `w2` `DOC+WEB`

- **ตรวจอะไร:** เทียบข้อว่าด้วยการแยกเงินระหว่างเอกสารฉบับที่ระบบส่งให้เราตอนสมัคร กับฉบับที่ดาวน์โหลดได้จากหน้าเว็บสาธารณะในวันเดียวกัน บันทึกเลขเวอร์ชัน วันที่มีผล และข้อความของข้อแยกเงินจากทั้งสองฉบับ เพื่อจับกรณีที่ฉบับสาธารณะกับฉบับที่ผูกพันลูกค้าจริงไม่ตรงกัน
- **ขั้นตอนการตรวจ:**
  1. ดาวน์โหลดเอกสารสัญญาจากหน้าเว็บสาธารณะในวันเดียวกับที่ตรวจ บันทึกเวลาและ URL
  2. เปิดไฟล์ฉบับที่ได้รับตอนสมัครจากข้อ 020 ขึ้นมาคู่กัน
  3. เทียบเลขเวอร์ชันและวันที่มีผลของทั้งสองฉบับ บันทึกส่วนต่าง
  4. คัดข้อว่าด้วยการแยกเงินจากทั้งสองฉบับเป็นข้อความล้วน แล้วเทียบด้วยเครื่องมือเทียบข้อความ
  5. บันทึกทุกจุดที่ข้อความต่างกัน และระบุว่าจุดนั้นทำให้ระดับการคุ้มครองต่างกันหรือไม่
  6. คำนวณ hash ของทั้งสองไฟล์ บันทึกลงทะเบียนหลักฐาน แล้วตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ไฟล์ทั้งสองฉบับ (`RST-BRKA-P02-021-01`, `-02`) · ผลการเทียบข้อความที่ระบุจุดต่าง · ตาราง hash
- **ผ่าน:** ข้อว่าด้วยการแยกเงินในสองฉบับตรงกัน หรือต่างเฉพาะรูปแบบการเขียนที่ไม่เปลี่ยนสาระ
- **ไม่ผ่าน:** ฉบับสาธารณะให้การคุ้มครองมากกว่าฉบับที่เราถูกผูกพันจริง
- **ยังไม่ได้ตรวจ:** เว็บสาธารณะไม่เปิดให้ดาวน์โหลดสัญญาโดยไม่ล็อกอิน
- **ตัวอย่าง:** ฉบับบนเว็บของ Broker C เป็น v4.0 ระบุการแยกเงินไว้ชัด ส่วนฉบับที่ระบบส่งให้ตอนสมัครเป็น v3.1 ที่ยังไม่มีข้อนี้ → **ไม่ผ่าน**

**P02-022 · เก็บสำเนาถาวรและ hash ของคำประกาศทุกฉบับหรือไม่** `w1` `WEB+DOC`

- **ตรวจอะไร:** ตรวจกระบวนการของผู้ตรวจเอง ว่าหน้าเว็บและเอกสารทุกชิ้นที่ใช้อ้างอิงในข้อ 001–021 ถูกเก็บเป็นสำเนาถาวรที่พิสูจน์เนื้อหา ณ วันตรวจได้ ไม่ใช่เก็บแค่ลิงก์สด และทุกไฟล์มี hash กับ Evidence ID ครบ
- **ขั้นตอนการตรวจ:**
  1. รวบรวมรายการแหล่งอ้างอิงทั้งหมดที่ใช้ในข้อ 001–021
  2. ตรวจทีละรายการว่ามีไฟล์สำเนาถาวร (PDF หรือ archive) หรือไม่ ทำเครื่องหมายรายการที่มีแต่ลิงก์
  3. เปิดไฟล์สำเนาแต่ละไฟล์ ตรวจว่าเนื้อหาครบ อ่านได้ และเห็น URL กับวันเวลา
  4. คำนวณ hash ของทุกไฟล์ แล้วบันทึกลงทะเบียนหลักฐาน
  5. ตรวจว่าทุกไฟล์ตั้งชื่อตามรูปแบบ Evidence ID และตรงกับที่อ้างในแต่ละข้อ
  6. บันทึกผลลงแบบฟอร์มควบคุมคุณภาพหลักฐานพร้อมรายการไฟล์ที่ยังขาด
- **หลักฐานที่ต้องเก็บ:** ทะเบียนหลักฐานพร้อม hash ทุกไฟล์ · ตารางตรวจสอบความครบถ้วนรายแหล่งอ้างอิง
- **ผ่าน:** ทุกแหล่งอ้างอิงที่ใช้ในข้อ 001–021 มีสำเนาถาวรพร้อม hash และ Evidence ID ครบ
- **ไม่ผ่าน:** มีอย่างน้อย 1 แหล่งที่เก็บแต่ลิงก์สดโดยไม่มีสำเนาถาวร
- **ยังไม่ได้ตรวจ:** ยังไม่ได้เก็บหลักฐานใดในหมวดนี้
- **ตัวอย่าง:** ตรวจรอบสองพบว่าโบรกแก้ถ้อยคำหน้า Fund Safety และไม่มีสำเนาฉบับเดิมไว้เทียบ ทำให้พิสูจน์ถ้อยคำ ณ วันฝากเงินไม่ได้ → **ไม่ผ่าน**

**P02-023 ● · มีข้อความที่ขัดกับคำประกาศแยกเงินอยู่ที่อื่นในเว็บหรือสัญญาหรือไม่** `w3` `WEB+DOC`

- **ตรวจอะไร:** ค้นทั้งเว็บและเอกสารทุกฉบับเพื่อหาข้อความที่ให้ภาพขัดกับคำประกาศ เช่น FAQ ที่บอกว่าเงินเข้าบัญชีดำเนินงานของบริษัท หรือหน้าฝากเงินที่บอกว่าโอนเข้าบัญชีบริษัทโดยตรง บันทึกทุกข้อความที่ขัดกันคู่กับข้อความคำประกาศที่ขัดด้วย พร้อม URL/เลขข้อของทั้งคู่
- **ขั้นตอนการตรวจ:**
  1. รวบรวมข้อความคำประกาศทั้งหมดจากข้อ 001–002 เป็นตัวตั้ง
  2. ค้นทั้งเว็บและทุกไฟล์เอกสารด้วยคำว่า `operating account` `company account` `general funds` `pooled` `บัญชีบริษัท` `บัญชีดำเนินงาน`
  3. อ่านทุกจุดที่พบทั้งย่อหน้า แล้วบันทึกว่าย่อหน้านั้นให้ภาพขัดกับคำประกาศหรือไม่
  4. จัดคู่ข้อความที่ขัดกันลงตาราง 2 คอลัมน์ (คำประกาศ / ข้อความที่ขัด) พร้อม URL หรือเลขข้อของทั้งคู่
  5. ตรวจว่ามีข้อความใดในเว็บหรือสัญญาที่อธิบายความต่างนี้ไว้หรือไม่ เช่น อธิบายว่าเป็นบัญชีคนละขั้นตอน
  6. จับภาพทุกจุดที่ขัดกัน แล้วบันทึกตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพทุกข้อความที่ขัดกัน (`RST-BRKA-P02-023-01` เป็นต้นไป) · ตารางจับคู่ข้อความ · สำเนาถาวรของหน้าที่พบ
- **ผ่าน:** ไม่พบข้อความที่ขัดกับคำประกาศ หรือพบแต่มีคำอธิบายกำกับให้เข้าใจได้ในแหล่งเดียวกัน
- **ไม่ผ่าน:** พบข้อความอย่างน้อย 1 จุดที่ขัดกับคำประกาศโดยไม่มีคำอธิบายใดที่ใดเลย
- **ยังไม่ได้ตรวจ:** ไม่มีคำประกาศให้เป็นตัวตั้ง (ผลผูกกับข้อ 001)
- **ตัวอย่าง:** หน้า Fund Safety ของ Broker A ประกาศว่าเงินอยู่ในบัญชีแยก แต่ FAQ ข้อ 12 เขียนว่า *"เงินฝากของท่านจะเข้าสู่บัญชีดำเนินงานของบริษัทและถูกปรับยอดในระบบเทรด"* โดยไม่มีคำอธิบายเชื่อมสองข้อความ → **ไม่ผ่าน**

**P02-024 · ตรวจซ้ำรอบถัดไปแล้วคำประกาศยังคงเดิมหรือไม่** `w2` `WEB+DOC`

- **ตรวจอะไร:** ทำขั้นตอนของข้อ 001 · 004 · 010 ซ้ำในรอบถัดไป แล้วเทียบกับสำเนาถาวรของรอบก่อน เพื่อจับการถอดคำประกาศออก การเพิ่มข้อยกเว้น หรือการลดขอบเขต โดยไม่แจ้งลูกค้า บันทึกทุกช่องที่เปลี่ยนพร้อมวันที่ของทั้งสองรอบ
- **ขั้นตอนการตรวจ:**
  1. กำหนดวันตรวจซ้ำตามรอบที่ประกาศ `[เกณฑ์เสนอ: ทุก 90 วัน]`
  2. ทำขั้นตอนของข้อ 001 · 004 · 010 ซ้ำทั้งชุด และเก็บสำเนาถาวรใหม่
  3. เปิดสำเนารอบก่อนวางเทียบทีละหัวข้อ: มีคำประกาศหรือไม่ · ถ้อยคำ · ข้อยกเว้น · ขอบเขตยอดเงิน
  4. บันทึกทุกจุดที่เปลี่ยนแปลง พร้อมข้อความเดิมและข้อความใหม่แบบคำต่อคำ
  5. ค้นในกล่องอีเมลของบัญชีทดสอบด้วยคำว่า `update` `amendment` `client money` `แจ้งเปลี่ยนแปลง` บันทึกว่าโบรกแจ้งหรือไม่ และแจ้งวันไหนเทียบกับวันที่มีผล
  6. บันทึกตารางเทียบสองรอบพร้อมผลการค้นอีเมล และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** สำเนาถาวรทั้งสองรอบ (`RST-BRKA-P02-024-01`, `-02`) · ตารางเทียบจุดที่เปลี่ยน · ภาพกล่องอีเมลหลังค้นคำ
- **ผ่าน:** คำประกาศไม่เปลี่ยน หรือเปลี่ยนแต่โบรกแจ้งลูกค้าก่อนหรือในวันที่มีผล
- **ไม่ผ่าน:** คำประกาศถูกลดขอบเขตหรือถูกถอดออก โดยไม่พบการแจ้งลูกค้าในกล่องอีเมล
- **ยังไม่ได้ตรวจ:** ยังไม่ถึงรอบตรวจซ้ำ
- **ตัวอย่าง:** รอบที่สองพบว่า Broker B เพิ่มข้อยกเว้น *"ไม่รวมบัญชีที่เปิดผ่านพันธมิตร"* ลงในข้อ 9.3 และค้นกล่องอีเมลย้อนหลังแล้วไม่พบการแจ้งใด → **ไม่ผ่าน**

**P02-025 ● · สรุปสถานะคำประกาศแยกบัญชีเงินลูกค้าทุกจุดสัมผัส** `w3` `รวมทุกวิธี` `G3`

- **ตรวจอะไร:** รวบรวมผลจากข้อ 001–024 ลงตารางเดียว แล้วตอบคำถามชี้ขาด 3 ข้อ: มีคำประกาศแยกเงินที่ตรวจสอบได้หรือไม่ · คำประกาศนั้นผูกพันในสัญญาที่เราเซ็นหรือไม่ · คำประกาศนั้นครอบคลุมนิติบุคคลคู่สัญญาและประเภทบัญชีของเราหรือไม่ ข้อนี้เป็นข้อสรุปของ S01 และผูกด่าน G3
- **ขั้นตอนการตรวจ:**
  1. สร้างตารางที่มีแถวเป็นจุดสัมผัส 7 จุด: หน้าเว็บสาธารณะ · หน้าฝากเงิน · สัญญาที่เซ็น · เอกสารนโยบายแยกฉบับ · หน้าจอสมัคร · คำตอบแชท · คำตอบอีเมล
  2. เติมสถานะของแต่ละแถวเป็น มี/ไม่มี/ขัดแย้ง พร้อม Evidence ID อ้างอิง จากผลข้อ 001, 003, 004, 013, 020, 017, 019
  3. ตอบคำถามชี้ขาด 3 ข้อโดยอ้างอิงแถวในตาราง ห้ามตอบโดยไม่อ้าง Evidence ID
  4. ทำเครื่องหมายทุกแถวที่มีสถานะ "ขัดแย้ง" แล้วสรุปว่าความขัดแย้งนั้นกระทบคำตอบข้อใดใน 3 ข้อ
  5. ตรวจว่าผลของข้อ 008 (entity) และข้อ 009 (ประเภทบัญชี) สอดคล้องกับบัญชีทดสอบที่เราเปิดจริงหรือไม่
  6. บันทึกตารางสรุปฉบับสมบูรณ์พร้อมคำตัดสิน และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางสรุป 7 จุดสัมผัสพร้อม Evidence ID ทุกแถว (`RST-BRKA-P02-025-01`) · เอกสารคำตอบคำถามชี้ขาด 3 ข้อ
- **ผ่าน:** ตอบว่า "ใช่" ครบทั้ง 3 คำถามชี้ขาด โดยแต่ละคำตอบอ้าง Evidence ID ได้
- **ไม่ผ่าน:** ตอบว่า "ไม่ใช่" อย่างน้อย 1 คำถามชี้ขาด
- **ยังไม่ได้ตรวจ:** ยังเก็บข้อมูลไม่ครบ 7 จุดสัมผัส
- **ตัวอย่าง:** Broker C มีคำประกาศบนเว็บและพนักงานยืนยันทางแชท แต่สัญญาที่เซ็นไม่มีข้อผูกพันใด และคำประกาศเป็นของ entity คนละรายกับคู่สัญญา ตอบ "ไม่ใช่" 2 ใน 3 คำถาม → **ไม่ผ่าน** ตกด่าน G3

## S02 · ธนาคารผู้รับฝากและการตรวจสอบย้อนกลับ (026–050)

**P02-026 ● · เว็บระบุชื่อธนาคารผู้รับฝากเงินลูกค้าหรือไม่** `w3` `WEB` `G3`

- **ตรวจอะไร:** ตรวจว่าเว็บไซต์สาธารณะหรือเอกสารที่ดาวน์โหลดได้ ระบุ **ชื่อธนาคารหรือสถาบันการเงินที่รับฝากเงินลูกค้า** เป็นชื่อเฉพาะเจาะจงหรือไม่ โดยดูหน้า Fund Safety · About · FAQ · Deposit · เอกสารนโยบายเงินลูกค้า บันทึกชื่อสถาบันทุกชื่อที่พบพร้อม URL หรือเลขข้อ ไม่นับข้อความกว้าง ๆ เช่น "ธนาคารชั้นนำระดับโลก" หรือ "Tier-1 banks" ที่ไม่มีชื่อกำกับ
- **ขั้นตอนการตรวจ:**
  1. เปิดหน้า Fund Safety · About · FAQ · Deposit และเอกสารนโยบายทุกฉบับที่ดาวน์โหลดได้
  2. ค้นทีละคำ: `bank` `banking partner` `custodian` `held with` `ธนาคาร` `สถาบันการเงิน` `ผู้รับฝาก`
  3. คัดลอกทุกข้อความที่พบทั้งประโยค พร้อม URL หรือเลขข้อและเลขหน้า
  4. จำแนกแต่ละข้อความเป็น 3 กลุ่ม: ระบุชื่อสถาบันเฉพาะเจาะจง · กล่าวลอย ๆ ไม่มีชื่อ · ไม่กล่าวถึงเลย
  5. จับภาพทุกจุดที่พบให้เห็นข้อความและ URL ในเฟรมเดียวกัน
  6. เก็บสำเนาถาวรของหน้าที่พบ แล้วบันทึกตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพทุกจุดที่กล่าวถึงสถาบันผู้รับฝาก (`RST-BRKA-P02-026-01` เป็นต้นไป) · ตารางจำแนก 3 กลุ่ม · สำเนาถาวร
- **ผ่าน:** พบชื่อสถาบันการเงินผู้รับฝากที่เฉพาะเจาะจงอย่างน้อย 1 ราย บนแหล่งสาธารณะที่เข้าถึงได้โดยไม่ต้องล็อกอิน
- **ไม่ผ่าน:** ไม่พบชื่อสถาบันใดเลย หรือพบเพียงคำกล่าวลอย ๆ ที่ไม่มีชื่อกำกับ
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** Broker A เขียนบนหน้า Fund Safety ว่า *"เงินลูกค้าฝากไว้กับธนาคารระดับ Tier-1 ในยุโรป"* ค้นทั้งเว็บและเอกสารทุกฉบับแล้วไม่มีชื่อธนาคารใดปรากฏ → **ไม่ผ่าน** ตกด่าน G3

**P02-027 · ระบุประเทศหรือเขตอำนาจของสถาบันผู้รับฝากหรือไม่** `w2` `WEB+DOC`

- **ตรวจอะไร:** ตรวจว่าแหล่งใดระบุประเทศหรือเขตอำนาจที่ตั้งของสถาบันผู้รับฝากเงินลูกค้าหรือไม่ บันทึกประเทศที่ระบุทุกรายการ และตรวจว่าประเทศนั้นเป็นประเทศเดียวกับที่ออกใบอนุญาตให้นิติบุคคลคู่สัญญาหรือไม่ ข้อนี้ให้ข้อมูลตั้งต้นแก่ข้อ 045
- **ขั้นตอนการตรวจ:**
  1. เปิดข้อความทุกจุดที่พบจากข้อ 026
  2. อ่านย่อหน้าเต็มของแต่ละจุด แล้วบันทึกชื่อประเทศหรือเขตอำนาจที่ระบุ ถ้าไม่ระบุ ให้บันทึกว่า "ไม่ระบุ"
  3. บันทึกประเทศที่ออกใบอนุญาตให้นิติบุคคลคู่สัญญา จากหน้า Regulation และจากสัญญา
  4. เทียบสองรายการ แล้วทำเครื่องหมายทุกกรณีที่ประเทศของสถาบันผู้รับฝากต่างจากประเทศผู้ออกใบอนุญาต

- **ตัวอย่าง:** พอร์ทัลของ Broker B แสดงเพียงยอดและวันที่ ไม่มีเลขอ้างอิงใด และไฟล์ส่งออกก็ไม่มีคอลัมน์อ้างอิง ทำให้จับคู่กับสลิปธนาคารไม่ได้ → **ไม่ผ่าน**

**P02-038 · ยอดและเวลาในสลิปธนาคารตรงกับที่บันทึกในบัญชีเทรดหรือไม่** `w2` `PAY+STM`

- **ตรวจอะไร:** จับคู่รายการฝากแต่ละครั้งระหว่างหลักฐานฝั่งธนาคารต้นทางกับรายการที่ปรากฏในพอร์ทัลลูกค้า โดยเทียบ 3 ตัวแปร: จำนวนเงินและสกุลเงิน · วันเวลาที่โอนเทียบกับวันเวลาที่ระบบบันทึกว่ารับเงิน (เวลา UTC) · เลขอ้างอิงที่ใช้เชื่อมสองฝั่ง บันทึกส่วนต่างของยอดและส่วนต่างของเวลาเป็นตัวเลข ข้อนี้ตรวจ **ความตามรอยได้** ไม่ใช่ตรวจค่าธรรมเนียมหรือความเร็วในการเข้าบัญชี ซึ่งอยู่ที่เสา P03
- **ขั้นตอนการตรวจ:**
  1. สร้างตารางจับคู่ที่มีแถวเป็นรายการฝากแต่ละครั้ง และคอลัมน์เป็น ฝั่งธนาคาร / ฝั่งพอร์ทัล
  2. เติมจำนวนเงินและสกุลเงินของทั้งสองฝั่งลงตาราง แล้วคำนวณส่วนต่างเป็นตัวเลขและร้อยละ
  3. เติมวันเวลาของทั้งสองฝั่งเป็นเวลา UTC แล้วคำนวณส่วนต่างเป็นชั่วโมงและนาที
  4. เติมเลขอ้างอิงของทั้งสองฝั่ง แล้วทำเครื่องหมายแถวที่ไม่มีเลขใดเชื่อมกันได้
  5. สำหรับแถวที่ยอดไม่ตรง ค้นในพอร์ทัลและอีเมลว่ามีรายการหักหรือคำอธิบายกำกับหรือไม่ บันทึกข้อความที่พบ
  6. บันทึกตารางจับคู่ฉบับสมบูรณ์พร้อมภาพทั้งสองฝั่ง และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางจับคู่ทุกรายการฝาก (`RST-BRKA-P02-038-01`) · ภาพสลิปคู่กับภาพรายการในพอร์ทัลของแต่ละครั้ง · บันทึกข้อความอธิบายส่วนต่าง ถ้ามี
- **ผ่าน:** ทุกรายการฝากจับคู่ได้ครบทั้งสองฝั่ง และส่วนต่างของยอดทุกรายการมีคำอธิบายกำกับในพอร์ทัลหรืออีเมล
- **ไม่ผ่าน:** มีรายการฝากอย่างน้อย 1 รายการที่จับคู่ไม่ได้ หรือยอดต่างกันโดยไม่มีคำอธิบายใด
- **ยังไม่ได้ตรวจ:** ยังไม่มีข้อมูลจากฝั่งใดฝั่งหนึ่ง (ผลผูกกับข้อ 036 และ 037)
- **ตัวอย่าง:** รายการฝากครั้งที่ 2 ของ Broker C ยอดในพอร์ทัลน้อยกว่าสลิป 25 หน่วยสกุลเงิน ค้นในพอร์ทัลและอีเมลแล้วไม่มีรายการหักหรือคำอธิบายใด → **ไม่ผ่าน**

**P02-039 · มีเลขอ้างอิงที่ตามรอยได้จากสลิปถึงรายการในพอร์ทัลหรือไม่** `w2` `PAY+STM+SUP`

- **ตรวจอะไร:** ตรวจว่าระบบของโบรกให้เลขอ้างอิงที่ลูกค้าใช้เชื่อมหลักฐานฝั่งธนาคารกับรายการในพอร์ทัลได้หรือไม่ ทั้งเลขอ้างอิงที่ระบบให้ก่อนโอน (payment reference ที่ต้องระบุตอนโอน) และเลขอ้างอิงที่ระบบให้หลังรับเงิน บันทึกว่ามีเลขใดบ้าง และทดสอบว่าเมื่อแจ้งเลขนั้นกับฝ่ายบริการ พนักงานค้นรายการเจอหรือไม่
- **ขั้นตอนการตรวจ:**
  1. บันทึกเลขอ้างอิงที่ระบบแสดงในหน้าคำแนะนำการโอนของทุกครั้ง พร้อมข้อความกำกับว่าต้องใส่ในช่องใดตอนโอน
  2. บันทึกเลขอ้างอิงที่ปรากฏในรายการของพอร์ทัลหลังเงินเข้า
  3. เทียบเลขจากสองขั้นข้างต้นกับเลขอ้างอิงในสลิปธนาคาร บันทึกว่าเลขใดตรงกัน
  4. ติดต่อฝ่ายบริการในฐานะลูกค้าที่ต้องการยืนยันรายการ แล้วแจ้งเฉพาะเลขอ้างอิง 1 เลขต่อ 1 รายการ บันทึกเวลาที่ส่งเป็นเวลา UTC
  5. บันทึกว่าพนักงานค้นรายการเจอหรือไม่ และใช้เวลากี่นาทีนับจากเวลาที่ส่งข้อความถึงเวลาที่ยืนยันรายการได้
  6. เก็บ transcript และภาพทุกฝั่ง แล้วบันทึกตารางเลขอ้างอิงและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางเลขอ้างอิง 3 แหล่งต่อรายการ (`RST-BRKA-P02-039-01`) · transcript การยืนยันรายการกับฝ่ายบริการ · ภาพหน้าคำแนะนำการโอนที่เห็นเลขอ้างอิง
- **ผ่าน:** ทุกรายการฝากมีเลขอ้างอิงอย่างน้อย 1 เลขที่เชื่อมสลิปกับรายการในพอร์ทัลได้ และฝ่ายบริการค้นเจอด้วยเลขนั้น
- **ไม่ผ่าน:** มีรายการฝากอย่างน้อย 1 รายการที่ไม่มีเลขใดเชื่อมสองฝั่งได้ และฝ่ายบริการค้นด้วยเลขที่มีอยู่ไม่เจอ
- **ยังไม่ได้ตรวจ:** ยังไม่ได้รับคำตอบจากฝ่ายบริการภายในรอบตรวจ `[เกณฑ์เสนอ: 7 วันทำการ]`
- **ตัวอย่าง:** Broker A ให้เลขอ้างอิงตอนโอน แต่พอร์ทัลไม่แสดงเลขนั้นเลย เมื่อแจ้งเลขกับฝ่ายบริการ พนักงานตอบว่าต้องใช้เลขภายในที่ลูกค้าไม่มี → **ไม่ผ่าน**

**P02-040 ● · เงินที่ถอนกลับมาโอนมาจากบัญชีชื่อใด** `w3` `PAY` `G3`

- **ตรวจอะไร:** ถอนเงินจริง แล้วบันทึก **ชื่อผู้โอน (originator/remitter) ที่ปรากฏในหลักฐานฝั่งธนาคารปลายทางของเรา** พร้อมธนาคารต้นทางของการโอนขากลับ ประเทศ และเลขอ้างอิง แล้วเทียบกับชื่อผู้รับเงินตอนฝากจากข้อ 029 และกับนิติบุคคลคู่สัญญา นี่คือหลักฐานฝั่งขากลับที่ลูกค้ารายย่อยเก็บได้เอง และเป็นจุดที่เห็นว่าเงินถูกจ่ายคืนจากกระเป๋าใด
- **ขั้นตอนการตรวจ:**
  1. ส่งคำสั่งถอนเงินจากพอร์ทัลลูกค้า `[เกณฑ์เสนอ: จำนวนขั้นต่ำที่โบรกกำหนด]` บันทึกวันเวลาที่กดยืนยันเป็นเวลา UTC
  2. จับภาพหน้าจอคำสั่งถอนและหน้าสถานะ ให้เห็นเลขอ้างอิงคำสั่ง URL และนาฬิกาเครื่อง
  3. เมื่อเงินเข้าบัญชีปลายทาง เปิด statement หรือรายการเดินบัญชีของธนาคารเรา แล้วบันทึกชื่อผู้โอนแบบคำต่อคำ
  4. บันทึกธนาคารต้นทางของการโอนขากลับ ประเทศ และเลขอ้างอิงที่ปรากฏในรายการเดินบัญชี
  5. เทียบชื่อผู้โอนขากลับกับชื่อผู้รับเงินตอนฝาก และกับชื่อนิติบุคคลคู่สัญญา บันทึกจุดที่ต่างกันทุกจุด
  6. เก็บ statement ฉบับเต็มและฉบับปิดบัง คำนวณ hash แล้วบันทึกผลและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าคำสั่งถอนและหน้าสถานะ (`RST-BRKA-P02-040-01`) · statement ธนาคารปลายทางที่เห็นชื่อผู้โอน ฉบับเต็มและฉบับปิดบัง (`-02`, `-03`) · ตารางเทียบชื่อผู้โอนขากลับกับผู้รับขาฝาก
- **ผ่าน:** ชื่อผู้โอนขากลับเป็นนิติบุคคลรายเดียวกับผู้รับเงินตอนฝากหรือกับคู่สัญญา หรือเป็นคนละรายแต่มีคำอธิบายบทบาทในเว็บหรือสัญญา
- **ไม่ผ่าน:** ชื่อผู้โอนขากลับเป็นนิติบุคคลหรือบุคคลที่ไม่ปรากฏคำอธิบายใดในเว็บและในสัญญา
- **ยังไม่ได้ตรวจ:** ยังไม่ได้ทำการถอนจริง หรือเงินยังไม่เข้าบัญชีปลายทางภายในรอบตรวจ
- **ตัวอย่าง:** Broker B รับเงินฝากในนาม *BrokerB Ltd* แต่จ่ายเงินถอนกลับมาจากผู้โอนชื่อ *Global Pay Services* ในอีกเขตหนึ่ง และไม่มีที่ใดในเว็บหรือสัญญากล่าวถึงชื่อนี้ → **ไม่ผ่าน** ตกด่าน G3

**P02-041 · นโยบายคืนเงินกลับช่องทางเดิมถูกประกาศและปฏิบัติจริงหรือไม่** `w2` `WEB+DOC+PAY`

- **ตรวจอะไร:** ตรวจว่าโบรกประกาศนโยบายคืนเงินกลับช่องทางและบัญชีเดิมของผู้ฝาก (return to source) ไว้หรือไม่ อยู่ที่ใด และผลการถอนจริงเป็นไปตามนั้นหรือไม่ บันทึกชื่อเจ้าของบัญชีปลายทางที่รับเงินถอนเทียบกับชื่อเจ้าของบัญชีต้นทางที่ใช้ฝาก ข้อนี้ตรวจ **ความสอดคล้องของเส้นทางเงิน** ไม่ตรวจเวลาถอนหรือค่าธรรมเนียม ซึ่งอยู่ที่เสา P03
- **ขั้นตอนการตรวจ:**
  1. ค้นในเว็บและเอกสารทุกฉบับด้วยคำว่า `return to source` `same method` `originating account` `ช่องทางเดิม` `บัญชีเดิม`
  2. คัดลอกข้อความนโยบายที่พบพร้อม URL หรือเลขข้อ ถ้าไม่พบ ให้บันทึกว่า "ไม่ประกาศนโยบาย"
  3. บันทึกชื่อเจ้าของบัญชีต้นทางที่ใช้ฝากเงินทุกครั้ง จากหลักฐานในข้อ 036
  4. บันทึกชื่อเจ้าของบัญชีปลายทางที่รับเงินถอน จากหลักฐานในข้อ 040
  5. เทียบสองรายการ แล้วบันทึกว่าเงินกลับเข้าบัญชีชื่อเดียวกันและช่องทางเดียวกันหรือไม่
  6. จับภาพนโยบายและหลักฐานทั้งสองฝั่ง แล้วบันทึกตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อความนโยบาย (`RST-BRKA-P02-041-01`) · ตารางเทียบบัญชีต้นทางขาฝากกับบัญชีปลายทางขาถอน · หลักฐานธนาคารทั้งสองฝั่ง
- **ผ่าน:** โบรกประกาศนโยบายคืนเงินกลับช่องทางเดิม และผลการถอนจริงเป็นไปตามนโยบายนั้น
- **ไม่ผ่าน:** ผลการถอนจริงไม่เป็นไปตามนโยบายที่ประกาศ หรือไม่ประกาศนโยบายใดและเงินกลับเข้าบัญชีที่ไม่ใช่บัญชีต้นทาง
- **ยังไม่ได้ตรวจ:** ยังไม่ได้ทำการถอนจริง
- **ตัวอย่าง:** Broker C ประกาศว่าคืนเงินกลับบัญชีต้นทางเสมอ แต่การถอนจริงถูกส่งเข้ากระเป๋าเงินอิเล็กทรอนิกส์ที่เราไม่เคยใช้ฝาก โดยไม่มีการแจ้งหรือขอความยินยอมล่วงหน้า → **ไม่ผ่าน**

**P02-042 · ฝ่ายบริการตอบคำถามเรื่องธนาคารผู้รับฝากอย่างไร** `w2` `SUP`

- **ตรวจอะไร:** ถามฝ่ายบริการในฐานะลูกค้าที่ต้องการทราบว่าเงินของตนอยู่ที่สถาบันใด ด้วยคำถามที่ลูกค้าทั่วไปถามได้ คือ "เงินที่ผมฝากไว้เก็บอยู่ที่ธนาคารไหน ประเทศอะไร" บันทึกคำตอบแบบคำต่อคำ เวลาที่ตอบ และเทียบกับชื่อสถาบันที่ประกาศบนเว็บและกับธนาคารปลายทางที่พบจริงจากข้อ 032 **ห้ามกดดันและห้ามเปิดเผยตัว**
- **ขั้นตอนการตรวจ:**
  1. เข้าแชทสดในฐานะลูกค้าที่มีบัญชีจริง บันทึกวันเวลาที่เริ่มสนทนาเป็นเวลา UTC
  2. ถามคำถาม 2 ข้อตามลำดับ: เงินเก็บอยู่ที่ธนาคารใด · ธนาคารนั้นอยู่ประเทศใด
  3. รอคำตอบโดยไม่ถามซ้ำและไม่เร่ง บันทึกเวลาที่ได้รับคำตอบแต่ละข้อ
  4. บันทึก transcript ทั้งบทสนทนาโดยไม่ตัดทอน
  5. เทียบคำตอบกับชื่อสถาบันที่ประกาศจากข้อ 026–027 และกับธนาคารปลายทางจริงจากข้อ 032 บันทึกจุดที่ตรงและจุดที่ขัดกัน

**P02-044 · สัญญาเปิดเผยว่าเงินอาจถูกฝากนอกเขตกำกับหรือไม่** `w2` `DOC+WEB`

- **ตรวจอะไร:** ค้นในสัญญาว่ามีข้อความเปิดเผยหรือไม่ว่าเงินลูกค้าอาจถูกฝากไว้กับสถาบันในเขตอำนาจอื่นนอกเขตที่ออกใบอนุญาต และมีคำเตือนว่าการคุ้มครองอาจต่างกันหรือไม่ บันทึกเลขข้อ ข้อความแบบคำต่อคำ และเทียบกับประเทศปลายทางจริงที่พบในข้อ 035

  1. เปิดสัญญาและนโยบายทุกฉบับ ค้นทีละคำ: `outside` `third country` `other jurisdiction` `different legal` `นอกเขต` `ต่างประเทศ`
  2. คัดลอกทุกข้อความที่พบพร้อมเลขข้อและเลขหน้า
  3. อ่านแต่ละข้อความ แล้วบันทึกว่ามีคำเตือนเรื่องระดับการคุ้มครองที่ต่างกันหรือไม่
  4. เปิดตารางประเทศปลายทางจริงจากข้อ 035 แล้วเทียบว่าประเทศที่พบจริงอยู่ในขอบเขตที่สัญญาเปิดเผยไว้หรือไม่
  5. ค้นในเว็บว่ามีการเปิดเผยเรื่องเดียวกันนอกเอกสารสัญญาหรือไม่ บันทึก URL ที่พบ
  6. จับภาพทุกจุด แล้วบันทึกตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อสัญญาที่เปิดเผย (`RST-BRKA-P02-044-01`) · ตารางเทียบข้อความเปิดเผยกับประเทศปลายทางจริง · ภาพจุดเปิดเผยบนเว็บ ถ้ามี
- **ผ่าน:** สัญญาเปิดเผยความเป็นไปได้ที่เงินจะถูกฝากนอกเขตกำกับพร้อมคำเตือนเรื่องระดับการคุ้มครอง หรือเงินไม่ได้ถูกฝากนอกเขตกำกับเลย
- **ไม่ผ่าน:** เงินถูกฝากนอกเขตกำกับจริงตามข้อ 035 แต่สัญญาไม่มีข้อใดเปิดเผยเรื่องนี้
- **ยังไม่ได้ตรวจ:** ยังไม่มีข้อมูลประเทศปลายทางจริง (ผลผูกกับข้อ 035)

**P02-045 ● · เขตอำนาจของผู้รับเงินต่างจากเขตของนิติบุคคลคู่สัญญาโดยไม่มีคำอธิบายหรือไม่** `w3` `PAY+WEB+DOC`

- **ผ่าน:** ทุกจุดอยู่ในเขตอำนาจเดียวกับนิติบุคคลคู่สัญญา หรือต่างแต่มีคำอธิบายที่ค้นเจอได้ในเว็บหรือสัญญา
- **ไม่ผ่าน:** มีอย่างน้อย 1 จุดที่อยู่นอกเขตอำนาจของนิติบุคคลคู่สัญญาโดยไม่มีคำอธิบายที่ใดเลย

**P02-046 · เก็บสำเนาถาวรและ hash ของหลักฐานการโอนทุกใบหรือไม่** `w1` `PAY`

- **ตัวอย่าง:** ช่องทางโอนธนาคารของ Broker B ชี้ไป *BrokerB Ltd* แต่ช่องทางบัตรพาไปหน้าชำระเงินของนิติบุคคลอีกรายในเขตอื่น ซึ่งไม่ถูกกล่าวถึงที่ใดในเว็บหรือสัญญา → **ไม่ผ่าน**

- **ตรวจอะไร:** ทำขั้นตอนของข้อ 026 · 029 · 047 ซ้ำในรอบถัดไป แล้วเทียบกับสำเนารอบก่อน เพื่อจับการเปลี่ยนสถาบันผู้รับฝากหรือเปลี่ยนผู้รับเงินโดยไม่แจ้งลูกค้า บันทึกทุกช่องที่เปลี่ยนพร้อมวันที่ของทั้งสองรอบ และผลการค้นการแจ้งในกล่องอีเมลกับประกาศในพอร์ทัล
- **ขั้นตอนการตรวจ:**
  1. กำหนดวันตรวจซ้ำตามรอบที่ประกาศ `[เกณฑ์เสนอ: ทุก 90 วัน]`
  2. ทำขั้นตอนของข้อ 026 · 029 · 047 ซ้ำทั้งชุด และเก็บสำเนาถาวรใหม่
  3. เปิดสำเนารอบก่อนวางเทียบทีละช่อง: ชื่อสถาบันที่ประกาศ · ชื่อผู้รับเงิน · ธนาคารปลายทาง · ประเทศ · รายชื่อช่องทางฝาก
  4. บันทึกทุกช่องที่เปลี่ยน พร้อมค่าเดิมและค่าใหม่แบบคำต่อคำ
  5. ค้นในกล่องอีเมลและประกาศในพอร์ทัลด้วยคำว่า `bank details` `payment details` `เปลี่ยนบัญชี` `แจ้งเปลี่ยน` บันทึกว่าพบการแจ้งหรือไม่ และวันที่แจ้งเทียบกับวันที่เปลี่ยน
  6. บันทึกตารางเทียบสองรอบพร้อมผลการค้น และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** สำเนาถาวรทั้งสองรอบ (`RST-BRKA-P02-048-01`, `-02`) · ตารางเทียบช่องที่เปลี่ยน · ภาพกล่องอีเมลและประกาศในพอร์ทัลหลังค้นคำ
- **ผ่าน:** ข้อมูลผู้รับเงินและสถาบันผู้รับฝากไม่เปลี่ยน หรือเปลี่ยนแต่มีการแจ้งผ่านช่องทางทางการก่อนหรือในวันที่มีผล
- **ไม่ผ่าน:** ข้อมูลเปลี่ยนโดยไม่พบการแจ้งผ่านช่องทางทางการใดเลย
- **ยังไม่ได้ตรวจ:** ยังไม่ถึงรอบตรวจซ้ำ
- **ตัวอย่าง:** รอบที่สองของ Broker A เปลี่ยนผู้รับเงินเป็นนิติบุคคลในเขตใหม่ ค้นกล่องอีเมลย้อนหลังและประกาศในพอร์ทัลแล้วไม่พบการแจ้งใด พบเพียงข้อความในหน้าฝากเงินที่เปลี่ยนไปเงียบ ๆ → **ไม่ผ่าน**

**P02-049 · โบรกเผยแพร่ข้อมูลผู้รับฝากอย่างตรวจสอบได้ หรือกล่าวเพียงลอย ๆ** `w2` `WEB+PUB`

- **ตรวจอะไร:** ประเมินคุณภาพการเปิดเผยข้อมูลสถาบันผู้รับฝากทั้งหมดที่โบรกเผยแพร่เอง โดยให้คะแนนตามเกณฑ์ 4 ข้อ: ระบุชื่อสถาบันเฉพาะเจาะจง · ระบุประเทศ · ระบุว่าสถาบันนั้นรับฝากเงินลูกค้าประเภทใด · เผยแพร่ในหน้าที่เข้าถึงได้โดยไม่ต้องล็อกอิน บันทึกผลรายข้อพร้อมหลักฐาน ข้อนี้เป็นการสรุปคุณภาพการเปิดเผย ไม่ใช่การตรวจหารายงานที่โบรกเปิดเผยตามกฎ ซึ่งอยู่ที่ `p02-02.md` S04
- **ขั้นตอนการตรวจ:**
  1. รวบรวมทุกจุดที่โบรกกล่าวถึงสถาบันผู้รับฝาก จากผลข้อ 026 · 027 · 013
  2. ให้ผลรายข้อตามเกณฑ์ 4 ข้อข้างต้น โดยเขียนว่าผ่านหรือไม่ผ่านพร้อม Evidence ID กำกับทุกข้อ
  3. นับจำนวนเกณฑ์ที่ผ่าน แล้วบันทึกเป็นตัวเลข
  4. ค้นเพิ่มด้วยคำโฆษณาเลี่ยงชื่อ เช่น `Tier-1` `top-tier` `leading banks` `ธนาคารชั้นนำ` บันทึกทุกจุดที่ใช้คำเหล่านี้แทนชื่อจริง
  5. เทียบจำนวนจุดที่ใช้คำเลี่ยงกับจำนวนจุดที่ระบุชื่อจริง บันทึกอัตราส่วน
  6. บันทึกตารางผลรายเกณฑ์พร้อมภาพหลักฐาน และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางผลรายเกณฑ์ 4 ข้อพร้อม Evidence ID (`RST-BRKA-P02-049-01`) · ภาพทุกจุดที่ใช้คำโฆษณาเลี่ยงชื่อ · สำเนาถาวร
- **ผ่าน:** ผ่านเกณฑ์อย่างน้อย 3 ใน 4 ข้อ `[เกณฑ์เสนอ: 3 จาก 4]`
- **ไม่ผ่าน:** ผ่านเกณฑ์น้อยกว่า 3 ข้อ
- **ยังไม่ได้ตรวจ:** ยังเก็บข้อมูลจากข้อ 026 และ 027 ไม่ครบ
- **ตัวอย่าง:** Broker C ระบุชื่อ *ธนาคาร X* และประเทศไว้ในเอกสาร PDF ที่โหลดได้โดยไม่ต้องล็อกอิน แต่ไม่ระบุว่าธนาคารนั้นรับฝากเงินลูกค้าประเภทใด ผ่าน 3 จาก 4 ข้อ → **ผ่าน**

**P02-050 ● · สรุปเส้นทางเงินของลูกค้าที่ตามรอยได้จากหลักฐานของตนเอง** `w3` `รวมทุกวิธี` `G3`

- **ตรวจอะไร:** รวบรวมผลจากข้อ 026–049 ลงตารางเส้นทางเงินเดียว แล้วตอบคำถามชี้ขาด 3 ข้อ: เงินที่เราโอนออกไปถึงนิติบุคคลที่เราทำสัญญาด้วยหรือไม่ · เส้นทางนั้นตามรอยได้ครบจากหลักฐานที่ลูกค้ามีเองหรือไม่ · ทุกตัวกลางบนเส้นทางถูกอธิบายไว้ในเว็บหรือสัญญาหรือไม่ ข้อนี้เป็นข้อสรุปของ S02 และผูกด่าน G3
- **ขั้นตอนการตรวจ:**
  1. สร้างตารางเส้นทางเงินที่มีแถวเป็น 6 จุด: บัญชีต้นทางของเรา · ผู้รับเงินที่ระบบโบรกแจ้ง · ผู้รับที่ธนาคารบันทึกจริง · ธนาคารปลายทาง · รายการที่ปรากฏในพอร์ทัล · ผู้โอนขากลับตอนถอน
  2. เติมชื่อ ประเทศ และ Evidence ID ของแต่ละแถว จากผลข้อ 029 · 030 · 033 · 036 · 037 · 040
  3. ทำเครื่องหมายทุกจุดที่ขาดหลักฐาน หรือที่ชื่อไม่เชื่อมกับจุดก่อนหน้า
  4. ตอบคำถามชี้ขาด 3 ข้อ โดยอ้าง Evidence ID ทุกคำตอบ ห้ามตอบโดยไม่อ้าง
  5. ตรวจว่าผลของข้อ 045 (เขตอำนาจ) และข้อ 047 (ช่องทางฝาก) สอดคล้องกับคำตอบทั้งสามหรือไม่
  6. บันทึกตารางเส้นทางเงินฉบับสมบูรณ์พร้อมคำตัดสิน และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางเส้นทางเงิน 6 จุดพร้อม Evidence ID ทุกแถว (`RST-BRKA-P02-050-01`) · เอกสารคำตอบคำถามชี้ขาด 3 ข้อ · รายการจุดที่ขาดหลักฐาน
- **ผ่าน:** ตอบว่า "ใช่" ครบทั้ง 3 คำถามชี้ขาด โดยแต่ละคำตอบอ้าง Evidence ID ได้
- **ไม่ผ่าน:** ตอบว่า "ไม่ใช่" อย่างน้อย 1 คำถามชี้ขาด
- **ยังไม่ได้ตรวจ:** ยังเก็บข้อมูลไม่ครบ 6 จุด หรือยังไม่ได้ทำการถอนจริง
- **ตัวอย่าง:** ตารางเส้นทางเงินของ Broker B เชื่อมได้ครบจนถึงธนาคารปลายทาง แต่ผู้รับที่ธนาคารบันทึกจริงเป็นนิติบุคคลที่ไม่ปรากฏในเว็บและสัญญา และผู้โอนขากลับเป็นอีกรายหนึ่ง ตอบ "ไม่ใช่" 2 ใน 3 คำถาม → **ไม่ผ่าน** ตกด่าน G3
