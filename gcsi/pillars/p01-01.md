## S01 · การยืนยันใบอนุญาตกับทะเบียนสาธารณะ (001–025)

**P01-001 ● · เว็บไซต์ระบุเลขใบอนุญาตหรือไม่** `w3` `WEB` `G1`

- **ตรวจอะไร:** ตรวจว่าเว็บไซต์สาธารณะของโบรกแสดง "เลขใบอนุญาต" ที่เป็นรหัสเจาะจงหรือไม่ โดยดูที่ footer หน้าแรก หน้า About หน้า Legal และหน้า Regulation บันทึกรหัสที่พบทุกตัวและตำแหน่งที่พบ ไม่นับข้อความลอย ๆ ว่า "ได้รับการกำกับดูแล" ที่ไม่มีรหัสกำกับ
- **ขั้นตอนการตรวจ:**
  1. เปิดเบราว์เซอร์โหมดไม่บันทึกประวัติ เข้าหน้าแรกของโบรกโดยพิมพ์โดเมนเอง **ห้ามเข้าผ่านลิงก์โฆษณาหรือลิงก์แนะนำ**
  2. จับภาพเต็มหน้าแรก (full-page capture) พร้อมให้เห็น URL และนาฬิกาเครื่อง
  3. กด `Ctrl+F` ค้นคำว่า `licence` `license` `ใบอนุญาต` `registration` ทีละคำ บันทึกจำนวนที่พบ
  4. เปิดหน้า About · Legal · Regulation · Terms ทีละหน้า ทำซ้ำขั้น 2–3 กับทุกหน้า
  5. คัดลอกรหัสทุกตัวที่พบลงตารางบันทึก พร้อม URL ของหน้าที่พบ
  6. บันทึกผลและตั้งชื่อไฟล์ตามรูปแบบ Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพเต็มหน้าทุกหน้าที่เปิด (`RST-BRKA-P01-001-01` ถึง `-05`) · ตารางรหัสที่พบพร้อม URL · สำเนาถาวรของหน้าที่พบรหัส
- **ผ่าน:** พบรหัสใบอนุญาตที่เป็นรหัสเจาะจงอย่างน้อย 1 จุดบนเว็บสาธารณะ โดยไม่ต้องล็อกอิน
- **ไม่ผ่าน:** ไม่พบรหัสใด ๆ หรือพบเพียงคำว่า "regulated" / "licensed" ที่ไม่มีรหัสกำกับ
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง — เช่น เว็บล่มตลอดช่วงที่พยายามเข้า
- **ตัวอย่าง:** Broker A เขียนใน footer ว่า *"Regulated broker since 2015"* ค้นทั้งเว็บแล้วไม่พบรหัสใด → **ไม่ผ่าน**

**P01-002 ● · ระบุชื่อหน่วยงานกำกับที่ออกใบอนุญาตชัดเจนหรือไม่** `w3` `WEB` `G1`

- **ตรวจอะไร:** ตรวจว่ารหัสใบอนุญาตที่พบในข้อ 001 มีชื่อหน่วยงานผู้ออกกำกับอยู่ด้วยหรือไม่ ต้องเป็นชื่อเต็มหรือชื่อย่อทางการที่นำไปค้นทะเบียนต่อได้ทันที ไม่ใช่คำกว้างเช่น "หน่วยงานยุโรป" หรือ "หน่วยงานสากล"
- **ขั้นตอนการตรวจ:**
  1. เปิดตารางรหัสจากข้อ 001 ขึ้นมา
  2. ไปที่ตำแหน่งของแต่ละรหัสบนหน้าเว็บจริง แล้วอ่านข้อความในระยะ 2 บรรทัดรอบรหัสนั้น
  3. บันทึกชื่อหน่วยงานที่ปรากฏคู่กับแต่ละรหัส ถ้าไม่มี ให้บันทึกว่า "ไม่ระบุ"
  4. นำชื่อหน่วยงานที่ได้ไปค้นในเครื่องมือค้นหาว่าเป็นหน่วยงานกำกับดูแลทางการเงินจริงหรือไม่ เก็บภาพหน้าทางการของหน่วยงาน
  5. จับภาพให้เห็นรหัสและชื่อหน่วยงานอยู่ในภาพเดียวกัน
  6. บันทึกผลลงแบบฟอร์มและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพที่เห็นรหัสและชื่อหน่วยงานในเฟรมเดียวกัน (`RST-BRKA-P01-002-01`) · ภาพหน้าทางการของหน่วยงาน
- **ผ่าน:** ทุกรหัสที่โชว์มีชื่อหน่วยงานกำกับทางการเงินกำกับอยู่ ทำให้ค้นทะเบียนต่อได้ทันที
- **ไม่ผ่าน:** มีรหัสอย่างน้อย 1 ตัวที่ไม่ระบุหน่วยงาน หรือระบุกว้างจนหาทะเบียนไม่ได้
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** Broker B เขียน *"Licence 284/15"* เฉย ๆ ไม่มีคำว่าหน่วยงานใดในหน้าเดียวกัน → **ไม่ผ่าน**

**P01-003 ● · ระบุชื่อนิติบุคคลที่ถือใบอนุญาตหรือไม่** `w3` `WEB` `G1`

- **ตรวจอะไร:** ตรวจว่าเว็บระบุชื่อ "บริษัท" ผู้ถือใบอนุญาต ไม่ใช่แค่ชื่อแบรนด์ ต้องมีคำต่อท้ายประเภทนิติบุคคล (Ltd · Limited · PLC · Pty · LLC · บจก.) และควรมีเลขทะเบียนบริษัทกำกับ
- **ขั้นตอนการตรวจ:**
  1. เปิด footer หน้าแรกและหน้า Legal
  2. ค้นคำต่อท้ายนิติบุคคลทีละคำ: `Ltd` `Limited` `LLC` `PLC` `Pty` `Inc` `บจก`
  3. บันทึกชื่อนิติบุคคลทุกชื่อที่พบ พร้อมหน้าที่พบ
  4. เทียบชื่อที่พบกับชื่อแบรนด์ที่ใช้ในพาดหัว บันทึกว่าเหมือนหรือต่างกัน
  5. จับภาพข้อความที่ระบุชื่อนิติบุคคลเต็ม
  6. บันทึกผลและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อความชื่อนิติบุคคลเต็ม (`RST-BRKA-P01-003-01`) · รายการชื่อทั้งหมดที่พบ
- **ผ่าน:** พบชื่อนิติบุคคลเต็มพร้อมประเภทนิติบุคคลอย่างน้อย 1 จุด
- **ไม่ผ่าน:** พบเพียงชื่อแบรนด์ ไม่มีจุดใดบอกว่าบริษัทชื่ออะไร
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** เว็บใช้แบรนด์ *BrokerA* ทุกที่ ค้นคำต่อท้ายนิติบุคคลทั้งเว็บแล้วไม่พบเลย → **ไม่ผ่าน**

**P01-004 ● · เลขใบอนุญาตค้นเจอในทะเบียนสาธารณะของหน่วยงานหรือไม่** `w3` `REG` `G1`

- **ตรวจอะไร:** ตรวจว่ารหัสใบอนุญาตที่โบรกอ้าง มีตัวตนอยู่จริงในทะเบียนสาธารณะของหน่วยงานนั้น โดยเข้าเว็บหน่วยงานโดยตรง **ห้าม**เข้าผ่านลิงก์ที่โบรกให้ เพราะลิงก์อาจถูกดัดแปลง
- **ขั้นตอนการตรวจ:**
  1. ค้นชื่อหน่วยงานในเครื่องมือค้นหา แล้วเข้าเว็บทางการของหน่วยงานด้วยตนเอง บันทึกโดเมนที่เข้า
  2. หาเมนูทะเบียนสาธารณะ (register / search firm / ตรวจสอบผู้ประกอบธุรกิจ)
  3. ค้นด้วย **รหัสใบอนุญาต** ก่อน จับภาพหน้าผลลัพธ์
  4. ค้นซ้ำด้วย **ชื่อนิติบุคคล** จับภาพหน้าผลลัพธ์
  5. เทียบว่าผลจากทั้งสองวิธีชี้ไปรายการเดียวกันหรือไม่
  6. บันทึกวันเวลาที่ค้น (UTC) และเก็บสำเนาถาวรของหน้ารายการ
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าผลค้นทั้งสองวิธีที่เห็นโดเมนหน่วยงาน (`RST-BRKA-P01-004-01`, `-02`) · สำเนา PDF ของหน้ารายการ · วันเวลา UTC
- **ผ่าน:** ค้นเจอรายการที่ตรงกับรหัสที่โบรกอ้าง และเป็นกิจการเดียวกัน
- **ไม่ผ่าน:** ค้นไม่เจอ หรือรหัสนั้นเป็นของกิจการอื่น
- **ยังไม่ได้ตรวจ:** ทะเบียนของหน่วยงานนั้นไม่เปิดให้ค้นสาธารณะ (ต้องบันทึกข้อเท็จจริงนี้ไว้ และห้ามตีความเป็นไม่ผ่าน)
- **ตัวอย่าง:** Broker C อ้างรหัส 12345 ค้นในทะเบียนแล้วรหัสนี้เป็นของบริษัทประกันคนละราย → **ไม่ผ่าน**

**P01-005 ● · ชื่อในทะเบียนตรงกับชื่อนิติบุคคลที่เว็บอ้างหรือไม่** `w3` `REG` `G1`

- **ตรวจอะไร:** เทียบชื่อนิติบุคคลในทะเบียนกับชื่อบนเว็บ **ทีละตัวอักษร** รวมคำต่อท้าย เครื่องหมายวรรคตอน และคำในวงเล็บ เพราะกลุ่มบริษัทมักมีหลาย entity ที่ชื่อคล้ายกันมากแต่คนละใบอนุญาต
- **ขั้นตอนการตรวจ:**
  1. คัดลอกชื่อจากทะเบียนเป็นข้อความ (ห้ามพิมพ์เอง เพื่อกันพิมพ์ผิด)
  2. คัดลอกชื่อจากเว็บโบรกเป็นข้อความ
  3. วางทั้งสองในเครื่องมือเทียบข้อความ บันทึกจุดที่ต่างกันทุกจุด
  4. ประเมินว่าจุดที่ต่างเป็นเพียงรูปแบบการเขียน (Ltd/Limited) หรือเปลี่ยนตัวตน (Capital/Markets)
  5. จับภาพสองแหล่งวางคู่กันในภาพเดียว
  6. บันทึกคำตัดสินพร้อมเหตุผลลงแบบฟอร์ม
- **หลักฐานที่ต้องเก็บ:** ภาพเทียบคู่ (`RST-BRKA-P01-005-01`) · ผลการเทียบข้อความที่ระบุจุดต่าง
- **ผ่าน:** ชื่อตรงกัน หรือต่างเฉพาะรูปแบบการเขียนที่ไม่เปลี่ยนตัวตนของนิติบุคคล
- **ไม่ผ่าน:** ต่างกันในระดับที่ถือเป็นคนละนิติบุคคล
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** เว็บเขียน *BrokerA Capital Ltd* ทะเบียนขึ้นเป็น *BrokerA Markets Ltd* → **ไม่ผ่าน** (คนละนิติบุคคล)

**P01-006 ● · สถานะในทะเบียนเป็น "ใช้งานอยู่" หรือไม่** `w3` `REG` `G1`

- **ตรวจอะไร:** อ่านช่องสถานะในรายการทะเบียน ว่าเป็น Authorised / Active / Current หรือเป็น Lapsed / Withdrawn / Suspended / Revoked / Cancelled พร้อมบันทึกวันที่มีผลของสถานะนั้น
- **ขั้นตอนการตรวจ:**
  1. เปิดหน้ารายการของโบรกในทะเบียน
  2. หาช่องสถานะ จับภาพให้เห็นทั้งชื่อบริษัทและสถานะในเฟรมเดียวกัน
  3. บันทึกข้อความสถานะแบบคำต่อคำ ห้ามสรุปเอง
  4. หาวันที่มีผลของสถานะ ถ้ามี บันทึกไว้
  5. เปิดหน้าคำอธิบายความหมายของสถานะในเว็บหน่วยงาน (ถ้ามี) แล้วเก็บภาพไว้ประกอบ
  6. บันทึกวันเวลาที่ตรวจ และเก็บสำเนาถาวร
- **หลักฐานที่ต้องเก็บ:** ภาพที่เห็นสถานะ (`RST-BRKA-P01-006-01`) · ภาพหน้าคำอธิบายสถานะ · สำเนาถาวร
- **ผ่าน:** สถานะเป็นใช้งานอยู่ ณ วันที่ตรวจ
- **ไม่ผ่าน:** สถานะเป็นสิ้นสุด ถูกเพิกถอน หรือถูกระงับ
- **ยังไม่ได้ตรวจ:** ทะเบียนไม่มีช่องสถานะ
- **ตัวอย่าง:** ทะเบียนขึ้นว่า Broker B สถานะ *Suspended* มา 3 เดือน แต่เว็บยังรับเปิดบัญชี → **ไม่ผ่าน** และตกด่าน G1

**P01-007 · วันที่ใบอนุญาตเริ่มมีผลตรงกับที่โบรกโฆษณาหรือไม่** `w2` `REG+WEB`

- **ตรวจอะไร:** เทียบวันที่ได้รับอนุญาตในทะเบียน กับข้อความโฆษณาประเภท "ให้บริการมาตั้งแต่ปี …" หรือ "ประสบการณ์ X ปี" ที่ปรากฏบนเว็บ
- **ขั้นตอนการตรวจ:**
  1. บันทึกวันที่ authorised จากทะเบียน
  2. ค้นทั้งเว็บด้วยคำว่า `since` `established` `ก่อตั้ง` `ตั้งแต่ปี` `ประสบการณ์`
  3. บันทึกทุกปีที่โบรกอ้าง พร้อมหน้าที่พบ
  4. เทียบปีที่อ้างกับวันที่ในทะเบียน คำนวณส่วนต่างเป็นจำนวนปี
  5. ตรวจว่ามีข้อความอธิบายส่วนต่างหรือไม่ (เช่น อ้างปีก่อตั้งกลุ่มบริษัท)
  6. บันทึกผลพร้อมภาพทั้งสองแหล่ง
- **หลักฐานที่ต้องเก็บ:** ภาพวันที่ในทะเบียน · ภาพข้อความโฆษณาทุกจุด (`RST-BRKA-P01-007-01` ถึง `-03`)
- **ผ่าน:** ปีที่อ้างไม่เก่ากว่าวันที่ได้รับอนุญาต หรือเก่ากว่าแต่มีคำอธิบายกำกับในหน้าเดียวกัน
- **ไม่ผ่าน:** อ้างว่าให้บริการนานกว่าที่ใบอนุญาตมีผล โดยไม่มีคำอธิบายใด
- **ยังไม่ได้ตรวจ:** ทะเบียนไม่แสดงวันที่เริ่มมีผล
- **ตัวอย่าง:** Broker C โฆษณา *"Trusted since 2008"* ทะเบียนระบุ authorised ปี 2021 ไม่มีคำอธิบาย → **ไม่ผ่าน**

**P01-008 ● · ทะเบียนแสดงการระงับหรือข้อจำกัดที่ยังมีผลหรือไม่** `w3` `REG` `G1`

- **ตรวจอะไร:** อ่านรายการทะเบียนทั้งหน้า รวมส่วนที่ต้องกดขยาย หาคำว่า restriction · requirement · condition · suspension · variation ที่ยังมีผลอยู่ และอ่านเนื้อหาของแต่ละรายการ
- **ขั้นตอนการตรวจ:**
  1. เปิดหน้ารายการทะเบียน แล้วกดขยายทุกส่วนที่ขยายได้จนไม่เหลือส่วนที่พับอยู่
  2. จับภาพเต็มหน้าหลังขยายครบ
  3. ค้นคำว่า `restriction` `requirement` `condition` `suspension` ทีละคำ
  4. อ่านเนื้อหาของทุกรายการที่พบ บันทึกวันที่มีผลและวันที่สิ้นสุด (ถ้ามี)
  5. นำเนื้อหาแต่ละข้อจำกัดไปค้นบนเว็บโบรก ว่าโบรกเปิดเผยเรื่องนี้หรือไม่
  6. บันทึกตารางเทียบ "ข้อจำกัดในทะเบียน" กับ "การเปิดเผยบนเว็บ"
- **หลักฐานที่ต้องเก็บ:** ภาพเต็มหน้าหลังขยายครบ (`RST-BRKA-P01-008-01`) · ตารางเทียบ · สำเนาถาวร
- **ผ่าน:** ไม่มีข้อจำกัดที่ยังมีผล หรือมีแต่โบรกเปิดเผยไว้บนเว็บอย่างเห็นได้
- **ไม่ผ่าน:** มีข้อจำกัดที่กระทบลูกค้าและยังมีผลอยู่ แต่เว็บไม่เปิดเผยเลย
- **ยังไม่ได้ตรวจ:** ทะเบียนไม่มีส่วนนี้
- **ตัวอย่าง:** ทะเบียนระบุ *ห้ามรับลูกค้ารายใหม่* แต่เว็บยังมีปุ่มสมัครและไม่มีคำใดกล่าวถึง → **ไม่ผ่าน**

**P01-009 · ที่อยู่ในทะเบียนตรงกับที่อยู่บนเว็บหรือไม่** `w2` `REG+WEB`

- **ตรวจอะไร:** เทียบที่อยู่จดทะเบียนในทะเบียนหน่วยงาน กับที่อยู่ที่เว็บแสดงในหน้า Contact และ footer ทั้งชื่อถนน เลขที่ เมือง และประเทศ
- **ขั้นตอนการตรวจ:**
  1. คัดลอกที่อยู่จากทะเบียนเป็นข้อความ
  2. คัดลอกที่อยู่ทุกแห่งที่ปรากฏบนเว็บ (footer · Contact · Legal) เป็นข้อความ
  3. จัดลงตารางเทียบทีละบรรทัด
  4. ถ้าต่างกัน ค้นในเว็บว่ามีคำอธิบายหรือไม่ เช่น "สำนักงานปฏิบัติการ" กับ "สำนักงานจดทะเบียน"
  5. ค้นที่อยู่ที่พบในแผนที่สาธารณะ บันทึกว่าเป็นอาคารสำนักงานหรือเป็นที่อยู่รับจดทะเบียน
  6. บันทึกผลพร้อมภาพทุกแหล่ง
- **หลักฐานที่ต้องเก็บ:** ภาพที่อยู่จากทั้งสองแหล่ง (`RST-BRKA-P01-009-01`, `-02`) · ตารางเทียบ · ภาพผลค้นแผนที่
- **ผ่าน:** ที่อยู่ตรงกัน หรือต่างกันแต่เว็บอธิบายบทบาทของแต่ละที่อยู่ไว้
- **ไม่ผ่าน:** ต่างกันโดยไม่มีคำอธิบาย หรือเว็บแสดงเฉพาะที่อยู่ที่ไม่ใช่ของนิติบุคคลผู้ถือใบอนุญาต
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** ทะเบียนระบุที่อยู่ในไซปรัส เว็บแสดงเฉพาะที่อยู่ในลอนดอนโดยไม่อธิบาย → **ไม่ผ่าน**

**P01-010 ● · โดเมนที่ใช้จริงถูกแจ้งไว้ในทะเบียนหรือไม่** `w3` `REG` `G1`

- **ตรวจอะไร:** ตรวจช่องเว็บไซต์หรือ trading name ในทะเบียน แล้วเทียบกับโดเมนที่เราใช้สมัครจริง — จุดนี้จับโบรกที่ใช้โดเมนโคลนสำหรับตลาดเฉพาะภูมิภาค
- **ขั้นตอนการตรวจ:**
  1. บันทึกโดเมนที่ใช้สมัครจริงแบบเต็ม รวม subdomain
  2. เปิดรายการทะเบียน หาช่อง website / URL / trading name
  3. บันทึกทุกโดเมนที่ทะเบียนแจ้งไว้
  4. เทียบว่าโดเมนที่ใช้จริงอยู่ในรายการหรือไม่
  5. ถ้าไม่อยู่ ให้ตรวจว่าโดเมนที่แจ้งไว้ redirect มาที่โดเมนที่ใช้จริงหรือไม่ บันทึกผล
  6. เก็บภาพและสำเนาถาวรของทั้งสองฝั่ง
- **หลักฐานที่ต้องเก็บ:** ภาพช่องเว็บไซต์ในทะเบียน (`RST-BRKA-P01-010-01`) · URL ที่ใช้สมัคร · บันทึกผล redirect
- **ผ่าน:** โดเมนที่ใช้จริงปรากฏในทะเบียน หรือทะเบียนไม่มีช่องนี้ (ต้องบันทึกว่าไม่มีช่อง)
- **ไม่ผ่าน:** ทะเบียนมีช่องเว็บไซต์ แต่โดเมนที่ใช้จริงไม่อยู่ในนั้นและไม่มี redirect เชื่อมโยง
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** ทะเบียนแจ้ง `brokera.com` แต่ลูกค้าไทยถูกส่งไปสมัครที่ `brokera-th.net` ซึ่งไม่อยู่ในทะเบียน → **ไม่ผ่าน**

**P01-011 · ชื่อทางการค้าที่ใช้ ถูกจดแจ้งไว้หรือไม่** `w2` `REG+WEB`

- **ตรวจอะไร:** กรณีแบรนด์ที่ใช้ไม่ตรงกับชื่อนิติบุคคล ตรวจว่าทะเบียนมีการแจ้งชื่อทางการค้านั้นไว้หรือไม่
- **ขั้นตอนการตรวจ:**
  1. บันทึกชื่อแบรนด์ที่ปรากฏบนพาดหัวเว็บและโลโก้
  2. เทียบกับชื่อนิติบุคคลจากข้อ 003 ถ้าเหมือนกันให้ข้ามไปขั้น 6
  3. เปิดรายการทะเบียน หาส่วน trading names / other names
  4. ค้นชื่อแบรนด์ในส่วนนั้น บันทึกว่าพบหรือไม่
  5. ถ้าไม่พบ ค้นทั้งหน้าทะเบียนอีกครั้งด้วยชื่อแบรนด์เพื่อยืนยัน
  6. บันทึกผลพร้อมภาพส่วน trading names
- **หลักฐานที่ต้องเก็บ:** ภาพส่วน trading names ในทะเบียน (`RST-BRKA-P01-011-01`) · ภาพโลโก้/พาดหัวเว็บ
- **ผ่าน:** แบรนด์ที่ใช้ปรากฏเป็น trading name ในทะเบียน หรือแบรนด์ตรงกับชื่อนิติบุคคลอยู่แล้ว
- **ไม่ผ่าน:** ใช้แบรนด์ที่ไม่เคยแจ้งไว้ในทะเบียน ทั้งที่ทะเบียนมีช่องให้แจ้ง
- **ยังไม่ได้ตรวจ:** ทะเบียนไม่มีส่วน trading names
- **ตัวอย่าง:** *BrokerA Capital Ltd* ทำตลาดในชื่อ *A-Trade* แต่ทะเบียนไม่มีชื่อนี้ในส่วน trading names → **ไม่ผ่าน**

**P01-012 · หมายเลขทะเบียนบริษัทตรวจสอบได้กับนายทะเบียนหรือไม่** `w2` `REG`

- **ตรวจอะไร:** นำหมายเลขจดทะเบียนบริษัท (คนละตัวกับเลขใบอนุญาต) ไปค้นในทะเบียนนิติบุคคลของประเทศที่จดทะเบียน แล้วดูชื่อและสถานะบริษัท
- **ขั้นตอนการตรวจ:**
  1. หาหมายเลขจดทะเบียนบริษัทจาก footer หรือหน้า Legal บันทึกไว้
  2. ระบุประเทศที่จดทะเบียนจากที่อยู่และจากทะเบียนหน่วยงานกำกับ
  3. เข้าเว็บนายทะเบียนบริษัทของประเทศนั้นโดยตรง
  4. ค้นด้วยหมายเลขจดทะเบียน จับภาพผลลัพธ์
  5. อ่านช่องสถานะบริษัท บันทึกข้อความแบบคำต่อคำ
  6. เก็บสำเนาถาวรและบันทึกวันเวลาที่ค้น
- **หลักฐานที่ต้องเก็บ:** ภาพผลค้นจากนายทะเบียนที่เห็นโดเมนทางการ (`RST-BRKA-P01-012-01`) · สำเนาถาวร
- **ผ่าน:** ค้นเจอ ชื่อบริษัทตรงกัน และสถานะเป็นดำเนินกิจการอยู่
- **ไม่ผ่าน:** ค้นไม่เจอ หรือสถานะเป็นเลิกกิจการ / อยู่ระหว่างชำระบัญชี
- **ยังไม่ได้ตรวจ:** ประเทศนั้นไม่มีทะเบียนนิติบุคคลที่ค้นสาธารณะได้
- **ตัวอย่าง:** นายทะเบียนแสดงสถานะ *Dissolved* แต่เว็บยังเปิดรับลูกค้า → **ไม่ผ่าน**

**P01-013 ● · ใบอนุญาตครอบคลุมการให้บริการ CFD หรือไม่** `w3` `REG` `G1`

- **ตรวจอะไร:** อ่านรายการกิจกรรมหรือสิทธิที่ได้รับอนุญาตในทะเบียน แล้วตรวจว่าครอบคลุมการซื้อขายตราสารอนุพันธ์ประเภท CFD ตามที่ให้บริการจริงหรือไม่
- **ขั้นตอนการตรวจ:**
  1. เปิดส่วน permissions / activities / ขอบเขตการประกอบธุรกิจ ในรายการทะเบียน
  2. คัดลอกรายการทั้งหมดเป็นข้อความ ห้ามสรุปย่อ
  3. เปิดแพลตฟอร์มของโบรก บันทึกประเภทตราสารที่เปิดให้เทรดจริง
  4. ทำตารางสองคอลัมน์: สิ่งที่อนุญาต กับ สิ่งที่ให้บริการจริง
  5. ทำเครื่องหมายทุกแถวที่ให้บริการจริงแต่ไม่ปรากฏในสิทธิที่อนุญาต
  6. บันทึกตารางและภาพหลักฐานทั้งสองฝั่ง
- **หลักฐานที่ต้องเก็บ:** ภาพส่วน permissions (`RST-BRKA-P01-013-01`) · ภาพรายการสินค้าในแพลตฟอร์ม · ตารางเทียบ
- **ผ่าน:** สิทธิที่ได้รับครอบคลุมการซื้อขายอนุพันธ์/CFD ตามที่ให้บริการจริง
- **ไม่ผ่าน:** ให้บริการ CFD ขณะที่สิทธิครอบคลุมเฉพาะกิจกรรมอื่น
- **ยังไม่ได้ตรวจ:** ทะเบียนไม่ระบุรายละเอียดขอบเขต
- **ตัวอย่าง:** Broker B ถือใบอนุญาตประเภทผู้ให้บริการชำระเงิน แต่แพลตฟอร์มเปิดให้เทรด CFD → **ไม่ผ่าน** ตกด่าน G1

**P01-014 ● · ได้รับอนุญาตให้ถือเงินลูกค้าหรือไม่** `w3` `REG` `G1`

- **ตรวจอะไร:** ตรวจว่าทะเบียนระบุสิทธิถือหรือควบคุมเงินลูกค้าหรือไม่ แล้วเทียบกับข้อเท็จจริงว่าโบรกรับเงินเข้าบัญชีของตนเองจริงหรือไม่
- **ขั้นตอนการตรวจ:**
  1. ค้นในส่วน permissions ด้วยคำว่า `client money` `client assets` `safeguarding` `ถือทรัพย์สินลูกค้า`
  2. บันทึกข้อความที่พบ หรือบันทึกว่า "ไม่พบ"
  3. เปิดหน้าฝากเงินของโบรก บันทึกว่าเงินถูกโอนเข้าบัญชีของใคร
  4. เทียบสองสิ่งนี้: มีสิทธิถือเงินลูกค้าหรือไม่ กับ รับเงินเข้าบัญชีตนเองหรือไม่
  5. ถ้าไม่มีสิทธิแต่รับเงิน ให้ค้นเพิ่มว่ามีการอธิบายโครงสร้างอื่นหรือไม่ (เช่น ใช้สถาบันรับฝากบุคคลที่สาม)
  6. บันทึกผลพร้อมภาพทั้งสองฝั่ง
- **หลักฐานที่ต้องเก็บ:** ภาพส่วน permissions (`RST-BRKA-P01-014-01`) · ภาพหน้าฝากเงินที่เห็นชื่อผู้รับ
- **ผ่าน:** มีสิทธิถือเงินลูกค้าและรับเงินเข้าบัญชีตนเอง หรือไม่มีสิทธิแต่ไม่ได้รับเงินเข้าบัญชีตนเองและอธิบายโครงสร้างไว้
- **ไม่ผ่าน:** ไม่มีสิทธิถือเงินลูกค้า แต่รับเงินเข้าบัญชีของตนเองโดยไม่มีคำอธิบาย
- **ยังไม่ได้ตรวจ:** ทะเบียนไม่ระบุรายละเอียดสิทธิระดับนี้
- **ตัวอย่าง:** ทะเบียนระบุ *Client money: No* แต่ลูกค้าโอนเงินเข้าบัญชีชื่อโบรกโดยตรง → **ไม่ผ่าน**

**P01-015 · ทะเบียนระบุว่าโบรกซื้อขายเพื่อบัญชีตนเองหรือไม่ และตรงกับที่โฆษณาหรือไม่** `w2` `REG+DOC+WEB`

- **ขั้นตอนการตรวจ:**
  1. ค้นในส่วน permissions ด้วยคำว่า `own account` `principal` `dealing`
  2. ค้นทั้งเว็บด้วยคำว่า `STP` `no dealing desk` `NDD` `ECN` `ไม่มีเดสก์`
  3. เปิดเอกสาร Order Execution Policy ค้นคำว่า `principal` `counterparty` `คู่สัญญา`
  4. ทำตารางสามคอลัมน์: ทะเบียนระบุอะไร · เว็บโฆษณาอะไร · สัญญาเขียนอะไร
  5. ทำเครื่องหมายจุดที่ขัดกัน
  6. บันทึกตารางพร้อมภาพทั้งสามแหล่ง
- **หลักฐานที่ต้องเก็บ:** ภาพสามแหล่ง (`RST-BRKA-P01-015-01` ถึง `-03`) · ตารางเทียบสามคอลัมน์
- **ผ่าน:** ทั้งสามแหล่งสอดคล้องกัน
- **ไม่ผ่าน:** โฆษณาว่าไม่เป็นคู่สัญญา ขณะที่ทะเบียนและ/หรือสัญญาระบุว่าเป็น principal
- **ยังไม่ได้ตรวจ:** ไม่มีเอกสาร Order Execution Policy ให้เข้าถึง
- **ตัวอย่าง:** Broker C โฆษณา *"100% STP"* แต่ทะเบียนระบุ dealing on own account และสัญญาเขียนว่าโบรกเป็น principal ทุกรายการ → **ไม่ผ่าน**

**P01-016 · ข้อจำกัดแนบท้ายใบอนุญาตถูกเปิดเผยต่อลูกค้าหรือไม่** `w3` `REG+WEB`

  1. เปิดตารางข้อจำกัดจากข้อ 008
  2. สำหรับแต่ละข้อจำกัด ค้นคำสำคัญของข้อนั้นในเว็บโบรกทั้งเว็บ
  3. ค้นซ้ำในเอกสารสัญญาและเอกสารเปิดเผยข้อมูล
  4. บันทึกว่าพบการเปิดเผยที่หน้าใด และต้องคลิกกี่ครั้งจากหน้าแรกจึงถึง
  5. ประเมินว่าจุดที่เปิดเผยอยู่ก่อนหรือหลังจุดตัดสินใจสมัคร
  6. บันทึกผลรายข้อจำกัด
- **หลักฐานที่ต้องเก็บ:** ตารางข้อจำกัดพร้อมสถานะการเปิดเผย · ภาพจุดที่เปิดเผย (ถ้ามี)
- **ผ่าน:** ทุกข้อจำกัดที่กระทบลูกค้าถูกเปิดเผยในจุดที่เห็นก่อนสมัคร
- **ไม่ผ่าน:** มีข้อจำกัดที่กระทบลูกค้าอย่างน้อย 1 ข้อที่ไม่ถูกเปิดเผยเลย
- **ยังไม่ได้ตรวจ:** ไม่พบข้อจำกัดใดในทะเบียน (ให้บันทึกว่าไม่มีข้อจำกัด แล้วข้อนี้ถือว่าไม่เกี่ยวข้อง)
- **ตัวอย่าง:** ทะเบียนระบุห้ามรับลูกค้ารายใหม่จนกว่าจะแก้ไขเงินกองทุน เว็บไม่มีคำใดกล่าวถึงและยังมีปุ่มสมัคร → **ไม่ผ่าน**

**P01-017 · การให้บริการข้ามพรมแดนถูกแจ้งไว้หรือไม่** `w2` `REG+ACC`

- **ตรวจอะไร:** ถ้าโบรกรับลูกค้าจากประเทศอื่นนอกประเทศที่ออกใบอนุญาต ตรวจว่ามีการแจ้งการให้บริการข้ามพรมแดนไว้กับหน่วยงานหรือไม่ และประเทศของบัญชีทดสอบอยู่ในรายชื่อหรือไม่
- **ขั้นตอนการตรวจ:**
  1. บันทึกประเทศที่ใช้สมัครบัญชีทดสอบ
  2. เปิดรายการทะเบียน หาส่วน passporting / cross-border / EEA services
  3. คัดลอกรายชื่อประเทศที่แจ้งไว้ทั้งหมด
  4. ตรวจว่าประเทศของบัญชีทดสอบอยู่ในรายชื่อหรือไม่
  5. ถ้าไม่อยู่ ค้นในเว็บหน่วยงานว่าระบบกำกับนั้นกำหนดให้ต้องแจ้งหรือไม่ เก็บภาพหน้าที่อธิบาย
  6. บันทึกผลพร้อมหลักฐานทั้งหมด
- **หลักฐานที่ต้องเก็บ:** ภาพรายชื่อประเทศในทะเบียน (`RST-BRKA-P01-017-01`) · ภาพหน้ากฎเกณฑ์ของหน่วยงาน
- **ผ่าน:** ประเทศของบัญชีทดสอบอยู่ในรายชื่อที่แจ้งไว้ หรือระบบกำกับนั้นไม่กำหนดให้ต้องแจ้ง
- **ไม่ผ่าน:** รับลูกค้าจากประเทศที่ไม่ได้แจ้งไว้ ทั้งที่ระบบกำกับกำหนดให้ต้องแจ้ง
- **ยังไม่ได้ตรวจ:** ทะเบียนไม่มีส่วนนี้และหาข้อกำหนดไม่พบ
- **ตัวอย่าง:** ทะเบียนแจ้งให้บริการเฉพาะ 4 ประเทศ แต่ Broker A เปิดบัญชีให้ผู้สมัครจากประเทศที่ 5 ได้ทันที → **ไม่ผ่าน**

**P01-018 · หลักฐานทะเบียนทุกชิ้นมีวันเวลากำกับหรือไม่** `w1` `REG`

- **ตรวจอะไร:** ตรวจกระบวนการของผู้ตรวจเอง ว่าหลักฐานทะเบียนทุกไฟล์มีวันเวลาที่เข้าดูกำกับ และตรงกับที่บันทึกในทะเบียนหลักฐาน
- **ขั้นตอนการตรวจ:**
  1. รวบรวมไฟล์หลักฐานทะเบียนทั้งหมดของโบรกรายนี้
  2. เปิดทีละไฟล์ ตรวจว่าเห็นนาฬิกาเครื่องหรือมีวันเวลาฝังในภาพหรือไม่
  3. เทียบวันเวลาในไฟล์กับที่บันทึกในทะเบียนหลักฐาน
  4. ตรวจ metadata ของไฟล์ว่าตรงกับวันเวลาที่อ้าง
  5. ทำเครื่องหมายไฟล์ที่ขาดวันเวลาหรือไม่ตรงกัน
  6. บันทึกผลลงแบบฟอร์มควบคุมคุณภาพหลักฐาน
- **หลักฐานที่ต้องเก็บ:** ตารางตรวจสอบไฟล์ทั้งหมดพร้อมสถานะ
- **ผ่าน:** ทุกไฟล์มีวันเวลากำกับและตรงกับทะเบียนหลักฐาน
- **ไม่ผ่าน:** มีอย่างน้อย 1 ไฟล์ที่ไม่มีวันเวลา หรือวันเวลาไม่ตรงกับที่บันทึก
- **ยังไม่ได้ตรวจ:** ยังไม่ได้เก็บหลักฐานทะเบียนใด ๆ
- **ตัวอย่าง:** ภาพทะเบียน 2 จาก 7 ไฟล์ไม่มีวันเวลา ทำให้อีก 6 เดือนพิสูจน์ไม่ได้ว่าตอนนั้นสถานะเป็นอย่างไร → **ไม่ผ่าน**

**P01-019 · เก็บสำเนาถาวรของหน้าทะเบียนหรือไม่** `w2` `REG`

- **ตรวจอะไร:** ตรวจว่าหน้าทะเบียนถูกเก็บเป็นสำเนาถาวรที่พิสูจน์เนื้อหา ณ วันตรวจได้ ไม่ใช่เก็บแค่ลิงก์สดที่เนื้อหาเปลี่ยนได้
- **ขั้นตอนการตรวจ:**
  1. สำหรับทุกหน้าทะเบียนที่ใช้เป็นหลักฐาน ตรวจว่ามีไฟล์ PDF หรือสำเนา archive หรือไม่
  2. เปิดไฟล์สำเนาแต่ละไฟล์ ตรวจว่าเนื้อหาครบและอ่านได้
  3. คำนวณ hash ของแต่ละไฟล์ บันทึกลงทะเบียนหลักฐาน
  4. ตรวจว่าแต่ละไฟล์มี Evidence ID ตามรูปแบบ
  5. ทำเครื่องหมายหน้าที่มีแต่ลิงก์ ไม่มีสำเนา
  6. บันทึกผลลงแบบฟอร์มควบคุมคุณภาพหลักฐาน
- **หลักฐานที่ต้องเก็บ:** ไฟล์สำเนาถาวรทุกหน้า · ตาราง hash · ทะเบียนหลักฐาน
- **ผ่าน:** ทุกหน้าทะเบียนที่ใช้อ้างอิงมีสำเนาถาวรพร้อม hash และ Evidence ID
- **ไม่ผ่าน:** มีหน้าที่เก็บแต่ลิงก์สดโดยไม่มีสำเนา
- **ยังไม่ได้ตรวจ:** ยังไม่ได้เข้าถึงทะเบียน
- **ตัวอย่าง:** ตรวจรอบสองพบว่าหน้าทะเบียนถูกอัปเดต และไม่มีสำเนาเก่าไว้เทียบ → **ไม่ผ่าน**

**P01-020 · ตรวจซ้ำรอบถัดไปแล้วสถานะยังคงเดิมหรือไม่** `w2` `REG`

- **ตรวจอะไร:** ตรวจทะเบียนซ้ำในรอบถัดไป แล้วเทียบกับสำเนารอบก่อน เพื่อจับการเปลี่ยนสถานะที่โบรกไม่แจ้งลูกค้า
- **ขั้นตอนการตรวจ:**
  1. กำหนดวันตรวจซ้ำตามรอบที่ประกาศ `[เกณฑ์เสนอ: ทุก 90 วัน]`
  2. ทำขั้นตอนของข้อ 004 และ 006 ซ้ำทั้งชุด
  3. เปิดสำเนารอบก่อนขึ้นมาวางเทียบทีละช่อง
  4. บันทึกทุกช่องที่เปลี่ยนแปลง พร้อมวันที่ของทั้งสองรอบ
  5. ถ้ามีการเปลี่ยนแปลง ค้นในกล่องอีเมลของบัญชีทดสอบว่าโบรกแจ้งหรือไม่ และแจ้งวันไหน
  6. บันทึกตารางเทียบและผลการค้นอีเมล
- **หลักฐานที่ต้องเก็บ:** สำเนาสองรอบ · ตารางเทียบช่องที่เปลี่ยน · ภาพกล่องอีเมลที่ค้นแล้ว
- **ผ่าน:** สถานะยังใช้งานอยู่ทั้งสองรอบ หรือเปลี่ยนแปลงแต่โบรกแจ้งลูกค้าก่อนหรือในวันที่มีผล
- **ไม่ผ่าน:** สถานะเปลี่ยนไปในทางแย่ลง โดยไม่มีการแจ้งลูกค้า
- **ยังไม่ได้ตรวจ:** ยังไม่ถึงรอบตรวจซ้ำ
- **ตัวอย่าง:** ไตรมาสถัดมาสถานะเปลี่ยนเป็น *Restricted* ค้นกล่องอีเมลแล้วไม่พบการแจ้งใด → **ไม่ผ่าน**

**P01-021 ● · นิติบุคคลอยู่ระหว่างล้มละลายหรือชำระบัญชีหรือไม่** `w3` `REG+PUB` `G1`

- **ตรวจอะไร:** ค้นสถานะทางกฎหมายของนิติบุคคลจากทะเบียนบริษัทและประกาศสาธารณะ หาคำว่า liquidation · administration · insolvency · receivership ที่ยังมีผลอยู่
- **ขั้นตอนการตรวจ:**
  1. เปิดรายการในทะเบียนนิติบุคคลจากข้อ 012
  2. อ่านช่องสถานะและส่วนประกาศ บันทึกข้อความคำต่อคำ
  3. ค้นชื่อนิติบุคคลในเครื่องมือค้นหาร่วมกับคำว่า `liquidation` `insolvency` `administration`
  4. เปิดเฉพาะผลลัพธ์ที่มาจากแหล่งทางการหรือประกาศราชการ เก็บภาพและ URL
  5. ตรวจว่าประกาศที่พบยังมีผลอยู่หรือถูกยกเลิกแล้ว
  6. บันทึกผลพร้อมหลักฐานทุกชิ้น
- **หลักฐานที่ต้องเก็บ:** ภาพทะเบียนบริษัท (`RST-BRKA-P01-021-01`) · ภาพประกาศทางการถ้ามี · รายการ URL ทั้งหมดที่ตรวจ
- **ผ่าน:** ไม่ปรากฏสถานะล้มละลายหรือชำระบัญชีที่ยังมีผล
- **ไม่ผ่าน:** ปรากฏสถานะดังกล่าวและยังมีผลอยู่
- **ยังไม่ได้ตรวจ:** ไม่มีทะเบียนหรือประกาศสาธารณะให้ค้นในเขตนั้น
- **ตัวอย่าง:** นายทะเบียนขึ้นว่า Broker C เข้าสู่กระบวนการ administration แล้ว แต่เว็บยังรับฝากเงิน → **ไม่ผ่าน** ตกด่าน G1

**P01-022 · ผู้ให้บริการเป็นตัวแทนของผู้ถือใบอนุญาตรายอื่นหรือไม่** `w3` `REG+WEB`

- **ตรวจอะไร:** ตรวจว่ารายการในทะเบียนเป็นผู้ถือใบอนุญาตเอง หรือเป็นตัวแทน/ผู้แนะนำที่ดำเนินการภายใต้ใบอนุญาตของรายอื่น และโบรกสื่อสารเรื่องนี้อย่างไร
- **ขั้นตอนการตรวจ:**
  1. อ่านประเภทของรายการในทะเบียน ค้นคำว่า `appointed representative` `tied agent` `introducing` `ตัวแทน`
  2. บันทึกประเภทที่พบ
  3. ถ้าเป็นตัวแทน ค้นชื่อผู้ถือใบอนุญาตหลักในทะเบียน แล้วเปิดรายการของรายนั้นด้วย
  4. กลับมาที่เว็บโบรก อ่านว่าโบรกอธิบายสถานะตนเองอย่างไร
  5. ทำตารางเทียบ: สถานะจริงในทะเบียน กับ สถานะที่สื่อสารบนเว็บ
  6. บันทึกผลพร้อมภาพทั้งสองฝั่ง
- **หลักฐานที่ต้องเก็บ:** ภาพประเภทรายการในทะเบียน (`RST-BRKA-P01-022-01`) · ภาพข้อความบนเว็บ · ตารางเทียบ
- **ผ่าน:** เป็นผู้ถือใบอนุญาตเอง หรือเป็นตัวแทนและเปิดเผยสถานะนี้ชัดเจนบนเว็บ
- **ไม่ผ่าน:** เป็นตัวแทนแต่สื่อสารในลักษณะที่ทำให้เข้าใจว่าตนถือใบอนุญาตเอง
- **ยังไม่ได้ตรวจ:** ทะเบียนไม่แยกประเภทรายการ
- **ตัวอย่าง:** เว็บเขียน *"เราได้รับใบอนุญาตเลขที่ X"* ทั้งที่เลข X เป็นของบริษัทแม่ และตนเองเป็นเพียงตัวแทน → **ไม่ผ่าน**

**P01-023 · ถ้าเป็นตัวแทน มีการระบุผู้รับผิดชอบต่อลูกค้าหรือไม่** `w2` `WEB+DOC`

- **ตรวจอะไร:** กรณีเป็นตัวแทน ตรวจว่าเว็บและสัญญาระบุชื่อผู้ถือใบอนุญาตหลักที่รับผิดชอบต่อลูกค้า และช่องทางร้องเรียนไปยังรายนั้นหรือไม่
- **ขั้นตอนการตรวจ:**
  1. ถ้าข้อ 022 พบว่าเป็นตัวแทน ให้ทำข้อนี้ต่อ ถ้าไม่ใช่ ให้บันทึกว่าไม่เกี่ยวข้อง
  2. ค้นชื่อผู้ถือใบอนุญาตหลักในเว็บโบรกทั้งเว็บ
  3. ค้นชื่อเดียวกันในเอกสารสัญญาและนโยบายข้อร้องเรียน
  4. ตรวจว่ามีช่องทางร้องเรียนไปยังผู้ถือใบอนุญาตหลักระบุไว้หรือไม่
  5. บันทึกจุดที่พบและจำนวนคลิกจากหน้าแรก
  6. บันทึกผลพร้อมภาพหลักฐาน
- **หลักฐานที่ต้องเก็บ:** ภาพจุดที่ระบุผู้รับผิดชอบ · ภาพส่วนช่องทางร้องเรียน
- **ผ่าน:** ระบุชื่อผู้รับผิดชอบหลักและช่องทางร้องเรียนไปยังรายนั้นอย่างชัดเจน
- **ไม่ผ่าน:** ไม่ระบุ ทำให้ลูกค้าไม่รู้ว่าจะเรียกร้องกับใคร
- **ยังไม่ได้ตรวจ:** ยังไม่ได้ผลจากข้อ 022
- **ตัวอย่าง:** เว็บบอกแค่ *"ดำเนินการภายใต้ใบอนุญาตของพันธมิตร"* โดยไม่บอกชื่อและไม่มีช่องทางร้องเรียน → **ไม่ผ่าน**

**P01-024 ● · มีการอ้างใบอนุญาตที่หมดอายุหรือถูกเพิกถอนแล้วหรือไม่** `w3` `WEB+REG`

- **ตรวจอะไร:** นำรหัสใบอนุญาตทุกตัวที่พบบนเว็บ (บางเว็บโชว์หลายเลข) ไปตรวจทีละตัว เพื่อจับกรณีที่ยังโชว์ใบอนุญาตเก่าที่หมดผลแล้ว
- **ขั้นตอนการตรวจ:**
  1. เปิดตารางรหัสทั้งหมดจากข้อ 001
  2. สำหรับแต่ละรหัส ทำขั้นตอนของข้อ 004 และ 006 ซ้ำ
  3. บันทึกสถานะของแต่ละรหัสลงตาราง
  4. สำหรับรหัสที่หมดอายุหรือถูกเพิกถอน กลับไปดูตำแหน่งที่โชว์บนเว็บ
  5. อ่านข้อความรอบรหัสนั้น ว่ามีคำกำกับว่าเป็นข้อมูลในอดีตหรือไม่

- **หลักฐานที่ต้องเก็บ:** ตารางรหัสทั้งหมดพร้อมสถานะ · ภาพทะเบียนของแต่ละรหัส · ภาพตำแหน่งที่โชว์บนเว็บ
- **ผ่าน:** ทุกรหัสที่โชว์ยังมีผลอยู่ หรือรหัสที่หมดผลมีคำกำกับชัดว่าเป็นข้อมูลในอดีต
- **ไม่ผ่าน:** มีรหัสที่หมดผลแสดงอยู่โดยไม่มีคำกำกับ
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** Broker A โชว์สองรหัสเรียงกันในกล่องเดียว โดยรหัสที่สองถูกเพิกถอนไปแล้วและไม่มีคำกำกับใด → **ไม่ผ่าน**

**P01-025 ● · มีการอ้างหน่วยงานที่ไม่ใช่หน่วยงานกำกับการเงินหรือไม่** `w3` `WEB+PUB`

  3. สำหรับแต่ละหน่วยงาน เปิดเว็บทางการของหน่วยงานนั้น อ่านส่วนอำนาจหน้าที่
  4. จำแนกแต่ละรายการเป็น: หน่วยงานกำกับการเงิน · นายทะเบียนบริษัท · สมาคมสมัครใจ · อื่น ๆ
  5. ตรวจว่ารายการที่ไม่ใช่หน่วยงานกำกับการเงิน มีคำกำกับบอกไว้หรือไม่
  6. บันทึกตารางจำแนกพร้อมภาพหลักฐาน
- **หลักฐานที่ต้องเก็บ:** ภาพทุกกล่องการกำกับดูแล (`RST-BRKA-P01-025-01` เป็นต้นไป) · ตารางจำแนกหน่วยงาน · ภาพหน้าอำนาจหน้าที่ของแต่ละหน่วยงาน
- **ผ่าน:** ทุกรายการในกล่องการกำกับดูแลเป็นหน่วยงานกำกับการเงินจริง หรือรายการที่ไม่ใช่มีคำกำกับบอกไว้
- **ไม่ผ่าน:** มีการจดทะเบียนทั่วไปหรือสมาชิกภาพสมาคม วางอยู่ในบริบทที่ทำให้เข้าใจว่าเป็นการกำกับทางการเงิน
- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** Broker B โชว์ *"Registered Company No. 5567"* ในกล่องที่พาดหัวว่า *Regulation* เรียงติดกับใบอนุญาตจริง → **ไม่ผ่าน**

## S02 · นิติบุคคลคู่สัญญาที่แท้จริง (026–050)

**P01-026 ● · สัญญาลูกค้าระบุชื่อนิติบุคคลคู่สัญญาหรือไม่** `w3` `DOC` `G1`

- **ตรวจอะไร:** เปิด Client Agreement ที่ได้ระหว่างสมัคร อ่านย่อหน้าคู่สัญญาและส่วนนิยาม ตรวจว่าระบุชื่อนิติบุคคลเต็ม เลขทะเบียน และที่อยู่หรือไม่
- **ขั้นตอนการตรวจ:**

  2. เปิดไฟล์ ค้นคำว่า `between` `the Company` `ระหว่าง` `บริษัท`
  3. อ่านส่วนนิยาม (Definitions) หาคำนิยามของคำที่ใช้แทนตัวโบรก
  4. บันทึกชื่อนิติบุคคล เลขทะเบียน และที่อยู่ที่พบ พร้อมเลขข้อและเลขหน้า
  5. ถ้าไม่พบ ให้ค้นทั้งไฟล์ด้วยคำต่อท้ายนิติบุคคลอีกครั้งเพื่อยืนยัน
  6. จับภาพหน้าที่ระบุคู่สัญญา และบันทึกผล
- **หลักฐานที่ต้องเก็บ:** ไฟล์ PDF สัญญาทั้งฉบับ (`RST-BRKA-P01-026-01`) · ภาพหน้าที่ระบุคู่สัญญาพร้อมเลขหน้า
- **ผ่าน:** ระบุชื่อนิติบุคคลเต็ม พร้อมเลขทะเบียนและที่อยู่
- **ไม่ผ่าน:** ใช้แค่ชื่อแบรนด์ หรือใช้คำแทนโดยไม่มีที่ใดนิยามว่าเป็นนิติบุคคลใด
- **ยังไม่ได้ตรวจ:** ระบบไม่ให้เข้าถึงสัญญาก่อนฝากเงิน (ต้องบันทึกข้อเท็จจริงนี้ และไปเชื่อมกับข้อ 070)
- **ตัวอย่าง:** สัญญาขึ้นต้นว่า *"ข้อตกลงนี้ทำระหว่างท่านกับ BrokerA"* ค้นทั้งฉบับไม่มีที่ใดนิยาม BrokerA → **ไม่ผ่าน**

**P01-027 ● · นิติบุคคลคู่สัญญาเป็นรายเดียวกับผู้ถือใบอนุญาตที่โฆษณาหรือไม่** `w3` `DOC+REG` `G1`

- **ตรวจอะไร:** เทียบชื่อคู่สัญญาในสัญญาจริง กับชื่อผู้ถือใบอนุญาตที่โฆษณาบนเว็บ — นี่คือจุดที่โบรกความเสี่ยงสูงมักไม่ตรงกัน และเป็นด่านบังคับ
- **ขั้นตอนการตรวจ:**
  1. คัดลอกชื่อคู่สัญญาจากสัญญาเป็นข้อความ
  2. คัดลอกชื่อผู้ถือใบอนุญาตที่โฆษณาบนเว็บเป็นข้อความ
  3. เทียบทีละตัวอักษรด้วยเครื่องมือเทียบข้อความ
  4. ถ้าต่างกัน ค้นชื่อคู่สัญญาในทะเบียนหน่วยงานกำกับ ว่ามีใบอนุญาตหรือไม่
  5. ถ้าไม่มีใบอนุญาต ค้นต่อว่าอยู่ในเขตอำนาจใดและมีการกำกับใดหรือไม่
  6. บันทึกตารางสรุปพร้อมภาพทั้งสองแหล่งวางคู่กัน
- **หลักฐานที่ต้องเก็บ:** ภาพเทียบคู่ (`RST-BRKA-P01-027-01`) · ผลค้นทะเบียนของชื่อคู่สัญญา · ตารางสรุป
- **ผ่าน:** คู่สัญญาเป็นนิติบุคคลรายเดียวกับผู้ถือใบอนุญาตที่โฆษณา
- **ไม่ผ่าน:** โฆษณาใบอนุญาตของบริษัทหนึ่ง แต่ให้เซ็นสัญญากับอีกบริษัทที่ไม่มีใบอนุญาตนั้น
- **ยังไม่ได้ตรวจ:** ยังไม่ได้รับสัญญา
- **ตัวอย่าง:** เว็บโฆษณาใบอนุญาตของ *BrokerA (Europe) Ltd* แต่สัญญาที่ให้เซ็นเป็นของ *BrokerA Global LLC* ในเขตที่ไม่มีการกำกับ → **ไม่ผ่าน** ตกด่าน G1

**P01-028 · สัญญาระบุกฎหมายที่ใช้บังคับหรือไม่** `w2` `DOC`

- **ตรวจอะไร:** หาข้อ Governing Law ในสัญญา ตรวจว่าระบุเขตอำนาจกฎหมายที่ใช้บังคับหรือไม่ และเขตนั้นสอดคล้องกับที่ตั้งของนิติบุคคลหรือไม่
- **ขั้นตอนการตรวจ:**
  1. ค้นในสัญญาด้วยคำว่า `governing law` `applicable law` `กฎหมายที่ใช้บังคับ`
  2. บันทึกเขตอำนาจที่ระบุ พร้อมเลขข้อและเลขหน้า
  3. เทียบกับประเทศที่นิติบุคคลจดทะเบียนและถูกกำกับ
  4. ถ้าต่างกัน บันทึกส่วนต่างและค้นว่าสัญญาอธิบายเหตุผลหรือไม่
  5. จับภาพข้อสัญญานั้น
  6. บันทึกผลลงแบบฟอร์ม
- **หลักฐานที่ต้องเก็บ:** ภาพข้อ Governing Law พร้อมเลขข้อ (`RST-BRKA-P01-028-01`)
- **ผ่าน:** ระบุเขตอำนาจที่มีตัวตนจริงและชัดเจน
- **ไม่ผ่าน:** ไม่ระบุเลย
- **ยังไม่ได้ตรวจ:** ยังไม่ได้รับสัญญา
- **ตัวอย่าง:** ค้นทั้งฉบับไม่พบข้อ governing law ทำให้ไม่รู้ว่าถ้ามีข้อพิพาทจะใช้กฎหมายใด → **ไม่ผ่าน**

**P01-029 · สัญญาระบุกระบวนการระงับข้อพิพาทที่ลูกค้าเข้าถึงได้จริงหรือไม่** `w2` `DOC`

- **ตรวจอะไร:** อ่านข้อ Jurisdiction / Dispute Resolution ตรวจว่าลูกค้าต้องไปฟ้องที่ไหน ต้องใช้อนุญาโตตุลาการหรือไม่ และค่าใช้จ่ายเริ่มต้นเทียบกับเงินฝากขั้นต่ำเป็นอย่างไร
- **ขั้นตอนการตรวจ:**
  1. ค้นในสัญญาด้วยคำว่า `jurisdiction` `arbitration` `dispute` `ระงับข้อพิพาท`
  2. บันทึกสถานที่และกระบวนการที่ระบุ พร้อมเลขข้อ
  3. บันทึกเงินฝากขั้นต่ำที่โบรกกำหนดจากหน้าเว็บ
  4. ถ้าเป็นอนุญาโตตุลาการ ค้นค่าธรรมเนียมเริ่มต้นจากเว็บทางการของสถาบันอนุญาโตตุลาการนั้น เก็บภาพ
  5. คำนวณอัตราส่วน ค่าธรรมเนียมเริ่มต้น ต่อ เงินฝากขั้นต่ำ
  6. บันทึกผลพร้อมหลักฐานทุกชิ้น
- **หลักฐานที่ต้องเก็บ:** ภาพข้อสัญญา · ภาพหน้าค่าธรรมเนียมของสถาบันอนุญาโตตุลาการ · ตารางคำนวณอัตราส่วน
- **ผ่าน:** ระบุชัด และค่าใช้จ่ายเริ่มต้นไม่เกินเกณฑ์ที่ประกาศ `[เกณฑ์เสนอ: ไม่เกินเงินฝากขั้นต่ำ]`
- **ไม่ผ่าน:** ค่าใช้จ่ายเริ่มต้นสูงกว่าเกณฑ์จนปิดทางเรียกร้องในทางปฏิบัติ หรือไม่ระบุกระบวนการเลย
- **ยังไม่ได้ตรวจ:** หาข้อมูลค่าธรรมเนียมของสถาบันอนุญาโตตุลาการไม่ได้
- **ตัวอย่าง:** สัญญากำหนดอนุญาโตตุลาการต่างประเทศที่ค่าธรรมเนียมเริ่มต้นสูงกว่าเงินฝากขั้นต่ำหลายเท่า → **ไม่ผ่าน**

**P01-030 · นิติบุคคลคู่สัญญาเปลี่ยนระหว่างขั้นตอนสมัครหรือไม่** `w3` `ACC+DOC`

  2. จับภาพทุกหน้าจอตามลำดับ ตั้งชื่อไฟล์เรียงเลขขั้นตอน

  5. ตรวจว่าหน้าที่เปลี่ยนมีข้อความอธิบายหรือช่องขอความยินยอมหรือไม่
  6. บันทึกลำดับภาพทั้งชุดเป็นหลักฐานเดียวกัน
- **หลักฐานที่ต้องเก็บ:** ภาพทุกขั้นตอนเรียงลำดับ (`RST-BRKA-P01-030-01` ถึง `-NN`) · ตารางชื่อ entity ต่อขั้นตอน

  2. เปิดไฟล์ อ่านหัวกระดาษและท้ายกระดาษ
  3. บันทึกชื่อนิติบุคคลและเลขทะเบียนที่พบ หรือบันทึกว่า "ไม่มี"
  4. เทียบกับชื่อคู่สัญญาจากข้อ 026
  5. ทำซ้ำกับ statement อีก 2 เดือน เพื่อดูว่าคงเส้นคงวาหรือไม่
  6. บันทึกไฟล์ทั้งหมดเป็นหลักฐาน
- **หลักฐานที่ต้องเก็บ:** ไฟล์ statement 3 เดือน (`RST-BRKA-P01-032-01` ถึง `-03`)
- **ผ่าน:** ทุกฉบับระบุนิติบุคคลตรงกับคู่สัญญา
- **ไม่ผ่าน:** มีฉบับที่ระบุคนละราย หรือไม่มีชื่อนิติบุคคลเลย
- **ยังไม่ได้ตรวจ:** ระบบไม่มี statement ให้ดาวน์โหลด
- **ตัวอย่าง:** statement ไม่มีหัวกระดาษ มีแต่โลโก้แบรนด์ ทำให้ใช้เป็นหลักฐานทางกฎหมายไม่ได้ → **ไม่ผ่าน**

**P01-033 ● · ชื่อผู้รับเงินตอนฝากเป็นนิติบุคคลคู่สัญญาหรือไม่** `w3` `PAY`

- **ตรวจอะไร:** ทำรายการฝากเงินจริง แล้วตรวจว่าชื่อผู้รับเงินปลายทาง — ทั้งในหน้าโอนและใน descriptor ที่ปรากฏในรายการเดินบัญชีฝั่งเรา — เป็นใคร
- **ขั้นตอนการตรวจ:**
  1. เลือกช่องทางฝากเงินช่องทางแรก จับภาพหน้าจอที่แสดงรายละเอียดผู้รับเงินก่อนกดยืนยัน
  2. ทำรายการฝากด้วยยอดทดสอบ บันทึกวันเวลาที่กดยืนยัน
  3. รอจนรายการปรากฏในรายการเดินบัญชีฝั่งเรา แล้วจับภาพ descriptor ที่ระบบธนาคารแสดง
  4. บันทึกชื่อผู้รับเงินที่ปรากฏจากทั้งสองแหล่ง
  5. เทียบกับชื่อคู่สัญญาและกับรายชื่อผู้ให้บริการชำระเงินที่โบรกประกาศไว้
  6. ทำซ้ำกับช่องทางฝากทุกช่องทางที่เปิดให้ใช้ แล้วรวมผลเป็นตารางเดียว
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าจอก่อนยืนยัน · สลิปโอน · ภาพ descriptor ในรายการเดินบัญชี (`RST-BRKA-P01-033-01` ถึง `-NN`) · ตารางผลรายช่องทาง
- **ผ่าน:** ทุกช่องทาง ผู้รับเงินคือคู่สัญญา หรือผู้ให้บริการชำระเงินที่โบรกประกาศชื่อไว้ล่วงหน้า
- **ไม่ผ่าน:** มีช่องทางใดที่ผู้รับเงินเป็นบุคคลธรรมดา หรือเป็นบริษัทที่ไม่เคยถูกกล่าวถึงที่ใดเลย
- **ยังไม่ได้ตรวจ:** ยังไม่ได้ทำรายการฝาก
- **ตัวอย่าง:** โอนเงินให้ Broker C แล้ว descriptor ขึ้นเป็นชื่อบุคคลธรรมดาในอีกประเทศ → **ไม่ผ่าน**

**P01-034 · ประเทศของบัญชีรับเงินสอดคล้องกับที่ตั้งนิติบุคคลหรือไม่** `w2` `PAY`

- **ตรวจอะไร:** ระบุประเทศของบัญชีปลายทางจากรหัสธนาคารหรือ IBAN แล้วเทียบกับประเทศที่นิติบุคคลจดทะเบียนและถูกกำกับ
- **ขั้นตอนการตรวจ:**
  1. บันทึกรายละเอียดบัญชีปลายทางทุกช่องทางฝาก
  2. ระบุประเทศจากรหัสธนาคาร/IBAN/ชื่อธนาคาร บันทึกไว้
  3. เทียบกับประเทศที่นิติบุคคลจดทะเบียน
  4. ถ้าต่างกัน ค้นในเว็บโบรกว่ามีคำอธิบายเรื่องนี้หรือไม่
  5. บันทึกว่าประเทศปลายทางเป็นเขตที่มีข้อมูลกำกับดูแลเปิดเผยหรือไม่
  6. บันทึกตารางผลรายช่องทาง
- **หลักฐานที่ต้องเก็บ:** ภาพรายละเอียดบัญชีปลายทางทุกช่องทาง · สลิป · ตารางสรุปประเทศ
- **ผ่าน:** อยู่ประเทศเดียวกัน หรือต่างประเทศแต่โบรกเปิดเผยและอธิบายเหตุผลไว้ล่วงหน้าบนเว็บ
- **ไม่ผ่าน:** อยู่คนละประเทศโดยไม่มีคำอธิบายใด
- **ยังไม่ได้ตรวจ:** ยังไม่ได้ทำรายการฝาก
- **ตัวอย่าง:** นิติบุคคลจดทะเบียนในยุโรป แต่บัญชีรับเงินอยู่ในเขตที่ไม่มีข้อมูลกำกับดูแล และเว็บไม่เคยพูดถึง → **ไม่ผ่าน**

**P01-035 · โบรกเปิดเผยรายชื่อผู้ให้บริการชำระเงินหรือไม่** `w2` `WEB+PAY`

- **ตรวจอะไร:** ตรวจว่าโบรกประกาศรายชื่อผู้ให้บริการชำระเงินบุคคลที่สามไว้บนเว็บหรือในสัญญาหรือไม่ แล้วเทียบกับผู้รับเงินจริงที่พบในข้อ 033
- **ขั้นตอนการตรวจ:**
  1. ค้นในเว็บด้วยคำว่า `payment provider` `payment processor` `ผู้ให้บริการชำระเงิน`
  2. ค้นซ้ำในสัญญาและนโยบายความเป็นส่วนตัว
  3. บันทึกรายชื่อที่พบทั้งหมด หรือบันทึกว่า "ไม่มีการประกาศ"
  4. เปิดตารางผู้รับเงินจริงจากข้อ 033
  5. ทำเครื่องหมายผู้รับเงินที่ไม่อยู่ในรายชื่อที่ประกาศ
  6. บันทึกตารางเทียบ
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าที่ประกาศรายชื่อ (ถ้ามี) · ตารางเทียบรายชื่อกับผู้รับเงินจริง
- **ผ่าน:** ผู้รับเงินจริงทุกรายอยู่ในรายชื่อที่ประกาศไว้
- **ไม่ผ่าน:** ไม่มีการประกาศรายชื่อเลย หรือมีผู้รับเงินที่ไม่อยู่ในรายชื่อ
- **ยังไม่ได้ตรวจ:** ยังไม่ได้ทำรายการฝาก
- **ตัวอย่าง:** เว็บไม่มีหน้าใดพูดถึงผู้ให้บริการชำระเงิน แต่เงินถูกโอนไปบริษัทที่สาม → **ไม่ผ่าน**

**P01-036 · นโยบายความเป็นส่วนตัวระบุผู้ควบคุมข้อมูลเป็นนิติบุคคลเดียวกันหรือไม่** `w1` `WEB`

  5. ถ้าต่างกัน ค้นในเอกสารว่ามีการอธิบายความสัมพันธ์หรือไม่
  6. จับภาพส่วนที่เกี่ยวข้องและบันทึกผล
- **หลักฐานที่ต้องเก็บ:** ภาพส่วนผู้ควบคุมข้อมูล (`RST-BRKA-P01-036-01`) · ไฟล์นโยบายทั้งฉบับ
- **ผ่าน:** เป็นรายเดียวกัน หรือคนละรายแต่ระบุความสัมพันธ์ไว้ชัด
- **ไม่ผ่าน:** เป็นคนละรายโดยไม่อธิบาย หรือไม่ระบุผู้ควบคุมข้อมูลเลย
- **ยังไม่ได้ตรวจ:** ไม่มี Privacy Policy บนเว็บ
- **ตัวอย่าง:** คู่สัญญาเป็นบริษัทในยุโรป แต่ผู้ควบคุมข้อมูลเป็นบริษัทคนละชื่อโดยไม่อธิบายความเกี่ยวข้อง → **ไม่ผ่าน**

**P01-037 · footer ทุกหน้าระบุนิติบุคคลตรงกันหรือไม่** `w1` `WEB`

- **ตรวจอะไร:** สุ่มเปิดหน้าเว็บหลายหน้า แล้วเทียบข้อความ footer ว่าระบุนิติบุคคลตรงกันทุกหน้า และมีหน้าใดที่ไม่มี footer เลยหรือไม่

  3. บันทึกชื่อนิติบุคคลที่พบในแต่ละหน้าลงตาราง
  4. ทำเครื่องหมายหน้าที่ไม่มี footer หรือระบุคนละชื่อ
  5. ตรวจซ้ำเฉพาะหน้าที่ผิดปกติอีกครั้งในอีกวันหนึ่ง เพื่อยืนยันว่าไม่ใช่ความผิดพลาดชั่วคราว
  6. บันทึกตารางสรุป
- **หลักฐานที่ต้องเก็บ:** ภาพ footer ทุกหน้าพร้อม URL · ตารางสรุป
- **ผ่าน:** ทุกหน้ามี footer ที่ระบุนิติบุคคลตรงกัน

- **ยังไม่ได้ตรวจ:** ตามนิยามกลาง
- **ตัวอย่าง:** หน้าโปรโมชันไม่มี footer ระบุนิติบุคคลและคำเตือน ต่างจากหน้าอื่นทั้งหมด → **ไม่ผ่าน**

**P01-038 · แอปมือถือระบุนิติบุคคลผู้ให้บริการหรือไม่** `w2` `PLT`

- **ตรวจอะไร:** เปิดแอปที่ดาวน์โหลดจากสโตร์ทางการ เข้าเมนู About / Legal / Settings ตรวจว่าระบุนิติบุคคลผู้ให้บริการและใบอนุญาตหรือไม่

  4. บันทึกชื่อนิติบุคคลที่พบ พร้อมเส้นทางเมนู
  5. เทียบกับคู่สัญญา
  6. บันทึกผลพร้อมเวอร์ชันแอป

- **ผ่าน:** ระบุนิติบุคคลและใบอนุญาต ตรงกับคู่สัญญา
- **ไม่ผ่าน:** ไม่ระบุ หรือระบุคนละราย

- **ตัวอย่าง:** แอปมีแต่หน้าแสดงเวอร์ชัน ไม่มีข้อมูลนิติบุคคลหรือใบอนุญาตในเมนูใดเลย → **ไม่ผ่าน**

**P01-039 · ผู้เผยแพร่แอปในสโตร์เป็นนิติบุคคลเดียวกันหรือไม่** `w2` `PLT`

- **ขั้นตอนการตรวจ:**
  1. เปิดหน้าแอปในสโตร์ทางการ
  2. จับภาพส่วนที่แสดงชื่อผู้เผยแพร่
  3. กดเข้าไปดูรายละเอียดผู้พัฒนา บันทึกชื่อนิติบุคคล ที่อยู่ และเว็บไซต์ที่แจ้งไว้
  4. เทียบกับคู่สัญญาและกับโดเมนที่ใช้จริง
  5. ตรวจว่าเว็บโบรกลิงก์มาที่แอปนี้จริงหรือไม่ (กันแอปปลอม)
  6. บันทึกผลพร้อมภาพ
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าแอปสโตร์และหน้าข้อมูลผู้พัฒนา (`RST-BRKA-P01-039-01`, `-02`)
- **ผ่าน:** ผู้เผยแพร่เป็นคู่สัญญา หรือบริษัทในเครือที่เว็บระบุความสัมพันธ์ไว้
- **ไม่ผ่าน:** ผู้เผยแพร่เป็นบุคคลธรรมดา หรือบริษัทที่ไม่ปรากฏความเกี่ยวข้องใด ๆ
- **ยังไม่ได้ตรวจ:** โบรกไม่มีแอปในสโตร์ทางการ
- **ตัวอย่าง:** แอปของ Broker B เผยแพร่โดยบัญชีนักพัฒนาที่เป็นชื่อบุคคลธรรมดา ไม่มีที่อยู่บริษัท → **ไม่ผ่าน**

**P01-040 · มีการให้เลือกนิติบุคคลตอนสมัครหรือไม่ และใช้เกณฑ์ใดจัด** `w2` `ACC`

- **ตรวจอะไร:** ตรวจว่าขั้นตอนสมัครให้เลือก entity หรือภูมิภาคหรือไม่ ระบบใช้อะไรเป็นเกณฑ์จัดลูกค้าเข้า entity และมีคำอธิบายความต่างหรือไม่
- **ขั้นตอนการตรวจ:**
  1. เริ่มสมัครใหม่ บันทึกว่ามีขั้นตอนให้เลือก entity/region หรือไม่
  2. ถ้ามีให้เลือก จับภาพตัวเลือกทั้งหมดและข้อความอธิบายที่แสดง
  3. ถ้าไม่มีให้เลือก ให้สังเกตว่าระบบถามอะไรก่อนจัด entity (ประเทศ · สัญชาติ · IP)
  4. ทดสอบซ้ำโดยเปลี่ยนประเทศที่กรอก **ตามความจริงของผู้ตรวจแต่ละคนเท่านั้น ห้ามกรอกข้อมูลเท็จ** แล้วบันทึกว่า entity เปลี่ยนหรือไม่
  5. ค้นในเว็บว่ามีหน้าอธิบายเกณฑ์การจัด entity หรือไม่
  6. บันทึกผลพร้อมภาพทุกขั้นตอน
- **หลักฐานที่ต้องเก็บ:** ภาพขั้นตอนที่เกี่ยวข้อง · ตารางเกณฑ์ที่สังเกตได้ · ภาพหน้าอธิบาย (ถ้ามี)
- **ผ่าน:** มีคำอธิบายว่าแต่ละ entity ต่างกันอย่างไร และผู้สมัครรับรู้ก่อนยืนยัน
- **ไม่ผ่าน:** ระบบจัด entity ให้เองโดยไม่แจ้ง หรือมีให้เลือกแต่ไม่อธิบายความต่าง
- **ยังไม่ได้ตรวจ:** สมัครไม่สำเร็จ
- **ตัวอย่าง:** ระบบเลือก entity offshore ให้อัตโนมัติหลังกรอกประเทศ โดยไม่มีข้อความใดแจ้งว่าสิทธิคุ้มครองต่างจากที่โฆษณา → **ไม่ผ่าน**

**P01-041 · เปิดเผยว่าแต่ละนิติบุคคลถูกกำกับโดยใครหรือไม่** `w3` `WEB`

- **ตรวจอะไร:** ถ้ากลุ่มมีหลาย entity ตรวจว่ามีหน้าเดียวที่แสดงครบว่า entity ไหนกำกับโดยใคร รหัสอะไร รับลูกค้าประเทศไหน และครบทุก entity ที่ใช้จริงหรือไม่
- **ขั้นตอนการตรวจ:**
  1. ค้นในเว็บด้วยคำว่า `entities` `group` `legal information` `นิติบุคคลในกลุ่ม`
  2. ถ้าพบหน้าดังกล่าว จับภาพเต็มหน้าและบันทึกรายชื่อ entity ทั้งหมด
  3. เปิดตารางนิติบุคคลที่พบจากทุกจุดสัมผัส (ข้อ 050) มาเทียบ
  4. ทำเครื่องหมาย entity ที่พบในการใช้งานจริงแต่ไม่ปรากฏในหน้ารวม
  5. ตรวจว่าหน้ารวมนั้นเข้าถึงได้จากเมนูหลักหรือ footer หรือต้องค้นเอง
  6. บันทึกตารางสรุปพร้อมภาพ
- **หลักฐานที่ต้องเก็บ:** ภาพหน้ารวม entity (`RST-BRKA-P01-041-01`) · ตารางเทียบกับ entity ที่พบจริง
- **ผ่าน:** มีหน้าที่แสดงครบทุก entity ที่ใช้จริง พร้อมหน่วยงานกำกับและรหัสของแต่ละราย
- **ไม่ผ่าน:** ไม่มีหน้ารวม หรือมีแต่ขาด entity ที่ใช้รับลูกค้าจริงอย่างน้อย 1 ราย
- **ยังไม่ได้ตรวจ:** ยังไม่ได้ทำตารางจากข้อ 050
- **ตัวอย่าง:** เว็บพูดถึงเฉพาะ entity ที่มีใบอนุญาตเข้ม แต่ไม่มีที่ใดบอกว่ามี entity offshore ที่ลูกค้าเอเชียถูกส่งไป → **ไม่ผ่าน**

**P01-042 · เปิดเผยความต่างของสิทธิคุ้มครองระหว่างนิติบุคคลหรือไม่** `w3` `WEB+DOC`

- **ตรวจอะไร:** ตรวจว่ามีการอธิบายว่าอยู่ entity ไหนแล้วได้หรือไม่ได้อะไร โดยเฉพาะกองทุนชดเชย การคุ้มครองยอดติดลบ เพดานเลเวอเรจ และการแยกบัญชีเงินลูกค้า
- **ขั้นตอนการตรวจ:**
  1. เปิดหน้ารวม entity จากข้อ 041
  2. ทำรายการหัวข้อสิทธิ 4 หัวข้อ: กองทุนชดเชย · คุ้มครองยอดติดลบ · เพดานเลเวอเรจ · การแยกบัญชีเงินลูกค้า
  3. สำหรับแต่ละ entity ค้นว่ามีข้อมูลครบทั้ง 4 หัวข้อหรือไม่ บันทึกลงตาราง
  4. ค้นข้อมูลเดียวกันในสัญญาของแต่ละ entity เพื่อยืนยัน
  5. ประเมินว่าการนำเสนอเน้นข้อดี (เลเวอเรจสูง) โดยละข้อเสีย (ไม่มีกองทุนชดเชย) หรือไม่
  6. บันทึกตารางความครบถ้วน 4×N พร้อมภาพ
- **หลักฐานที่ต้องเก็บ:** ตารางความครบถ้วนรายหัวข้อรายentity · ภาพหน้าเปรียบเทียบ · สัญญาของแต่ละ entity
- **ผ่าน:** อธิบายครบทั้ง 4 หัวข้อสำหรับทุก entity ที่รับลูกค้าจริง
- **ไม่ผ่าน:** ขาดหัวข้อใดหัวข้อหนึ่งสำหรับ entity ใด entity หนึ่ง หรือเน้นเฉพาะข้อดี
- **ยังไม่ได้ตรวจ:** ไม่มีหน้ารวม entity ให้เริ่มต้น
- **ตัวอย่าง:** หน้าเปรียบเทียบพูดถึงแต่เลเวอเรจที่สูงกว่าของ entity offshore แต่ไม่มีบรรทัดใดบอกว่าไม่มีกองทุนชดเชย → **ไม่ผ่าน**

**P01-043 · สัญญาให้สิทธิโบรกโอนสัญญาไปนิติบุคคลอื่นได้หรือไม่** `w3` `DOC`

- **ตรวจอะไร:** หาข้อ Assignment / Transfer / Novation ในสัญญา อ่านว่าโบรกโอนสิทธิและหน้าที่ไปบริษัทอื่นได้โดยไม่ต้องขอความยินยอมหรือไม่ และลูกค้ามีทางออกอย่างไร
- **ขั้นตอนการตรวจ:**
  1. ค้นในสัญญาด้วยคำว่า `assign` `transfer` `novation` `โอนสิทธิ`
  2. อ่านข้อที่พบทั้งข้อ บันทึกเลขข้อและเลขหน้า
  3. บันทึกว่า: ต้องขอความยินยอมหรือไม่ · ต้องแจ้งล่วงหน้ากี่วัน · ลูกค้าถอนเงินออกได้ก่อนหรือไม่ · มีค่าใช้จ่ายหรือไม่
  4. ค้นข้อที่เกี่ยวกับการเปลี่ยนแปลงเงื่อนไขฝ่ายเดียวประกอบด้วย
  5. จับภาพข้อสัญญาทั้งหมดที่เกี่ยวข้อง
  6. บันทึกตารางสรุป 4 ประเด็น
- **หลักฐานที่ต้องเก็บ:** ภาพข้อสัญญาพร้อมเลขข้อ (`RST-BRKA-P01-043-01`) · ตารางสรุป 4 ประเด็น
- **ผ่าน:** ไม่มีสิทธิโอนฝ่ายเดียว หรือมีแต่ต้องแจ้งล่วงหน้าและให้ลูกค้าถอนเงินออกได้ก่อนโดยไม่มีค่าใช้จ่าย
- **ไม่ผ่าน:** โอนได้ทันทีโดยไม่ต้องแจ้งและไม่ให้ทางออกแก่ลูกค้า
- **ยังไม่ได้ตรวจ:** ยังไม่ได้รับสัญญา
- **ตัวอย่าง:** สัญญาเขียนว่าโบรกโอนบัญชีลูกค้าไปยังบริษัทในเครือใดก็ได้ทุกเมื่อ โดยถือว่าลูกค้ายินยอมล่วงหน้าแล้ว → **ไม่ผ่าน**

**P01-044 · เกิดการย้ายนิติบุคคลของลูกค้าระหว่างช่วงตรวจหรือไม่** `w3` `ACC+DOC+STM`

- **ตรวจอะไร:** เฝ้าติดตามตลอดช่วงตรวจว่าชื่อนิติบุคคลในบัญชี สัญญา และ statement เปลี่ยนหรือไม่ และถ้าเปลี่ยน มีการแจ้งล่วงหน้าและให้ทางออกหรือไม่
- **ขั้นตอนการตรวจ:**
  1. บันทึกชื่อนิติบุคคลตั้งต้นจากสัญญา อีเมล และ statement เดือนแรก
  2. ตรวจซ้ำทุกเดือนตลอดช่วงตรวจ บันทึกชื่อที่ปรากฏในแต่ละเดือน
  3. ตรวจกล่องอีเมลของบัญชีทดสอบทุกเดือน ค้นคำว่า `transfer` `entity` `เปลี่ยนแปลง`
  4. ถ้าพบการเปลี่ยน บันทึกวันที่พบ และวันที่ของอีเมลแจ้ง (ถ้ามี)
  5. คำนวณจำนวนวันระหว่างวันที่แจ้งกับวันที่มีผล
  6. บันทึกไทม์ไลน์พร้อมหลักฐานทุกชิ้น
- **หลักฐานที่ต้องเก็บ:** statement ทุกเดือน · อีเมลแจ้ง (ถ้ามี) · ไทม์ไลน์
- **ผ่าน:** ไม่มีการย้าย หรือมีการย้ายพร้อมแจ้งล่วงหน้าและให้สิทธิปิดบัญชีถอนเงิน
- **ไม่ผ่าน:** ย้ายโดยไม่แจ้ง หรือแจ้งหลังมีผลแล้ว
- **ยังไม่ได้ตรวจ:** ช่วงตรวจสั้นเกินกว่าจะสังเกตได้
- **ตัวอย่าง:** statement เดือนที่สามเปลี่ยนหัวกระดาษเป็นอีกบริษัท ค้นกล่องอีเมลแล้วไม่พบการแจ้งใด → **ไม่ผ่าน**

**P01-045 · ชื่อผู้โอนเงินตอนถอนเป็นนิติบุคคลคู่สัญญาหรือไม่** `w3` `PAY`

- **ตรวจอะไร:** ทำรายการถอนจริง แล้วตรวจว่าเงินที่เข้ามาโอนมาจากใคร ทั้งจาก descriptor ในรายการเดินบัญชีและจากเอกสารยืนยันของโบรก
- **ขั้นตอนการตรวจ:**
  1. ทำรายการถอนด้วยยอดทดสอบ บันทึกวันเวลาที่กดยืนยัน
  2. บันทึกวันเวลาที่สถานะเปลี่ยนเป็นอนุมัติ และวันเวลาที่เงินเข้าบัญชีปลายทาง (UTC ทั้งหมด)
  3. จับภาพ descriptor ของรายการรับเงินในรายการเดินบัญชีฝั่งเรา
  4. เทียบชื่อผู้โอนกับคู่สัญญาและกับรายชื่อผู้ให้บริการชำระเงินที่ประกาศไว้
  5. ทำซ้ำกับทุกช่องทางถอนที่เปิดให้ใช้
  6. บันทึกตารางผลรายช่องทางพร้อมหลักฐาน
- **หลักฐานที่ต้องเก็บ:** ภาพ descriptor ทุกช่องทาง (`RST-BRKA-P01-045-01` เป็นต้นไป) · เอกสารยืนยันจากโบรก · ตารางเวลา
- **ผ่าน:** ทุกช่องทาง ผู้โอนคือคู่สัญญา หรือผู้ให้บริการชำระเงินที่เปิดเผยไว้
- **ไม่ผ่าน:** มีช่องทางใดที่ผู้โอนเป็นบุคคลธรรมดา หรือบริษัทที่ไม่มีความเกี่ยวข้องปรากฏ
- **ยังไม่ได้ตรวจ:** ยังไม่ได้ทำรายการถอน
- **ตัวอย่าง:** ถอนเงินจาก Broker C แล้วเงินเข้ามาจากบัญชีบุคคลธรรมดาในต่างประเทศ → **ไม่ผ่าน**

**P01-046 · เอกสารการเงินระบุนิติบุคคลผู้ออกหรือไม่** `w1` `STM`

- **ตรวจอะไร:** ตรวจเอกสารสรุปค่าธรรมเนียมหรือใบเสร็จที่ระบบออกให้ ว่ามีชื่อและเลขทะเบียนนิติบุคคลผู้ออกหรือไม่ ใช้อ้างอิงทางบัญชีได้หรือไม่
- **ขั้นตอนการตรวจ:**
  1. เข้าพื้นที่ลูกค้า หาเมนูเอกสาร/รายงาน/ใบเสร็จ
  2. ดาวน์โหลดเอกสารทุกประเภทที่มี บันทึกรายการประเภทที่พบ
  3. เปิดแต่ละไฟล์ ตรวจว่ามีชื่อนิติบุคคลและเลขทะเบียนหรือไม่
  4. ถ้าไม่มีเมนูดังกล่าว ให้ขอผ่านฝ่ายบริการในฐานะลูกค้าที่ต้องใช้เอกสารทางบัญชี บันทึก transcript
  5. บันทึกว่าได้รับหรือไม่ ภายในกี่วัน
  6. บันทึกผลพร้อมไฟล์ทั้งหมด
- **หลักฐานที่ต้องเก็บ:** ไฟล์เอกสารทุกประเภท · transcript การขอ (ถ้ามี)
- **ผ่าน:** มีเอกสารที่ระบุชื่อและเลขทะเบียนนิติบุคคลผู้ออก
- **ไม่ผ่าน:** ไม่มีเอกสารลักษณะนี้ หรือมีแต่ไม่ระบุผู้ออก
- **ยังไม่ได้ตรวจ:** ยังไม่มีรายการค่าธรรมเนียมเกิดขึ้นในบัญชี
- **ตัวอย่าง:** ดาวน์โหลดสรุปค่าธรรมเนียมได้แต่เป็นไฟล์ที่มีแค่ตัวเลข ไม่มีชื่อผู้ออกเอกสาร → **ไม่ผ่าน**

**P01-047 · ชื่อนิติบุคคลบนเว็บภาษาไทยตรงกับภาษาอังกฤษหรือไม่** `w2` `WEB`

- **ตรวจอะไร:** สลับภาษาเว็บระหว่างไทยกับอังกฤษ แล้วเทียบชื่อนิติบุคคล รหัสใบอนุญาต และชื่อหน่วยงานใน footer และหน้า Legal
- **ขั้นตอนการตรวจ:**
  1. เปิดหน้าแรกภาษาอังกฤษ จับภาพ footer และหน้า Legal
  2. สลับเป็นภาษาไทยที่หน้าเดียวกัน จับภาพ footer และหน้า Legal
  3. บันทึกชื่อนิติบุคคล รหัสใบอนุญาต และชื่อหน่วยงาน ของทั้งสองภาษาลงตาราง
  4. ทำเครื่องหมายทุกช่องที่ต่างกันหรือหายไป
  5. ทำซ้ำกับหน้าสมัครและหน้าเงื่อนไข
  6. บันทึกตารางเทียบพร้อมภาพ
- **หลักฐานที่ต้องเก็บ:** ภาพ footer สองภาษาวางคู่กัน (`RST-BRKA-P01-047-01`) · ตารางเทียบ
- **ผ่าน:** ข้อมูลตรงกันทั้งสองภาษา
- **ไม่ผ่าน:** ต่างกัน หรือเวอร์ชันภาษาไทยตัดข้อมูลใบอนุญาตออก
- **ยังไม่ได้ตรวจ:** เว็บไม่มีภาษาไทย
- **ตัวอย่าง:** หน้าอังกฤษระบุ entity ยุโรปพร้อมรหัสใบอนุญาต แต่หน้าไทยระบุ entity offshore และไม่มีรหัสใด → **ไม่ผ่าน**

**P01-048 · โดเมนภูมิภาคอื่นของแบรนด์เดียวกันใช้นิติบุคคลใด** `w2` `WEB+PUB`

- **ตรวจอะไร:** ค้นหาโดเมนอื่นของแบรนด์เดียวกัน แล้วเทียบว่านิติบุคคลและใบอนุญาตต่างกันหรือไม่ และมีหน้าอธิบายความสัมพันธ์หรือไม่
- **ขั้นตอนการตรวจ:**
  1. ค้นชื่อแบรนด์ในเครื่องมือค้นหา บันทึกโดเมนทั้งหมดที่ดูเป็นของแบรนด์เดียวกัน
  2. เปิดทีละโดเมน จับภาพ footer และหน้า Legal
  3. บันทึกนิติบุคคลและรหัสใบอนุญาตของแต่ละโดเมนลงตาราง
  4. ตรวจว่าโดเมนหลักมีหน้าที่กล่าวถึงโดเมนอื่นเหล่านี้หรือไม่
  5. ทำเครื่องหมายโดเมนที่ไม่ระบุ entity หรือระบุ entity ที่ไม่มีใบอนุญาต
  6. บันทึกตารางสรุปโดเมนทั้งหมด
- **หลักฐานที่ต้องเก็บ:** ภาพ footer ทุกโดเมนพร้อม URL · ตารางสรุปโดเมน
- **ผ่าน:** ทุกโดเมนระบุ entity และใบอนุญาตชัดเจน และโดเมนหลักมีหน้าอธิบายความสัมพันธ์
- **ไม่ผ่าน:** มีโดเมนที่ไม่ระบุ entity หรือระบุ entity ที่ไม่มีใบอนุญาตใด ๆ
- **ยังไม่ได้ตรวจ:** พบเพียงโดเมนเดียว
- **ตัวอย่าง:** โดเมนหลักระบุ entity ที่ถูกกำกับ ส่วนโดเมนที่ยิงโฆษณาในไทยไม่ระบุ entity เลย → **ไม่ผ่าน**

**P01-049 · หน้าโปรโมชันหรือ landing page ระบุนิติบุคคลหรือไม่** `w2` `WEB+PUB`

- **ตรวจอะไร:** เก็บ landing page ที่มาจากโฆษณาหรือลิงก์แนะนำ แล้วตรวจว่าระบุนิติบุคคล ใบอนุญาต และคำเตือนความเสี่ยงหรือไม่
- **ขั้นตอนการตรวจ:**
  1. ตลอดช่วงตรวจ เก็บทุก landing page ที่พบจากโฆษณาหรือลิงก์แนะนำ บันทึก URL และวันที่พบ
  2. จับภาพเต็มหน้าของแต่ละ landing page
  3. ตรวจแต่ละหน้าว่ามี 3 อย่างครบหรือไม่: ชื่อนิติบุคคล · รหัสใบอนุญาต · คำเตือนความเสี่ยง
  4. บันทึกลงตาราง 3 คอลัมน์
  5. ทำเครื่องหมายหน้าที่ขาดข้อใดข้อหนึ่ง
  6. บันทึกตารางสรุปพร้อมภาพทุกหน้า
- **หลักฐานที่ต้องเก็บ:** ภาพเต็มหน้าทุก landing page พร้อม URL และวันที่ · ตาราง 3 คอลัมน์
- **ผ่าน:** ทุก landing page มีครบทั้ง 3 อย่าง
- **ไม่ผ่าน:** มีหน้าใดขาดข้อใดข้อหนึ่ง
- **ยังไม่ได้ตรวจ:** ไม่พบ landing page ใดในช่วงตรวจ
- **ตัวอย่าง:** landing page แคมเปญมีแต่ปุ่มสมัครกับข้อความผลตอบแทน ไม่มี footer ใด ๆ → **ไม่ผ่าน**

**P01-050 ● · สรุปความสอดคล้องของนิติบุคคลทุกจุดสัมผัส** `w3` `รวมทุกวิธี` `G1`

- **ตรวจอะไร:** รวบรวมชื่อนิติบุคคลที่พบจากทุกจุดสัมผัสลงตารางเดียว แล้วนับว่ามีกี่ชื่อ และมีชื่อใดที่ไม่ถูกอธิบายที่ใดเลย — ข้อนี้เป็นข้อสรุปของ S02 และผูกด่าน G1
- **ขั้นตอนการตรวจ:**
  1. สร้างตารางที่มีแถวเป็นจุดสัมผัส 9 จุด: เว็บ footer · หน้า Legal · สัญญา · อีเมลยืนยัน · statement · ผู้รับเงินตอนฝาก · ผู้โอนเงินตอนถอน · แอป · หน้าแอปสโตร์
  2. เติมชื่อนิติบุคคลที่พบในแต่ละแถว พร้อม Evidence ID อ้างอิง จากผลข้อ 003, 026, 031, 032, 033, 038, 039, 045
  3. นับจำนวนชื่อที่ไม่ซ้ำกันทั้งหมด
  4. สำหรับแต่ละชื่อ ตรวจว่ามีหน้าใดบนเว็บหรือข้อใดในสัญญาที่อธิบายบทบาทของชื่อนั้นหรือไม่
  5. ทำเครื่องหมายชื่อที่ไม่มีที่ใดอธิบายเลย
  6. บันทึกตารางสรุปฉบับสมบูรณ์พร้อมคำตัดสิน
- **หลักฐานที่ต้องเก็บ:** ตารางสรุป 9 จุดสัมผัสพร้อม Evidence ID ทุกแถว · รายการชื่อที่ไม่ถูกอธิบาย
- **ผ่าน:** ทุกจุดชี้ไปนิติบุคคลเดียวกัน หรือมีมากกว่าหนึ่งแต่ทุกชื่อถูกอธิบายบทบาทไว้
- **ไม่ผ่าน:** พบนิติบุคคลที่ไม่ถูกอธิบายที่ใดเลยอย่างน้อย 1 ราย
- **ยังไม่ได้ตรวจ:** ยังเก็บข้อมูลไม่ครบ 9 จุดสัมผัส
- **ตัวอย่าง:** ตารางสรุปพบ 4 ชื่อ โดย 2 ชื่อไม่เคยปรากฏบนเว็บหรือในสัญญาเลย → **ไม่ผ่าน** ตกด่าน G1
