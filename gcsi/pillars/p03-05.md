## หมายเหตุขอบเขตและนิยามที่ไฟล์นี้อ้างอิง

**ไฟล์นี้ไม่ตั้งนิยามใหม่ใด ๆ** — ใช้ **ชุดยอดเงินมาตรฐาน (ยอด A · ยอด B · ยอด C · ยอด D)** และ **นิยามจับเวลา T0–T6** ตามที่ประกาศไว้ในหัวไฟล์ [`p03-01.md`](p03-01.md) ทั้งชุด ถ้าตัวเลขหรือจุดเวลาใดขัดกัน **ให้ยึด `p03-01.md` เป็นหลักเสมอ** ทุกเวลาบันทึกเป็น **UTC** รูปแบบ `YYYY-MM-DDThh:mm:ssZ` และต้องเทียบนาฬิกาเครื่องกับแหล่งเวลามาตรฐานสาธารณะก่อนเริ่มทุกรอบ พร้อมบันทึกค่าคลาดเคลื่อนเป็นวินาที

ในบริบท **ฝั่งถอน** จุดเวลาชุดเดียวกันของ `p03-01.md` ตกกับเหตุการณ์ต่อไปนี้ (เป็นการชี้ตำแหน่งเหตุการณ์ ไม่ใช่การตั้งนิยามใหม่):

| จุดเวลา | เหตุการณ์ฝั่งถอนที่ตรงกับนิยามใน `p03-01.md` |
|---|---|
| `T0` | เวลาที่กดปุ่มยืนยันคำขอถอนครั้งสุดท้ายในฝั่งผู้ตรวจ |
| `T1` | เวลาที่ยอดถูกตัดออกจากยอดคงเหลือของบัญชีเทรด |
| `T2` | เวลาที่ยอดปรากฏจริงในบัญชีปลายทางของผู้ตรวจ |
| `T3` | เวลาที่ยอดปลายทางถูกใช้ได้จริง (พ้นสถานะรอเคลียร์) |
| `T4` | เวลาที่เงินกลับคืนเข้าบัญชีเทรดเต็มจำนวน เมื่อคำขอถูกปฏิเสธหรือถูกยกเลิก |
| `T5` | เวลาที่ผู้ตรวจแจ้งปัญหาผ่านช่องทางลูกค้าปกติ |
| `T6` | เวลาที่คำตอบหรือการแจ้งเตือนจากโบรกมาถึงผู้ตรวจ |

**ขอบเขตที่ไฟล์นี้ตรวจ และที่ไม่ตรวจ**

- ไฟล์นี้ตรวจเฉพาะ **การปฏิเสธคำขอถอน · การหน่วงคำขอถอน · และเงื่อนไขที่งอกขึ้นภายหลังการเปิดบัญชี** เท่านั้น
- **ไม่ตรวจซ้ำ:** ช่องทางถอนและการทดสอบถอนจริงรายช่องทางอยู่ที่ `p03-03.md` · เวลาถอนจริงและค่าธรรมเนียมถอนอยู่ที่ `p03-04.md` · การถอนทั้งหมดและปิดบัญชีอยู่ที่ `p03-06.md` · เงื่อนไขโบนัสในตัวสัญญาอยู่ที่ `p07-04.md`

**ข้อห้ามเฉพาะไฟล์นี้ — สำคัญที่สุด**

1. **ห้ามจงใจสร้างเหตุให้ถูกปฏิเสธ** — ห้ามยื่นคำขอที่รู้อยู่แล้วว่าผิดเงื่อนไข ห้ามกรอกข้อมูลผิดเพื่อดูปฏิกิริยา ห้ามใช้บัญชีปลายทางของบุคคลอื่น
2. **ห้ามใช้กลยุทธ์เทรดที่ผิดเงื่อนไขของโบรกเพื่อทดสอบ** ทุกกรณี การเทรดต้องเป็นการใช้บริการตามปกติเท่านั้น
3. ทุกข้อในไฟล์นี้เขียนแบบ **"ถ้าเหตุนี้เกิดขึ้นเองระหว่างใช้บริการตามปกติ ให้บันทึกอย่างไรและตัดสินอย่างไร"** — ถ้าตลอดรอบตรวจไม่เกิดเหตุเลย ให้ลงผลเป็น **ยังไม่ได้ตรวจ** พร้อมหลักฐานว่าไม่เกิด **ห้ามตีความว่าไม่ผ่าน และห้ามตีความว่าผ่านโดยอัตโนมัติ**
4. **ห้ามเปิดเผยตัวว่าเป็นผู้ตรวจ** ในทุกขั้นตอน การร้องเรียนทุกครั้งต้องทำ **ในฐานะลูกค้าที่เดือดร้อนจริงจากเงินของตนเอง** ห้ามอ้างชื่อ RedStarTrust ห้ามอ้างว่าเป็นสื่อ ห้ามขู่ว่าจะเผยแพร่

## S09 · การปฏิเสธและการหน่วงคำสั่งถอน (201–225)

**P03-201 ● · โบรกประกาศ "เหตุที่คำขอถอนจะถูกปฏิเสธ" ไว้ล่วงหน้าหรือไม่** `w3` `WEB+DOC` `G4`

- **ตรวจอะไร:** ตรวจว่าก่อนที่ลูกค้าจะยื่นคำขอถอนครั้งแรก มีเอกสารสาธารณะหรือเอกสารในระบบหลังบ้านของบัญชีที่ระบุ **รายการเหตุที่โบรกจะปฏิเสธคำขอถอน** เป็นข้อ ๆ หรือไม่ ต้องเป็นข้อความที่ระบุเหตุเจาะจงพอจะรู้ล่วงหน้าว่าต้องหลีกเลี่ยงอะไร เช่น "ชื่อบัญชีปลายทางไม่ตรงกับชื่อเจ้าของบัญชี" ไม่นับข้อความกว้างแบบ "บริษัทสงวนสิทธิ์ปฏิเสธคำขอใด ๆ ตามดุลพินิจ" ให้บันทึกข้อความทุกข้อแบบคำต่อคำ URL หรือชื่อเอกสาร วันที่บนเอกสาร และเวลา UTC ที่เปิดดู
- **ขั้นตอนการตรวจ:**
  1. เปิดหน้า Withdrawal / Funding / FAQ และหน้าเงื่อนไขการใช้บริการจากโดเมนหลักของโบรกโดยพิมพ์เอง บันทึก URL ทุกหน้า
  2. ค้นคำว่า `reject` `decline` `refuse` `cancel` `ปฏิเสธ` `ไม่อนุมัติ` `ยกเลิกคำขอ` ทีละคำในทุกหน้า บันทึกจำนวนที่พบต่อหน้า
  3. คัดลอกทุกข้อความที่พบลงตาราง "เหตุปฏิเสธที่ประกาศ" แบบคำต่อคำ พร้อมหน้าที่พบและย่อหน้าที่อ้างอิงได้
  4. ทำเครื่องหมายแยกระหว่างข้อที่ **ระบุเหตุเจาะจง** กับข้อที่เป็น **ดุลพินิจเปิดกว้าง** นับจำนวนของแต่ละกลุ่ม
  5. ล็อกอินเข้าระบบหลังบ้านของบัญชี เปิดหน้าคำขอถอน ตรวจว่ามีลิงก์หรือข้อความเงื่อนไขปรากฏก่อนกดยืนยันหรือไม่ จับภาพให้เห็นทั้งข้อความและปุ่มยืนยันในเฟรมเดียวกัน
  6. เก็บสำเนาถาวรของทุกหน้าที่พบข้อความ (PDF หรือ single-file HTML) พร้อมบันทึกเวลา UTC ที่บันทึก เพราะหน้านี้จะถูกนำไปเทียบอีกครั้งในข้อ 233
  7. บันทึกผลลงตารางกลางของไฟล์นี้ และตั้งชื่อไฟล์ตามรูปแบบ Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพเต็มหน้าทุกหน้าที่พบข้อความพร้อม URL และเวลา (`RST-BRKA-P03-201-01` ถึง `-05`) · สำเนาถาวร PDF ของทุกหน้า (`RST-BRKA-P03-201-06`) · ตารางเหตุปฏิเสธที่ประกาศแยกกลุ่มเจาะจง/ดุลพินิจ
- **ผ่าน:** พบเอกสารที่ลูกค้าเข้าถึงได้ก่อนยื่นคำขอถอน และระบุเหตุปฏิเสธแบบเจาะจงอย่างน้อย 1 ข้อ
- **ไม่ผ่าน:** ไม่พบเอกสารใดระบุเหตุปฏิเสธเลย หรือพบเพียงข้อความดุลพินิจเปิดกว้างโดยไม่มีเหตุเจาะจงแม้แต่ข้อเดียว
- **ยังไม่ได้ตรวจ:** ระบบหลังบ้านล่มตลอดช่วงที่พยายามเข้าและบันทึกความพยายามไว้ครบทุกครั้ง
- **ตัวอย่าง:** Broker A มีหน้า Withdrawal FAQ ที่เขียนเพียงว่า *"เราอาจปฏิเสธคำขอถอนได้ตามดุลพินิจของบริษัท"* ค้นทั้งเว็บและเอกสารในระบบหลังบ้านแล้วไม่พบเหตุเจาะจงแม้แต่ข้อเดียว → **ไม่ผ่าน**

**P03-202 ● · เมื่อปฏิเสธคำขอถอนจริง โบรกให้เหตุผลที่เจาะจงพอจะแก้ไขได้หรือไม่** `w3` `PAY+SUP` `G4`

- **ตรวจอะไร:** เมื่อเกิดเหตุการณ์ที่คำขอถอนของผู้ตรวจถูกปฏิเสธเองระหว่างใช้บริการตามปกติ ให้ตรวจ **เนื้อความของเหตุผลที่โบรกแจ้ง** ว่าระบุ (ก) เหตุคืออะไร (ข) ต้องทำอะไรจึงจะผ่าน (ค) อ้างอิงข้อสัญญาหรือข้อเงื่อนไขใด ครบหรือไม่ บันทึกข้อความแบบคำต่อคำ ช่องทางที่แจ้ง เวลา UTC ที่ได้รับ และเทียบกับเวลา `T0` ของคำขอนั้น **ห้ามยื่นคำขอที่รู้อยู่แล้วว่าผิดเงื่อนไขเพื่อให้เกิดการปฏิเสธ**
- **ขั้นตอนการตรวจ:**
  1. ยื่นคำขอถอนตามการใช้บริการปกติด้วย **ยอด A** บันทึก `T0` เป็น UTC และจับภาพหน้าจอยืนยันที่เห็นหมายเลขคำขอ
  2. เฝ้าสถานะคำขอทุก `[เกณฑ์เสนอ: 6 ชั่วโมง]` จับภาพหน้าสถานะทุกครั้งที่ตรวจ พร้อมเวลา UTC บนภาพ
  3. เมื่อสถานะเปลี่ยนเป็นถูกปฏิเสธ ให้บันทึกเวลานั้นเป็น `T1` ทันที และจับภาพเต็มหน้ารายการคำขอ
  4. คัดลอกข้อความเหตุผลจากทุกช่องทางที่โบรกแจ้ง (หน้าจอ · อีเมล · แจ้งเตือนในแอป) แบบคำต่อคำ บันทึกเวลา UTC ที่แต่ละช่องทางมาถึงเป็น `T6`
  5. ให้คะแนนความครบของเหตุผลตาม 3 องค์ประกอบ (เหตุ · วิธีแก้ · ข้ออ้างอิง) ลงตาราง โดยทำเครื่องหมายครบ/ไม่ครบทีละองค์ประกอบ
  6. ถ้าเหตุผลไม่ครบ ให้สอบถามผ่านช่องทางลูกค้าปกติ **ในฐานะลูกค้าที่ต้องการทำให้ถูกต้อง** บันทึก `T5` และเก็บสำเนาข้อความที่ส่ง
  7. บันทึกคำตอบที่ได้กลับ พร้อม `T6` และตรวจว่าคำตอบเติมองค์ประกอบที่ขาดได้ครบหรือไม่
  8. ทำซ้ำการบันทึกนี้กับ **ทุกคำขอที่ถูกปฏิเสธ** ที่เกิดขึ้นตลอดรอบตรวจ ห้ามเลือกเฉพาะบางรายการ
  9. บันทึกไทม์ไลน์ `T0/T1/T5/T6` รายคำขอ และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้ายืนยันคำขอที่เห็นหมายเลขคำขอ (`RST-BRKA-P03-202-01`) · ภาพหน้าสถานะทุกครั้งที่ตรวจ (`RST-BRKA-P03-202-02` ถึง `-NN`) · อีเมลแจ้งการปฏิเสธต้นฉบับพร้อมหัวจดหมาย (`RST-BRKA-P03-202-20`) · สำเนาบทสนทนากับฝ่ายบริการทั้งชุด · ตารางคะแนน 3 องค์ประกอบ
- **ผ่าน:** ทุกคำขอที่ถูกปฏิเสธมีเหตุผลครบทั้ง 3 องค์ประกอบ ไม่ว่าจะได้จากการแจ้งครั้งแรกหรือจากคำตอบหลังสอบถาม
- **ไม่ผ่าน:** มีอย่างน้อย 1 คำขอที่ถูกปฏิเสธโดยไม่ได้องค์ประกอบครบ แม้สอบถามแล้วภายใน `[เกณฑ์เสนอ: 7 วันหลัง T5]`
- **ยังไม่ได้ตรวจ:** ตลอดรอบตรวจไม่มีคำขอถอนใดถูกปฏิเสธเลย และมีบันทึกคำขอทุกรายการพร้อมสถานะสุดท้ายครบถ้วน
- **ตัวอย่าง:** Broker B ปฏิเสธคำขอถอนของผู้ตรวจด้วยข้อความบรรทัดเดียวว่า *"Request declined — policy"* ผู้ตรวจถามผ่านแชทและอีเมลรวม 3 ครั้งใน 9 วัน ได้คำตอบเดิมทุกครั้งโดยไม่ระบุข้อเงื่อนไขใด → **ไม่ผ่าน** และตกด่าน G4

**P03-203 · เหตุผลที่ใช้ปฏิเสธจริง อยู่ในรายการเหตุที่ประกาศไว้ล่วงหน้าหรือไม่** `w3` `DOC+WEB` `G4`

- **ตรวจอะไร:** เทียบ **เหตุผลที่โบรกใช้ปฏิเสธจริง** (จากข้อ 202) กับ **รายการเหตุปฏิเสธที่ประกาศไว้ล่วงหน้า** (จากข้อ 201 และสำเนาถาวรที่เก็บไว้ตั้งแต่วันเปิดบัญชี) ทีละรายการ เพื่อดูว่าเป็นเหตุที่ลูกค้ารู้ล่วงหน้าได้หรือเป็นเหตุที่เพิ่งปรากฏตอนถูกปฏิเสธ บันทึกผลการจับคู่รายคำขอ พร้อมหมายเลขข้อของเอกสารที่จับคู่ได้
- **ขั้นตอนการตรวจ:**
  1. เปิดตาราง "เหตุปฏิเสธที่ประกาศ" จากข้อ 201 และสำเนาถาวรฉบับวันเปิดบัญชี วางเรียงกัน
  2. เปิดข้อความเหตุผลจริงของทุกคำขอที่ถูกปฏิเสธจากข้อ 202
  3. จับคู่ทีละคำขอ บันทึกว่า **จับคู่ได้** (ระบุข้อที่ตรง) หรือ **จับคู่ไม่ได้**
  4. สำหรับรายการที่จับคู่ไม่ได้ ให้ค้นคำสำคัญของเหตุผลนั้นในเอกสารเงื่อนไขทุกฉบับที่ดาวน์โหลดไว้ บันทึกผลการค้นเป็นจำนวนที่พบ
  5. จับภาพเอกสารกับข้อความเหตุผลวางคู่กันในภาพเดียว เห็นวันที่ของเอกสารด้วย
  6. บันทึกตารางจับคู่รายคำขอและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางจับคู่เหตุผลจริงกับข้อที่ประกาศ (`RST-BRKA-P03-203-01`) · ภาพเทียบคู่รายคำขอ (`RST-BRKA-P03-203-02` ถึง `-NN`) · สำเนาถาวรเอกสารเงื่อนไขฉบับวันเปิดบัญชี
- **ผ่าน:** ทุกเหตุผลที่ใช้ปฏิเสธจริงจับคู่ได้กับข้อที่ประกาศไว้ล่วงหน้าก่อนวันยื่นคำขอ
- **ไม่ผ่าน:** มีอย่างน้อย 1 คำขอที่ถูกปฏิเสธด้วยเหตุที่ไม่ปรากฏในเอกสารใดก่อนวันยื่นคำขอ
- **ยังไม่ได้ตรวจ:** ไม่มีคำขอถอนใดถูกปฏิเสธตลอดรอบตรวจ
- **ตัวอย่าง:** Broker C ปฏิเสธคำขอถอนโดยอ้างว่า *"บัญชียังไม่ครบระยะสะสม 90 วัน"* ผู้ตรวจค้นเอกสารเงื่อนไขฉบับวันเปิดบัญชีและหน้าเว็บทุกหน้าแล้วไม่พบคำว่าระยะสะสมเลย → **ไม่ผ่าน** และตกด่าน G4

**P03-204 ● · โบรกขอเอกสารเพิ่มเติมหลังยื่นคำขอถอนแล้ว โดยไม่เคยแจ้งตอนเปิดบัญชีหรือไม่** `w3` `PAY+DOC` `G4`

- **ตรวจอะไร:** ตรวจเหตุการณ์ที่โบรกส่งคำขอเอกสารเพิ่มเติม **หลังจากคำขอถอนถูกยื่นแล้ว** ให้บันทึกรายชื่อเอกสารที่ถูกขอทุกฉบับ เวลา UTC ที่คำขอเอกสารมาถึงเทียบกับ `T0` ของคำขอถอน และตรวจว่าเอกสารแต่ละฉบับเคยปรากฏในรายการเอกสารที่โบรกแจ้งตอนเปิดบัญชีหรือไม่ ประเด็นสำคัญไม่ใช่ว่า "ขอเอกสารได้หรือไม่" แต่คือ **ขอสิ่งที่ไม่เคยบอกล่วงหน้า ในจังหวะที่เงินถูกล็อกอยู่แล้ว หรือไม่**
- **ขั้นตอนการตรวจ:**
  1. เปิดรายการเอกสารที่โบรกแจ้งตอนเปิดบัญชี (จากสำเนาถาวรที่เก็บไว้ตั้งแต่วันเปิดบัญชี) จัดเป็นตารางตั้งต้น
  2. ยื่นคำขอถอนตามการใช้บริการปกติ บันทึก `T0` เป็น UTC
  3. เฝ้าอีเมลและกล่องข้อความในระบบทุก `[เกณฑ์เสนอ: 12 ชั่วโมง จนถึง 30 วันหลัง T0]` บันทึกทุกคำขอเอกสารที่ได้รับพร้อมเวลา UTC
  4. คัดลอกรายชื่อเอกสารที่ถูกขอแบบคำต่อคำ ลงตารางเทียบกับรายการตั้งต้น ทำเครื่องหมาย **เคยแจ้ง** หรือ **ไม่เคยแจ้ง** ทีละฉบับ
  5. บันทึกว่าคำขอเอกสารระบุ **กรอบเวลาที่ต้องส่ง** และ **ผลถ้าไม่ส่ง** หรือไม่ คัดลอกข้อความส่วนนี้ไว้ด้วย
  6. ส่งเอกสารที่ขอตามปกติในฐานะลูกค้า บันทึกเวลาที่ส่งและเก็บหลักฐานการส่ง **ห้ามส่งเอกสารปลอมหรือเอกสารของบุคคลอื่นทุกกรณี**
  7. บันทึกว่าหลังส่งครบแล้ว มีการขอเอกสารรอบใหม่อีกหรือไม่ ถ้ามีให้นับเป็น **รอบที่ 2, 3, …** พร้อมเวลา UTC ของแต่ละรอบ
  8. คำนวณจำนวนรอบการขอเอกสารทั้งหมดต่อคำขอถอน 1 รายการ และบันทึกไทม์ไลน์ทั้งชุดตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** สำเนาถาวรรายการเอกสารฉบับวันเปิดบัญชี (`RST-BRKA-P03-204-01`) · อีเมลคำขอเอกสารต้นฉบับทุกฉบับพร้อมหัวจดหมาย (`RST-BRKA-P03-204-02` ถึง `-NN`) · ตารางเทียบเอกสารเคยแจ้ง/ไม่เคยแจ้ง · หลักฐานการส่งเอกสารทุกครั้ง · ไทม์ไลน์ UTC
- **ผ่าน:** ไม่มีการขอเอกสารเพิ่มหลัง `T0` หรือมีแต่ทุกฉบับปรากฏอยู่ในรายการที่แจ้งตั้งแต่วันเปิดบัญชีแล้ว
- **ไม่ผ่าน:** มีเอกสารอย่างน้อย 1 ฉบับที่ถูกขอหลัง `T0` และไม่เคยปรากฏในรายการที่แจ้งตอนเปิดบัญชี
- **ยังไม่ได้ตรวจ:** ไม่มีคำขอถอนใดถูกยื่นสำเร็จตลอดรอบตรวจ หรือสำเนารายการเอกสารฉบับวันเปิดบัญชีสูญหายจนเทียบไม่ได้ (ต้องบันทึกเหตุไว้)
- **ตัวอย่าง:** Broker A ขอ "ภาพถ่ายผู้ถือบัญชีคู่กับบัตรประชาชนและใบเสร็จค่าน้ำค่าไฟย้อนหลัง 6 เดือน" ในวันที่ 4 หลังยื่นคำขอถอน ทั้งที่ตอนเปิดบัญชีแจ้งเพียงบัตรประชาชนและหลักฐานที่อยู่ 1 ฉบับ → **ไม่ผ่าน** และตกด่าน G4

**P03-205 · คำขอเอกสารเพิ่มเติมระบุกรอบเวลาและผลของการไม่ส่งหรือไม่** `w2` `DOC`

- **ตรวจอะไร:** ตรวจคุณภาพของคำขอเอกสารทุกฉบับจากข้อ 204 ว่าระบุ (ก) เอกสารที่ต้องการแบบเจาะจง (ข) รูปแบบไฟล์และคุณภาพที่ยอมรับ (ค) กำหนดเวลาที่ต้องส่ง (ง) ผลที่จะเกิดถ้าไม่ส่งภายในกำหนด ครบทั้ง 4 องค์ประกอบหรือไม่ คำขอที่คลุมเครือทำให้ลูกค้าส่งผิดซ้ำหลายรอบและยืดเวลาการถอนออกไปโดยไม่มีที่สิ้นสุด
- **ขั้นตอนการตรวจ:**
  1. เปิดคำขอเอกสารทุกฉบับที่เก็บไว้จากข้อ 204 เรียงตามเวลา UTC
  2. อ่านทีละฉบับ ทำเครื่องหมายครบ/ไม่ครบทีละองค์ประกอบใน 4 องค์ประกอบ ลงตาราง
  3. บันทึกจำนวนครั้งที่ผู้ตรวจต้องส่งเอกสารซ้ำเพราะคำขอไม่ชัด พร้อมเหตุผลที่โบรกให้ในแต่ละครั้ง
  4. คำนวณจำนวนวันรวมที่ใช้ไปกับรอบเอกสาร นับจากคำขอเอกสารฉบับแรกถึงวันที่โบรกยืนยันว่าเอกสารครบ
  5. จับภาพคำขอทุกฉบับให้เห็นเวลาที่ได้รับ
  6. บันทึกตารางองค์ประกอบและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางองค์ประกอบ 4 ข้อรายคำขอ (`RST-BRKA-P03-205-01`) · ภาพคำขอทุกฉบับพร้อมเวลา (`RST-BRKA-P03-205-02` ถึง `-NN`) · บันทึกจำนวนรอบการส่งซ้ำ
- **ผ่าน:** คำขอเอกสารทุกฉบับระบุครบทั้ง 4 องค์ประกอบ
- **ไม่ผ่าน:** มีคำขออย่างน้อย 1 ฉบับที่ขาดองค์ประกอบใดองค์ประกอบหนึ่ง
- **ยังไม่ได้ตรวจ:** ไม่มีคำขอเอกสารเพิ่มเติมเกิดขึ้นเลยตลอดรอบตรวจ
- **ตัวอย่าง:** Broker B ส่งอีเมลว่า *"กรุณาส่งเอกสารยืนยันเพิ่มเติม"* โดยไม่ระบุว่าเอกสารอะไร ไม่มีกำหนดส่ง และไม่บอกผลถ้าไม่ส่ง ผู้ตรวจต้องถามกลับ 2 รอบจึงรู้ว่าต้องการอะไร → **ไม่ผ่าน**

**P03-206 ● · คำขอถอนค้างสถานะรอดำเนินการเกินกรอบเวลาที่โบรกประกาศหรือไม่** `w3` `PAY` `G4`

- **ตรวจอะไร:** วัดว่าคำขอถอนแต่ละรายการค้างอยู่ในสถานะรอดำเนินการ (pending / processing / under review) นานเท่าใด นับจาก `T0` ถึงเวลาที่สถานะเปลี่ยนเป็นสถานะสุดท้าย (จ่ายแล้ว · ปฏิเสธ · ยกเลิก) แล้วเทียบกับ **กรอบเวลาที่โบรกประกาศไว้เอง** ข้อนี้ตรวจเฉพาะ **การค้างเกินกรอบที่โบรกประกาศ** ส่วนการวัดเวลาถอนจริงโดยรวมและการเทียบกับที่ประกาศอยู่ที่ `p03-04.md`
- **ขั้นตอนการตรวจ:**
  1. บันทึกกรอบเวลาดำเนินการคำขอถอนที่โบรกประกาศไว้ แปลงเป็นชั่วโมงและระบุว่านับเป็นวันทำการหรือวันปฏิทิน พร้อมจับภาพหน้าที่ประกาศ
  2. ยื่นคำขอถอนตามการใช้บริการปกติ บันทึก `T0` เป็น UTC
  3. เปิดหน้าสถานะคำขอทุก `[เกณฑ์เสนอ: 12 ชั่วโมง]` จับภาพสถานะพร้อมเวลาทุกครั้ง ห้ามพึ่งความจำ
  4. บันทึกเวลา UTC ทุกครั้งที่ข้อความสถานะเปลี่ยน พร้อมคัดลอกข้อความสถานะแบบคำต่อคำ
  5. เมื่อสถานะถึงสถานะสุดท้าย บันทึกเวลานั้น แล้วคำนวณ **ระยะเวลาค้าง = เวลาสถานะสุดท้าย − `T0`** เป็นชั่วโมง
  6. เทียบระยะเวลาค้างกับกรอบที่ประกาศ บันทึกส่วนเกินเป็นชั่วโมงและเป็นเท่าของกรอบที่ประกาศ
  7. ทำซ้ำกับคำขอถอนทุกรายการตลอดรอบตรวจ อย่างน้อย `[เกณฑ์เสนอ: 3 รายการ กระจายห่างกันรายการละ 1 สัปดาห์]`
  8. บันทึกตารางระยะเวลาค้างรายรายการ พร้อมค่าต่ำสุด สูงสุด ค่ากลาง และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าที่ประกาศกรอบเวลาพร้อมวันที่ (`RST-BRKA-P03-206-01`) · ภาพหน้าสถานะทุกครั้งที่ตรวจ (`RST-BRKA-P03-206-02` ถึง `-NN`) · ตารางระยะเวลาค้างรายรายการเป็น UTC
- **ผ่าน:** ทุกคำขอเข้าสู่สถานะสุดท้ายภายในกรอบเวลาที่โบรกประกาศ หรือเกินแต่โบรกแจ้งเหตุและกรอบเวลาใหม่ก่อนครบกำหนดเดิม
- **ไม่ผ่าน:** มีคำขออย่างน้อย 1 รายการค้างเกินกรอบที่ประกาศ โดยไม่มีการแจ้งใด ๆ ก่อนครบกำหนด
- **ยังไม่ได้ตรวจ:** โบรกไม่ประกาศกรอบเวลาใดเลย (ให้บันทึกข้อเท็จจริงนี้ และส่งผลไปตัดสินที่ `p03-04.md` แทน)
- **ตัวอย่าง:** Broker C ประกาศว่าดำเนินการภายใน 24 ชั่วโมงทำการ คำขอของผู้ตรวจค้างสถานะ *Under review* 11 วันโดยไม่มีข้อความใดถึงผู้ตรวจเลย → **ไม่ผ่าน** และตกด่าน G4

**P03-207 · สถานะคำขอถอนเปลี่ยนย้อนกลับหรือเปลี่ยนโดยไม่มีการแจ้งหรือไม่** `w2` `PAY`

- **ตรวจอะไร:** ตรวจความน่าเชื่อถือของสถานะที่ระบบแสดง โดยดูว่ามีกรณีที่สถานะ **เดินถอยหลัง** (เช่น จาก Approved กลับเป็น Pending) หรือ **เปลี่ยนโดยลูกค้าไม่ได้รับการแจ้งใด ๆ** หรือไม่ บันทึกลำดับสถานะทั้งหมดพร้อมเวลา UTC และเทียบกับการแจ้งเตือนที่ได้รับจริง
- **ขั้นตอนการตรวจ:**
  1. เปิดชุดภาพหน้าสถานะที่เก็บไว้จากข้อ 206 เรียงตามเวลา UTC
  2. สร้างลำดับสถานะรายคำขอ บันทึกเป็นตาราง `เวลา UTC → ข้อความสถานะ`
  3. ทำเครื่องหมายทุกจุดที่สถานะเดินถอยหลังหรือข้ามขั้น พร้อมภาพก่อน–หลังของจุดนั้น
  4. เทียบทุกการเปลี่ยนสถานะกับกล่องอีเมลและกล่องแจ้งเตือนในระบบ บันทึกว่ามีการแจ้งหรือไม่ และห่างจากเวลาที่สถานะเปลี่ยนเท่าใด
  5. บันทึกจำนวนการเปลี่ยนสถานะที่ **ไม่มีการแจ้งเลย** เป็นจำนวนครั้งและเป็นร้อยละของการเปลี่ยนทั้งหมด
  6. บันทึกตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางลำดับสถานะรายคำขอเป็น UTC (`RST-BRKA-P03-207-01`) · ภาพก่อน–หลังของทุกจุดที่สถานะถอยหลัง (`RST-BRKA-P03-207-02` ถึง `-NN`) · อีเมลแจ้งเตือนต้นฉบับ
- **ผ่าน:** ไม่มีสถานะใดเดินถอยหลัง และการเปลี่ยนสถานะทุกครั้งมีการแจ้งถึงลูกค้าอย่างน้อย 1 ช่องทาง
- **ไม่ผ่าน:** มีสถานะเดินถอยหลังอย่างน้อย 1 ครั้งโดยไม่มีคำอธิบาย หรือมีการเปลี่ยนสถานะที่ไม่แจ้งเลยอย่างน้อย 1 ครั้ง
- **ยังไม่ได้ตรวจ:** ระบบไม่แสดงสถานะคำขอถอนเลย (บันทึกข้อเท็จจริงนี้และอ้างอิงต่อในข้อ 247)
- **ตัวอย่าง:** คำขอของผู้ตรวจที่ Broker A ขึ้นสถานะ *Approved* ในวันที่ 2 แล้วกลับเป็น *Pending* ในวันที่ 5 โดยไม่มีอีเมลหรือข้อความใดถึงผู้ตรวจ → **ไม่ผ่าน**

**P03-208 ● · โบรกยกเลิกคำขอถอนเองโดยลูกค้าไม่ได้กดยกเลิกหรือไม่** `w3` `PAY` `G4`

**P03-209 · เมื่อคำขอถูกปฏิเสธหรือยกเลิก เงินกลับเข้าบัญชีเทรดเต็มจำนวนและทันเวลาหรือไม่** `w3` `PAY+STM` `G4`

- **ตรวจอะไร:** ตรวจว่าเมื่อคำขอถอนไม่สำเร็จ ยอดที่ถูกกันไว้กลับคืนสู่ยอดคงเหลือที่ใช้ได้ **เต็มจำนวน** และภายในเวลาเท่าใด นับจากเวลาที่สถานะเปลี่ยนเป็นปฏิเสธ/ยกเลิก ถึง `T4` และตรวจว่ามีการหักค่าธรรมเนียมใดจากรายการที่ไม่สำเร็จหรือไม่
- **ขั้นตอนการตรวจ:**
  1. บันทึกยอดคงเหลือและยอดที่ใช้ได้ (available balance) ทันทีก่อนยื่นคำขอถอน จับภาพให้เห็นตัวเลขเต็มทศนิยม

  3. เมื่อคำขอถูกปฏิเสธหรือยกเลิก บันทึกเวลานั้น แล้วเฝ้ายอดคงเหลือทุก `[เกณฑ์เสนอ: 3 ชั่วโมง จนถึง 14 วัน]`

  6. ดาวน์โหลดรายการเดินบัญชีของบัญชีเทรดที่ครอบคลุมช่วง `T0` ถึง `T4` เป็นไฟล์ที่ดาวน์โหลดได้
  7. คำนวณ `T4 −` เวลาที่สถานะเปลี่ยน เป็นชั่วโมง บันทึกลงตารางรายคำขอ

- **ผ่าน:** ทุกคำขอที่ไม่สำเร็จ เงินกลับเข้าเต็มจำนวนพอดี และภายใน `[เกณฑ์เสนอ: 24 ชั่วโมงหลังสถานะเปลี่ยน]`

**P03-210 ● · โบรกเงียบไม่ตอบเมื่อลูกค้าสอบถามสถานะคำขอถอนหรือไม่** `w3` `SUP` `G4`

**P03-211 · ลูกค้าถูกส่งต่อระหว่างฝ่ายวนไปมาโดยไม่มีใครรับผิดชอบหรือไม่** `w2` `SUP`

  4. ทำเครื่องหมายทุกจุดที่วนกลับไปฝ่ายที่เคยส่งต่อมาแล้ว นับเป็นจำนวนรอบวน

  6. บันทึกแผนผังและตารางสรุป แล้วตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** แผนผังการส่งต่อรายเรื่อง (`RST-BRKA-P03-211-01`) · บันทึกแชทและอีเมลฉบับเต็มทุกช่วง (`RST-BRKA-P03-211-02` ถึง `-NN`) · ภาพหมายเลขเรื่องที่ได้รับ

- **ไม่ผ่าน:** ไม่มีหมายเลขเรื่องให้ติดตาม หรือมีการวนกลับไปฝ่ายเดิมเกินเกณฑ์ข้างต้น จนเรื่องไม่คืบภายใน `[เกณฑ์เสนอ: 14 วันหลัง T5]`

**P03-214 · การหน่วงเกิดเฉพาะช่วงที่บัญชีมีกำไรสะสมหรือไม่** `w3` `PAY` `G4`

**P03-215 · การหน่วงกระจุกอยู่ที่ช่องทางถอนบางช่องทางหรือไม่ และโบรกแจ้งล่วงหน้าหรือไม่** `w2` `PAY`

**P03-216 · การหน่วงเกิดเฉพาะคำขอที่ยื่นนอกเวลาทำการหรือวันหยุดหรือไม่ และประกาศไว้หรือไม่** `w2` `PAY`

- **ยังไม่ได้ตรวจ:** คำขอทั้งหมดตกอยู่ในกลุ่มเดียว จึงไม่มีกลุ่มให้เทียบ
- **ตัวอย่าง:** Broker C ไม่ประกาศเวลาทำการของฝ่ายการเงินเลย คำขอที่ยื่นคืนวันศุกร์ค้างถึงบ่ายวันอังคารทุกครั้ง ขณะที่คำขอวันอังคารเช้าจบใน 3 ชั่วโมง และหน้าถอนไม่มีข้อความเตือนใด → **ไม่ผ่าน**

**P03-217 ● · มีช่องทางร้องเรียนภายในสำหรับกรณีถอนเงินไม่ได้หรือไม่ และลูกค้าหาเจอหรือไม่** `w2` `WEB+DOC`

- **ตรวจอะไร:** ตรวจว่าโบรกมี **ขั้นตอนร้องเรียนอย่างเป็นทางการ** ที่ลูกค้าใช้ได้เมื่อถอนเงินไม่ได้หรือไม่ ต้องดูว่ามีเอกสารระบุ (ก) ช่องทางยื่นเรื่อง (ข) ข้อมูลที่ต้องแนบ (ค) กรอบเวลาที่โบรกจะตอบ (ง) ขั้นถัดไปถ้าไม่พอใจผล และวัดว่าลูกค้าต้องคลิกกี่ครั้งจากหน้าแรกจึงจะพบ
- **ขั้นตอนการตรวจ:**
  1. เปิดหน้าแรกของโบรกในโหมดไม่บันทึกประวัติ แล้วพยายามหาหน้าร้องเรียนโดยไม่ใช้เครื่องมือค้นหาภายนอก บันทึกจำนวนคลิกจากหน้าแรก
  2. ถ้าหาไม่พบใน `[เกณฑ์เสนอ: 5 คลิก]` ให้ใช้ช่องค้นหาในเว็บของโบรกเอง แล้วบันทึกคำที่ใช้ค้นและผลที่ได้
  3. ค้นคำว่า `complaint` `dispute` `grievance` `ร้องเรียน` `ข้อพิพาท` ในทุกหน้าเอกสารสัญญาที่ดาวน์โหลดไว้ บันทึกจำนวนที่พบต่อเอกสาร
  4. อ่านเอกสารที่พบ ทำเครื่องหมายครบ/ไม่ครบทีละองค์ประกอบใน 4 องค์ประกอบข้างต้น
  5. จับภาพเต็มหน้าร้องเรียนพร้อม URL และเก็บสำเนาถาวร PDF เพราะหน้านี้จะถูกนำไปเทียบซ้ำในข้อ 233
  6. บันทึกผลลงตารางและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพเต็มหน้าร้องเรียนพร้อม URL (`RST-BRKA-P03-217-01`) · สำเนาถาวร PDF (`RST-BRKA-P03-217-02`) · บันทึกจำนวนคลิกและเส้นทางที่ใช้หา · ตารางองค์ประกอบ 4 ข้อ
- **ผ่าน:** พบเอกสารขั้นตอนร้องเรียนที่ลูกค้าเข้าถึงได้ และระบุครบอย่างน้อยองค์ประกอบ (ก) และ (ค)
- **ไม่ผ่าน:** ไม่พบเอกสารขั้นตอนร้องเรียนใดเลย หรือพบแต่ไม่ระบุช่องทางยื่นเรื่องที่ใช้ได้จริง
- **ยังไม่ได้ตรวจ:** เว็บล่มตลอดช่วงที่พยายามเข้าและบันทึกความพยายามไว้ครบ
- **ตัวอย่าง:** Broker A มีคำว่า *"ลูกค้าสามารถร้องเรียนได้"* อยู่ในสัญญาฉบับ PDF หน้า 42 โดยไม่ระบุช่องทาง ที่อยู่อีเมล หรือกรอบเวลาใด และไม่มีหน้าเว็บใดกล่าวถึงเรื่องนี้ → **ไม่ผ่าน**

**P03-218 · การร้องเรียนภายในเมื่อถอนเงินไม่ได้ ให้ผลจริงอย่างไร** `w3` `SUP` `G4`

- **ตรวจอะไร:** เมื่อเกิดเหตุคำขอถอนค้างหรือถูกปฏิเสธจริง และผู้ตรวจได้ใช้ช่องทางร้องเรียนตามข้อ 217 **ในฐานะลูกค้าที่เดือดร้อนจากเงินของตนเอง** ให้วัดผลจริงสามอย่าง คือ ได้รับการตอบรับหรือไม่และเมื่อใด · ได้คำวินิจฉัยเป็นลายลักษณ์อักษรหรือไม่ · เงินได้รับการจ่ายหรือไม่หลังร้องเรียน **ห้ามเปิดเผยตัวว่าเป็นผู้ตรวจ ห้ามอ้างองค์กรใด ห้ามขู่ว่าจะเผยแพร่ ห้ามร้องเรียนในกรณีที่ไม่ได้เดือดร้อนจริง**
- **ขั้นตอนการตรวจ:**
  1. ยืนยันก่อนว่ามีเหตุจริง คือคำขอค้างเกินกรอบที่ประกาศตามข้อ 206 หรือถูกปฏิเสธด้วยเหตุที่ไม่เคยประกาศตามข้อ 203
  2. ยื่นเรื่องตามขั้นตอนที่โบรกประกาศไว้ทุกประการ แนบเฉพาะข้อมูลของบัญชีผู้ตรวจเอง บันทึก `T5` เป็น UTC
  3. เก็บสำเนาข้อความที่ยื่นและหลักฐานการยื่น (หมายเลขเรื่อง อีเมลตอบรับอัตโนมัติ) ทันที
  4. บันทึกเวลาที่ได้รับการตอบรับที่เป็นเนื้อหาเป็น `T6` และคำนวณ `T6 − T5` เป็นวัน
  5. ติดตามทุก `[เกณฑ์เสนอ: 7 วัน จนครบ 60 วันหลัง T5]` บันทึกทุกความเคลื่อนไหวพร้อมเวลา
  6. บันทึกว่าได้รับ **คำวินิจฉัยเป็นลายลักษณ์อักษร** ที่ระบุผลและเหตุผลหรือไม่ ถ้าได้ให้เก็บไฟล์ต้นฉบับ
  7. บันทึกว่าเงินถูกจ่ายหรือไม่หลังร้องเรียน ถ้าจ่ายให้บันทึก `T2` และยอดที่ได้รับจริงเทียบกับยอดที่ขอ
  8. บันทึกไทม์ไลน์ `T5/T6/T2` ทั้งชุด และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** สำเนาเรื่องที่ยื่นพร้อมเวลา (`RST-BRKA-P03-218-01`) · หลักฐานการตอบรับและหมายเลขเรื่อง (`RST-BRKA-P03-218-02`) · คำวินิจฉัยเป็นลายลักษณ์อักษรต้นฉบับ (`RST-BRKA-P03-218-03`) · รายการเดินบัญชีปลายทางถ้ามีการจ่าย · ไทม์ไลน์ UTC
- **ผ่าน:** ได้รับการตอบรับที่เป็นเนื้อหาภายใน `[เกณฑ์เสนอ: 14 วันหลัง T5]` และได้คำวินิจฉัยเป็นลายลักษณ์อักษรภายใน `[เกณฑ์เสนอ: 60 วันหลัง T5]` ไม่ว่าผลจะเป็นคุณหรือไม่
- **ไม่ผ่าน:** ไม่ได้รับการตอบรับที่เป็นเนื้อหาภายในกรอบข้างต้น หรือได้รับแต่ไม่มีคำวินิจฉัยเป็นลายลักษณ์อักษรเลยจนครบ 60 วัน
- **ยังไม่ได้ตรวจ:** ไม่เกิดเหตุที่เข้าเงื่อนไขให้ร้องเรียนตลอดรอบตรวจ **ห้ามยื่นเรื่องร้องเรียนเพื่อทดสอบโดยไม่มีเหตุจริง**
- **ตัวอย่าง:** ผู้ตรวจยื่นเรื่องกับ Broker B ตามขั้นตอนที่ประกาศ เพราะคำขอถอนค้าง 21 วัน ได้อีเมลตอบรับอัตโนมัติวันเดียวกัน แต่ครบ 60 วันแล้วไม่มีคำวินิจฉัยใดและเงินยังไม่เข้า → **ไม่ผ่าน** และตกด่าน G4

**P03-219 · โบรกให้ข้อมูลขั้นยกระดับไปหน่วยงานภายนอกหรือไม่ เมื่อผลร้องเรียนภายในไม่เป็นที่พอใจ** `w2` `WEB+SUP`

- **ตรวจอะไร:** ตรวจว่าเอกสารขั้นตอนร้องเรียนหรือคำวินิจฉัยที่ได้รับ ระบุ **ขั้นถัดไป** หรือไม่ เช่น ชื่อหน่วยงานหรือกลไกระงับข้อพิพาทที่ลูกค้ายื่นต่อได้ ช่องทางติดต่อ และกรอบเวลาที่ต้องยื่นภายใน ข้อนี้ตรวจเฉพาะ **การให้ข้อมูลขั้นยกระดับในบริบทของการถอนเงินไม่ได้** ไม่ใช่การประเมินตัวหน่วยงานกำกับซึ่งอยู่ที่เสา P01

  1. เปิดเอกสารขั้นตอนร้องเรียนจากข้อ 217 และคำวินิจฉัยจากข้อ 218 (ถ้ามี)
  2. ค้นคำว่า `ombudsman` `escalate` `external` `dispute resolution` `หน่วยงาน` `ยกระดับ` บันทึกจำนวนที่พบ
  3. คัดลอกข้อความขั้นถัดไปทุกจุดแบบคำต่อคำ พร้อมชื่อหน่วยงานหรือกลไกที่ระบุ
  4. ตรวจว่าชื่อที่ระบุมีตัวตนสาธารณะจริงหรือไม่ โดยค้นชื่อนั้นและเปิดเว็บทางการของหน่วยงานเอง จับภาพหน้าทางการพร้อมโดเมน
  5. บันทึกว่าเอกสารระบุกรอบเวลาที่ลูกค้าต้องยื่นต่อภายในกี่วันหรือไม่
  6. บันทึกตารางผลและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อความขั้นยกระดับในเอกสารโบรก (`RST-BRKA-P03-219-01`) · ภาพหน้าทางการของหน่วยงานที่ถูกอ้างพร้อมโดเมน (`RST-BRKA-P03-219-02`) · ตารางผลการตรวจสอบตัวตน
- **ผ่าน:** เอกสารระบุขั้นถัดไปพร้อมชื่อหน่วยงานหรือกลไกที่มีตัวตนสาธารณะจริง และมีช่องทางติดต่อที่ใช้ได้
- **ไม่ผ่าน:** ไม่ระบุขั้นถัดไปเลย หรือระบุชื่อที่ค้นแล้วไม่พบตัวตนสาธารณะใด
- **ยังไม่ได้ตรวจ:** ไม่มีเอกสารขั้นตอนร้องเรียนให้ตรวจตั้งแต่ข้อ 217
- **ตัวอย่าง:** Broker C เขียนว่าลูกค้ายื่นต่อได้ที่ *"คณะกรรมการไกล่เกลี่ยอิสระของบริษัท"* ผู้ตรวจค้นแล้วไม่พบตัวตนสาธารณะใด ไม่มีที่อยู่ อีเมล หรือหน้าเว็บ → **ไม่ผ่าน**

**P03-220 · ชุดหลักฐานขั้นต่ำเมื่อคำขอถอนถูกปฏิเสธ ถูกเก็บครบทุกรายการหรือไม่** `w2` `DOC`

**P03-222 · บัญชีถูกจำกัดการเข้าใช้หรือถูกระงับพร้อมกับที่คำขอถอนค้างหรือไม่** `w3` `ACC+PAY` `G4`

  8. บันทึกไทม์ไลน์การเปลี่ยนสิทธิเทียบกับสถานะคำขอถอน และตั้งชื่อไฟล์ตาม Evidence ID

**P03-223 · โบรกเสนอสิ่งอื่นแทนการจ่ายเงินเมื่อลูกค้าขอถอนหรือไม่** `w3` `SUP`

**P03-224 · อัตราส่วนคำขอถอนที่สำเร็จ ค้าง และถูกปฏิเสธ ตลอดรอบตรวจเป็นเท่าใด** `w3` `STM` `G4`

- **ตัวอย่าง:** ตลอดรอบตรวจ 8 สัปดาห์ ผู้ตรวจยื่นคำขอถอนกับ Broker B รวม 7 รายการ จ่ายครบ 5 รายการ ถูกปฏิเสธ 1 รายการด้วยเหตุที่ประกาศไว้และคืนเงินครบ และค้าง 1 รายการมูลค่า 62% ของมูลค่ารวมทั้งหมดจนจบรอบโดยไม่มีคำอธิบาย → **ไม่ผ่าน** และตกด่าน G4

**P03-225 · กรณีไม่เกิดเหตุปฏิเสธหรือหน่วงเลยตลอดรอบตรวจ ถูกบันทึกอย่างถูกวิธีหรือไม่** `w1` `DOC`

- **ตรวจอะไร:** ควบคุมคุณภาพของหมวด S09 ในกรณีที่ **ไม่เกิดเหตุใดเลย** ซึ่งเป็นผลลัพธ์ที่พบได้และต้องบันทึกให้ถูก ไม่ใช่ปล่อยว่าง ให้ตรวจว่าแฟ้มของหมวดนี้มีเอกสารยืนยันเชิงบวกว่า "ตรวจแล้วไม่พบเหตุ" ครบหรือไม่ ได้แก่ รายการคำขอถอนทั้งหมดพร้อมสถานะสุดท้าย · ภาพหน้าประวัติที่แสดงว่าไม่มีรายการค้าง · บันทึกวันเริ่มและวันปิดรอบตรวจเป็น UTC · คำอธิบายว่าเหตุใดข้อ 202–223 จึงลงผลเป็น **ยังไม่ได้ตรวจ**
- **ขั้นตอนการตรวจ:**
  1. เปิดตารางสรุปจากข้อ 224 ตรวจว่าทุกรายการจบด้วยการจ่ายครบหรือไม่
  2. จับภาพหน้าประวัติคำขอถอนทั้งหมดในวันปิดรอบตรวจ ให้เห็นว่าไม่มีรายการค้าง พร้อมเวลา UTC
  3. ไล่ข้อ 202 ถึง 223 ทีละข้อ บันทึกผลเป็น **ยังไม่ได้ตรวจ** พร้อมเหตุผลอ้างอิงถึงตารางสรุปข้อ 224
  4. ตรวจว่าไม่มีข้อใดถูกบันทึกเป็น **ผ่าน** โดยอัตโนมัติเพียงเพราะไม่เกิดเหตุ ถ้าพบให้แก้เป็นยังไม่ได้ตรวจ
  5. บันทึกวันเริ่มและวันปิดรอบตรวจเป็น UTC พร้อมจำนวนสัปดาห์รวม เทียบกับ **ช่วงตรวจ** ที่กำหนดใน `p03-01.md`
  6. บันทึกเอกสารสรุปของหมวดและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าประวัติคำขอถอนวันปิดรอบ (`RST-BRKA-P03-225-01`) · เอกสารสรุปสถานะรายข้อ 202–223 (`RST-BRKA-P03-225-02`) · บันทึกวันเริ่ม–วันปิดรอบตรวจเป็น UTC
- **ผ่าน:** มีเอกสารยืนยันเชิงบวกครบทั้ง 4 รายการ และไม่มีข้อใดถูกบันทึกเป็นผ่านโดยอัตโนมัติจากการไม่เกิดเหตุ
- **ไม่ผ่าน:** ขาดเอกสารยืนยันรายการใดรายการหนึ่ง หรือมีข้อที่ถูกบันทึกเป็นผ่านทั้งที่ไม่เกิดเหตุให้ตรวจ
- **ยังไม่ได้ตรวจ:** มีเหตุปฏิเสธหรือหน่วงเกิดขึ้นจริงในรอบตรวจ จึงไม่เข้าเงื่อนไขของข้อนี้
- **ตัวอย่าง:** รอบตรวจ Broker C ไม่มีคำขอถอนใดถูกปฏิเสธหรือค้างเลย แต่ผู้ตรวจบันทึกข้อ 202 ถึง 223 เป็น **ผ่าน** ทั้งหมดโดยไม่มีเอกสารยืนยันว่าไม่เกิดเหตุ → **ไม่ผ่าน**

## S10 · การถอนกำไรและเงื่อนไขพิเศษที่เพิ่มขึ้นภายหลัง (226–250)

**P03-226 ● · การถอนส่วนที่เป็นกำไร ทำได้เหมือนการถอนเงินต้นหรือไม่** `w3` `PAY` `G4`

- **ตรวจอะไร:** เทียบ **ขั้นตอน เงื่อนไข และผลลัพธ์** ของการถอนสองแบบในบัญชีเดียวกัน คือถอนยอดที่ไม่เกินเงินต้นที่เคยฝาก กับถอนยอดที่มีส่วนของกำไรรวมอยู่ ให้ควบคุมช่องทางและช่วงเวลาให้เหมือนกัน แล้วบันทึกความต่างทุกจุด ทั้งจำนวนขั้นตอนบนหน้าจอ · เอกสารที่ถูกขอ · ระยะเวลาจาก `T0` ถึง `T2` · ยอดที่ได้รับจริง กำไรที่ใช้ตรวจต้องเกิดจากการเทรดตามปกติเท่านั้น **ห้ามปรับพฤติกรรมการเทรดเพื่อสร้างกำไรให้ทดสอบ และห้ามใช้กลยุทธ์ที่ผิดเงื่อนไขของโบรก**
- **ขั้นตอนการตรวจ:**
  1. บันทึกยอดเงินต้นสะสมที่ฝากเข้าบัญชีทั้งหมด และยอดกำไรสะสม ณ วันเริ่มทดสอบ จากรายงานบัญชีของโบรก จับภาพให้เห็นตัวเลข
  2. ยื่นคำขอถอน **ยอด A** ที่อยู่ในส่วนไม่เกินเงินต้น บันทึก `T0` แล้วติดตามจนถึง `T2` บันทึกทุกขั้นตอนบนหน้าจอเป็นลำดับ
  3. เว้นระยะ `[เกณฑ์เสนอ: อย่างน้อย 5 วัน]` แล้วยื่นคำขอถอน **ยอด A** เท่ากัน ผ่านช่องทางเดิม ในช่วงที่ยอดคงเหลือประกอบด้วยกำไรสะสม บันทึก `T0`
  4. บันทึกทุกขั้นตอนบนหน้าจอของรอบที่สอง เทียบกับลำดับของรอบแรก ทำเครื่องหมายขั้นที่เพิ่มขึ้น
  5. บันทึกเอกสารหรือคำถามเพิ่มเติมที่ถูกขอในแต่ละรอบ พร้อมเวลา UTC ที่ถูกขอเทียบกับ `T0`
  6. บันทึก `T2` และยอดที่เข้าบัญชีปลายทางจริงของทั้งสองรอบ เต็มทศนิยม
  7. ทำซ้ำคู่เทียบนี้ `[เกณฑ์เสนอ: 2 คู่ ห่างกันคู่ละ 2 สัปดาห์]` เพื่อกันความบังเอิญ
  8. บันทึกตารางเทียบสองแบบพร้อมเงื่อนไขควบคุม และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพรายงานบัญชีที่แสดงเงินต้นและกำไรสะสม (`RST-BRKA-P03-226-01`) · ภาพทุกขั้นตอนบนหน้าจอของทั้งสองรอบ (`RST-BRKA-P03-226-02` ถึง `-NN`) · อีเมลคำขอเอกสารเพิ่ม (ถ้ามี) · ตารางเทียบขั้นตอน เอกสาร เวลา และยอดที่ได้รับ
- **ผ่าน:** การถอนที่มีส่วนของกำไรใช้ขั้นตอนและเอกสารเท่ากับการถอนเงินต้น และระยะเวลา `T2 − T0` ไม่เกิน `[เกณฑ์เสนอ: 1.5 เท่า]` ในทุกคู่เทียบ
- **ไม่ผ่าน:** การถอนที่มีส่วนของกำไรถูกเพิ่มขั้นตอน เพิ่มเอกสาร หรือใช้เวลาเกินเกณฑ์ข้างต้น โดยไม่มีข้อเงื่อนไขที่ประกาศไว้ล่วงหน้ารองรับ
- **ยังไม่ได้ตรวจ:** บัญชีไม่มีกำไรสะสมเลยตลอดรอบตรวจ จึงไม่มีคู่เทียบ (ต้องบันทึกข้อเท็จจริงนี้พร้อมรายงานบัญชี)
- **ตัวอย่าง:** ที่ Broker A การถอนยอดเท่ากันช่องทางเดียวกัน รอบที่ไม่มีกำไรใช้ 3 ขั้นตอนและเงินเข้าใน 5 ชั่วโมง ส่วนรอบที่มีกำไรถูกขอเอกสารเพิ่ม 2 ฉบับและเงินเข้าในวันที่ 9 ทั้งที่เอกสารเงื่อนไขไม่มีข้อใดแยกการถอนกำไรออกจากการถอนเงินต้น → **ไม่ผ่าน** และตกด่าน G4

**P03-227 · เงื่อนไขปริมาณการเทรดขั้นต่ำก่อนถอน ถูกประกาศไว้ล่วงหน้าและคำนวณตามได้หรือไม่** `w3` `WEB+DOC`

- **ตรวจอะไร:** ตรวจว่ามีเงื่อนไข **ปริมาณการเทรดขั้นต่ำ** (เช่น จำนวนล็อตสะสม จำนวนรายการ หรือมูลค่าซื้อขายรวม) ที่ต้องทำก่อนจึงจะถอนได้หรือไม่ ถ้ามี ต้องตรวจว่าประกาศไว้ที่ใด ตั้งแต่เมื่อใด และ **สูตรคำนวณชัดพอที่ลูกค้าคำนวณเองได้หรือไม่** ต้องระบุครบทั้งหน่วยที่นับ ตัวคูณ ประเภทสินค้าที่นับได้ และช่วงเวลาที่นับ
- **ขั้นตอนการตรวจ:**
  1. ค้นคำว่า `volume` `turnover` `lot` `trading requirement` `ปริมาณการเทรด` `ยอดซื้อขาย` ในทุกหน้าเว็บและเอกสารสัญญาที่ดาวน์โหลดไว้ บันทึกจำนวนที่พบต่อเอกสาร
  2. คัดลอกข้อความที่พบทุกจุดแบบคำต่อคำ พร้อม URL หรือชื่อเอกสารและหมายเลขหน้า
  3. ตรวจว่าข้อความระบุครบ 4 องค์ประกอบหรือไม่ คือ หน่วยที่นับ · ตัวคูณ · ประเภทสินค้าที่นับได้ · ช่วงเวลาที่นับ
  4. ลองคำนวณตามสูตรที่ประกาศด้วยตัวเลขการเทรดจริงของบัญชีผู้ตรวจ บันทึกว่าคำนวณได้ผลลัพธ์เดียวหรือได้หลายผลลัพธ์เพราะข้อความกำกวม
  5. เทียบตัวเลขที่คำนวณได้กับตัวเลขที่ระบบโบรกแสดง (ถ้าระบบแสดง) บันทึกส่วนต่าง
  6. เก็บสำเนาถาวรของทุกหน้าที่พบข้อความ พร้อมเวลา UTC เพราะจะถูกนำไปเทียบซ้ำในข้อ 233
  7. บันทึกตารางผลและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อความเงื่อนไขทุกจุดพร้อม URL (`RST-BRKA-P03-227-01` ถึง `-NN`) · สำเนาถาวร PDF (`RST-BRKA-P03-227-10`) · เอกสารการคำนวณของผู้ตรวจพร้อมตัวเลขที่ใช้
- **ผ่าน:** ไม่มีเงื่อนไขปริมาณการเทรดขั้นต่ำ หรือมีแต่ประกาศครบทั้ง 4 องค์ประกอบจนลูกค้าคำนวณเองได้ผลลัพธ์เดียว
- **ไม่ผ่าน:** มีเงื่อนไขแต่ขาดองค์ประกอบใดองค์ประกอบหนึ่ง จนคำนวณได้หลายผลลัพธ์หรือคำนวณไม่ได้เลย
- **ยังไม่ได้ตรวจ:** เอกสารสัญญาไม่เปิดให้ดาวน์โหลดจนตรวจไม่ได้ (ต้องบันทึกความพยายามไว้ครบ)
- **ตัวอย่าง:** Broker B เขียนว่า *"ลูกค้าต้องมีปริมาณการเทรดที่เพียงพอก่อนถอน"* โดยไม่ระบุหน่วย ตัวคูณ หรือช่วงเวลา ผู้ตรวจถามฝ่ายบริการ 2 ครั้งได้ตัวเลขต่างกัน → **ไม่ผ่าน**

**P03-228 ● · เงื่อนไขปริมาณการเทรดถูกนำมาใช้จริงตรงกับที่ประกาศหรือไม่** `w3` `PAY+STM` `G4`

- **ตรวจอะไร:** เทียบ **เงื่อนไขที่ประกาศ** (จากข้อ 227) กับ **สิ่งที่โบรกใช้จริงตอนพิจารณาคำขอถอน** โดยคำนวณปริมาณการเทรดสะสมของบัญชีผู้ตรวจ ณ วันยื่นคำขอ แล้วดูว่าโบรกอนุมัติหรือปฏิเสธสอดคล้องกับสูตรที่ประกาศหรือไม่ ถ้าโบรกอ้างตัวเลขที่ต่างจากที่ลูกค้าคำนวณได้ ต้องบันทึกทั้งสองตัวเลขและวิธีที่มา
- **ขั้นตอนการตรวจ:**
  1. ดาวน์โหลดประวัติการเทรดทั้งหมดของบัญชีจนถึงวันยื่นคำขอ เป็นไฟล์ที่ดาวน์โหลดได้ บันทึกเวลา UTC ที่ดาวน์โหลด
  2. คำนวณปริมาณการเทรดสะสมตามสูตรที่โบรกประกาศ บันทึกตัวเลขที่ได้พร้อมวิธีคำนวณทีละขั้น
  3. ยื่นคำขอถอนตามการใช้บริการปกติ บันทึก `T0` และยอดที่ขอ
  4. บันทึกผลการพิจารณาและข้อความที่โบรกให้ ถ้ามีการอ้างตัวเลขปริมาณการเทรด ให้คัดลอกตัวเลขนั้นแบบคำต่อคำ
  5. เทียบตัวเลขของโบรกกับตัวเลขที่ผู้ตรวจคำนวณ บันทึกส่วนต่างและร้อยละของส่วนต่าง
  6. ถ้าตัวเลขต่างกัน ให้ขอคำอธิบายวิธีคำนวณผ่านช่องทางลูกค้าปกติ บันทึก `T5` และคำตอบที่ได้
  7. ทำซ้ำการตรวจนี้กับคำขอถอนทุกรายการที่โบรกอ้างเงื่อนไขนี้ตลอดรอบตรวจ
  8. บันทึกตารางเทียบตัวเลขรายคำขอ และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ประวัติการเทรดฉบับดาวน์โหลด (`RST-BRKA-P03-228-01`) · เอกสารการคำนวณของผู้ตรวจทีละขั้น (`RST-BRKA-P03-228-02`) · ข้อความที่โบรกอ้างตัวเลข (`RST-BRKA-P03-228-03`) · ตารางเทียบตัวเลขรายคำขอ
- **ผ่าน:** ผลการพิจารณาทุกคำขอสอดคล้องกับสูตรที่ประกาศ หรือตัวเลขต่างกันแต่โบรกอธิบายวิธีคำนวณจนกระทบยอดได้
- **ไม่ผ่าน:** มีคำขออย่างน้อย 1 รายการที่ถูกปฏิเสธหรือถูกหน่วงโดยอ้างเงื่อนไขปริมาณการเทรด ทั้งที่คำนวณตามสูตรที่ประกาศแล้วเข้าเงื่อนไข และโบรกอธิบายวิธีคำนวณไม่ได้ภายใน `[เกณฑ์เสนอ: 14 วันหลัง T5]`
- **ยังไม่ได้ตรวจ:** โบรกไม่เคยอ้างเงื่อนไขปริมาณการเทรดกับคำขอใดตลอดรอบตรวจ

**P03-230 ● · โบรกอ้าง "การตรวจสอบเพิ่มเติม" เฉพาะกับบัญชีที่มีกำไรหรือไม่** `w3` `PAY+SUP` `G4`

**P03-231 · โบรกประกาศกรอบเวลาสูงสุดของ "การตรวจสอบเพิ่มเติม" ไว้หรือไม่** `w2` `WEB+DOC`

**P03-232 · สำเนาถาวรของหน้าเงื่อนไขถอน ณ วันเปิดบัญชี ถูกเก็บไว้ครบหรือไม่** `w3` `DOC`

- **ตัวอย่าง:** แฟ้มของ Broker A มีสำเนาหน้าเงื่อนไขการถอนและหน้าค่าธรรมเนียม แต่ไม่มีหน้าเอกสารที่ต้องใช้ ทำให้เมื่อโบรกขอเอกสารเพิ่มในภายหลัง ผู้ตรวจพิสูจน์ไม่ได้ว่ารายการเดิมมีอะไรบ้าง → **ไม่ผ่าน**

**P03-233 ● · เงื่อนไขการถอน ณ วันขอถอน ต่างจาก ณ วันเปิดบัญชีหรือไม่** `w3` `WEB+DOC` `G4`

- **ตรวจอะไร:** เทียบ **เนื้อหาของหน้าเงื่อนไขการถอน** ระหว่างสำเนาถาวรฉบับวันเปิดบัญชี (จากข้อ 232) กับฉบับที่ดึงใหม่ ณ วันยื่นคำขอถอน ทีละย่อหน้า เพื่อหาข้อที่ **เพิ่มขึ้น หายไป หรือถูกแก้ไข** โดยเฉพาะข้อที่ทำให้ถอนยากขึ้น เช่น เพิ่มเอกสาร เพิ่มปริมาณการเทรดขั้นต่ำ เพิ่มระยะเวลารอ เพิ่มค่าธรรมเนียม หรือเพิ่มดุลพินิจของโบรก
- **ขั้นตอนการตรวจ:**
  1. ดึงหน้าเงื่อนไขการถอนทุกหน้าใหม่ในวันยื่นคำขอถอน เก็บเป็นสำเนาถาวรพร้อมเวลา UTC และค่าแฮช
  2. แปลงทั้งสองฉบับเป็นข้อความล้วน แล้ววางในเครื่องมือเทียบข้อความ
  3. บันทึกทุกจุดที่ต่างกันลงตาราง โดยระบุ **เพิ่ม / ลบ / แก้ไข** และคัดลอกข้อความทั้งฉบับเดิมและฉบับใหม่แบบคำต่อคำ
  4. ให้ผลกระทบของแต่ละจุดเป็น **ทำให้ถอนยากขึ้น** · **ทำให้ถอนง่ายขึ้น** · **ไม่กระทบการถอน** พร้อมเหตุผลสั้น
  5. ตรวจว่าหน้าใหม่ระบุวันที่มีผลของฉบับปัจจุบันหรือไม่ และวันที่นั้นอยู่ก่อนหรือหลังวันเปิดบัญชี
  6. ค้นในกล่องอีเมลว่าเคยได้รับการแจ้งการเปลี่ยนแปลงนี้หรือไม่ บันทึกวันที่ที่ได้รับ (ส่งต่อไปตัดสินที่ข้อ 234)
  7. จับภาพสองฉบับวางคู่กันในภาพเดียว ให้เห็นวันที่ของทั้งสองฉบับ
  8. บันทึกตารางความต่างและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** สำเนาถาวรฉบับวันยื่นคำขอ (`RST-BRKA-P03-233-01`) · ผลการเทียบข้อความที่ระบุจุดต่างทุกจุด (`RST-BRKA-P03-233-02`) · ภาพเทียบคู่ที่เห็นวันที่ทั้งสองฉบับ (`RST-BRKA-P03-233-03`) · ตารางประเมินผลกระทบรายจุด
- **ผ่าน:** ไม่มีจุดใดต่างกัน หรือมีจุดต่างแต่ไม่มีจุดใดจัดเป็น "ทำให้ถอนยากขึ้น"
- **ไม่ผ่าน:** มีอย่างน้อย 1 จุดที่จัดเป็น "ทำให้ถอนยากขึ้น" และเกิดขึ้นหลังวันเปิดบัญชีของผู้ตรวจ
- **ยังไม่ได้ตรวจ:** ไม่มีสำเนาถาวรฉบับวันเปิดบัญชีให้เทียบ ตามที่บันทึกไว้ในข้อ 232
- **ตัวอย่าง:** สำเนาหน้าเงื่อนไขถอนของ Broker B ฉบับวันเปิดบัญชีไม่มีข้อกำหนดปริมาณการเทรด แต่ฉบับวันยื่นคำขอเพิ่มข้อว่า *"ต้องมีปริมาณสะสมไม่น้อยกว่า 10 ล็อตก่อนถอน"* โดยไม่ระบุวันที่มีผล → **ไม่ผ่าน** และตกด่าน G4

**P03-234 · โบรกแจ้งลูกค้าล่วงหน้าก่อนเปลี่ยนเงื่อนไขการถอนหรือไม่** `w3` `DOC`

- **ตรวจอะไร:** สำหรับทุกจุดที่พบว่าเปลี่ยนแปลงในข้อ 233 ให้ตรวจว่าโบรก **แจ้งลูกค้าล่วงหน้า** หรือไม่ ผ่านช่องทางใด ล่วงหน้ากี่วันก่อนมีผล และข้อความที่แจ้งระบุเนื้อหาของการเปลี่ยนแปลงหรือเป็นเพียงข้อความกว้างว่ามีการปรับปรุงเอกสาร รวมทั้งตรวจว่าสัญญาระบุวิธีแจ้งการเปลี่ยนแปลงไว้อย่างไรและโบรกทำตามนั้นหรือไม่
- **ขั้นตอนการตรวจ:**
  1. เปิดตารางจุดเปลี่ยนแปลงจากข้อ 233 เรียงตามลำดับผลกระทบ
  2. ค้นกล่องอีเมลทั้งกล่อง รวมโฟลเดอร์ขยะ ด้วยคำว่า `update` `amend` `terms` `เปลี่ยนแปลง` `ปรับปรุงเงื่อนไข` บันทึกทุกฉบับที่พบพร้อมวันที่
  3. เปิดกล่องข้อความในระบบบัญชีและหน้าประกาศของเว็บ บันทึกประกาศที่เกี่ยวข้องพร้อมวันที่
  4. จับคู่จุดเปลี่ยนแปลงแต่ละจุดกับการแจ้งที่พบ บันทึกว่า **มีการแจ้ง** หรือ **ไม่มีการแจ้ง** และคำนวณจำนวนวันล่วงหน้า
  5. อ่านข้อความที่แจ้ง ทำเครื่องหมายว่าระบุเนื้อหาการเปลี่ยนแปลงหรือเป็นข้อความกว้าง
  6. ค้นในสัญญาว่าระบุวิธีและระยะเวลาการแจ้งการเปลี่ยนแปลงไว้อย่างไร คัดลอกข้อความนั้น แล้วเทียบกับสิ่งที่เกิดขึ้นจริง
  7. บันทึกตารางจับคู่และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางจับคู่จุดเปลี่ยนแปลงกับการแจ้ง (`RST-BRKA-P03-234-01`) · อีเมลแจ้งการเปลี่ยนแปลงต้นฉบับพร้อมหัวจดหมาย (`RST-BRKA-P03-234-02` ถึง `-NN`) · ภาพข้อความในสัญญาที่ระบุวิธีแจ้ง
- **ผ่าน:** ทุกจุดที่จัดเป็น "ทำให้ถอนยากขึ้น" มีการแจ้งล่วงหน้าที่ระบุเนื้อหาการเปลี่ยนแปลง และล่วงหน้าไม่น้อยกว่าที่สัญญากำหนด หรือไม่น้อยกว่า `[เกณฑ์เสนอ: 14 วัน]` ถ้าสัญญาไม่กำหนด
- **ไม่ผ่าน:** มีอย่างน้อย 1 จุดที่ไม่มีการแจ้งเลย หรือแจ้งเป็นข้อความกว้างที่ไม่ระบุเนื้อหา หรือแจ้งช้ากว่าที่สัญญากำหนด
- **ยังไม่ได้ตรวจ:** ไม่พบจุดเปลี่ยนแปลงใดในข้อ 233
- **ตัวอย่าง:** Broker A เปลี่ยนเงื่อนไขให้ต้องรอ 14 วันก่อนถอนกำไร โดยส่งอีเมลฉบับเดียวเนื้อความว่า *"เราได้ปรับปรุงเอกสารเงื่อนไขการใช้บริการ"* พร้อมลิงก์ ในวันเดียวกับที่มีผล → **ไม่ผ่าน**

**P03-235 ● · โบรกยกเลิกหรือหักกำไรย้อนหลังโดยอ้างพฤติกรรมการเทรดหรือไม่** `w3` `STM+PAY` `G4`

- **ตรวจอะไร:** ตรวจเหตุการณ์ที่กำไรที่เคยปรากฏในบัญชีถูก **ยกเลิก ปรับ หรือหักออกย้อนหลัง** โดยโบรกอ้างเหตุเกี่ยวกับพฤติกรรมการเทรด เช่น อ้างว่าเป็นการเทรดที่ไม่เหมาะสม อ้างว่าราคาผิดพลาด อ้างว่าใช้ประโยชน์จากความหน่วงของระบบ ให้บันทึกรายการที่ถูกปรับทุกบรรทัด ยอดที่หายไป และเทียบกับข้อสัญญาที่ถูกอ้าง การตรวจนี้ทำจากผลของการเทรดตามปกติเท่านั้น **ห้ามใช้กลยุทธ์ที่ผิดเงื่อนไขของโบรกเพื่อทดสอบโดยเด็ดขาด**
- **ขั้นตอนการตรวจ:**
  1. ดาวน์โหลดประวัติรายการและรายงานบัญชีเก็บไว้นอกระบบโบรก `[เกณฑ์เสนอ: ทุกสัปดาห์ตลอดช่วงตรวจ]` เพื่อให้มีฉบับก่อนการปรับเสมอ
  2. เมื่อพบว่ายอดคงเหลือหรือกำไรสะสมลดลงโดยไม่ได้เกิดจากการเทรดของผู้ตรวจ ให้จับภาพทันทีพร้อมเวลา UTC
  3. เทียบรายงานฉบับล่าสุดกับฉบับก่อนหน้า ระบุรายการที่ถูกปรับทีละบรรทัด บันทึกหมายเลขรายการ เวลาเปิด–ปิด และยอดที่เปลี่ยน
  4. คำนวณยอดรวมที่ถูกหักออก เต็มทศนิยม พร้อมระบุสกุลเงิน
  5. ค้นข้อความหรืออีเมลที่โบรกแจ้งเหตุการปรับ คัดลอกเหตุผลและข้อสัญญาที่ถูกอ้างแบบคำต่อคำ พร้อมเวลาที่ได้รับ
  6. เปิดสำเนาถาวรของสัญญาฉบับวันเปิดบัญชี ค้นข้อที่ถูกอ้าง บันทึกว่าพบหรือไม่พบ และข้อความตรงกันหรือไม่
  7. ทักท้วงผ่านช่องทางลูกค้าปกติโดยอ้างหมายเลขรายการที่ถูกปรับ บันทึก `T5` และคำตอบที่ได้
  8. บันทึกตารางรายการที่ถูกปรับทั้งชุดพร้อมไทม์ไลน์ และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** รายงานบัญชีฉบับก่อนและหลังการปรับ (`RST-BRKA-P03-235-01`, `-02`) · ภาพยอดคงเหลือก่อน–หลังพร้อมเวลา (`RST-BRKA-P03-235-03`) · ข้อความแจ้งเหตุการปรับต้นฉบับ (`RST-BRKA-P03-235-04`) · สำเนาสัญญาฉบับวันเปิดบัญชีที่มีข้อที่ถูกอ้าง · ตารางรายการที่ถูกปรับทีละบรรทัด
- **ผ่าน:** ไม่มีการปรับกำไรย้อนหลัง หรือมีแต่โบรกแจ้งเหตุเป็นลายลักษณ์อักษร ระบุรายการที่ถูกปรับทีละรายการ และอ้างข้อสัญญาที่มีอยู่จริงตั้งแต่วันเปิดบัญชี
- **ไม่ผ่าน:** มีการปรับกำไรย้อนหลังอย่างน้อย 1 ครั้ง โดยไม่แจ้ง หรือแจ้งแต่อ้างข้อที่ไม่มีในสัญญาฉบับวันเปิดบัญชี หรือไม่ระบุรายการที่ถูกปรับ
- **ยังไม่ได้ตรวจ:** ไม่เกิดการปรับกำไรย้อนหลังเลยตลอดรอบตรวจ และมีรายงานบัญชีรายสัปดาห์ครบทุกฉบับยืนยัน
- **ตัวอย่าง:** ยอดกำไรสะสมของผู้ตรวจที่ Broker C ลดลง 1,240 หน่วยในคืนวันหนึ่ง โดยรายงานใหม่ไม่มีรายการที่เคยปิดกำไรไว้ 6 รายการ และไม่มีอีเมลหรือข้อความใดแจ้งเหตุเลย → **ไม่ผ่าน** และตกด่าน G4

**P03-236 · นิยาม "พฤติกรรมการเทรดที่ไม่เหมาะสม" ในสัญญา ชัดพอให้ลูกค้าปฏิบัติตามได้หรือไม่** `w3` `DOC`

- **ตรวจอะไร:** อ่านข้อสัญญาที่กำหนดพฤติกรรมการเทรดที่โบรกถือว่าไม่เหมาะสม แล้วประเมินว่า **ลูกค้าทั่วไปอ่านแล้วรู้ล่วงหน้าได้หรือไม่ว่าต้องหลีกเลี่ยงอะไร** เกณฑ์คือข้อความต้องมีตัวชี้วัดที่วัดได้ เช่น ระยะเวลาถือคำสั่งขั้นต่ำเป็นวินาที จำนวนคำสั่งต่อหน่วยเวลา หรือรูปแบบที่บรรยายได้ชัด ไม่ใช่คำกว้างอย่าง "การเทรดที่ผิดปกติ" หรือ "การใช้ประโยชน์โดยมิชอบ" ที่ตีความได้ไม่จำกัด
- **ขั้นตอนการตรวจ:**
  1. เปิดสัญญาและเอกสารประกอบทุกฉบับ ค้นคำว่า `abusive` `improper` `manipulat` `arbitrage` `scalp` `latency` `ไม่เหมาะสม` `ผิดปกติ`
  2. คัดลอกทุกข้อที่พบแบบคำต่อคำ พร้อมหมายเลขข้อและหน้า
  3. ประเมินแต่ละข้อว่ามี **ตัวชี้วัดที่วัดได้** หรือไม่ ทำเครื่องหมายมี/ไม่มี พร้อมระบุตัวชี้วัดที่พบ
  4. สำหรับข้อที่ไม่มีตัวชี้วัด ให้สอบถามฝ่ายบริการในฐานะลูกค้าที่อยากปฏิบัติให้ถูก ว่าเกณฑ์ตัวเลขคืออะไร บันทึกคำถามและคำตอบ
  5. เทียบคำตอบที่ได้กับข้อความในสัญญา บันทึกว่าคำตอบเพิ่มความชัดหรือไม่
  6. บันทึกตารางประเมินรายข้อและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพข้อสัญญาทุกข้อที่เกี่ยวข้องพร้อมหมายเลขข้อ (`RST-BRKA-P03-236-01` ถึง `-NN`) · ตารางประเมินตัวชี้วัดรายข้อ (`RST-BRKA-P03-236-10`) · บันทึกคำถาม–คำตอบกับฝ่ายบริการ
- **ผ่าน:** ทุกข้อที่ใช้เป็นเหตุยกเลิกกำไรได้ มีตัวชี้วัดที่วัดได้ระบุไว้ในสัญญาหรือในคำตอบที่เป็นลายลักษณ์อักษร
- **ไม่ผ่าน:** มีอย่างน้อย 1 ข้อที่ไม่มีตัวชี้วัดใด และเมื่อสอบถามแล้วยังไม่ได้เกณฑ์ที่ชัดภายใน `[เกณฑ์เสนอ: 14 วัน]`
- **ยังไม่ได้ตรวจ:** สัญญาไม่เปิดให้ดาวน์โหลดหรืออ่านฉบับเต็มได้ (ต้องบันทึกความพยายามไว้ครบ)
- **ตัวอย่าง:** สัญญาของ Broker A ระบุว่าบริษัทอาจยกเลิกกำไรที่เกิดจาก *"รูปแบบการเทรดที่บริษัทเห็นว่าไม่เหมาะสม"* โดยไม่มีตัวเลขใด และฝ่ายบริการตอบว่า *"ขึ้นกับการพิจารณาของฝ่ายที่เกี่ยวข้อง"* → **ไม่ผ่าน**

**P03-239 · มีการบังคับให้คงยอดขั้นต่ำไว้ในบัญชีเมื่อถอนกำไรหรือไม่ และประกาศไว้หรือไม่** `w2` `PAY+WEB`

  2. บันทึกเวลาปิดสถานะที่ทำกำไรจากการเทรดตามปกติ เป็น UTC พร้อมหมายเลขรายการและยอดกำไร เต็มทศนิยม
  3. เปิดหน้ายอดคงเหลือทันทีหลังปิดสถานะ บันทึกยอดรวมและยอดที่ระบบระบุว่าถอนได้ แล้วจับภาพ
  4. เปิดหน้าเดิมซ้ำ `[เกณฑ์เสนอ: ทุก 12 ชั่วโมง จนครบ 7 วัน]` บันทึกยอดที่ถอนได้ทุกครั้งพร้อมเวลา UTC
  5. ระบุเวลาแรกที่ยอดกำไรก้อนนั้นถูกนับเป็นยอดที่ถอนได้ แล้วคำนวณระยะล็อกจริงเป็นชั่วโมง
  6. ยื่นคำขอถอนที่รวมกำไรก้อนนั้นทันทีที่ระบบระบุว่าถอนได้ บันทึก `T0` และผลว่าคำขอถูกรับหรือถูกปฏิเสธ
  7. เทียบระยะล็อกจริงกับตัวเลขที่ประกาศ บันทึกส่วนต่างเป็นชั่วโมง
  8. บันทึกตารางเวลา–ยอดที่ถอนได้ และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้ายอดที่ถอนได้ทุกครั้งที่บันทึกพร้อมเวลา (`RST-BRKA-P03-244-01` ถึง `-NN`) · รายงานบัญชีที่แสดงเวลาปิดสถานะและยอดกำไร (`RST-BRKA-P03-244-20`) · สำเนาถาวรหน้าที่ประกาศระยะเวลา (`RST-BRKA-P03-244-21`) · ตารางเวลา–ยอดที่ถอนได้
- **ผ่าน:** กำไรถอนได้ทันทีหลังปิดสถานะ หรือมีระยะล็อกแต่ประกาศไว้ก่อนกดยืนยัน และระยะที่บังคับใช้จริงไม่เกินตัวเลขที่ประกาศ
- **ไม่ผ่าน:** มีระยะล็อกที่ไม่ปรากฏในเอกสารใดก่อนกดยืนยัน หรือระยะที่บังคับใช้จริงยาวกว่าตัวเลขที่ประกาศเกิน `[เกณฑ์เสนอ: 24 ชั่วโมง]`
- **ยังไม่ได้ตรวจ:** ตลอดรอบตรวจไม่มีสถานะที่ปิดแล้วได้กำไร หรือระบบไม่แยกแสดงยอดที่ถอนได้ออกจากยอดคงเหลือรวมจนวัดระยะล็อกไม่ได้ (ต้องบันทึกภาพหน้าจอที่ยืนยันว่าไม่มีการแยกแสดง)
- **ตัวอย่าง:** ผู้ตรวจที่ Broker A ปิดสถานะได้กำไร 320 หน่วย หน้าเงื่อนไขระบุว่ากำไรถอนได้หลัง 24 ชั่วโมง แต่ยอดที่ถอนได้เพิ่งขยับหลังผ่านไป 118 ชั่วโมง และคำขอที่ยื่นก่อนหน้าถูกปฏิเสธด้วยเหตุ *"ยอดยังไม่พร้อมถอน"* → **ไม่ผ่าน**

**P03-245 · การเข้าร่วมโปรแกรมส่งเสริมการขายหรือการเลื่อนระดับบัญชี เพิ่มเงื่อนไขการถอนโดยลูกค้าไม่ได้เลือกหรือไม่** `w3` `ACC+DOC`

- **ตรวจอะไร:** ตรวจว่าบัญชีของผู้ตรวจถูกใส่เข้าโปรแกรมส่งเสริมการขาย โปรแกรมสะสมแต้ม หรือถูกเลื่อนระดับบัญชีโดยอัตโนมัติหรือไม่ และการเข้าร่วมนั้นทำให้เงื่อนไขการถอนเปลี่ยนไปหรือไม่ พร้อมตรวจว่ามีทางถอนตัวออกจากโปรแกรมได้จริงหรือไม่ และการถอนตัวมีผลกระทบต่อยอดที่มีอยู่หรือไม่ ข้อนี้ต่างจาก `P03-229` ที่ตรวจเงื่อนไขผูกโบนัสที่ลูกค้าไม่เคยรับ — ข้อนี้ตรวจ **กลไกการเข้าร่วมและการถอนตัวจากโปรแกรม และผลของมันต่อสิทธิการถอน**
- **ขั้นตอนการตรวจ:**
  1. เปิดหน้าโปรไฟล์บัญชีและหน้าโปรแกรมส่งเสริมการขายทั้งหมด บันทึกสถานะการเข้าร่วมของบัญชีผู้ตรวจ พร้อมจับภาพและเวลา UTC
  2. ค้นย้อนหลังในอีเมลและข้อความในระบบ ว่าผู้ตรวจเคยกดสมัครโปรแกรมใดหรือไม่ บันทึกวันที่และข้อความที่พบ หรือบันทึกว่าไม่พบการสมัครใด
  3. เปิดเงื่อนไขของทุกโปรแกรมที่บัญชีถูกนับว่าเข้าร่วม ค้นข้อที่กระทบการถอน คัดลอกคำต่อคำพร้อมหมายเลขข้อ
  4. เทียบเงื่อนไขการถอนของบัญชีที่อยู่ในโปรแกรม กับเงื่อนไขมาตรฐานที่ประกาศบนหน้าสาธารณะ บันทึกข้อที่ต่างกันเป็นตาราง
  5. ค้นปุ่มหรือช่องทางถอนตัวจากโปรแกรม บันทึกว่าพบหรือไม่พบ ถ้าพบให้จับภาพข้อความเตือนที่ระบบแสดงก่อนถอนตัว
  6. สอบถามผ่านช่องทางลูกค้าปกติว่าถอนตัวออกจากโปรแกรมแล้วเงื่อนไขการถอนกลับเป็นมาตรฐานหรือไม่ และยอดที่มีอยู่ได้รับผลกระทบหรือไม่ บันทึก `T5` และคำตอบ
  7. บันทึกตารางเทียบเงื่อนไขและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ภาพหน้าสถานะการเข้าร่วมโปรแกรมของบัญชี (`RST-BRKA-P03-245-01`) · สำเนาถาวรเงื่อนไขโปรแกรมทุกฉบับที่เกี่ยวข้อง (`RST-BRKA-P03-245-02` ถึง `-NN`) · ภาพช่องทางถอนตัวหรือภาพยืนยันว่าไม่มีช่องทาง (`RST-BRKA-P03-245-10`) · บันทึกคำถาม–คำตอบกับฝ่ายบริการ · ตารางเทียบเงื่อนไข
- **ผ่าน:** บัญชีไม่ถูกใส่เข้าโปรแกรมใดโดยอัตโนมัติ หรือถูกใส่แต่เงื่อนไขการถอนไม่ต่างจากมาตรฐาน หรือต่างแต่ลูกค้าถอนตัวออกได้เองภายใน `[เกณฑ์เสนอ: 5 วันทำการ]` โดยยอดที่มีอยู่ไม่ถูกหัก
- **ไม่ผ่าน:** บัญชีถูกใส่เข้าโปรแกรมโดยผู้ตรวจไม่ได้กดสมัคร และเงื่อนไขการถอนเข้มขึ้นอย่างน้อย 1 ข้อ โดยไม่มีช่องทางถอนตัวหรือถอนตัวแล้วยอดที่มีอยู่ถูกหัก
- **ยังไม่ได้ตรวจ:** โบรกไม่มีโปรแกรมส่งเสริมการขายหรือระดับบัญชีใดเลย (ต้องบันทึกภาพหน้าโปรไฟล์บัญชีและหน้าสาธารณะที่ยืนยันข้อเท็จจริงนี้)
- **ตัวอย่าง:** บัญชีของผู้ตรวจที่ Broker C ถูกแสดงสถานะ *"ระดับเงิน"* โดยผู้ตรวจไม่เคยกดสมัคร และเงื่อนไขระดับเงินกำหนดว่าต้องเทรดครบปริมาณที่กำหนดก่อนถอนกำไร ทั้งที่หน้าสาธารณะไม่มีเงื่อนไขนี้ และไม่มีปุ่มถอนตัวจากระดับ ฝ่ายบริการตอบว่า *"ระบบกำหนดให้อัตโนมัติ ยกเลิกไม่ได้"* → **ไม่ผ่าน**

**P03-246 · ข้อความเรื่องการถอนกำไรในสื่อโฆษณาและหน้าโปรโมชัน ตรงกับเงื่อนไขที่บังคับใช้จริงหรือไม่** `w2` `PUB+WEB`

- **ตรวจอะไร:** ตรวจว่าคำโฆษณาที่โบรกเผยแพร่สู่สาธารณะเกี่ยวกับการถอน เช่น ข้อความทำนอง "ถอนได้ทันที" "ไม่มีค่าธรรมเนียมถอน" "ถอนกำไรได้ตลอดเวลา" ตรงกับเงื่อนไขที่พบจริงในเอกสารสัญญาและที่ระบบบังคับใช้จริงหรือไม่ ต้องเก็บข้อความโฆษณาแบบคำต่อคำพร้อมแหล่งและวันที่ แล้วจับคู่ทีละข้อความกับข้อสัญญาและกับผลจริงที่ผู้ตรวจวัดได้ในข้อก่อนหน้าของหมวดนี้ ข้อนี้ตรวจ **ความไม่ตรงกันระหว่างคำโฆษณากับเงื่อนไขจริง** ไม่ใช่รสนิยมการใช้ถ้อยคำ
- **ขั้นตอนการตรวจ:**
  1. รวบรวมสื่อสาธารณะของโบรกที่กล่าวถึงการถอน ได้แก่ หน้าแรก หน้าโปรโมชัน หน้าคำถามพบบ่อย และบัญชีสื่อสังคมทางการ จับภาพทุกหน้าพร้อม URL และเวลา UTC
  2. คัดข้อความที่เป็นคำกล่าวอ้างเรื่องการถอนออกมาทีละข้อความ บันทึกคำต่อคำ พร้อมแหล่งและวันที่เผยแพร่ถ้ามี
  3. เปิดสำเนาถาวรของสัญญาและหน้าเงื่อนไขการถอน ค้นข้อที่ควบคุมคำกล่าวอ้างแต่ละข้อ บันทึกหมายเลขข้อและข้อความ
  4. จับคู่คำกล่าวอ้างกับผลจริงที่วัดได้จาก `P03-226` `P03-240` `P03-244` และ `P03-249` บันทึกตัวเลขจริงที่ใช้เทียบทุกครั้ง
  5. ทำเครื่องหมายแต่ละคำกล่าวอ้างว่า ตรง ตรงบางส่วน หรือขัดกับเงื่อนไขจริง พร้อมเหตุผลหนึ่งบรรทัด
  6. เก็บสำเนาถาวรของหน้าโฆษณาทุกหน้าที่ถูกใช้เทียบ เพราะเนื้อหาเปลี่ยนได้ตลอดเวลา
  7. บันทึกตารางจับคู่คำกล่าวอ้าง–ข้อสัญญา–ผลจริง และตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** สำเนาถาวรทุกหน้าโฆษณาที่ใช้เทียบ พร้อม URL และเวลา (`RST-BRKA-P03-246-01` ถึง `-NN`) · ภาพข้อสัญญาที่ควบคุมแต่ละคำกล่าวอ้าง (`RST-BRKA-P03-246-20`) · ตารางจับคู่คำกล่าวอ้าง–ข้อสัญญา–ผลจริง (`RST-BRKA-P03-246-30`)
- **ผ่าน:** ทุกคำกล่าวอ้างเรื่องการถอนในสื่อสาธารณะ มีเงื่อนไขจริงรองรับ หรือมีข้อจำกัดกำกับไว้ในหน้าเดียวกันในลักษณะที่ลูกค้าอ่านเห็นได้โดยไม่ต้องเปิดหน้าอื่น
- **ไม่ผ่าน:** มีคำกล่าวอ้างอย่างน้อย 1 ข้อความที่ขัดกับเงื่อนไขในสัญญา หรือขัดกับผลจริงที่ผู้ตรวจวัดได้ โดยไม่มีข้อจำกัดกำกับไว้ในหน้าเดียวกัน
- **ยังไม่ได้ตรวจ:** โบรกไม่มีสื่อสาธารณะที่กล่าวถึงการถอนเลย หรือผู้ตรวจยังไม่มีผลจริงจากข้อ `P03-226` `P03-240` `P03-244` `P03-249` มากพอจะจับคู่ได้
- **ตัวอย่าง:** หน้าแรกของ Broker A ระบุว่า *"ถอนกำไรได้ทันที ไม่มีเงื่อนไข"* แต่สัญญากำหนดปริมาณการเทรดขั้นต่ำก่อนถอนกำไร และผู้ตรวจวัดได้ว่าคำขอที่มีกำไรถูกกันไว้ 5 วันก่อนอนุมัติ โดยหน้าแรกไม่มีข้อความกำกับข้อจำกัดใด → **ไม่ผ่าน**

**P03-247 · การถอนกำไรทำให้สถานะหรือเงื่อนไขของบัญชีเปลี่ยนไปในทางเสียเปรียบหรือไม่** `w2` `ACC+PLT`

- **ตรวจอะไร:** ตรวจว่าหลังจากถอนกำไรออกไปแล้ว บัญชีถูกปรับสถานะหรือเงื่อนไขการเทรดให้แย่ลงหรือไม่ เช่น ถูกลดระดับบัญชี ถูกเปลี่ยนประเภทบัญชี ถูกเปลี่ยนเงื่อนไขราคาหรือค่าธรรมเนียมการเทรด ถูกลดวงเงินหรือเครื่องมือที่ใช้ได้ ต้องบันทึกค่าตั้งต้นของบัญชีก่อนถอนทุกตัวแปร แล้วเทียบกับค่าเดียวกันหลังถอน โดยเปรียบเทียบที่ **ช่วงเวลาตลาดใกล้เคียงกันและตราสารเดียวกัน** เพื่อไม่ให้ความผันผวนของตลาดทำให้อ่านผลผิด
- **ขั้นตอนการตรวจ:**
  1. บันทึกค่าตั้งต้นของบัญชีก่อนยื่นคำขอถอนกำไร ได้แก่ ประเภทบัญชี ระดับบัญชี ค่าธรรมเนียมการเทรดที่แสดง วงเงินที่ใช้ได้ และรายการตราสารที่เปิดให้เทรด พร้อมจับภาพทุกหน้าและเวลา UTC
  2. บันทึกค่าราคาที่แสดงของตราสารอ้างอิงที่เลือกไว้ `[เกณฑ์เสนอ: 3 ตราสาร]` เป็นชุดตัวเลข ณ เวลาเดียวกัน
  3. ยื่นคำขอถอนที่มีส่วนของกำไรตามการใช้บริการปกติ บันทึก `T0` และยอดที่ขอ
  4. หลังคำขอปิดสถานะแล้ว ให้เปิดหน้าเดิมทุกหน้าอีกครั้งในช่วงเวลาของวันเดียวกันกับรอบแรก บันทึกค่าเดิมทุกตัวแปร พร้อมจับภาพและเวลา UTC
  5. เทียบค่าก่อน–หลังทีละตัวแปร บันทึกตัวแปรที่เปลี่ยน ทิศทางการเปลี่ยน และขนาดการเปลี่ยนเป็นตัวเลข
  6. ทำซ้ำการวัดหลังถอน `[เกณฑ์เสนอ: 3 ครั้ง ห่างกันครั้งละ 2 วัน]` เพื่อแยกการเปลี่ยนถาวรออกจากความผันผวนชั่วคราว
  7. ค้นในสัญญาและหน้าเงื่อนไขว่ามีข้อใดระบุว่าการถอนมีผลต่อสถานะบัญชีหรือไม่ บันทึกข้อที่พบหรือบันทึกว่าไม่พบ
  8. บันทึกตารางเทียบก่อน–หลัง และตั้งชื่อไฟล์ตาม Evidence ID

**P03-249 ● · คำขอถอนที่มีส่วนของกำไร ใช้เวลานานกว่าคำขอเงินต้นล้วนที่ยอดและช่องทางเดียวกันหรือไม่** `w3` `PAY` `G4`

  6. ตรวจว่าข้อที่ผูกด่าน `G4` ในหมวดนี้ ข้อใดถูกตัดสินว่าไม่ผ่านบ้าง แล้วบันทึกเป็นรายการแยก
  7. บันทึกตารางสรุปหมวดและตั้งชื่อไฟล์ตาม Evidence ID
- **หลักฐานที่ต้องเก็บ:** ตารางสรุปสถานะรายข้อของทั้งหมวด (`RST-BRKA-P03-250-01`) · รายการ Evidence ID ที่เปิดไม่ได้หรือหายไป (`RST-BRKA-P03-250-02`) · บันทึกการจัดกลุ่มปัญหาและรายการข้อที่ผูกด่าน G4 ที่ไม่ผ่าน (`RST-BRKA-P03-250-03`)
- **ผ่าน:** ทุกข้อของ `P03-226` ถึง `P03-249` ตรวจแล้วครบและมีสถานะเป็น ผ่าน หรือ ไม่ผ่าน เท่านั้น ไม่มีข้อใดค้างเป็น ยังไม่ได้ตรวจแม้แต่ข้อเดียว และไฟล์หลักฐานตาม Evidence ID ที่อ้างเปิดได้ทุกรายการ
- **ไม่ผ่าน:** มีข้อใดไม่มีสถานะกำกับ หรือมีไฟล์หลักฐานที่ถูกอ้างแล้วเปิดไม่ได้ หรือมีข้ออย่างน้อย 1 ข้อใน `P03-226` ถึง `P03-249` ที่ยังคงเป็น ยังไม่ได้ตรวจ
- **ยังไม่ได้ตรวจ:** รอบตรวจของไฟล์นี้ยังไม่ปิด จึงยังสรุปผลรวมของหมวดไม่ได้ (ต้องระบุวันที่คาดว่าจะปิดรอบไว้)
- **ตัวอย่าง:** ผู้ตรวจสรุปหมวดของ Broker B ได้ 24 ข้อครบทุกสถานะ แต่ Evidence ID สามรายการที่อ้างในข้อ `P03-235` และ `P03-244` เปิดไม่ได้เพราะไฟล์ถูกบันทึกทับ และมีข้อที่เป็น ยังไม่ได้ตรวจ 9 ข้อ → **ไม่ผ่าน** (มีข้อค้างยังไม่ได้ตรวจ) และต้องเก็บหลักฐานรอบใหม่ก่อนออกผลของเสานี้
