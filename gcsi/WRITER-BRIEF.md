## 2. รูปแบบบังคับของข้อตรวจ — 8 ส่วน ครบทุกข้อ

```markdown
**P0X-NNN ● · ชื่อข้อที่บอกได้ว่าตรวจอะไร** `w3` `WEB` `G1`

- **ตรวจอะไร:** <ย่อหน้าเดียว บอกว่าต้องดูอะไร ที่ไหน ตัวแปรใดที่ต้องบันทึก ละเอียดพอที่ผู้ตรวจสองคนอ่านแล้วเข้าใจตรงกัน>
- **ขั้นตอนการตรวจ:**
  1. <คำสั่งที่ทำตามได้ทันที ขึ้นต้นด้วยคำกริยา>
  2. <…>
  3. <…>
  4. <…>
  5. <…>
  6. <ขั้นสุดท้ายต้องเป็นการบันทึกผลและตั้งชื่อไฟล์หลักฐานเสมอ>
- **หลักฐานที่ต้องเก็บ:** <ชนิดไฟล์ + Evidence ID + สำเนาถาวรถ้าเนื้อหาเปลี่ยนได้>
- **ผ่าน:** <เงื่อนไขเดียว ชัดเจน ไม่ต้องตีความ>
- **ไม่ผ่าน:** <เงื่อนไขเดียว ชัดเจน ไม่ต้องตีความ>
- **ยังไม่ได้ตรวจ:** <กรณีเฉพาะของข้อนี้ ถ้าไม่มีให้เขียน "ตามนิยามกลาง">
- **ตัวอย่าง:** <กรณีก้ำกึ่ง ใช้ชื่อสมมติ Broker A/B/C จบด้วย → **ผ่าน** หรือ → **ไม่ผ่าน**>
```

**บรรทัดหัวข้อ** ต้องขึ้นต้นด้วย `**P0X-NNN` ชิดซ้ายเสมอ (สคริปต์นับใช้ regex นี้)
ข้อที่โชว์บนเว็บใส่ `●` คั่นด้วยช่องว่างหนึ่งเคาะหลังรหัส: `**P01-001 ● · ...`

### รหัสที่ใช้ได้

| กลุ่ม | ค่า |
|---|---|
| น้ำหนัก | `w3` วิกฤต (กระทบเงิน/สิทธิโดยตรง) · `w2` สำคัญ (กระทบต้นทุน/คุณภาพ) · `w1` พื้นฐาน (ความโปร่งใส) |
| วิธี | `WEB` `REG` `ACC` `DOC` `PLT` `TRD` `PAY` `SUP` `STM` `PUB` (ผสมได้ เช่น `REG+WEB`) |
| ด่าน | `G1`–`G6` เฉพาะข้อที่ผูกด่านบังคับ ถ้าไม่ผูกไม่ต้องใส่ |

### กฎย่อยที่ตกบ่อย

1. **ขั้นตอนขั้นต่ำ 4 ขั้น** — ข้อภาคปฏิบัติ (PAY/TRD/SUP) ต้อง 6–10 ขั้น
2. ทุกขั้น **ขึ้นต้นด้วยคำกริยา** — เปิด · กด · กรอก · จับเวลา · บันทึก · เทียบ · ดาวน์โหลด · ทำซ้ำ
3. ถ้าต้องทำซ้ำ **ต้องบอกจำนวนครั้งและระยะห่าง** เช่น "ทำซ้ำ 3 รอบ ห่างกันรอบละ 1 สัปดาห์"
4. ถ้าวัดเวลา **ต้องบอกว่านับจากเหตุการณ์ใดถึงเหตุการณ์ใด และใช้ UTC**
5. ถ้าเทียบกับภายนอก **ต้องบอกแหล่งที่เทียบ และเก็บภาพแหล่งนั้นที่เวลาเดียวกัน**
6. Evidence ID รูปแบบ `RST-BRKA-P01-004-01` — ใช้รหัสโบรกสมมติ `BRKA` ทุกไฟล์
7. **ตัวเลขเกณฑ์ตัดสินทุกตัวที่ยังไม่ได้ประกาศ ต้องเขียนเป็น `[เกณฑ์เสนอ: …]`** — ห้ามแต่งตัวเลขลอย ๆ
8. ตัวอย่าง **ห้ามใช้ชื่อโบรกจริง** เด็ดขาด ใช้ Broker A / B / C เท่านั้น
9. **ผ่าน/ไม่ผ่านต้องครอบคลุมกันพอดี** ห้ามมีช่องว่างที่ตัดสินไม่ได้
10. ห้ามข้อซ้ำกับไฟล์อื่น — ยึดขอบเขตหมวดย่อยของไฟล์ตาม `ITEM-MAP.md` อย่างเคร่งครัด

## 3. โครงไฟล์ — ทุกไฟล์เหมือนกันหมด

```markdown
# P0X · <ชื่อเสา> — ไฟล์ N/6 (ข้อ NNN–NNN)

**มิติ DX · น้ำหนักเสา X% · คุมด่าน GX**
**ขอบเขตไฟล์นี้:** S<nn> <หมวดย่อยที่ 1> · S<nn> <หมวดย่อยที่ 2>

> รูปแบบและกฎการเขียนดูที่ [`../INSPECTION-STANDARD.md`](../INSPECTION-STANDARD.md)
> `●` = โชว์บนเว็บ · `w1/w2/w3` = น้ำหนัก · `G1–G6` = ด่านบังคับ
> **ชื่อโบรกในตัวอย่างเป็นชื่อสมมติทั้งหมด**
> Evidence ID ในไฟล์นี้ใช้รหัสโบรกสมมติ `BRKA`

---

## S<nn> · <หมวดย่อยที่ 1> (NNN–NNN)

<25 ข้อ>

---

## S<nn> · <หมวดย่อยที่ 2> (NNN–NNN)

<25 ข้อ>
```

- **ทุกไฟล์ 50 ข้อพอดี** แบ่ง 2 หมวดย่อย หมวดละ 25 ข้อ
- รหัสข้อ **นับต่อเนื่องทั้งเสา** `P0X-001` … `P0X-300` ไม่ใช่รีเซ็ตรายไฟล์
- ใช้ [`p01-01.md`](pillars/p01-01.md) เป็นแม่แบบอ้างอิงคุณภาพ

## 4. วิธีผลิต — ห้ามทำผิดวิธี (บทเรียนจากรอบที่แล้ว)

| # | ห้าม | ให้ทำแทน |
|---|---|---|
| 1 | เขียนไฟล์ 200 KB รวดเดียว | เขียน **หัวไฟล์ + 10 ข้อแรก** ด้วย Write แล้ว **ต่อท้ายทีละ 10 ข้อ** ด้วย Edit |
| 2 | ใช้ heredoc / `echo` ผ่าน shell | ใช้เครื่องมือ **Write / Edit** เท่านั้น — parser พังมาแล้ว |
| 3 | รายงานว่าเขียนครบโดยไม่นับ | **นับจากไฟล์จริงด้วยสคริปต์** ก่อนรายงานทุกครั้ง |
| 4 | เขียนทับไฟล์ที่มีข้อเดิมอยู่แล้ว | ถ้าไฟล์มีอยู่แล้ว ให้ **อ่านท้ายไฟล์ก่อน** แล้วต่อจากข้อสุดท้าย ห้ามลบของเดิม |

### คำสั่งนับที่ต้องรันก่อนรายงาน

```bash
powershell -c "Get-ChildItem C:\RedStarTrust\gcsi\pillars\*.md | Sort-Object Name | ForEach-Object { $raw=[System.IO.File]::ReadAllText($_.FullName,[System.Text.Encoding]::UTF8); $t=([regex]::Matches($raw,'(?m)^\*\*P\d{2}-\d{3}')).Count; $p=([regex]::Matches($raw,'(?m)^\*\*P\d{2}-\d{3}\s+●')).Count; [PSCustomObject]@{File=$_.Name;Items=$t;Public=$p} } | Format-Table -AutoSize"
```

## 5. โควตา `●` ที่โชว์บนเว็บ

เป้าหมายทั้งชุด **1,000 ข้อ** = เสาละ **100 ข้อ** → โควตารายไฟล์ **17 · 17 · 17 · 17 · 16 · 16**

- ระหว่างเขียน ให้ติด `●` **ตามโควตาของไฟล์ตัวเอง** (ไฟล์ที่ 1–4 ใส่ 17 ข้อ · ไฟล์ที่ 5–6 ใส่ 16 ข้อ)
- เลือกข้อที่ **ผู้อ่านทั่วไปเข้าใจได้เอง** และข้อที่ผูกด่าน `G1`–`G6`
- ข้อที่เป็นการควบคุมคุณภาพภายในของผู้ตรวจ (เช่น การเก็บ hash) **ห้ามติด ●**
