## 2. GCSI คืออะไร (สรุปเท่าที่จำเป็นต่อการทำงานต่อ)

**GCSI = Global Client Safety Index** — เกณฑ์ตรวจโบรกเกอร์ CFD/Forex ฉบับร่าง 2.0

**หลักการที่ห้ามลืม:** ตรวจในฐานะ **เทรดเดอร์รายย่อยแฝงตัว** — โบรกไม่รู้ตัว ไม่มีสิทธิพิเศษ ไม่ขอเอกสารภายใน ไม่เปิดเผยตัว
บททดสอบข้อเดียว: *"ลูกค้ารายย่อยที่ไม่มีสถานะพิเศษทำข้อนี้ได้จริงไหม"* — ตอบไม่ได้ = ข้อนั้นตก

## 4. งานที่ผมทำเสร็จแล้ว (15 ส.ค. 2569)

Boss สั่งให้แก้จุดที่ขัดกัน 4 ข้อที่ผมพบตอนอ่านโปรเจ็ค — **แก้ครบแล้ว**

| # | จุดที่ขัดกัน | สิ่งที่แก้ |
|---|---|---|
| 1 | ITEM-MAP บังคับ "ไฟล์ละ 25 ข้อ" × 6 = 150/เสา ขัดกับ README ที่ 100/เสา | แก้ `ITEM-MAP.md` เป็นตารางโควตา **17·17·17·17·16·16 = 100** + กฎ "ห้ามเกินห้ามขาด ไฟล์ใดไม่ตรงโควตา = ยังไม่ผ่านการตรวจรับ" |
| 2 | `p01-01.md` สรุปท้ายไฟล์เขียน G1 = 13 ข้อ แต่จริง 14 | แก้บรรทัดสรุปเป็น ● 17 · G1 14 |
| 3 | README §6 เขียน "แบ่งไฟล์ย่อยละ 100 ข้อ" ขัดกับของจริงที่ 50 | แก้เป็น 6 ไฟล์ × 50 ข้อ |
| 4 | README §6 ระบุไฟล์ที่ยังไม่มี และตกไฟล์ที่มีอยู่จริง | เพิ่ม `INSPECTION-STANDARD.md` + `ITEM-MAP.md` · ใส่คอลัมน์สถานะ (ภายหลัง Doing มาต่อยอดตารางนี้) |

**งานเพิ่มเติมที่ทำ:**
- ถอด `●` ออกจาก `p01-01.md` 8 ข้อ (18 → 17 ตรงโควตา) — ถอดจาก P01-028, 029, 030, 034, 041, 042, 043, 045 · เก็บข้อ G1 ครบ 14 ข้อ + P01-024, 025, 033 · **ไม่มีข้อใดถูกลบ** แค่ย้ายไปเป็นข้อหลังบ้าน
- แก้บรรทัดสรุปท้ายไฟล์ที่ตัวเลขค้างเป็น "โชว์บนเว็บ 25 ข้อ" ใน **7 ไฟล์** ให้ตรงจำนวนจริง: `p01-02/03/04` → 17 · `p01-05/06` → 16 · `p02-01/02` → 17
- ตรวจแล้วว่าจำนวนข้อผูกด่าน (G1/G3/G6) ในบรรทัดสรุปของ 7 ไฟล์นั้น **ถูกต้องอยู่แล้ว** ไม่ต้องแก้

**เกณฑ์เลือกว่าข้อไหนได้ติด `●` (จาก ITEM-MAP) — ใช้ชุดนี้ต่อถ้าต้องปรับอีก:**
1. ข้อผูกด่าน G1–G6 ติด `●` เกือบทั้งหมด (สาธารณะควรรู้)
2. ผู้อ่านทั่วไปเข้าใจได้โดยไม่ต้องมีความรู้เฉพาะทาง
3. ข้อควบคุมคุณภาพภายในของผู้ตรวจเอง (เก็บ hash, เก็บสำเนาถาวร) **ไม่ควรติด `●`**

```powershell
$r = Get-ChildItem C:\RedStarTrust\gcsi\pillars -Filter *.md | Sort-Object Name | ForEach-Object {
  $h = Get-Content $_.FullName -Encoding UTF8 | Where-Object { $_ -match '^\*\*P\d{2}-\d{3}' }
  $w = ($h | Where-Object { $_ -match ([char]0x25CF) }).Count
  [pscustomobject]@{ File=$_.Name; Items=$h.Count; Web=$w; OffQuota=($w -ne $q[[int]$_.Name.Substring(4,2)-1]) }
}
"FILES: {0}  ITEMS: {1}  WEB: {2}  OFF-QUOTA: {3}" -f $r.Count, ($r|Measure-Object Items -Sum).Sum, ($r|Measure-Object Web -Sum).Sum, ($r|Where-Object OffQuota).Count
$r | Where-Object { $_.Items -ne 50 -or $_.OffQuota } | Format-Table -AutoSize
```

## 7. บทเรียนทางเทคนิคที่ต้องจำ

**⚠️ การนับอักขระ `●` ในไฟล์ภาษาไทย — เคยนับผิดมาแล้วและรายงาน Boss ผิด**

- **ห้ามใช้** `Select-String` แล้วต่อด้วย `-match '●'` ใน PowerShell 5.1 → ได้ตัวเลขผิด (เคยได้ 23 ทั้งที่จริง 25)
- **ให้ใช้** `Get-Content -Encoding UTF8` แล้ว match ด้วย `([char]0x25CF)` **หรือ** ใช้เครื่องมือ Grep
- **Read tool อาจไม่แสดงอักขระ `●`** ในบางบรรทัด — อย่าเชื่อสายตาจาก Read ให้ยืนยันด้วย Grep เสมอ

**บทเรียนที่ Doing บันทึกไว้เรื่องการสั่งงาน Going** (`RESUME.md` §3) — ถ้าถูกสั่งให้เขียนไฟล์เสา ให้ทำตามนี้:
- รับงานครั้งละ **ไม่เกิน 4–5 ไฟล์** (เคยรับ 17 ไฟล์พร้อมกันแล้วชน session limit ตายกลางทาง 14 ไฟล์)
- **เขียนหัวไฟล์ + 10 ข้อ แล้วต่อท้ายทีละ 10 ข้อ** อย่าเขียนไฟล์ 200 KB รวดเดียว
- ใช้เครื่องมือ Write/Edit **ห้ามใช้ heredoc ผ่าน shell** (parser พัง)
- **รายงานจากการนับไฟล์จริงเสมอ** อย่ารายงานจากความจำ — เคยรายงานว่าเขียนครบทั้งที่ไฟล์ไม่ครบ

**การแก้ไฟล์เสา:** หัวข้อข้อตรวจรูปแบบ `**P0X-NNN ● · ชื่อข้อ** `wN` `วิธี` `GN``
ถอด `●` = ลบ `● ` ออกจากหัวข้อเท่านั้น ไม่แตะเนื้อหาข้างใน · แก้บรรทัด "สรุปไฟล์" ท้ายไฟล์ให้ตรงจำนวนจริงด้วยทุกครั้ง
